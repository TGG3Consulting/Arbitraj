## Что сделано

1. **Формат ядра** — `gateway/price_band.rs`: `PriceBandRule` (множители опорной цены по сторонам + постоянные границы
   + текст «от какой цены») в `SpotPairState.price_band` (необязательный, `#[serde(default)]`, Box); `PriceBand`
   (границы сейчас); `miss` — внутри / «дальше» (покупка выше верха, продажа ниже низа) / «не с той стороны». Контракт
   `price_band(asset)` (по умолчанию NotApplicable).
2. **Адаптеры** (по таблице): MEXC, Binance — правило из справочника × опорная цена по REST; Bybit — готовые
   границы; Poloniex — highestBid / lowestAsk без запроса; XT и OKX — разбор есть, ядру не отдаётся (ревью).
   Остальные — без изменений.
3. **Ядро** — `core/price_band.rs`: перед пересчётом предпроверки (precheck.rs) у сторон-бирж с правилом — чтение
   обеих сторон одновременно → `DirCtx.band_a / band_b` → `precheck::replan_pre`; в `costs.rs` после `order_limits`
   — `price_band::check` для A (покупка) и B (продажа): «дальше» → `Fail::TooLarge` (подбор объёма монотонен — берёт
   меньший объём внутри коридора), «не с той стороны» → `Fail::Stop`. Не прочитан — без коридора (как раньше) и строка
   в журнал / хронологию.
4. **Отказ покупки PriceOutOfRange** — без паузы направления только при учтённом коридоре A (`buy_refusal_pauses`,
   Calc::buy_band, ревью Б2), пометка `NO_PAUSE_RANGE`.
   «Ордер отправлен и не исполнился» (OrderNotFilled) — как раньше.
5. **Правило шлюза** — для PriceOutOfRange только своё (общее и площадки); `pick_rule_or_fallback` удалён (меняет
   дополнение A2 решения 268). Совет FIRST_RUN — «Отменить, не повторять».
6. **Пробный ордер** (п. 4 задания): проверка продажи на B (precheck_sell.rs) идёт после пересчёта — объём плана уже
   ограничен коридором B, худшая цена берётся по живому стакану на этот объём; отказ коридором теперь случается, только
   если цена / стакан сдвинулись после чтения коридора. Поведение «отказ — сделки нет» оставлено: это защита (не
   покупаем то, что сейчас не продать). Согласовано.

## Отказ PriceOutOfRange, когда своё правило шлюза НЕ задано (ревью прогона 777ccf54)

По коду core/rules_apply.rs on_error: журнал core.op_error, уведомление события кода и счётчик ошибок подряд (не
считается) — до выбора правила, как раньше. Дальше:
- было (дополнение A2 решения 268): бралось правило OrderRejected — CancelNoRetry / NotifyOnly → Next::Stop; StopVenue /
  StopAll → Next::Stop и пауза площадки / всего; Retry для кода уже был запрещён → Next::Stop;
- стало: правила нет → Warn core.rules «Правила для PriceOutOfRange нет — операция остановлена» → Next::Stop.

Вызывающий (исполнение сделки, sell_range) получает тот же Next::Stop при любом прежнем правиле OrderRejected; пропадает
только пауза площадки / всего, если OrderRejected = «Стоп площадка» / «Стоп всё» — это и требовалось задачей
(отказ по коридору цены одной монеты не останавливает биржу). Хуже не становится — запасной путь к OrderRejected не
возвращён. Тест tests/core_price_range_268.rs `retry_rule_does_not_apply_and_errors_not_counted` проверял старое
поведение A2 (устарел из-за решения 390) — переписан: Next::Stop, запись «правила нет», паузы площадки нет.

## Правки по ревью t180 (второй коммит правок)

- Б2: без паузы направления отказ покупки PriceOutOfRange идёт только если лимит покупки посчитан внутри
  прочитанного коридора A (Calc::buy_band). У бирж, где коридор не читается (BingX, Bitget, KuCoin, Gate, HTX, CoinEx),
  или когда чтение не удалось — пауза, как до решения 390: иначе каждый тик слал бы тот же отклонённый ордер.
- Б3 / Н5: XT и OKX коридор ядру не отдают (опорная цена XT и спот OKX документацией прямо не подтверждены).
- Н2: MEXC ticker/price — вес 10 в окне venue.public_ip_weight_10s, без пропуска сверх бюджета и без ожидания
  (места нет — запрос не уходит, расчёт без коридора). Тест tests/mexc_ip_weight.rs использовал ticker/price как
  пример пути «без веса»: ошибся не код, а пример теста стал неверным, когда у пути появился вес из документации;
  путь сделки по-прежнему не ждёт ограничителя (slot для срочных не менялся), пример заменён на /api/v3/trades.
- Н3: коридор читается одновременно с шагами сторон предпроверки; у Binance три запроса одновременно; строка времени
  «коридор цены (одновременно с шагами сторон)». Сторона B оставлена (согласует пробный ордер продажи и не покупает
  то, что B сейчас не примет), идёт одновременно со стороной A.
- Н4: подтверждено по коду (final_calc отвергает сделку целиком, если финальная котировка сдвинула цену за коридор),
  не исправлено — docs/TASKS.md.

## Пример «было → стало»

MEXC, монета X: последняя сделка 0.0010, bidMultiplierUp 0.2 → покупка не дороже 0.0012. Стакан: 10 000 монет по
0.0011, 50 000 по 0.0013. На B монету покупают по 0.01.
- Было: подбор взял 60 000 монет, лимит покупки 0.0013 → MEXC 30087 на весь ордер → сделка закрыта, направление на
  паузе `signal.route_cooldown_s`, ничего не заработано.
- Стало: перед покупкой прочитан коридор (≤ 0.0012); объём 60 000 даёт худшую цену 0.0013 → TooLarge → подбор берёт
  10 000 по 0.0011 — ордер проходит, прибыль считается на 10 000 (если она выше порогов). Если всё же отказ (цена
  сдвинулась) — сделка закрыта без паузы направления, следующий сигнал считается заново.

- Пересчёты после предпроверки, собирающие контекст заново (refit.rs, precheck_dex_cut.rs — меньший объём; buy_replan.rs

  Binance `<symbol>@referencePrice` / `<symbol>@avgPrice`, XT — лента сделок): тогда коридор был бы в памяти и у
  кандидата, без REST в предпроверке. Решает Тигран.
