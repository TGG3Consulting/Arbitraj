### Н1: правило вытеснения (на пальцах)

Цикл измерил покупку на 1 / 20 / 100 USDT, hooks.impact_points = 2. Сделки пробуют 26, 32, 38 USDT. После третьей
пробы точек сделки 3 > 2: вытесняется точка с наименьшим относительным зазором до соседней, кроме самой новой (38):
у 26 наименьший зазор — до 32: (32 − 26)/32 = 0,19, у 32 — до 38: (38 − 32)/38 = 0,16 → вытесняется 32, её влияние переходит БОЛЬШЕЙ соседке 38 (максимум; независимое
ревью t173, Н-1: передача меньшей соседке завышала малые суммы).
Значение на 32 после этого — ближайшая большая точка (38), не меньше факта на 32 (лесенка неубывающая) — расчёт не
лучше факта; наибольшее влияние не падает.

### Н5: ветки записи

- check/hook_store.rs fold_head: правило вернуло None → `false` → поколение (решение 352) не растёт, checked_at и
  hook_wait не трогаются (короб допуска 363 — ключ hook_mark не меняется).
- on_success: без лесенки — None; лесенка не изменилась — None (`m != *old`, hook_fold.rs:138); изменилась (новая
  точка, вытеснение) — запись и рост поколения (нужен: котировка видит новую лесенку).
- on_failure: без лесенки — None; ничего не убрано — None (новое); убрано — запись.
- put_head (цикл, перемер) — пишет всегда, когда блок не старше записанного: это новый замер (новый блок, новое время).
- Пропуска нужного повышения нет: всякое изменение фактов пула идёт через update_pool_if с `true`.

### Н4: почему новая настройка

Существующего предела времени пути сделки нет: verify.timeout_ms — предел одного перечтения пулов маршрута,
verify.max_staleness_blocks — отставание прочитанного блока от головы, send.* — после отправки. Поэтому — число
hooks.trade_probe_rounds_max (необязательное; не задано — ровно два круга).

### Н7: почему без настройки

Повторная проба делается на блоке первой (eth_call с номером блока; записи верификации маршрута — только того же
блока, иначе пулы читаются на нём в том же пакете). Все точки сделки — одна картина пула; разрыв «между пробами»
исчезает по построению. Возраст картины — не больше времени двух (или hooks.trade_probe_rounds_max) кругов до узла.
Дальше по пути сделки — прежние страховки (верификация, симуляция, amountOutMin).

### Н-ж: граница риска

Покрыто: вход каждого шага с крючком и в путях «как посчитаны», и в путях по порядку исполнения (resequence) — факт
квотера на этой сумме. Не покрыто: крючок, влияние которого зависит от СОСТОЯНИЯ пула после прошлых долей (квотер
меряет на состоянии блока). В записях такого крючка нет (у 0x32c59d… влияние зависит от суммы; гипотеза о
зависимости от состояния не проверена). Страховки: бандл — eth_simulateV1 проводит доли по порядку (exec/bundle_send.rs),
откат — сделки нет; amountOutMin каждой ноги (exec/leg_min.rs) — потеря доли не больше допуска минимума; исполнитель
(умный режим) — amountOutMin и MixedQuoter.

## Нагрузка на узел (по коду)

- Цикл крючков: на пул с крючком за hooks.recheck_interval_s — до 2 · n вызовов квотера (n = hooks.impact_points на

## Независимое ревью t173 — правки

- Н-1: значение вытесненной точки — большей соседке (меньшей — только при вытеснении последней): суммы не больше меньшей
  соседки не меняются, на суммах до вытесненной значение — большая соседка ≥ вытесненной (не лучше факта). Пример
  ревью: GAIB цикл 1 / 20 / 100 USDT, предел 2, сделки 21 / 60 / 90 — вытесняется 21; раньше 0,674 % уходило точке
  20 USDT (суммы 1–20 считались с 0,674 % вместо 0,099 %), теперь — точке 60.
- Н-3: resequence в цикле пробы сделки — только когда шаг может завершиться или поставить пробу.
- Падение b2_failure_cuts_side_only (прогон ff3e71a3): ошибся тест. Помощник записи даёт точкам продажи usd = 0 (вход
  в монетах), а правило Н1 считает usd = 0 точкой сделки: при пределе (по точкам цикла стороны — 0 → 1) три «точки
  сделки» продажи обрезались, итог менялся. У цикла крючков usd точек продажи > 0 (check/hooks_probe.rs ladder). Тест
  получил суммы 1 / 20 / 100 USDT продажи (README записи); код — предел применяется, только если проба добавила точку
  сделки.
- Н-5 — вопрос в TASKS; Н-6 — открыто в TASKS; Н-2 — при слиянии с t168.

## Слияние с решением 382 (t168) в rel/dex-all — независимое ревью t173, Н-2

На втором проходе t168 (Quoting.pinned — пулы маршрута, перечитанные на голове H после расхождения с квотером) пути
считаются и сверяются на H, а проба крючка t173 начиналась с pin = None и шла на блоке верификации маршрута
(route_fresh, старше H) или на голове latest (новее H): влияние крючка снималось не на том блоке, что пути и сверка.
Правка при слиянии:
- exec/hook_trade.rs paths: начальный pin = quoter_refetch::block(v.q) (блок H, если перечитывание было; иначе None —
  как раньше, блок первой пробы);
- exec/trade_probe.rs hooks_again: записи пробы — Quoting.pinned раньше Quoting.route_fresh (тот же фильтр по pin).
check/hook_batch.rs measure берёт записи, только если в них есть все пулы пробы; иначе читает пулы на блоке head, а он
при pin = Some(H) равен H — проба в любом случае на H. Без теста на записи (асинхронный путь с узлом).
