# t186 — проба шага пула менеджера через исполнитель кошелька (решение 401, 17.11.2026)

Ветка t186/hook-probe-executor от rel/dex-all 4656c113. Цель владельца (17.11): «V4, V3, V2 — все DEX и всё, что с ними
связано, должно активно торговаться». cargo локально не запускался — сборка и тесты в GitHub.

## 1. Как было (факт кода 4656c113)

### 1.1. Проверки пулов (src/venues/bsc_dex/check/)

Группа крючка (core/types/pool.rs HookGroup; pools/hooks.rs): A — не трогает обмен и комиссию; B — динамическая комиссия
или before/afterSwap без ReturnsDelta; C — может менять сумму (ReturnsDelta). Допуск котировки — quote/select.rs hook:

Факты пула — check/state.rs PoolFacts (по PoolRef), общие для всех кошельков (кроме налогов сделки t78). Факта «пускает ли
крючок вызывающего» нет нигде: проба налогов и квотер вызывают пул через Universal Router / квотер, не через исполнитель.

### 1.2. Исполнимость шага исполнителем (котировка и сделка — одно правило)

`exec/executor/entry.rs fits(e)` → supported + ключ (валюты ERC-20 = пара записи) + `live_proof::admits(вид, Stable,
крючок)` — класс принят записью симуляции (решение 400). Зовут: quote/graph_executor.rs all_via, quote/graph_fit.rs (S2),
exec/executor/mod.rs takes (сделка), exec/cycle_gate.rs step_why (DEX ↔ DEX), check/probe_exec.rs emitter. Сборка шага
— entry.rs singleton (тот же admits) ← call::build (сделка, сухая сделка). Перед каждым шагом `via_executor` (вид шага,
адрес исполнителя кошелька, версия: шаги 19–21 только у v3 — pools/exec_callback.rs step_missing). fits видел только
запись реестра — фактов проверок и кошелька не видел.

Приняты на записи 17.11: Uniswap V4 без крючка, Infinity CL без крючка. Не приняты: V4 с крючком, CL с крючком, Bin, Stable.

### 1.3. Что торгуется у кошельков v2 (все 10 кошельков живого бота — v2, проверено чтением 17.11)

- Пулы V4 / Infinity CL / Bin / Stable (tradable = да) — Universal Router своей DEX: прямой путь, умный путь (все шаги в
  одном UR) или бандл свопов (каждая доля внутри одного роутера, dex.bundle_max_routers, каналы с бандлом). С крючком — если
  группа допущена и влияние в пределе (quote/select.rs), с пробой крючка на сумме сделки (exec/hook_trade.rs).
- Маршрут, где V4 / Infinity смешан в ОДНОЙ ноге с DEX без своего UR (DODO, Algebra, Solidly, …) или роутеров больше
  dex.bundle_max_routers, — у v2 не исполняется (шагов 19–21 в v2 нет), сигнал.
- Через исполнитель v3 (после развёртывания) — только принятые классы и только там, где бандла нет (bundle_first).

### 1.4. Проба перед сделкой через исполнитель

exec/executor/sim.rs run (сделка с переводом, через remeasure.rs) и exec/cycle_exec.rs probe (DEX ↔ DEX): одна
eth_simulateV1 `execute` от кошелька поверх блока сборки, minOut, цена. Откат — сделки нет, но пул нигде не помечался:
следующий сигнал строился через тот же пул.

## 2. Что сделано (решение 401)

### 2.1. Проба (check/pass_probe.rs, разбор — check/pass_judge.rs)

Для пула шага менеджера (вид 19 / 20 / 21, Infinity Stable) и КАЖДОГО кошелька с исполнителем v3 (у записи кошелька
версия «v3», сверена onchain.rs) — две eth_simulateV1 от адреса кошелька поверх головы H, вторая — продолжение первой:

1. перевод встречного токена (USDT или промежуточная) на кошелёк из другого пула реестра (как проба налогов) на
   check.probe_usdt; approve исполнителю; квотер DEX на покупку; `execute` одним шагом пула; balanceOf(исполнитель) по
   обоим токенам;
2. то же + approve монеты; квотер на продажу купленного (состояние после покупки); `execute` продажи; остатки.

**Адрес — настоящий исполнитель кошелька, код не подменяется.** Крючок получает `sender` = msg.sender вызова swap
менеджера (факт официального кода, копии в contracts/evmtest/vendor: v4-core src/libraries/Hooks.sol beforeSwap —
`abi.encodeCall(IHooks.beforeSwap, (msg.sender, …))`; infinity-core src/pool-cl/libraries/CLHooks.sol beforeSwap — так же),
а swap менеджера в сделке вызывает сам исполнитель. Поэтому проба на «виртуальном» адресе ничего не говорит о настоящем:
запись t185 шла на X = 0x…a4b0e0c3, и её «отверг / пустил» к адресам кошельков не переносится (гипотеза, не проверено:
крючки 0xddc53a1a… «UA» и 0x70201397… «Not allowed» проверяют именно sender — их кода в репозитории нет). Нет v3 у кошелька — проб нет, факт «не
проверено», пул через исполнитель этого кошелька идёт только по приёмке класса (решение 400).

Итог стороны (pass_judge.rs side):
- execute откатился крючком пула — WrappedError(target = крючок ключа) — **отвергнут** («крючок 0x… отверг вызов
  исполнителя (функция крючка 0xe592dc93): UA»);
- откатился, а квотер ответил — **отвергнут** (квотер пропускает, исполнитель — нет);
- откатились и квотер, и исполнитель без крючка — **не проверено** (пул не берёт сумму пробы — свойство суммы);
- прошёл: получено > 0, |получено − квотер| / квотер ≤ dex.quoter_max_diff_pct, остаток на исполнителе 0 по обоим токенам;
  иначе — отвергнут (расхождение, остаток) или не проверено (квотер не ответил, нули, не по ABI, срок вышел).

Пул: обе стороны прошли — **проходит**; иначе первый отказ. До пробы: налоги монеты в ЭТОМ пуле (PoolFacts.taxes) измерены
и все нули, иначе «не проверено» (налоговая монета через исполнитель пулом менеджера не идёт: вход переводом через
исполнитель — налог дважды, quote/graph_executor.rs tax; выход с налогом с квотером не сверить). Сбой узла, нет пула-
источника, откат подготовки (перевод из источника, approve) — помеха: прежний факт остаётся.

Пример (запись узла 17.11, тест tests/bsc_dex_pool_pass_401.rs): пул Infinity CL 0x25c3a0dd… с крючком 0xddc53a1a…:
покупка 20 USDT прошла, получено = квотер 10783822784291601; продажа откатилась
`WrappedError(hook=0xddc53a1a…, selector=0xe592dc93, reason=Error("UA"))` → «отвергнут: продажа: крючок 0xddc53a1a… отверг
вызов исполнителя (функция крючка 0xe592dc93): UA». Пул 0xc6104625… с крючком 0x5c9717dd…: обе стороны совпали с квотером,
остаток 0 → «проходит».

### 2.2. Факт и перепроверка (exec/executor/pool_pass.rs, check/pass_cycle.rs)

Факт — по (адрес исполнителя, пул): проходит / отвергнут (причина; deal = откат пробы сделки) / не проверено (причина),
время, блок. Только в памяти (как check/state.rs): после запуска — до первой пробы действует приёмка класса.

Перепроверка — существующий цикл крючков (check/cycle.rs one → pass_cycle::pool, Box::pin): полный проход раз в
hooks.recheck_interval_s, «Перепроверить», «новые пулы», «пул готов», смена настройки. Новой настройки и своего опроса нет.
Пробуется пул, если класс записью не принят, или пул помечен откатом сделки. Смена итога — поколение итогов проверок
(эпоха котировки, решение 352) и журнал dex.check.

Откат пробы сделки (sim.rs run, cycle_exec.rs probe → pool_pass::on_sim, синхронно): не помечает успех, срок, minOut.
WrappedError с крючком пула вызова — помечается пул этого крючка; иначе — пулы, допущенные только пробой (by_pass).
Метка «отвергнут» держится до перепроверки ближайшим проходом цикла крючков.

### 2.3. Одно правило (exec/executor/pool_gate.rs)

entry.rs fits(ctx, e) и singleton → pool_gate::admits(ctx, e, вид, крючок), кошелёк — окружения (счёт сделки или строка
«Пробы»):
- факт «проходит» — исполним (и в непринятом классе);
- факт «отвергнут» — НЕ исполним (и в принятом классе);
- нет факта / «не проверено» — решение 400 (только принятый класс).

Места: graph_executor all_via, graph_fit S2, executor/mod.rs takes, cycle_gate step_why, probe_exec emitter, call::build
(singleton). Проба перед отправкой и minOut — как были. Отвергнутый пул не выбрасывается: если маршрут собирается бандлом /
Universal Router — идёт им (bundle_first и прежние формы), иначе сигнал с причиной «… исполнитель v3 кошелька «…»:
отвергнут (время): …».

### 2.4. Нагрузка (по коду)

За проход цикла крючков: (пулы менеджера непринятых классов + помеченные откатом) × (кошельки с v3) × 2 eth_simulateV1 +
пачка balanceOf источников на встречный токен (Sources — на проход). Все запросы — через общую очередь узла
(node/pace.rs, bsc.node_http_rps). Пока ни у одного кошелька нет v3 — ни одной пробы. Пробы последовательны внутри цикла
крючков (как его квотер), отдельного таймера нет.

### 2.5. Интерфейс

- «Монеты» → карточка пула (PoolDepthCell, details): «исполнитель v3: класс «…» принят записью / не принят — через
  исполнитель только после пробы этого пула» и по каждому кошельку с v3: «проходит обе стороны (время, блок)» / «отвергнут
  (время): причина» / «не проверено: причина».
- «Маппинг кошельков» → таблица «Классы шага v3» (ExecutorDeploy): колонка «Пулы кошелька» — у непринятого класса «прошли
  / отвергнуты / не проверено», у принятого — «отвергнуты пробой или откатом сделки». Данные — по каждому кошельку
  (GET /api/wallets executor_v3_classes[].live).

## 3. Что начнёт торговаться и когда

**Сразу после выкладки (все кошельки v2): ничего не меняется** — шагов 19–21 у v2 нет (step_missing), проб нет.

**После развёртывания v3 владельцем на кошельке (кнопка уже доступна, решение 400):**
- с первым проходом цикла крючков (при старте — сразу, как пул достоверен; далее раз в hooks.recheck_interval_s) каждый
  пул V4 с крючком, Infinity CL с крючком, Infinity Bin, Infinity Stable пробуется через исполнитель этого кошелька;
- «проходит» — шаг пула исполним исполнителем этого кошелька: маршруты, где такой пул смешан с DEX без своего UR (DODO,
  Algebra, Solidly, …) или бандл не собирается (роутеров больше предела, каналы без бандла), из сигнала становятся сделкой
  одной транзакцией через v3. Где бандл / UR собирается — по-прежнему бандл / UR (bundle_first);
- «отвергнут» — пул идёт прежним путём; «не проверено» — как решение 400.

Условия «проходит»: налоги монеты в пуле измерены и нули; есть пул-источник встречного токена с суммой пробы; квотер DEX
отвечает на обе стороны; получено совпало с квотером в dex.quoter_max_diff_pct; остаток 0. Пул должен ещё пройти обычные
допуски котировки (налоги, крючок B/C — hooks.allowed_groups и предел влияния, сверка с квотером, глубина).

## 4. Чего запись не проверяет (честно)

- Сборка пробы через узел (pass_probe.rs) — не прогонялась: запись t185 шла на виртуальном X с подменой кода и подменой
  балансов (stateDiff), а проба 401 — настоящим адресом исполнителя, перевод USDT из пула-источника, без подмен. Проверить
  после развёртывания v3: журнал dex.check (итоги проб), карточка пула.
- Разбор итога (pass_judge.rs) проверен на записанных ответах узла (calls.json / raw_rpc): 7 «проходит», 6 «отвергнут»
  (Not allowed — 1, UA — 4 на покупке, 1 на продаже), 3 «не проверено».
- Откат по minOut в записи не встречается — правило «minOut не помечает» проверено только кодом (remeasure::is_min_out).
- Uniswap V4 с крючком, Infinity Bin с ликвидностью, Infinity Stable в записи отсутствуют — для них проба 401 и есть
  первая проверка на живых пулах.
- Факт по крючку с белым списком меняется, если владелец крючка добавит / уберёт исполнитель — перепроверка ловит это
  следующим проходом; между проходами страхует проба execute перед отправкой и метка откатом сделки.
