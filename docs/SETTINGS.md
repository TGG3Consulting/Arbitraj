# SETTINGS — каталог настроек

> Каждый параметр системы описан здесь и в `src/settings/schema.rs`. В коде значений нет.
> **Стартовых значений нет.** Все параметры задаёт Тигран в интерфейсе.
> Параметр не задан → функция, которой он нужен, не работает, а интерфейс показывает, что его нужно задать.
> Торговля не включается, пока не заданы все параметры групп `money.*` и `risk.*`.
> Новый параметр → строка здесь + описание в `schema.rs` + поле в интерфейсе (экран «Настройки»).

## Узел BSC

Ключ провайдера стоит в адресе (NodeReal, Infura — research/flow/bsc_node.md): в настройке пишется `{key}`,
сам ключ — секрет `bsc.node_ws_key` / `bsc.node_http_key` (docs/SECURITY.md). Нет `{key}` — секрет не нужен.

| Имя | Что означает | Единица | Область |
| --- | --- | --- | --- |
| bsc.node_ws_url | WebSocket узла BSC (подписки logs; номер блока — опросом по HTTP, решение 57) | URL | вся система |
| bsc.blocks_poll_ms | Опрос номера блока eth_blockNumber по HTTP вместо подписки newHeads (решение 57): раз в столько мс; строго меньше feed.stale_after_ms (иначе подписка на рынок DEX не начинается — причина в журнале). Опрос идёт мимо очереди bsc.node_http_rps, чтобы проверки не отодвигали его (от него зависит свежесть): к узлу добавляется 1000 / значение вызовов в секунду (eth_blockNumber — 5 CU у NodeReal). Время блока для deadline и пробы налогов — eth_getBlockByNumber (15 CU) только по запросу, раз на блок. Не задана — подписка на рынок DEX не начинается | мс | вся система |
| bsc.node_http_url | HTTP узла BSC (eth_call, eth_getLogs, eth_estimateGas, квитанции) | URL | вся система |
| bsc.node_http_rps | Темп вызовов узла HTTP — именно вызовов JSON-RPC в секунду, не CU провайдера (у NodeReal лимит в CU, цена методов разная — значение подбирается под тариф; node/pace.rs): все запросы адаптера DEX (проверки, сверка, загрузка пулов) идут в общей очереди не чаще этого; пачка JSON-RPC из N вызовов — N. На «превышен лимит» (HTTP 429) — правило шлюза «Превышен лимит запросов» (RateLimited, Retry: пауза всей очереди и повтор); правила нет — проверка «не выполнена», не вердикт. Не задана — запросы к узлу не уходят | вызовов в секунду | вся система |

| send.max_wait_blocks | Сколько блоков ждать квитанции, прежде чем отменить транзакцию (0 BNB себе с тем же nonce, цена газа выше на send.cancel_gas_bump_pct); снова не занят — следующая отмена через столько же блоков, дороже | блоков | по площадке DEX |
| send.replaced_confirm_blocks | Nonce кошелька занят, а своей квитанции нет: сколько ещё блоков искать её (квитанция и eth_getTransactionByHash по исходной и отменам), прежде чем «вытеснена» (исход неизвестен — ручная проверка) | блоков | по площадке DEX |
| send.cancel_max_gas_gwei | Потолок цены газа отмены; следующая отмена дороже — отмен больше нет, очередь кошелька остановлена до ручной проверки (Telegram send.queue_halted) | gwei | по площадке DEX |
| send.cancel_max_attempts | Сколько отмен одной транзакции; больше — очередь кошелька остановлена до ручной проверки | раз | по площадке DEX |
| send.queue_max_wait_s | Сколько очередь кошелька ждёт итога одной транзакции (узел недоступен, нет BNB на отмену, nonce не перечитан); дольше — остановка до ручной проверки | секунды | по площадке DEX |
| send.bundle_max_blocks | Бандл: maxBlockNumber = текущий блок + это число (не больше send.max_wait_blocks, иначе отправка не работает) | блоков | по площадке DEX |
| send.cancel_gas_bump_pct | Не попала за send.max_wait_blocks — отмена: 0 BNB себе с тем же nonce, цена газа выше прошлой на столько % (очередь кошелька ждёт, пока nonce не занят в блоке) | % | по площадке DEX |
| send.deposit_confirmations | Зачисление в кошелёк (депозит DEX): «Зачислен» — только при ненулевом Transfer монеты на кошелёк и когда после блока перевода прошло столько блоков | блоков | по площадке DEX |

### Каналы отправки (область «канал», id — из списка адаптера DEX)

Ключ канала — секрет `channel.<id>.key`; если по документации канала ключ стоит в адресе — в `channel.url` пишется `{key}`.
Открытая отправка (`public`) идёт через узел или провайдера: `{key}` в её `channel.url` заменяется ключом узла — секрет `bsc.node_http_key` (как в `bsc.node_http_url`).

Поиск пулов: V2 — `getPair`, V3 — `getPool` по `dex.v3_fee_tiers` (без истории блоков), стартуют сразу. V4 — в фоне, история
`Initialize` от блока развёртывания менеджера (бинарный поиск `eth_getCode`); блок, найденные пулы и последний прочитанный блок
хранятся в SQLite (таблица `venue_state`) — после перезапуска читаются только новые блоки;
узлу нужен доступ к истории состояния (архивный) — «Проверить подключение» площадки DEX это показывает.
Канал с ключом не используется, пока ключ не введён (решение 41). Несколько закрытых каналов — параллельно и без чаевых;
открытый канал — только один, не вместе с закрытыми (решение 33).

| Имя | Что означает | Единица |
| --- | --- | --- |
| channel.enabled | Канал включён | да/нет |
| channel.url | Адрес канала из его официальной документации | URL |
| channel.method | `single` — одиночная / `bundle` — бандл из одной транзакции без разрешения на откат (решение 43) | выбор |
| channel.min_gas_price_gwei | Минимальная цена газа канала; ниже — в канал не отправляется (решение 44) | gwei |
| channel.tip_enabled | Чаевые билдеру включены | да/нет |
| channel.tip_bnb | Сумма чаевых | BNB |
| channel.tip_address | Куда переводить чаевые — адрес из официальной документации канала | адрес |

## Области значений

Значение задаётся для области: вся система, площадка, монета, событие, DEX, канал отправки.
Для системы, площадки и монеты действует самое узкое заданное: монета сильнее площадки, площадка сильнее всей системы.
Событие, DEX и канал — отдельные предметы: значение задаётся ровно для своего id, без подстановки.
Для какой области можно задавать настройку — в `src/settings/catalog/`.

| Область | id | Откуда список id |
| --- | --- | --- |
| Площадка (`venue:`) | `bingx`, `bsc_dex` | реестр шлюза (`GET /api/venues`) |
| Монета (`coin:`) | тикер | справочник монет |
| Событие (`event:`) | код события | `src/notify/catalog.rs` |
| DEX (`dex:`) | имя DEX (`pancakeswap`) или вид пула (`pancakeswap_v3`) | адаптер DEX: `dex_families()` |
| Канал (`channel:`) | id канала (`club48`) | адаптер DEX: `send_channels()` |

Почему DEX и канал — свои области, а не «площадка»: это части одного адаптера `bsc_dex` (один кошелёк, один узел),
а не отдельные площадки реестра; у них свой набор настроек, и подстановка «монета → площадка → система» к ним не подходит.

## Виды значений

`Decimal`, `Integer` (может иметь верхнюю границу `max`), `Bool`, `Text`, `Url` (только https/wss), `TextList`, `Ip`,
`Choice` (один из вариантов `choices`), `Address` (адрес BSC: 0x + 40 hex), `AddressList` (список адресов BSC). Описание — `src/settings/schema.rs`.

Область «площадка» у настроек времени в пути (`profit.transit_*`) означает **площадку, с которой переводим** (решение 51):
`bingx` — вывод BingX → кошелёк, `bsc_dex` — кошелёк → биржа. В схеме это `venue_role: "TransferSource"`; интерфейс подписывает области направлением.
