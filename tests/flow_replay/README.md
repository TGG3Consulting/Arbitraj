# Сравнение кадров перед очередью ядра и после неё

`market_flow_replay.rs` пропускает упорядоченные записи через штатный `BookOut::book` и общий `core_out::Feed` с включённым сохранением последнего снимка. Для рынка пула используется тот же ключ площадки и контракта, что при публикации обновления из реестра. Замеры запускает GitHub Actions, workflow **Recorded market flow**.

* **Архив**. В 191 окне за 14–16 ноября записано 14 970 кадров. Источник содержит вспомогательный канал BingX для окна, который не публикует стаканы ядру. После его исключения повторные кадры пересекающихся окон объединяются по площадке, тикеру и наносекунде получения. Перед объединением сверяются уровни. Архив покрывает только рынки и периоды своих окон.
* **Стаканы SOL и пул BSC**. Происхождение компактных записей — в [описании источника](../data/market_flow_2026-11-23/README.md). Потоки разделены по времени наблюдения. Для пула известны блок и состояние после Swap. Время приёма этого состояния работающим ботом неизвестно.
* **Режим потребителя**. Контрольный прогон освобождает канал после каждого входного события. В остальных сценариях потребитель освобождает его на границе корзины времени или номера блока. Вместимость 1 и 8 относится к экспериментальному каналу. 1993 мс взяты как наблюдавшийся максимум задержки публикации BSC для сценария нагрузки, фактические времена освобождения канала неизвестны.
* **Планы**. Python связывает план с окном только при совпадении площадки, направления, монеты и включении момента плана в интервал от начала окна до последнего штатного кадра. Считает достижение исходной валовой выручки на всём исходном объёме продажи по десяти записанным бидам. Если плану соответствуют два окна, он попадает в отдельный счётчик. Несколько планов могут видеть один физический кадр. Для SOL дополнительно замораживаются DEX-покупка, постоянные расходы и доли комиссии продажи и резерва в выручке. Без свежей котировки покупки и сопоставимых часов обеих ног такие сравнения не измеряют исполнимую чистую прибыль.
* **Граница входа**. В MEXC tap записывается до `ws_out::give`. Основные/быстрые каналы, повтор полных уровней и старое время могут остановить публикацию. Полная глубина и состояние соединения в архиве отсутствуют. 6584 декодированных снимка подаются в штатную очередь как контролируемый вход; точный состав производственного входа неизвестен.
* **Метрики**. Для книги age — наносекунды от получения кадра адаптером до конца смоделированной корзины; для пула — блоки. Для каждой доставленной книги, проходящей порог выручки, сравнивается последняя записанная книга рынка на момент сценарной доставки. Момент за концом окна или недостаточная наблюдаемая глубина учитываются как неизвестный исход. `resource.txt` содержит CPU, время и максимальный RSS тестового процесса на GitHub, включая чтение записей и запись промежуточного файла идентификаторов. Сборка и сводка Python измеряются отдельно от процесса Rust.
