# SETTINGS_CASES — журнал настроек: зачем создана, что ставить, что будет, если не задана

> Правило Тиграна (17.11.2026): **каждая новая настройка** получает здесь запись **в том же коммите**, где она появилась
> в каталоге (`src/settings/catalog/*.rs`). Настройки создаются пачками, потом про них забывают — этот файл не даёт забыть.
> Сторож — `tests/settings_cases_guard.rs`: ключ из каталога без записи здесь (и не в списке долга
> `tests/data/settings_cases_legacy.txt`) — тест падает.
>
> Только факты: кейс — из `docs/DECISIONS.md` и `docs/notes/`; совет — из `docs/FIRST_RUN.md` / `config/first_run.toml`;
> поведение без значения — по коду (файл:строка). Нет факта — так и пишется, вопрос — в `docs/TASKS.md`.

## Формат записи (проверяет сторож)

Заголовок — `### ` и ключ в обратных кавычках, ниже — поля списком, каждое на одной строке:

- **Задача / решение:** номер t… и номер решения из `docs/DECISIONS.md`.
- **Появилась:** дата и коммит первого появления ключа в каталоге (`git log -S`).
- **Кейс:** какой реальный случай её породил — простыми словами, с цифрами, если они записаны. *(обязательно, не пусто)*
- **Где задаётся:** экран интерфейса и область (вся система / по площадке / по направлению / по монете / DEX).
- **Что ставить:** совет из FIRST_RUN; нет совета — «совета нет, решает Тигран». *(обязательно, не пусто)*
- **Если не задана:** точное поведение по коду, файл:строка. *(обязательно, не пусто)*
- **Влияет на торговлю:** да / нет — и как.
- **Связанные ключи:** что работает рядом.
- **Статус:** «в релизе <sha>» или «ещё не в релизе (ветка …)».

Ключ, которого нет в каталоге этой ветки, допускается только со статусом «ещё не в релизе» или «удалена».

## Записи

### `exec.dex_buy_replan_max`

- **Задача / решение:** t167, решение 381.
- **Появилась:** 2026-11-17, коммит f46e9958.
- **Кейс:** живой случай ESIM bsc_dex → kucoin 17.11: из 17 покупок на DEX не исполнились 14 при плановой прибыли 0.9–4.9 USDT на ~40 USDT (2.3–12 % вложения); 8 — «Цена в пуле сейчас … хуже допустимой», 2 — верификация «свежая средняя цена дороже границы сделки», 2 — «не попала в блок». Сделка снималась при сдвиге цены больше допуска, даже когда прибыль оставалась выше порога (DECISIONS 381, docs/notes/t167-buy-price-moved-2026-11-17.md).
- **Где задаётся:** «Площадки» → карточка DEX и «Настройки», группа «Исполнение»; область — по площадке, читается только у площадки DEX (bsc_dex).
- **Что ставить:** `1`; поднять до `2`, если в хронологиях «Пересчёт плана после срыва покупки» второй срыв подряд — тоже «цена ушла», а прибыль нового плана заметно выше порога (docs/FIRST_RUN.md).
- **Если не задана:** 0 — пересчёта нет, как до решения 381: срыв покупки DEX закрывает сделку. Код: src/core/buy_replan.rs:49-58 (не задана, не читается или площадка покупки не DEX — 0), src/core/executor.rs:432 (повтор только при `tries < replans`).
- **Влияет на торговлю:** да — после срыва «цена ушла» до отправки бот покупает по новому плану, если он выше порогов прибыли; каждый пересчёт держит монету занятой (десятки мс — до секунд).
- **Связанные ключи:** exec.dex_slippage_pct, money.min_profit_usd, money.min_profit_pct; уведомление deal.replanned.
- **Статус:** в релизе 141619bc.

### `hooks.trade_probe_rounds_max`

- **Задача / решение:** t173, решение «335 (лесенка влияния, ревью 4 — правки)», замечание Н4.
- **Появилась:** 2026-11-17, коммит e13e702b.
- **Кейс:** ревью 4 (Н4): предел кругов пробы крючка на пути сделки брался из числа точек лесенки hooks.impact_points — это другое число. Два круга (проба на оценке и проба с подъёмом) сделаны константой способа; больше двух — только этим числом, потому что предела времени пути сделки в проекте нет (docs/notes/t173-hook-ladder-review4-2026-11-17.md, «Н4: почему новая настройка»). Живого случая (монета, цифры) в документах нет.
- **Где задаётся:** «Площадки» → карточка DEX и «Настройки», группа «Налоги и крючки»; область — по площадке, читается только у площадки DEX (bsc_dex). Значение — целое больше нуля.
- **Что ставить:** не задавать (ровно два круга). Задавать `3`, только если в журнале dex.check / причинах отказа часто «не покрыто фактом пробы за 2 кругов» (docs/FIRST_RUN.md).
- **Если не задана:** ровно два круга пробы; 1 работает как 2. Код: src/venues/bsc_dex/exec/hook_trade.rs:59-63 (не задана — None; задана в неверном виде — ошибка пути сделки), src/venues/bsc_dex/exec/hook_drive.rs:56 (`unwrap_or(2).max(2)`).
- **Влияет на торговлю:** да — вход, не покрытый фактом пробы за предел, получает отказ «не покрыто фактом пробы за N кругов»; каждый лишний круг — ещё одна задержка до узла перед отправкой.
- **Связанные ключи:** hooks.impact_points. Открытый вопрос Тиграну (Н-5) про верхний предел — docs/TASKS.md.
- **Статус:** в релизе 141619bc.

### `dex.shallow_pools_per_pair`

- **Задача / решение:** t178, решение 393 (ревью t178, Б2; ревью 2 — Н-B1, Н-B2).
- **Появилась:** 2026-11-17, коммит 1c9458ac.
- **Кейс:** живой бот (разбор extreme-5): 213 монет «не проверено», из них 212 — «нет достоверного пула, глубокого в оба направления (dex.min_pool_liquidity_usd = 10 в полосе dex.depth_band_pct = 2 %)», 210 из них есть на бирже (NFP, BRIC, VEREM и др.). Решение 393 пустило мелкие пулы в пробу налогов; ревью t178 (Б2) ограничило их число на пару этой настройкой — это предел нагрузки, который тестом не замерить (DECISIONS 393, docs/notes/t178-tax-probe-shallow-2026-11-17.md).
- **Где задаётся:** «Площадки» → карточка DEX и «Настройки», группа «DEX»; область — по площадке, читается только у площадки DEX (bsc_dex). Смена на лету пересобирает граф и подписку.
- **Что ставить:** `1` — начать с одного мелкого пула на пару, посмотреть нагрузку (время прохода налогов и сверки с квотером, CPU, log.quote_timing, очередь узла) и число монет «не проверено»; затем 2–3 (docs/FIRST_RUN.md).
- **Если не задана:** 0 — мелкие пулы не допускаются, как до решения 393: мелкая сторона не котируется, мелкие пулы не пробуются, не сверяются с квотером, спят, не в графе. Код: src/venues/bsc_dex/quote/shallow_pick.rs:36-42 (не задана или неверна — 0), :131-133 (admitted = false), src/venues/bsc_dex/quote/select.rs:110-116 (отказ мелкой стороны).
- **Влияет на торговлю:** да — больше монет с мелкими пулами проверяются и торгуются; выше нагрузка (eth_simulateV1 пробы, вызовы квотера, события ws, рёбра графа).
- **Связанные ключи:** dex.min_pool_liquidity_usd, dex.depth_band_pct, check.probe_usdt, dex.quoter_max_diff_pct.
- **Статус:** в релизе 141619bc.
