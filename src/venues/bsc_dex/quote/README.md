# venues/bsc_dex/quote — котировка DEX

Режим `dex.swap_mode`: `direct` — лучший одиночный пул (решение 29); `smart` — умный маршрут по пулам PancakeSwap
против прямой сделки в лучшем пуле Uniswap, берётся больший итог (решение 38).

| Файл | Что делает |
| --- | --- |
| `mod.rs` | Вход котировки: режим, свежесть блока, decimals, сборка, газ разрешений, чаевые |
| `select.rs` | Можно ли использовать пул: включён, крючок допущен и в допуске, сверен с квотером, газ измерен, ликвидность ≥ `dex.min_pool_liquidity_usd` |
| `pool_quote.rs` | Обмен в одном пуле по локальной математике; полная комиссия V4 (протокольная + LP) |
| `direct.rs` | Лучший пул с учётом налогов монеты и влияния крючка; расчёт доли в пуле (`calc`); частичная ликвидность → `fillable_qty` |
| `smart.rs` | Умный маршрут: деление объёма шагами `smart.split_step_pct` между пулами PancakeSwap (не больше `smart.max_splits`); монета с налогом — только V2 |
| `smart_ways.rs` | Кандидаты деления умного маршрута: пулы с USDT и пары через промежуточные; расчёт кандидата |
| `smart_quote.rs` | Режим `smart`: умный маршрут против прямой сделки Uniswap, больший итог; затраты долей складываются |
| `mixed_quoter.rs` | Сверка долей умного маршрута с MixedQuoter PancakeSwap перед отправкой |
| `direct_route.rs` | Режим `direct`: лучший пул с USDT против лучшей пары через промежуточную (один Universal Router), больший итог |
| `path.rs` | Путь: один пул или два через промежуточную монету — в порядке исполнения, итог |
| `via.rs` | Расчёт пути через промежуточную в паре пулов (покупка и продажа, налоги и крючки на своих шагах) |
| `via_pools.rs` | Допуск промежуточной (проверена, без налогов), пулы шагов, лучшая пара |
| `steps.rs` | Затраты каждого шага с `Cost::with_step`: газ, комиссия пула, налог, крючок; тикеры USDT / монета / промежуточная |
| `pick.rs` | Больший итог из двух котировок (количество, затем итог после газа) |
| `rate.rs` | Пересчёт USDT ↔ промежуточная по живому пулу «промежуточная — USDT» (проба, ликвидность) |
| `approve_gas.rs` | Газ разрешений, если их ещё нет |
| `costs.rs` | Котировка ядру: средняя цена, маршрут, затраты (комиссия пула, налоги, крючок — в цене; газ — отдельно, BNB) |
| `gas.rs` | Цена газа `eth_gasPrice` + `send.gas_price_markup_pct`, раз в блок (в котировке — не ниже минимума каналов) |
| `quoter.rs` | Выход по квотеру DEX (eth_call) и сверка с математикой (`dex.quoter_max_diff_pct`) |
| `quoter_calls.rs` | Данные вызова квотера и разбор ответа (eth_call и симуляция) |
| `emptiness.rs` | Пустой пул (резерв 0, ликвидность 0, нет бинов) и причины «не хватает ликвидности на сумму сверки» |
| `quoter_revert.rs` | Откаты квотера «не хватает ликвидности»: NotEnoughLiquidity, BinPool__OutOfLiquidity, SPL, Unexpected error — читаемым текстом |

Газ разрешений (`ApproveGas`) — если разрешений ещё нет (Universal Router своей DEX или `smart.universal_router`);
чаевые (`ChannelTip`) — если настроен ровно один канал бандлом с чаевыми.

Промежуточные монеты (решение 52): пулы «монета — промежуточная» и «промежуточная — USDT» (pools/mids.rs); путь
«USDT → промежуточная → монета» в одной транзакции — в прямом режиме лучшая пара одного Universal Router, в умном —
доля через промежуточную (одна лучшая пара на промежуточную монету). Все затраты — по шагам маршрута (`steps.rs`).
Промежуточная монета используется, только если проверена и без налогов (любой налог — не используется: налог
на переходе между пулами в одной транзакции официально не описан; решение техлида, Issue #7); монета с налогом — только V2 на каждом шаге.

Проскальзывания отдельным видом затраты нет (решение техлида, Issue #7): цена каждого шага посчитана по реальной
ликвидности его пула и уже в средней цене; `exec.dex_slippage_pct` — защита минимумом выхода, не затрата.
