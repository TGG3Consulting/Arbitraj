# t181 — исполнитель v3: все виды пулов одной транзакцией (решение 395, 17.11.2026)

Номер решения — 395 (ревью 2 t181: 390–394 заняты другими задачами). Текущая сборка v3: bin-runtime SHA-256
`c8885a75f7318513c6c7303012e56bcc651ea5def431edb98b2111221bf537c5` (`contracts/out/ArbExecutor.sha256`).

Требование Тиграна: «Сделай так, чтобы мы умели все варианты». Повод — чужой арбитражник продал NFP одной транзакцией
сплитом по 5 пулам разных DEX (3 пула DODO, Uniswap V4, мост WBNB → ETH → USDT) через свой контракт.

## 1. Что было (факт кода HEAD 982e0503)

Маршрут графа идёт одной транзакцией тремя способами (quote/graph_exec.rs executable):
- **Universal Router** своей DEX (прямой путь или «умный путь» — все шаги в одном UR; pools/families.rs tradable, не форк);
- **бандл свопов** — каждая доля внутри ОДНОГО роутера, каналы отправки умеют бандл (graph_exec.rs collectable);
- **свой исполнитель ArbExecutor** — только если КАЖДЫЙ шаг маршрута — вид шага исполнителя (quote/graph_executor.rs
  all_via, pools/exec_kind.rs via_executor).

У Uniswap V4 и PancakeSwap Infinity шага исполнителя не было (pools/exec_kind.rs: `of()` → None; exec/executor/entry.rs
supported: «пул внутри менеджера исполнитель не вызывает»). Поэтому маршрут, где V4/Infinity смешаны с пулом без своего
Universal Router (DODO, Algebra, Solidly, StableSwap, Maverick, форки, …), не исполнялся НИКАК — оставался сигналом.

**Сочетания, которые НЕ исполнялись одной транзакцией (до):**
1. V4 / Infinity (CL, Bin, Stable) + любой пул без своего UR (DODO, Algebra, Solidly, StableSwap, Curve, Maverick, форки
   V3, Slipstream, Metric, iZi, DMM, SmarDex, Balancer, LB, v2_fork_executor) — ни исполнитель (у V4 шага нет), ни UR
   (у второго пула UR нет), ни бандл (нога через не-tradable) → сигнал. **Это случай NFP (DODO + Uniswap V4).**
2. Нога маршрута через два разных роутера с V4/Infinity (например, Uniswap V4 → PancakeSwap V3 в одной доле, или Uniswap
   V4 + PancakeSwap Infinity в одной ноге) — бандл такую ногу не собирает (graph_exec.rs collectable) → сигнал.
3. V4/Infinity + другие UR — только бандлом и только если ВСЕ включённые каналы отправки бандловые; иначе сигнал.
4. Цикл DEX ↔ DEX через V4/Infinity и пул без UR — ни исполнитель, ни бандл (exec/cycle_gate.rs) → сигнал.
5. Любой маршрут через KyberSwap Elastic или WooFi — сигнал (не меняется).

**После (кошелёк с исполнителем v3):** сочетания 1–4 исполняются одной атомарной транзакцией через исполнитель
(graph_exec.rs: all_via = да, форма не UR → исполнитель; cycle_gate.rs: форма «исполнитель» предпочтительна). Остаётся
«не исполнимо»: KyberSwap Elastic, WooFi (п. 5); монета с налогом на входе в маршруте из нескольких долей или с первым
шагом не «вход переводом в пул» (graph_executor.rs tax — V4/Infinity тоже «через исполнитель»: Vault/PoolManager при
settle недосчитается налога и откатит); шаг пула менеджера на хопе, который касается BNB, когда BNB — монета сделки (ExecKind::singleton
исключён в exec/native_exec.rs и quote/graph_route.rs native_ok_at — газ обёртки через эти шаги не мерится; как до решения
395). Хоп V4 / Infinity, НЕ касающийся BNB, в маршруте BNB у кошелька v3 строится — executeNative с шагом 19–21 (ревью 2
t181; контракт исполняет корректно, EVM G7);
пул менеджера с нативной валютой в ключе (address 0) — шаг не строится (kind_key.rs, контракт «native»).

**Правило выбора пути у кошелька v3 (ревью t181, Н3; quote/graph_exec.rs bundle_first — одно правило для котировки и
сделки, exec/executor/mod.rs takes; для циклов — exec/cycle_gate.rs form):** маршрут с шагом пула менеджера (V4 /
Infinity), который собирается ПРЕЖНИМ путём (бандл свопов: все пулы со своим путём, каждая доля внутри одного роутера,
роутеров ≤ dex.bundle_max_routers, каналы умеют бандл, нет BNB через ногу форка), идёт прежним путём — как у кошелька v2.
Исполнитель v3 берёт маршрут с V4 / Infinity только там, где прежнего пути нет (DODO + V4 и т. п.). Так монета с налогом
на входе и первым шагом V4/Infinity (через исполнитель менеджер откатил бы) и крючки, не пускающие исполнитель, не
превращают прежнюю сделку в сигнал. Маршруты без шага менеджера — прежнее правило (исполнитель раньше бандла, решение 122).
Пул менеджера с нативной валютой в ключе или с ключом не от пары записи — не исполним исполнителем (entry.rs fits — Н1);
ссылка Contract у шага менеджера — только Infinity Stable со сверкой крючка и менеджера (Н2).

**Кошельки v1 / v2:** всё как раньше (step_missing: «исполнитель v2 не знает шаг исполнителя UNI_V4 (вид шага есть с v3)
— переразверните исполнитель»; пулы V4/Infinity по-прежнему идут своим UR).

## 4. Модель угроз шагов UNI_V4 / INF_CL / INF_BIN (контракт с деньгами)

| Угроза | Что защищает |
|---|---|
| Чужой зовёт unlockCallback / lockAcquired и заставляет исполнитель платить | Обмен только если `msg.sender == expPool` (менеджер / Vault ТЕКУЩЕГО шага, transient, ставится перед unlock/lock) и `keccak256(data) == expHash` (данные этого шага); оба стираются ДО обмена. Вне шага expPool = 0 → «pool». EVM: посторонний и владелец вне шага — «pool» |
| Крючок пула входит повторно (unlockCallback / lockAcquired с данными шага, uniswapV3SwapCallback и т. п.) | expPool / expHash уже стёрты, `_pay` пускает только expPool → откат вызова крючка; `execute` — только владелец и замок `locked`. EVM: крючок ReenterHook сделал 3 попытки — все отказаны, обмен прошёл |
| Крючок забирает с исполнителя больше суммы шага (дельта входа больше amount) | `require(0 < долг ≤ amount)` — «owed»; платится ровно долг, не баланс |
| Крючок урезает выход (комиссия дельтой) | Берётся ровно кредит исполнителя у менеджера (не выход пула); итог маршрута проверяет `received ≥ minOut` у кошелька. EVM: FeeTakingHook — получено = выход − 1,23 % |
| Произвольный вызов по адресу из данных | Вызываются только фиксированные функции интерфейсов (unlock / lock / swap / sync / settle / take / exttload / currencyDelta) по адресам из шага, который задаёт владелец (как у прежних видов); менеджер Infinity из ключа — чужой / незарегистрированный менеджер откатит Vault (onlyRegisteredApp / NoLocker) |
| Ключ не того пула, токены шага не валюты ключа, нативная валюта (address 0) | Контракт: «key» / «native»; бот — до отправки (kind_key.rs check_tokens) и PoolId ключа = id ссылки (entry.rs) |
| Недоплата / переплата менеджеру | Платится ровно долг; settle засчитывает прирост баланса менеджера — налог на перевод даст недоплату → менеджер откатит всё (CurrencyNotSettled); незакрытые дельты — откат всего unlock/lock |
| Токены застряли на исполнителе | Выход — take прямо получателю; остаток входа (пул взял меньше — предел цены) — `_sweepAll` владельцу в конце `execute` (как у прежних видов). EVM: «на исполнителе ничего не осталось» во всех сценариях |
| Обратного вызова не было (менеджер не тот) | `require(expHash == 0)` после unlock/lock — «cb»; вид UNI_V4 по адресу Vault / INF_CL по адресу PoolManager — откат (EVM) |
| Устаревшие expToken / expMax прошлого шага V3 (менеджер шага зовёт pancakeV3SwapCallback) | Ревью t181 (Н5): `_singleton` стирает expToken / expMax вместе с expPool до unlock / lock — `_pay` откатит «owed». EVM: поддельный менеджер пробует — отказано |
| Поддельный «менеджер» (произвольный контракт в роли s.pool) | Переводится не больше долга ≤ суммы шага, дальше нет выхода — итог откатывается minOut; долг больше суммы — «owed». EVM (FakeManager) |
| Старый кошелёк v1 / v2 получает шаг 19–21 | Бот: step_missing / step_absent — путь не строится; контракт v1 / v2 — «kind» (EVM на out/v2 и out/v1) |

Где возможна потеря при ошибке шага: только при неверном minOut (итог проверяется у кошелька — недобор = откат всего) или
при ошибке расчёта выхода (котировка — та же математика V4/Infinity, что и для UR; сверка с квотером, решение 73).
Сама транзакция атомарна: ошибка любого шага — откат всего, деньги на месте, теряется только газ отклонённой транзакции
(при отправке приватным каналом откат не включается в блок — решение 41).

### Процедура «только чтение» для серверного ИИ (eth_simulateV1, подмена кода исполнителя) — ревью t181, Н6
Только eth_simulateV1 своего узла BSC. Взять номер H (eth_blockNumber) и передавать H вторым параметром eth_simulateV1:
вызовы исполняются в НОВОМ блоке H+1 поверх состояния H (execution-apis eth_simulateV1; время блока — H.time + 1, если
blockOverrides не заданы). eth_call / eth_getStorageAt для ключей, квотеров и слотов — на H. Срок execute — H.time + 600.
Ничего не подписывать и не отправлять. Ключи бота не нужны: вызовы идут от адреса кошелька проб без подписи
(eth_simulateV1 с `validation: false`).

1. **Код.**
   - Из ветки t181 взять `contracts/out/ArbExecutor.bin-runtime`.
   - SHA-256 текста файла должен совпасть со строкой `ArbExecutor.bin-runtime` в `contracts/out/ArbExecutor.sha256`.
   - Значения: X — пустой адрес (eth_getCode = 0x, eth_getBalance = 0), W — адрес кошелька строки «Пробы и сигналы»,
     WBNB — dex.native_wrapped.
2. **Подмена — только `stateDiff`, не `state`.** `state` заменяет ВСЁ хранилище контракта: у токена обнулятся балансы
   пулов и менеджеров, и симуляция станет ложной. В `stateOverrides`:
   - `X: { "code": <bin-runtime>, "stateDiff": { "0x0…0": <W словом 32 байта>, "0x0…1": <WBNB словом> } }`
     (owner — слот 0, wnative — слот 1: `contracts/out/ArbExecutor.layout.json`);
   - `USDT: { "stateDiff": { <слот баланса W>: <20e18 + текущий баланс W>, <слот allowance(W, X)>: <2^256−1> } }`.
   Как найти слоты, без догадок:
   - взять любой адрес A с ненулевым USDT (например PoolManager);
   - для i = 0…20 сравнить `eth_getStorageAt(USDT, keccak256(abi.encode(A, i)), H)` с `balanceOf(A)` на H; совпало — номер
     слота балансов b;
   - так же для allowance: слот `keccak256(abi.encode(X, keccak256(abi.encode(W, a))))`; номер a подобрать по паре
     (владелец, получатель) с известным `allowance(владелец, получатель)` на H;
   - если не нашлось — записать «слоты USDT не найдены» и взять кошелёк, у которого есть ≥ 20 USDT; allowance всё равно
     только через stateDiff.
   Монета на продажу (обратная сторона) — тем же способом для её токена, либо из выхода первого вызова в той же
   симуляции (второй вызов того же блока; allowance монеты — stateDiff).
   **Ни одного вызова approve** в симуляции.
3. **Пулы.** По 2–3 пула каждого вида, с USDT в паре и ненулевой ликвидностью на H (если пулов вида с USDT нет — см. п. 6):
   - Uniswap V4 без крючка (hooks = 0) и с крючком;
   - PancakeSwap Infinity CL без крючка и с крючком (из 37 пулов tests/data/hook_pools_2026-11-16);
   - Infinity Bin;
   - Infinity Stable (крючок из dex.stable_hooks).
   Ключ — poolKeys / poolIdToPoolKey; проверить `keccak256(abi.encode(ключ)) == PoolId`. Валюта 0 в ключе — пул не брать.
4. **Вызовы** — все в одном `blockStateCalls[0].calls` на H, `from = W`:
   - (а) `X.execute(USDT, 20e18, монета, 1, H.time + 600, [шаг])`, где шаг = (вид, пул, USDT, монета, 10000,
     abi.encode(ключ)): вид 19 — пул = PoolManager (dex.pool_manager), 20/21 — пул = Vault (dex.vault); Infinity Stable —
     вид 20, ключ с крючком;
   - (б) обратная сторона того же пула: `X.execute(монета, M, USDT, 1, …)`. Данные вызова фиксируются до запуска, поэтому
     «получено из (а)» в ту же симуляцию подставить нельзя: ДВА запуска на одном H — запуск 1: только (а), из returnData
     взять получено M; запуск 2: (а) и (б) с этим M (баланс и allowance монеты у W после (а) — из (а) же; allowance монеты
     исполнителю X — stateDiff монеты, как у USDT);
   - (в) один смешанный маршрут из двух долей одного входа: доля 1 — шаг V2 (PancakeSwap V2 пара той же монеты, вид 0,
     data = abi.encode(uint32 2500)), доля 2 — шаг вида 19 или 20 (bps долей — как в contracts/README.md «Вызов»);
   - (г) один цикл: `X.execute(USDT, 20e18, USDT, 1, …, [шаг 19/20/21 USDT → монета, шаг другого вида монета → USDT])`;
   - для сравнения тем же H — квотер DEX (dex.quoter этой DEX, hookData 0x) на ту же сумму (eth_call) и Universal Router
     своей DEX той же суммой от W (команды как у бота, exec/swap_v4.rs). Universal Router берёт вход через Permit2: без
     approve это делается stateDiff у USDT — allowance(W, Permit2) = 2^256−1 — и stateDiff у Permit2 — разрешение (W, USDT,
     Universal Router): сумма, срок, nonce в слоте `allowance[W][USDT][UR]` (вложенный mapping Permit2 AllowanceTransfer;
     номер слота найти так же — eth_getStorageAt по известному разрешению на H). Не удалось — сравнение с UR пропустить
     и написать это в README записи (сравнение с квотером обязательно).
5. **Записать по каждому вызову:** status, returnData (получено — возврат execute), gasUsed, логи целиком (Swap менеджера,
   Transfer всех токенов), текст отката (error.message / data), а также `balanceOf(X)` по USDT и монете вызовом в той же
   симуляции после шага (ожидается 0).
6. **Критерии приёмки:**
   - получено = кредит исполнителя из события Swap менеджера (с учётом дельты крючка) и совпадает с квотером в пределах
     dex.quoter_max_diff_pct (живое значение настройки — записать рядом);
   - у X нулевые балансы токенов после каждого вызова;
   - откаты — только объяснимые. Крючок отвергает вызывающего (проверка sender) — пул в список «крючок не пускает
     исполнитель»: такие пулы исполнителем не брать (задача в docs/TASKS.md);
   - пулов вида с USDT нет (например Infinity Bin или Infinity Stable): в summary.json — строка `{case: "нет пулов",
     kind, query, result}` с доказательством запроса (какие ключи / события перебраны, на каком H, сколько найдено), вид
     считается НЕПРОВЕРЕННЫМ — приёмка остальных видов не ждёт его, но шаг этого вида исполнителем до своей записи не
     считать готовым (TASKS).
7. **Куда положить:** `tests/data/executor_v3_live_<ГГГГ-ММ-ДД>/` (как прочие записи узла):
   - `raw_rpc.json` — массив `{t, method, params, result | error}` всех вызовов (eth_blockNumber, eth_getBlockByNumber H,
     eth_getStorageAt поиска слотов, eth_call ключей / квотеров, eth_simulateV1 целиком);
   - `summary.json` — по вызову: `{case, kind, pool_id, manager, hooks, token_in, token_out, amount_in, got, quoter_out,
     ur_out, gas, status, revert, x_left}`;
   - `hooks_reject.json` — `[{pool_id, hooks, revert}]` (пусто — пусто);
   - `README.md` — блок H, адреса из настроек, **SHA-256 bin-runtime, который симулировался** (решение 400: запись
     относится к сборке, только если README содержит SHA-256 текущего bin-runtime; `code::LIVE_PROOF` убран).
   По ним — приёмка по классам шага (решение 400, exec/executor/live_proof.rs) и тест tests/bsc_dex_executor_v3_live.rs.

## 7. dex.graph_exec_fallback (решение 300)

Что делает: если ЛУЧШИЙ маршрут графа неисполним, на котировке решения/исполнения повторяет сплит на подмножествах путей,
исполнимых по построению (S1 — один UR PancakeSwap, S2 — все шаги исполнителем, S3 — бандл внутри одного роутера), и даёт
лучший исполнимый (quote/graph_fit.rs). Почему не включена: решение 300 сделало её необязательной («не задавать при
первом запуске; «да» — после приёмки решения 300», docs/FIRST_RUN.md); S2/S3 на записанных данных не проверены.
После решения 395 (кошелёк v3) лучший маршрут неисполним только в редких случаях (Elastic, WooFi, налог на входе в
нескольких долях, BNB через шаг менеджера, DEX без dex.vault) — fallback почти не будет срабатывать и стоит мало. До
переразвёртывания (v1 / v2) именно он даёт сделку вместо сигнала в случае NFP: S2 без пулов V4 (DODO + PCS V3 + мост).
**Рекомендация:** включить «да» (деньги не рискуют: каждый кандидат снова проходит executable и costs; цена — до 3
доп. сплитов только на котировке решения/исполнения). Настройку не трогал — решение владельца.
