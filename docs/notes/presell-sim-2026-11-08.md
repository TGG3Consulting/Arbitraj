# Продажа DEX до покупки — симуляция кошельком сделки (решение 234, 08.11.2026)

Живой случай (Тигран 08.11): монета ASS `0x7c63f96feafacd84e75a594c00fac3693386fbf0` (налог при переводе, не ханипот),
направление mexc → bsc_dex, сделки 20261108113609086ASS и 20261108175020857ASS. План показал прибыль (SellTax 3.166 % в
затратах), каждая продажа на DEX откатывалась `minOut` (contracts/ArbExecutor.sol:120) — монету купили на MEXC и вывели,
продать не смогли.

## Что было (факты кода, ветка feat/own-bsc-node, 19a1c46)

- Налог меряет проба (check/taxes.rs, check/probe.rs) кошельком строки «пробы» (ctx_wallet.rs `wallet()`, без счёта —
  `ROW_PROBE`) на сумму `check.probe_usdt`, монетами, купленными в той же симуляции. Продаёт другой кошелёк (счёт сделки по
  маппингу), на сумму сделки, монетами из вывода.
- Свежесть налога (CoinCheck.checked_at) в котировке не проверяется (quote/direct.rs `taxes`, quote/pool_tax.rs).
- core/precheck_sell.rs для DEX сразу `Ok(())`. Единственная проба `execute` с minOut и кошельком сделки —
  exec/executor/sim.rs, уже на этапе продажи (exec/executor/trade.rs).
- minOut — exec/leg_min.rs от `req.worst_price` = средняя котировки × (1 − exec.dex_slippage_pct); средняя котировки —
  с модельным налогом пула.
- При откате sim.rs писал только текст узла — без minOut, ожидаемого и модельного налога.

## Что стало (по пункту — отдельный коммит ветки t39/presell-sim)

1. **Продажа DEX до покупки** (core/precheck_dex_sell.rs → контракт `dex_presell` → venues/bsc_dex/exec/presell.rs).
   Запрос продажи — тот же, что строит ядро для биржи B (precheck_sell::request: количество `Calc::sell_qty` = приход
   после вывода и налога перевода, худшая цена worst.rs, маршрут — из котировки продажи плана). Адаптер — вид на счёт
   сделки (dex_account::venue_dir, Ctx::bound): сборка exec/dry_build.rs в режиме AsTrade (те же функции и порядок, что
   exec/trade.rs: прямой / умный / бандл / исполнитель при exec.executor_address), минимумы — exec/leg_min.rs.
   Монет на кошельке нет — приём сухой сделки (решение 121 C4) и пробы налогов: первым вызовом той же eth_simulateV1
   перевод монет от пула-источника ВНЕ маршрута (exec/dry_fund.rs; пул маршрута не трогается — у V2 перевод из пары
   исказил бы вход продажи). Выход = баланс USDT кошелька после − до → после реального налога на реальной сумме реальным
   кошельком. Ядро пересчитывает: выручка = выход, прибыль = прибыль плана + (выход − выручка плана), пороги
   money.min_profit_usd / money.min_profit_pct. Откат / отказ сборки / ниже порога — сделки нет, причина в журнал
   отказов (выход, ожидаемое, минимумы по долям, модельный налог). Удача — строка в журнал core.precheck.
2. **Налог по кошельку сделки** — не сделан, вопрос Тиграну (ниже).
3. **Свежесть налога** — tax.max_age_s (core/tax_age.rs), необязательная.
4. **Диагностика отката** — exec/executor/sim.rs: к ошибке пробы — minOut каждой доли, ожидаемое каждой доли,
   модельный налог доли; текст ошибки продажи уходит в хронологию сделки (алерт manual / manual_outcome).

## Ограничения (факты кода)

- Пополнение — только от пула V2/V3 реестра вне маршрута с балансом ≥ суммы (dry_fund::source). У монеты с одним пулом
  источника нет → симуляция не выполняется → сделки нет (причина «пула-источника … нет»). Не торгуем вслепую.
- Перевод от пула токен может считать покупкой (антибот, лимит кошелька, кулдаун) — тогда откат в симуляции и отказ,
  хотя настоящий приход идёт с адреса биржи. Отказ — в безопасную сторону.
- Нативная BNB: продаётся value транзакции, в симуляции не пополняется; у кошелька меньше суммы — NotApplicable, запись
  в журнал, проверка как раньше (у нативной монеты нет контракта — налога токена нет).
- exec.via_kyber = да: настоящая продажа идёт через KyberSwap, симуляция — своим сборщиком (его путь — запасной при
  NoRoute KyberSwap). Вопрос Тиграну.
- Сверка хопов Maverick: dry_build зовёт `precheck_quoter::hops` (строго), продажа выхода — `hops_exit` (по квотеру).
  До покупки строгая сверка — отказ в безопасную сторону.
- Записанного состояния сети для ASS в tests/data нет: сама симуляция на ASS не прогнана; тесты — пересчёт плана на
  записанных данных CAKE (tests/core_presell.rs).

## П.2: налог каждым кошельком маппинга — цена в запросах

check/probe.rs::run на один пул: 2 × eth_simulateV1 + 2 × balanceOf для базы Universal Router (part → token_units) —
4 запроса к узлу; плюс check/taxes.rs: decimals, источники (Multicall3 balanceOf). Замер каждым кошельком умножает
это на число кошельков маппинга, на каждый проход tax.recheck_interval_s и на каждую новую монету/пул. Сколько монет и
пулов у живого бота — в этой работе данных нет. Риск п.2 закрывает п.1: налог продажи кошельком сделки на сумме сделки
меряется симуляцией перед каждой покупкой.
