# SETTINGS — каталог настроек

> Каждый параметр системы описан здесь и в `src/settings/schema.rs`. В коде значений нет.
> **Стартовых значений нет.** Все параметры задаёт Тигран в интерфейсе.
> Параметр не задан → функция, которой он нужен, не работает, а интерфейс показывает, что его нужно задать.
> Торговля не включается, пока не заданы все параметры групп `money.*` и `risk.*`.
> Новый параметр → строка здесь + описание в `schema.rs` + поле в интерфейсе (экран «Настройки»).

## Уведомления в Telegram

Токен бота — в зашифрованных секретах (docs/SECURITY.md), вводится в интерфейсе.

| Имя | Что означает | Единица | Область |
| --- | --- | --- | --- |
| notify.telegram_api_url | Адрес Telegram Bot API (из официальной документации core.telegram.org/bots/api) | URL | вся система |
| notify.telegram_chat | Куда слать уведомления | ID чата | вся система |
| notify.event.enabled | Присылать ли это событие | да/нет | по событию |
| notify.event.venues | Для каких площадок присылать (пусто — для всех) | список | по событию |
| notify.event.condition | Условие отправки, где оно имеет смысл (например, сделка с прибылью или убытком больше суммы) | зависит от события | по событию |
| notify.summary_interval_s | Как часто присылать сводку | секунды | вся система |
| notify.updates_timeout_s | Кнопки Telegram: таймаут длинного опроса getUpdates (параметр timeout Bot API) | секунды | вся система |

Настройки событий хранятся с областью «событие» (код события из `src/notify/catalog.rs`): одно имя, своё значение на каждое событие.

У события могут быть кнопки (`buttons` в `src/notify/catalog.rs`) — например «Продать сейчас» и «Беру на себя»
у `stuck.loss_alert`; нажатие принимается только из чата `notify.telegram_chat` (решение 37).

События (группы): сделки, ошибки исполнения, риск, площадки, монеты и направления, застрявшие монеты, ручное управление, отправка транзакций, система, сводка. Полный список — в ТЗ, раздел «Уведомления в Telegram». Новая фича добавляет свои события сюда.

## Области значений

Значение задаётся для области: вся система, площадка, монета, событие, DEX, канал отправки.
Для системы, площадки и монеты действует самое узкое заданное: монета сильнее площадки, площадка сильнее всей системы.
Событие, DEX и канал — отдельные предметы: значение задаётся ровно для своего id, без подстановки.
Для какой области можно задавать настройку — в `src/settings/catalog/`.

| Область | id | Откуда список id |
| --- | --- | --- |
| Площадка (`venue:`) | `bingx`, `bsc_dex` | реестр шлюза (`GET /api/venues`) |
| Монета (`coin:`) | тикер | справочник монет |
| Событие (`event:`) | код события | `src/notify/catalog.rs` |
| DEX (`dex:`) | имя DEX (`pancakeswap`) или вид пула (`pancakeswap_v3`) | адаптер DEX: `dex_families()` |
| Канал (`channel:`) | id канала (`club48`) | адаптер DEX: `send_channels()` |

Почему DEX и канал — свои области, а не «площадка»: это части одного адаптера `bsc_dex` (один кошелёк, один узел),
а не отдельные площадки реестра; у них свой набор настроек, и подстановка «монета → площадка → система» к ним не подходит.

## Виды значений

`Decimal`, `Integer` (может иметь верхнюю границу `max`), `Bool`, `Text`, `Url` (только https/wss), `TextList`, `Ip`,
`Choice` (один из вариантов `choices`), `Address` (адрес BSC: 0x + 40 hex). Описание — `src/settings/schema.rs`.
