# notify/ctl — чат «Управление» Telegram (решение 176)

Главное меню кнопками: «Состояние», «Балансы» (с «Продать»), «Перевести USDT», «Ручное управление», «📊 Отчёты»
(решение 215: Excel-файл отчёта в этот чат). Каждая денежная
кнопка — та же команда ядра, что у интерфейса (`Core::command` / `ManualAction`: `SellBalance`, `TransferUsdt`, команды
плашки режима), через общий вопрос «Да, …» (`notify/press_confirm.rs`). Экран — одно сообщение, правится на месте.
callback_data: `k:<экран>` (навигация, без денег), `s:<номер>.<строка>` («Продать»), `t:<номер>.<шаг>` (перевод),
`c:<что>` (плашка режима, общий с меню /menu «Общего»), `r:<что>` (отчёты: `r:m` — какой, `r:res` / `r:mis` — период,
`r:<отчёт>.<d|w|m|a>` — файл). Номер отрисовки — с времени запуска, только растёт.

| Файл | Что делает |
| --- | --- |
| `mod.rs` | Список модулей |
| `kb.rs` | Общий рендер клавиатур: кнопка (предел callback_data 64 байта), ряды, ссылка, «Назад» и «Главное меню» |
| `sessions.rs` | Память экранов: отрисовки с денежными кнопками по номеру, диалог перевода, вопросы суммы, срок notify.dialog_ttl_s, пауза 429 |
| `screens.rs` | Экраны без денег: «Главное меню», «Состояние» (кнопки плашки), «Ручное управление» (сводка и ссылка на чат «Неудачные») |
| `card.rs` | Решение 192: карточка проблемной сделки («Обработать» на «Ручном управлении»): текст и кнопки записи, «Предыдущая» / «Следующая»; обработанная — только навигация; `k:mc.<позиция>.<ключ>` |
| `balances.rs` | Экраны «Балансы»: список бирж и кошельков, счета биржи с «Продать», кошелёк DEX |
| `transfer.rs` | Экраны шагов перевода USDT: «Откуда», «Куда», «Сколько», сводка |
| `view.rs` | Сборка экрана по виду из данных ядра (память ядра и панели «Балансы»); общая у нажатий и лайва |
| `press.rs` | `k:` — экран на месте, `/menu`, срок и устаревание денежных кнопок, показ экрана (правка или новое сообщение) |
| `sell.rs` | `s:` — «Продать»: доступность заново, вопрос «Да, продать …» → SellBalance |
| `transfer_press.rs` | `t:` — шаги диалога перевода, доли notify.transfer_pct |
| `transfer_input.rs` | «Ввести сумму» (ForceReply), ответ числом, «Отправить» → вопрос «Да, перевести USDT» → TransferUsdt |
| `progress.rs` | Перевод отдельной задачей; ход «проверка → отправлено → в сети → итог» правкой того же сообщения |
| `report.rs` | Решение 215: «📊 Отчёты» — «Итоги сделок» / «Упущено» → «Сутки», «7 дней», «30 дней», «За всё время» → «Готовлю отчёт…» и sendDocument в чат; больше 50 МБ или сбой — причина в чат и журнал |
| `report_sig.rs` | Решение 255: «Сигналы и сделки» — периоды «За всё время», «Текущий день», «3 / 5 / 7 дней», «Свой интервал» (ForceReply «дд.мм.гг – дд.мм.гг», ошибка — причина и вопрос заново); файлы частями, если больше предела sendDocument |
| `report_cap.rs` | Решение 256: «Сделки, лимиты и капитал» — те же периоды и ввод своего интервала, что у `report_sig.rs` (свой вопрос ForceReply, память — `cap_prompts`); файлы частями по дням, если больше предела sendDocument |
| `live.rs` | Лайв-обновление: не чаще notify.live_refresh_s, пока были нажатия в notify.live_idle_s, потом «заморожен»; 429 — пауза retry_after |

Настройки: `notify.control_chat`, `notify.control_users`, `notify.live_refresh_s`, `notify.live_idle_s`,
`notify.dialog_ttl_s`, `notify.transfer_pct`, `ui.balances_refresh_ms`; секрет `telegram.control_token`.
