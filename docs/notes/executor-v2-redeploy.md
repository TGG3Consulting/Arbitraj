# Переразвёртывание исполнителя ArbExecutor v2 (решение 272)

> **ЧЕРНОВИК ДО ФИНАЛЬНОЙ ВЕРСИИ КОНТРАКТА. Переразвёртывать ещё РАНО.** В контракт v2 до развёртывания войдут
> дополнительные шаги для других DEX (решение владельца: одно переразвёртывание на всё). Хеш байткода ниже — версии
> после ревью 272; после следующих правок контракта он сменится, и этот документ будет обновлён.

Зачем: исполнитель v2 умеет `executeNative`, и через него BNB (монета сделки) торгуется через пулы форков V2/V3,
Algebra, Solidly, DODO, StableSwap, Maverick и Slipstream. Старые исполнители (v1) после обновления бота работают
как раньше (ERC-20 через исполнитель — байт в байт), только BNB через них не идёт. Переразвёртывать нужно кошельки,
через которые должен идти BNB, и кошелёк строки «Пробы и сигналы» (им мерится газ обёртки).

## Перед началом
1. Обновлённый бот запущен, секреты разблокированы.
2. Задана **`dex.native_wrapped`** (адрес WBNB) — «Настройки» → DEX. Ревью 272 (А1): этот адрес уходит аргументом
   конструктора и **навсегда** записывается в исполнитель (сеттера нет). Не задана — «Развернуть исполнитель» отвечает
   «не задана dex.native_wrapped …» и ничего не отправляет.
3. На кошельке есть BNB на газ развёртывания: окно подтверждения покажет точную сумму в BNB и USDT.

## Порядок — для каждого кошелька
Экран **«Маппинг кошельков»** → вкладка «Кошельки» → карточка кошелька → блок «Исполнитель ArbExecutor».
1. Строка «Версия» сейчас: «v1 — нативный BNB через форки не торгуется, переразверните» (или «не сверена» —
   нажмите «Проверить подключение» рядом с «Развернуть исполнитель», она покажет v1). При первой сверке v1 бот один раз
   шлёт уведомление `wallet.executor_v1` («у кошелька X исполнитель v1 — нативный BNB через форки не торгуется»;
   включается на экране «Уведомления», группа «Кошельки DEX»).
2. Нажмите **«Развернуть исполнитель»**. В окне проверьте: кошелёк (владелец) — этот кошелёк; стоимость; **«Обёртка BNB
   (навсегда)»** — адрес WBNB из `dex.native_wrapped`; SHA-256 байткода — `26dde48a346d8f132000d5c8af9ee80667935d2e03ba448159e3ba77f99088d8`
   (код создания v2 без аргумента конструктора, `contracts/out/ArbExecutor.sha256`); solc 0.8.37.
3. **«Подтвердить и отправить»**. После блока: «Исполнитель развёрнут: 0x… Код в сети совпал с репозиторием, обёртка в
   конструкторе 0x… Сверка: Подключено: … версия v2, обёртка 0x… = dex.native_wrapped …». Новый адрес записан у
   кошелька сам, в Telegram — `wallet.executor_deployed`.
4. Строка «Версия» — **«v2 — нативный BNB монетой сделки идёт через исполнитель (обёртка 0x…)»**. Если «не сверена» —
   нажмите «Проверить подключение» исполнителя. Если «v2, но обёртка в исполнителе … ≠ dex.native_wrapped …» — адрес
   обёртки в настройке сменили после развёртывания: BNB через этот исполнитель не идёт (ERC-20 — как обычно);
   переразверните при верной настройке.
5. Повторите для следующего кошелька (у каждого кошелька свой исполнитель, решение 132). Порядок между кошельками не
   важен: пока кошелёк не переразвёрнут, его старый исполнитель работает как раньше. Запись версии при сверке не
   перезапускает слежение за кошельками (ревью 272, Б1) — ожидания зачислений идущих сделок не теряются.

## Кошелёк строки «Пробы и сигналы»
- Газ обёртки BNB для пулов, через которые BNB идёт только исполнителем, бот мерит сам пробой
  (`check/native_probe_exec.rs`) кошельком строки «Пробы и сигналы». Пока замера нет, котировка BNB через такой пул —
  «не проверено» (CoinNotChecked).
- **Пока у кошелька проб исполнитель v1 / не сверен / с другой обёрткой**, в фактах таких пулов и в журнале
  «dex.native_probe» (один раз): «проба нативной монеты (WRAP/UNWRAP) не запускается — газ обёртки через исполнитель не
  измерен: у кошелька «…» исполнитель 0x… версии v1 (executeNative нет) — переразверните исполнитель (кошелёк строки
  «Пробы и сигналы» — переразверните исполнитель кошелька проб; после сверки газ перемеряется сам)». Котировка BNB через
  такой пул отвечает «проба WRAP/UNWRAP не прошла — …» с той же причиной.
- **После переразвёртывания кошелька проб** газ обёртки перемеряется сразу, не дожидаясь планового прохода
  `tax.recheck_interval_s`: сверка исполнителя кошелька проб (после развёртывания, «Записать после проверки» или
  «Проверить подключение» исполнителя) нашла v2 с верной обёрткой — бот ставит монету BNB во внеочередную перепроверку
  (та же очередь, что кнопка «Перепроверить» / `POST /api/coins/recheck`: налоги, крючки, сверка с квотером её пулов;
  проба пулов WBNB перемеряет газ обёртки через исполнитель). В журнале «dex.native_probe»: «исполнитель кошелька проб
  «…» сверен (v2, обёртка = dex.native_wrapped) — внеочередная перепроверка BNB …», затем первый замер. Если нужно
  повторить вручную — экран «Монеты» → строка BNB → «Перепроверить на bsc_dex».

## Что будет после
- **Разовый approve новому адресу.** Разрешения ERC-20 выдаются адресу исполнителя, а у нового адреса их нет. Первая
  сделка через новый исполнитель по каждому токену отправит approve — это газ, он попадёт в итог этой сделки. Продажа
  BNB разрешения не требует (BNB идёт value транзакции).
- Разрешения старому адресу остаются. Вызвать старый исполнитель может только владелец (кошелёк бота). Кнопки отзыва
  разрешений в боте нет.

## Что проверить
1. «Ручное управление» → «Сухая сделка DEX», монета BNB, продажа и покупка на маленькую сумму, режим «как пойдёт
   сделка»: форма — «граф: исполнитель 0x…», проба прошла. Режим «через исполнитель» (код v2 и слот обёртки =
   `dex.native_wrapped` подставлены) проверяет то же до развёртывания.
2. Первая реальная сделка BNB через форк: в хронологии сделки — исполнитель, монеты — по событию `NativeSettled`.
3. Снимите квитанции продажи и покупки для теста — шапка `tests/bsc_dex_executor_v2_live.rs`.

## Если что-то не так
- «код по адресу … не совпал ни с v2 …, ни с v1 …» — адрес не наш или бот старой версии: адрес не использовать.
- «исполнитель … версия v1, executeNative нет — нативный BNB не исполняется» — версия у кошелька не совпала с кодом в
  сети; нажмите «Проверить подключение» исполнителя (версия перезапишется по коду).
- «обёртка в исполнителе … ≠ dex.native_wrapped …» — см. шаг 4 порядка.
- Вернуть старый исполнитель: «Записать после проверки» со старым адресом (версия станет v1). Если проверка нового
  адреса не прошла, прежний адрес и его сверенная версия возвращаются как были (ревью 272, Б2).
