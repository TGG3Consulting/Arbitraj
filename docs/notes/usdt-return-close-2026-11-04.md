# Возврат USDT после закрытия сделки — разбор 04.11.2026 (решение 138)

Ветка `router/retfix` (от `feat/own-bsc-node` 03f70e3). Разбор — Claude.

## Живые случаи

**20261104030213216TWT** (bingx → bsc_dex, кошелёк DEX «BingX» w1, `usdt_return.mode = per_trade`):
03:02:13 покупка 64.336 TWT на bingx → 03:02:27 перевод зачислен на bsc_dex → 03:02:27 «Застрявшая монета: режим relay» →
03:02:30 продажа на bsc_dex, выручка 24.69 USDT → 03:02:35 «Closed: продано (перегон не выгоднее продажи здесь)».
Возврата bsc_dex → bingx не было, в журнале нет `core.usdt_return`, алерта не было. 24.69 USDT остались в кошельке DEX.

**20261103201513697WKC** (покупка не на mexc, продано вручную на MEXC, «Продано вручную» — ввод человека): выручка
44.74 USDT осталась на MEXC без возврата на площадку покупки.

## Что показал код (до правки)

Путь TWT в коде: `relay::run` → `stuck::sold_by_market` → `sell::market` → `sell::sell` → `ledger::finish(Closed)` →
`usdt_return::after_deal`. То есть вызов возврата в этом пути **был** (тот же, что у «продано (выгодно)»). Почему он
не дал ни одной записи — по коду однозначно не доказать, журнала и консоли живого бота у меня нет. Что было слабым местом
и могло так проявиться:

1. **Задача перегона без класса срочности.** `after_deal` запускала перегон через `tokio::spawn` — класс задачи не
   наследуется (gateway/urgency.rs), значит перегон шёл классом **Background** в очереди узла BSC (ниже Trade, Check и
   Quote; решение 61): баланс кошелька, nonce, отправка и слежение за транзакцией стояли в хвосте очереди.
2. **Запись в журнал — только в конце.** Перегон писал `core.usdt_return` только по итогу (после зачисления или ошибки),
   без ID сделки. Пока задача ждала (очередь узла, слот nonce кошелька, ожидание баланса), в журнале не было ничего.
3. **Паника в задаче — молча.** Оборвись задача — ни журнала, ни уведомления, ни следа в сделке.
4. **Перезапуск** во время перегона — задача терялась, у закрытой сделки следа не оставалось.
5. **Возврат вызывался не из одного места**: только `sell.rs` после своего `ledger::finish`. Любой другой путь закрытия
   (уже есть: «Продано вручную»; новые — в будущем) мог его забыть.

Чтобы точно назвать причину именно у TWT, нужны журнал и вывод консоли 03:02:35–03:10 (записи `core.transfer_sent` /
`core.credit_event` с ID `20261104030213216TWTu`, строки `panicked at` в консоли, состояние очереди кошелька w1).

## Все пути закрытия сделки (Step::Closed) и возврат

Все закрытия идут через `ledger::finish(…, Step::Closed, …)`; других мест, где ставится Closed, нет (тест-страж).

| Путь | Где выручка | Возврат (per_trade) |
|---|---|---|
| Закрыта до покупки (нет бюджета, сухой режим, свободного не хватило, пересчёт невыгоден, покупка не исполнилась) — executor.rs | выручки нет | не нужен |
| Частичная покупка → «продать на A» — executor.rs → sell::market | на площадке покупки | не нужен (решение 108) |
| Перевод не состоялся → застрявшая монета на A → продажа на A | на площадке покупки | не нужен |
| Обычная продажа «продано (выгодно)» — sell::sell_or_stuck | на B | да (было) |
| Застрявшая: «Ожидание» — стало выгодно / время вышло (авто-продажа по сроку) | на B | да (было) |
| Застрявшая: «Порог убытка» — убыток ≤ порога | на B | да (было) |
| Застрявшая: «Перегон» — продано здесь (перегон не выгоднее) / перегоны исчерпаны (**живой TWT**) | на B | да (вызов был; см. выше) |
| Застрявшая: «Перегон» на третью площадку и продажа там | на третьей | да, с третьей на площадку покупки (было) |
| Продано не всё → остаток через застрявшую монету | там, где продано | да (было) |
| «Продать сейчас» / «Продать и перегнать» по алерту — manual.rs | там, где лежали монеты | да; «Продать и перегнать» — при любом режиме (решение 101) |
| «Продать сейчас» / «Продать и перегнать» у остановленной — manual_halted.rs | там же | да; то же |
| «Вернуть боту» → продажа (сделка «…r») — manual_return.rs | там, где лежали монеты | да (было) |
| **«Продано вручную»** (ввод человека) — manual_halted.rs | неизвестно боту (обычно deal.at) | **не было**; по решению 100 бот выручку не двигает → теперь страховка |
| Цикл DEX ↔ DEX — cycle_deal.rs | на той же площадке (bsc_dex) | не нужен |
| Возврат «идёт» и перезапуск | на отправителе или в пути | **не было следа** → теперь страховка |

Режим `usdt_return.mode = separate` — возврат по сделке не делается (решение 34: перегон по порогу остатка при сверке);
страховки в этом режиме нет (кроме «Продать и перегнать»).

«Продано вручную» и возврат: решение 100 описывает только ввод выручки, о перегоне в нём ничего нет; решение 101 прямо
оставляет «Продано вручную» без перегона. Бот не знает, где человек продал и где лежат USDT, поэтому сам не перегоняет —
только страховка. Сделать ли кнопку «Перегнать выручку» для закрытой сделки — вопрос Тиграну (docs/TASKS.md).

## Что сделано (решение 138)

- Общий шаг закрытия: `ledger::finish` при `Step::Closed` вызывает `usdt_return_deal::prepare` (до сохранения: состояние
  «идёт» пишется в ту же запись), после сохранения — `Job::start` (`usdt_return_job.rs`). Вызов из `sell.rs` убран. Любой новый путь закрытия
  получает возврат сам.
- Состояние возврата в сделке — `Deal.usdt_return`: `pending` (сумма, откуда, куда) / `done` (зачислено) /
  `not_returned` (сумма, где лежат, почему). Строка на экране «Сделки».
- В журнал сразу при закрытии — «Сделка X: возврат USDT N: from → to начат» (`core.usdt_return`, с ID сделки).
- Перегон — задачей класса **Trade** (путь сделки), не Background.
- Страховка «USDT не вернулись: сделка X, сумма N USDT, лежат на V — причина» — журнал `core.usdt_not_returned` (Error),
  событие Telegram `usdt.not_returned` (каталог уведомлений, «Риск»), строка на экране сделки. Срабатывает: перегон не
  состоялся (отказ, нет адреса, площадка не подключена), исход перегона неизвестен (текст: «перевод мог уйти — проверьте
  обе площадки»), нет кошелька сделки, задача оборвалась (паника), перезапуск во время перегона, «Продано вручную»
  не на площадке покупки (`Deal.usdt_return_skip`).
- `usdt.relay_failed` (решение 108) остаётся как было — при сбое перегона придут оба события.
- `ledger.rs` → загрузка вынесена в `ledger_load.rs` (файл был 216 строк).

## Тесты

`tests/core_usdt_return_close.rs` (настоящая SQLite, ядро без площадок, как остальные тесты учёта):
закрытие тем же вызовом, что делает продажа «перегон не выгоднее продажи здесь», запускает возврат (состояние «идёт»,
запись журнала с ID) → площадки нет → «не вернулись» и страховка с суммой и местом; «Продано вручную» на mexc при покупке
на bingx → страховка без перегона; «отдельно» и продажа на площадке покупки → ничего; «идёт» после перезапуска →
«не вернулись». `tests/core_close_guard.rs` — страж по исходникам — `usdt_return_deal::prepare` только в ledger.rs, `usdt_return::relay(` только в
usdt_return_job.rs, `step = Step::Closed` нигде. Продажу целиком (через площадку) без моков не прогнать — площадок в
реестре тестов нет; поэтому гарантия — общий шаг в `ledger::finish` плюс страж.
