# Повтор проверки пулов справочника DEX

В `cc1b4ef0` при старте подписки результат `take` использовался для записи статусов, но число пулов со сбоем не передавалось наблюдателю. Позже наблюдатель очищал задержку повтора перед каждой проверкой. После сбоя по монете A успешная проверка B снимала повтор и могла оставить A в статусе «не проверен» до обновления самого A или настройки.

Теперь из итогов строк берутся монеты с `Verdict::Failed`, в том числе после развёртки многомонетного пула. При новом обновлении удаляются только монеты, охваченные завершённым проходом. Повтор имеет абсолютный срок и при готовности проходит раньше ожидающего сигнала B. Необработанный B остаётся в очереди. При повторном отказе узла новый срок отсчитывается после проверки. Изменение настроек вызывает полный проход, взятый пул подключается обычным путём. Пустая настройка интервала не создаёт опрос. Число строк «не проверен» сохраняет прежний смысл.

При одном устойчиво сбойном токене повторная проверка узлом ограничена пулами этой монеты и новыми парами многомонетной развёртки. Используется уже существующий `index::take(Some(coins))`. Для CAKE в записи индекса от 24.10.2026 два сбойных пула дают одну монету повтора; это проверяет также старт подписки. Отдельный тест подаёт серию обновлений B, одновременно готовые B и таймер A, устойчивый отказ и последующее восстановление.

В снимке аудита 23.11.2026 не обнаружено строк «не проверен». Для измерения влияния нужны время первого и повторного результата по тому же пулу, доступность маршрута и его чистая прибыль на соответствующих входах.
