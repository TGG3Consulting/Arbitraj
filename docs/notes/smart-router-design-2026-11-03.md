# Умный маршрутизатор как у KyberSwap — проект решения (решение 122)

Ветка `feat/own-bsc-node`. Основание: сравнение «KyberSwap против нас» (03.11, ответ Тиграну), разбор
`own-exec-vs-kyber-audit-2026-11-03.md`, карта покрытия DEX (проект Arbitraj, `claude/dex-coverage-map.md`, 31.10).
Решения Тиграна 03.11: делать все пункты, где KyberSwap сильнее, кроме RFQ; DEX подключать **все по объёму**;
**свой контракт-исполнитель — да** (развёртывает Тигран, ≈0.07 USDT газа один раз).

## Что делаем и как это устроено у KyberSwap (по офдоке)
- Маршрут — «массив массивов»: несколько путей (split), в каждом шаги через промежуточные токены (multi-hop);
  `gasInclude` (по умолчанию да) — газ учитывается при поиске лучшего маршрута.
- Исполнение — одной транзакцией через свой роутер `MetaAggregationRouterV2` и его исполнитель, по любым DEX.

## Часть R. Маршрутизатор (без контракта)

### R1. Учёт газа при выборе маршрута
- Сейчас: `quote/graph_route.rs::split` добавляет долю по наибольшему приросту выхода; газ считается после выбора.
- Решение: прирост доли и выбор пути — **чистый**: выход минус газ шага в единицах выходного токена.
  Газ шага — по виду пула (уже измеряется пробами, `quote/gas.rs`), цена газа — текущая (`gas.wei`), перевод в
  токен выхода — по средней цене маршрута. Новая доля/путь добавляется, только если её чистый прирост > 0 и больше,
  чем у увеличения уже открытой доли. Выбор между путями разной длины — тоже по чистому выходу.
- Настройка: **`dex.route_gas_aware`** (да/нет, площадка DEX; не задана — как сейчас, без учёта).

### R2. Многошаговые пути в одной транзакции Universal Router
- Сейчас: исполнимо не больше 2 шагов на ногу (`graph_route.rs:189`).
- Универсальный роутер PancakeSwap (V2/V3/Infinity) и Uniswap (V2/V3/V4) исполняет цепочку команд в одной
  транзакции, промежуточный токен остаётся на роутере (`ADDRESS_THIS`) — по офрепозиториям роутеров (ссылки в
  `exec/ur.rs`). Решение: нога из N шагов внутри одного семейства роутера — исполнима; предел — `dex.route_max_hops`
  (уже есть). Шаги разных семейств — через контракт-исполнитель (часть X) или бандл.

### R3. BNB в бандле
- Сейчас: маршрут с нативным BNB в бандле помечен исполнимым, но бандл BNB не поддерживает.
- Решение: обёртка/развёртка WBNB — отдельным шагом бандла; пока не сделано — такой маршрут неисполним с причиной.

## Часть X. Контракт-исполнитель `ArbExecutor` (как исполнитель KyberSwap)

### Принцип
- Минимальный контракт на Solidity (последняя стабильная 0.8.x). **Денег не хранит**: в конце каждой транзакции
  баланс исполнителя по всем токенам маршрута = 0 (остатки — получателю). **Вызывать может только владелец** —
  кошелёк бота (адрес владельца — в хранилище контракта, задаётся при развёртывании). Обновлений, прокси, делегатных
  вызовов, произвольных внешних вызовов нет.
- Вход: кошелёк даёт исполнителю `approve` на входной токен (один раз на токен), исполнитель забирает
  `transferFrom(owner, this, amountIn)`.
- Тело: список шагов. Шаг = (вид, пул, токен входа, токен выхода, доля входа в bps от текущего баланса исполнителя
  по токену входа, параметры вида). Последний шаг по токену берёт **весь** остаток — точные суммы, без пыли.
- Конец: весь токен выхода — получателю (кошелёк); проверка `получено ≥ minOut` (иначе откат всей транзакции);
  остатки промежуточных токенов — получателю.
- Обратные вызовы пулов (V3-подобные, Algebra, Maverick): исполнитель платит пулу ровно запрошенное, **только если**
  вызывающий = пул текущего шага (адрес пула записан перед вызовом и стирается после).

### Виды шагов (каждый — по официальному интерфейсу контракта DEX, ссылка в коде)
| Вид | DEX | Как вызывается |
|---|---|---|
| `V2` | PancakeSwap V2/V1, форки V2 (Biswap, BabySwap, MDEX, Sushi, ApeSwap, Nomiswap, Baryon…), Uniswap V2 | перевод входа в пару, выход по резервам и комиссии пары (поддержка токенов с налогом: вход = баланс пары − резерв), `pair.swap` |
| `V3` | PancakeSwap V3, Uniswap V3, форки V3, Topaz Slipstream, KyberSwap Elastic | `pool.swap(recipient, zeroForOne, +amountIn, предел цены, data)` + обратный вызов своего имени |
| `ALGEBRA` | THENA Fusion | `pool.swap(...)` + `algebraSwapCallback` |
| `SOLIDLY` | THENA V1 (volatile и stable) | `pair.getAmountOut` в самом контракте, перевод, `pair.swap` |
| `CURVE` | Ellipsis, Lista, Nerve, Pancake Stable | `approve` пулу + `exchange(i, j, dx, 0)` |
| `DODO` | DODO V2 (DVM/DPP/DSP) | перевод в пул, `sellBase(to)` / `sellQuote(to)` |
| `WOO` | WooFi (WooPPV2) | перевод в пул, `swap(...)` |
| `MAVERICK` | Maverick V2 | `pool.swap(...)` + обратный вызов |
PancakeSwap Infinity и Uniswap V4 (общий PoolManager) — через свой Universal Router, как сейчас (часть R2).

### Бот
- Настройка **`exec.executor_address`** (адрес, площадка DEX; не задана — маршруты через разные роутеры идут бандлом,
  как сейчас). Задана — маршрут, которого не исполняет один Universal Router, собирается шагами исполнителя и уходит
  **одной транзакцией** любым каналом.
- Перед отправкой — та же симуляция `eth_simulateV1` и сверка с `req.worst_price`.
- **Проверка до развёртывания**: «Сухая сделка DEX» (решение 121, C4) получает режим «через исполнитель»: байткод
  исполнителя подставляется в симуляцию (`eth_simulateV1` state override — `code` и `storage` владельца) на
  свободный адрес — исполнитель проверяется на живой сети, не будучи развёрнутым.
- **Развёртывание**: кнопка «Развернуть исполнитель» (Площадки → DEX) — показывает газ и цену в USDT, просит
  подтверждения, отправляет транзакцию создания с кошелька бота, показывает адрес; Тигран вписывает его в
  `exec.executor_address`. Байткод — из репозитория (`contracts/`), сборка `solc` с фиксированной версией и
  проверкой хеша.

## Часть F. Исполнимость DEX по объёму (с исполнителем)
Порядок (карта покрытия): Topaz Slipstream → THENA Fusion → форки V3 → THENA V1 (+ математика stable-инварианта
Solidly `x³y + xy³ = k`) → стейблсвапы Curve (Lista/Ellipsis/Nerve; математика есть — подключить к графу) → DODO
(+ поиск пулов по фабрикам DVM/DPP/DSP, т.к. индексатор их не отдаёт) → WooFi (математика есть) → Maverick V2
(цикл свопа по бинам).
- Для каждого: чтение состояния и события пула → ребро графа → котировка → шаг исполнителя → проба налога через
  этот пул (если нужно) → тест на записанных данных (живые ответы узла; где записей нет — записать на сервере, бот
  умеет писать сырые ответы).
- Без адреса исполнителя эти семейства — сигнал (как сейчас); с адресом — исполнимы.

## Не делаем
- RFQ / PropAMM (Tessera, Native, Metric…) — закрытые API (карта покрытия: ~3% объёма).
