# Причина HTTP 429 в справочнике пулов

В снимке Arbitrum 23 ноября у 3127 из 3142 монет последней ошибкой был HTTP 429. Снимок содержал код HTTP и путь запроса. В нём отсутствовали тело ответа и время попытки. Поставщик указывает для Demo до 100 запросов в минуту и 10 000 кредитов в месяц. Успешный ответ списывает месячный кредит. Запросы со статусом 4xx и 5xx входят в минутный лимит. Определить конкретную исчерпанную квоту по одному HTTP-коду невозможно. [Правила учёта](https://support.coingecko.com/articles/1864417806-how-does-coingecko-api-count-the-api-usage-credit) и [тарифы](https://www.coingecko.com/en/api/pricing).

В опубликованных записях запросов CoinGecko передаёт код в `status.error_code` и пояснение в `status.error_message`. Встречались код 429 с сообщением о частоте и код 10006 с сообщением о достигнутом числе вызовов. В UI выводятся числовой код и сведения, явно присутствующие в распознанном пояснении. Неопознанные объекты и текст дают сообщение о неизвестном типе лимита. Полные тексты поставщика, URL и другие поля в сообщение 429 не переносятся. Для GeckoTerminal поддержан формат `errors[].title`, уже встречавшийся в записи проекта. [Ответ с кодом 429](https://github.com/freqtrade/freqtrade/issues/9461) и [ответ с кодом 10006](https://github.com/nirholas/three.ws/blob/main/docs/ops/production-log-triage.md).

У каждой монеты показывается известное в текущем процессе время **начала последней попытки фоновой проверки**. В попытку могут входить очередь, несколько страниц и повторы. Дата получения последнего полного ответа хранится отдельно. При новой попытке предыдущий исход может оставаться видимым до получения нового. История снимков прежних версий читается без нового поля.
