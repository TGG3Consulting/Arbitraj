## 1. Где обрывается путь сигнала (как было)

| Шаг | BingX ↔ DEX | DEX ↔ DEX до решения 124 |
| --- | --- | --- |
| Сигнал | тик монеты → `core/evaluate.rs` → `signal.rs` → очередь кандидатов | `quote/cycle_scan.rs` считается **только по запросу интерфейса** (`GET /api/venues/{id}/dex-cycles` → `Venue::dex_cycles`). Ядро циклы не видит вовсе |
| Кандидаты, бюджет | `core/candidates.rs` → `limits::budget` | нет |
| Размер | `core/size_search.rs` (кривая `costs.rs`) | фиксированный `dex_dex.probe_input_base` (техдолг «очень срочно») |
| Прибыль, пороги | `core/profit.rs` | только сортировка сигналов по `dex_dex.min_profit_base` |
| Финальная котировка, предпроверка | `final_scope`, `precheck.rs` | нет |
| Исполнение | `executor.rs` → `trade_ops` → `Venue::trade` | **обрыв**: у `exec/cycle_bundle.rs` нет вызывающего; `dex_dex.execute` читает только `require_execute`, которую никто не зовёт |
| План ↔ факт, «Сделки», Telegram | `ledger.rs`, `fills.rs`, `deal.closed` | нет |

Итог: переключатель `dex_dex.execute` ни на что не влиял; направление давало только карточки сигналов.

## 2. Как ядро видит сделку цикла

- **Отдельного вида сделки нет.** Сделка — тот же `Deal` (`core/deal.rs`) с направлением
  `Direction { asset: базовая монета (тикер, адрес), buy_on = sell_on = площадка DEX }`. Признак цикла —
  `buy_on == sell_on` (у BingX ↔ DEX и биржа ↔ биржа площадки всегда разные). Так «Сделки», итог дня, лимиты по монете,
  карантин, пауза площадки, замок «одна сделка на монету» (по базовой монете) работают без изменений.
- **Шаги, которые к циклу не применяются, не вызываются вовсе** — у цикла свой короткий исполнитель
  (`core/cycle_deal.rs`), а не ветка внутри `executor.rs`: перевод, депозит, зачисление, режим застрявшей монеты,
  частичная покупка, перегон, возврат USDT. Деньги не покидают кошелёк: цикл атомарен, либо весь в блоке, либо ничего.
- Учёт: `invested` = вход × курс базовой в USDT, `proceeds` = выход × курс, `spent` = газ (BNB) × курс BNB — курсы
  даёт адаптер по своим пулам (как сигнал цикла: базовая USDT — 1, WBNB — пул WBNB–USDT). `buy` = итог свопа
  (`TradeResult`, сторона Sell «базовая → базовая»: qty = вход, avg_price = выход/вход, fee = газ BNB). Шаг `Buying` →
  `Closed` (или `Halted` при неизвестном исходе).

## 3. Путь цикла после решения 124

```
событие пула (tick.rs) ──kick──► core/cycle_watch.rs (одна задача; толчки сливаются; dex_dex.scan_min_interval_ms)
   └─ для каждой DEX с dex_dex.execute = да: Venue::dex_cycles() (тот же граф 80, оба обхода — отдельные сигналы)
      └─ кандидаты: executable && чистая прибыль сигнала > 0 (на оптимальном входе ≤ probe), лучший первым
         └─ core/cycle_plan.rs: risk::can_open (money.*, risk.*, режим, пауза, карантин) → бюджет limits (money.*,
            сухой — dry.budget_usdt) ∧ баланс базовой у кошелька (Venue::dex_cycle_quote с кошельком)
            → размер: core/size_search.rs с кривой цикла (Venue::dex_cycle_quote на каждую точку, шаг
              dex_dex.size_step_base, size.*) → порог: чистая × курс базовой ≥ dex_dex.min_profit_usd (USDT)
            → граница minOut = вход + затраты (газ свопов + approve + чаевые, в базовой) + порог;
              не ниже ожидаемого × (1 − exec.dex_slippage_pct)
         ├─ сухой режим: Venue::dex_dry_cycle (сборка + eth_simulateV1, ничего не уходит) → журнал, cycle.dry
         └─ живой: core/cycle_deal.rs → ledger::open → Venue::dex_cycle_trade (один вызов, без повторов)
            └─ адаптер exec/cycle_trade.rs: dex_dex.execute → пулы цикла заново Multicall3 на голове (verify.*) →
               пересчёт на входе → ожидаемое ≥ minOut → форма:
               (b) исполнитель ArbExecutor, если задан exec.executor_address и ВСЕ шаги — виды исполнителя
                   (exec/cycle_exec.rs): onchain::ensure → approve базовой исполнителю (один раз; отправлено — всё
                   заново на живом состоянии, второго approve нет) → eth_simulateV1 (received ≥ minOut, газ
                   симуляции съел прибыль — отказ) → одна транзакция (txs::send) → факт по Transfer базовой;
               (a) бандл свопов cycle_bundle (решения 84, 86), только если все включённые каналы бандловые
                   (решение 121 B3) и все шаги — Universal Router без форков; последний хоп несёт границу minOut;
               иначе — NoRoute с причиной (цикл остаётся сигналом).
            └─ ядро: ledger (план ↔ факт), deal.closed, ошибки — rules_apply (журнал, exec.*, пауза при неизвестном
               исходе), без повторов
```

Почему исполнитель предпочтительнее: одна транзакция, атомарна сама по себе (не зависит от бандл-каналов), без
пыли межроутерного перехода, любые виды пулов (V2/V3/Algebra/Solidly/DODO/Curve). Бандл v1 передаёт промежуточную
монету по **гарантированному минимуму** предыдущего участка (решение 86) — второй участок считается от входа, уже
уменьшенного на допуск `exec.dex_slippage_pct`; при допуске 0,5 % и двух участках это съедает больше, чем дают
типичные циклы, поэтому граница minOut на последнем хопе в бандле почти всегда не проходит (отказ до отправки, без
потерь). Это честное ограничение v1; для бандла остаются циклы внутри одного Universal Router (один участок, пыли нет).

### Контракт ArbExecutor при tokenIn == tokenOut (проверено по `contracts/ArbExecutor.sol`, не менялся)

- `direct` = false (условие `tokenIn != tokenOut`) — прямой вход в пул для цикла выключен, как в contracts/README.md:
  вход сначала `transferFrom(владелец → исполнитель, amountIn)`.
- `before = balanceOf(владелец)` читается **после** забора входа, поэтому `received = баланс после − before` — это
  весь выход цикла (не прибыль). Значит `minOut` = вход + затраты + порог: контракт сам откатит транзакцию, если
  вернулось меньше.
- Шаг с `tokenOut == tokenOut маршрута` отдаёт выход сразу владельцу. Базовая монета встречается в цикле только в
  начале и в конце (`route_paths::enumerate_cycles`: внутренние токены не повторяются) — поэтому промежуточные шаги
  идут на исполнитель, последний — кошельку. Остатки (`_sweep`) — кошельку и тоже входят в `received`.
- Факт: вход = Transfer базовой **из** кошелька, выход = Transfer базовой **на** кошелёк (exec/result.rs по логам).
  Разбор `executor/fact.rs` («возврат неистраченного входа») к циклу НЕ применяется: у цикла вход и выход — один токен,
  и последний хоп CURVE отдаёт выход через исполнитель — вычитание исказило бы факт.

## 4. Прогон по сценариям

1. **Прибыльный цикл** USDT → CAKE → WBNB → USDT (V3 Pancake, V2, V3 Uniswap), исполнитель задан. Сигнал: чистая
   0,4 USDT на пробе. Размер: тернарный поиск даёт вход 230 USDT, чистая 0,9. minOut = 230 + 0,05 (газ+чаевые) +
   порог 0,1 = 230,15; ожидаемое 231,0 × (1 − 0,5 %) = 229,8 — граница 230,15. Пулы перечитаны, ожидаемое 230,9 ≥
   230,15. Разрешение есть. Симуляция: received 230,9, газ 310 000 → чистая 0,85 ≥ 0,1. Транзакция в блоке. Факт:
   ушло 230, пришло 230,88 → Deal: invested 230, proceeds 230,88, spent 0,05, итог 0,83 USDT, deal.closed.
2. **Цена изменилась к блоку**: между симуляцией и блоком кто-то сдвинул пул — `received < minOut` → контракт
   откатывает всю транзакцию. Деньги на месте; потерян только газ отката (приватный канал может не включить
   откатную транзакцию — тогда и газа нет). Ядро: SwapReverted → spent = газ, Deal Closed с убытком на газ,
   exec.swap_reverted. Повтора нет. Если сдвиг заметен до отправки — отказ на пересчёте или симуляции, сделки нет (в
   журнал, без «Сделок»).
3. **Монета с налогом в цикле**: `cycle_scan::tax_free` не строит цикл через токен с налогом (налог мид-свопа
   официально не описан, не гадаем) — сигнала нет, исполнения нет. Базовая монета с налогом в `dex_dex.base_tokens` —
   налог базовой на переводе кошелёк → исполнитель уменьшит вход шага, итог упадёт → откат по minOut (без потерь).
   Поддержать токены с налогом — вопрос Тиграну (ниже).
4. **Бандл не попал в блок** (форма a): приватный бандл истекает по maxBlockNumber, газа нет, nonce свободны
   (решение 84) → TxNotIncluded, сделка Closed с итогом 0 (без затрат), send.tx_not_included. Одиночная транзакция
   исполнителя не попала — трекер ждёт `send.max_wait_blocks`, отменяет; nonce занят отменой — TxNotIncluded со
   стоимостью отмены; исход неизвестен (Replaced) — OutcomeUnknown: Halted, площадка на паузу, ручная проверка.
5. **Базовая BNB/WBNB**: базовая — адрес из `dex_dex.base_tokens`, т. е. WBNB (ERC-20). Цикл WBNB → … → WBNB идёт как
   обычный ERC-20 (исполнитель и бандл). Нативный BNB (адрес 0 у пулов V4/Infinity с нативной валютой) внутри цикла
   — отказ до отправки («нативный BNB внутри цикла в v1 не исполняется»). Газ платится из BNB кошелька, его резерв
   `risk.min_bnb_balance` проверяет отправка. Курс WBNB → USDT для учёта — лучший пул WBNB–USDT реестра.

## 5. Управление

- Есть: `dex_dex.enabled` (сигнал), `dex_dex.execute` (авто-исполнение), `dex_dex.min_profit_base` (теперь только
  сортировка сигнала), `dex_dex.max_cycle_len` (число шагов), `exec.executor_address`.
  обязателен для исполнения), `dex_dex.max_cycle_len` (число шагов), `exec.executor_address`.
- Новые: `dex_dex.min_profit_usd` (порог исполнения в USDT — один для базовых USDT и WBNB), `dex_dex.size_step_base` (шаг объёма в базовой монете для подбора размера — без него размер не подбирается,
  сделки нет), `dex_dex.scan_min_interval_ms` (необязательная: наименьший промежуток между поисками циклов для
  исполнения, как `signal.eval_min_interval_ms`).
- «Сухая сделка DEX» → режим «цикл»: выбрать цикл из текущих сигналов, бюджет (USDT, необязательно — иначе лимиты
  money.*), «как сделка» / «через исполнитель (код подставлен)» → весь путь ядра (бюджет, размер, граница) и
  симуляция без отправки (`POST /api/dex/dry-cycle`).

## 7. Дополнение координатора (живые данные 03.11)

На работающем боте `dex-cycles` давал 6 циклов, все в минусе на фиксированном входе 40 USDT (лучший −0,17).
- **Вход сигнала — оптимальный** (`quote/cycle_opt.rs`): газ и чаевые от входа не зависят, кривая «выход − вход» у
  пулов вогнута → тернарный поиск на (0, `dex_dex.probe_input_base`], шагов `size.refine_steps`; не задана — как
  раньше, на самой границе. `probe_input_base` — верхняя граница сигнала. Исполнение подбирает вход заново общим поиском
  ядра в пределах money.* и баланса кошелька. Карточка цикла и «Сухая сделка» показывают оптимальный вход и прибыль на
  нём. Если и на оптимуме чистая < 0 — цикла нет (минус на 40 USDT при газе ~0,1 USDT обычно значит, что валовая на
  любом входе меньше газа).
- **Базовая WBNB**: курс WBNB→USDT — лучший пул WBNB–USDT, газ BNB = базовая 1:1, бюджет money.* (USDT) переводится во
  вход WBNB по курсу; порог исполнения — `dex_dex.min_profit_usd` в USDT (раньше один `min_profit_base` значил бы
  0,05 USDT для USDT-циклов и 0,05 WBNB ≈ 30 USDT для WBNB-циклов). Тест — `wbnb_base_cycle_end_to_end_without_network`.
