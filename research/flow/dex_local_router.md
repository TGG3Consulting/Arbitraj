# Локальный маршрутизатор DEX — проект (решения 80–82)

> Статус: проект на утверждение Тиграна. Код не начат. Оформлено 2026-10-28.
> Основание: решение Тиграна (28.10) — свой граф-маршрутизатор в ОЗУ вместо чужого API,
> KyberSwap только как ещё одна площадка DEX. Вариант 2: BingX ↔ DEX, BingX в игре.

## 1. Итог решения Тиграна (28.10)

- **Вариант 2:** арбитраж BingX ↔ DEX с транзитным мостом на стороне DEX. BingX остаётся. Миссия
  проекта НЕ меняется — это улучшение ноги DEX, а не новый источник.
- **Свой граф, не чужой API.** Маршруты ищем сами в ОЗУ. KyberSwap Aggregator API для поиска НЕ
  используем (офдока: лимит 3 запроса/с, один запрос = одна пара/сумма, кэш маршрута ≤ 5–10 с —
  «все монеты без отставания» через него невозможно).
- **KyberSwap = ещё одна площадка DEX:** её пулы (KyberSwap Elastic) участвуют в графе наравне с
  Pancake/Uniswap/Biswap; её роутер — одна из целей исполнения свапа, когда путь выгоднее через неё.

## 2. Что УЖЕ построено (НЕ переписываем, переиспользуем)

- **Приватное исполнение ноги DEX:** каналы приватной отправки + бандлы + мин-газ по каналам
  (решения 41–45: 48 Club, BlockRazor, PancakeSwap MEV Guard, Blink, JetBuilder, NodeReal, bloXroute,
  Flashblock). Проверка попадания в блок своим узлом (42).
- **Защита от убытка = amountOutMin:** проверка реально полученного баланса в той же транзакции
  обмена, откат всей tx при недоборе (решение 40) — всегда включена.
- **Математика пулов:** V2, V3 (Pancake/Uniswap), Infinity CL/Bin, Uniswap V4 — `math/*`,
  карта тиков и глубина по сторонам (решение 73).
- **Маршрутизация (частичная):** путь через одну промежуточную монету (решение 52, `quote/via.rs`);
  умный сплит суммы (решение 38, `quote/smart*.rs`); выбор лучшего (`quote/pick.rs`, `select.rs`).
- **Данные:** обнаружение пулов, разбор событий по семействам, ws-источник событий (решение 79).

## 3. Что НОВОЕ (объём работ)

### Решение 80 — полноценный локальный граф-маршрутизатор
Сейчас маршрут ограничен: мост `via` — одна промежуточная монета, а в `smart_ways` мост считается
только по пулам PancakeSwap и по списку `mids`. Это не полный граф по рынку.

Новое:
- **граф токенов в ОЗУ по ВСЕМ отслеживаемым пулам всех DEX** (а не только Pancake на мосту);
- **поиск путей глубины 2–3** (BFS/DFS) через набор промежуточных монет (BNB, USDT и настраиваемый
  список) с любой площадки;
- **сплит суммы между несколькими пулами** одной пары (как агрегатор), нашей математикой (73) и со
  всеми затратами (`quote/costs.rs` остаётся);
- **глобально лучший маршрут на сторону** (покупка/продажа), `amountOutMin` — наш;
- всё в памяти, без внешних вызовов; глубина/ширина поиска — настройки (чтобы держать скорость).

Переиспользуем: `math/*`, `quote/pool_quote.rs`, `costs.rs`, `select.rs`, `pools/mids.rs`; обобщаем
`via`/`smart` в граф. Ядро и шлюз не меняются — расширяется адаптер DEX.

### Решение 81 — KyberSwap Elastic как семейство DEX
- Elastic — концентрированная ликвидность (похоже на V3, но своя: reinvestment liquidity, свой
  tick-механизм, свои Factory/Router/QuoterV2/TickReader, свои события Swap).
- Только по офдокам KyberSwap: адреса контрактов на BSC, ABI событий и свопа, формула шага цены.
- Добавить: `families` (classify), `discover` пулов, разбор событий, математику свопа Elastic
  (отдельный модуль рядом со `swap_cl.rs`), квотер/роутер для сверки и исполнения.
- Исполнение свопа Elastic — через её роутер, тем же путём приватной отправки (41–45).

### Решение 82 — Biswap как семейство DEX
- Biswap — форк Uniswap V2 с иной комиссией пула (уточнить по офдокам/контракту). V2-математика уже
  есть; добавить `families` + `discover` + адреса фабрики/роутера.

## 4. Открытый вопрос по данным (нужно решение Тиграна)

Твоя схема рисует Multicall3 на всё состояние каждый блок. Текущий бот — событийный (ws, решение 79)
плюс чтение глубины по требованию. Два варианта:
- **(A)** оставить событийный (ws) + чтение по требованию, Multicall3 — только на кандидатах и перед
  сделкой. Легче для узла, уже построено.
- **(B)** добавить периодический Multicall3-снимок всех пулов каждый блок. «Полная карта» всегда
  свежая, но тяжелее по узлу (и это та нагрузка, из-за которой были отставания).

Рекомендация: **(A)** — событийный скан + Multicall3 точечно. Подтвердить.

## 7. Бэклог фазы 80 — граф-маршрутизатор (пошагово для агента)

Правила проекта на каждом шаге: без хардкодов (всё в настройках), без моков (тесты на записанных
данных), файлы ≤ ~200 строк, шапки и комментарии, ядро не импортирует адаптеры, готовая фича =
код + настройки + UI + комментарии + ARCHITECTURE + DECISIONS. Отдельный PR на фазу, ревью, слияние.

Сначала — РЕКОН (не код): прочитать и описать текущие возможности и точки расширения
`quote/{via,via_pools,smart,smart_ways,smart_quote,pick,select,path,rate,direct,direct_route,pool_quote,costs}.rs`,
`pools/{mids,families,registry}.rs`. Понять, как сейчас формируется множество пулов пары, список
промежуточных монет (mids), сплит и выбор лучшего — чтобы ОБОБЩАТЬ, а не дублировать.

Шаги:
1. **Модель графа в ОЗУ.** Структура: узлы — токены, рёбра — пулы (с видом/семейством, адресом/PoolId,
   текущим состоянием для математики). Построение из реестра пулов; обновление ребра по событию пула
   (решение 83, точечно). Индексы «пары → список пулов», «токен → рёбра». Настройки: список
   промежуточных монет (расширить `dex.intermediate_tokens`), максимум пулов на ребро.
2. **Перечисление путей.** BFS/DFS глубины `dex.route_max_hops` (новая настройка, 2–3) от USDT к монете
   и обратно, только через разрешённые промежуточные. Ограничение ширины `dex.route_max_paths`
   (новая настройка), чтобы держать время. Отсев заведомо мелких рёбер (ниже
   `dex.min_pool_liquidity_usd`, решение 73).
3. **Оценка пути и сплит.** Для каждого пути — точный расчёт нашей математикой (решение 73, `pool_quote`),
   со всеми затратами (`costs.rs`), по сторонам (покупка/продажа). Сплит суммы между несколькими
   путями/пулами пары: алгоритм распределения (например, по убыванию предельной отдачи), шаг сплита —
   настройка (`smart.split_step_pct` уже есть, переиспользовать/обобщить). Итог стороны — лучший
   суммарный выход и его `amountOutMin`.
4. **Встраивание в котировку.** Результат графа отдаётся туда же, куда сейчас `via`/`smart` (через
   `select.rs`/`pick.rs`), чтобы ядро и экраны не менялись. Переключатель источника маршрута
   (`dex.router_mode = прямой+via | граф`, новая настройка; старое поведение остаётся по умолчанию,
   ничего не ломаем — как и другие переключатели проекта).
5. **Верификация перед сделкой (решение 83).** Перед бандлом — целевой Multicall3 по пулам выбранного
   маршрута, пересчёт `amountOutMin` на свежих данных; расхождение с планом сверх допуска — отмена
   (как сейчас отменяет сверка с квотером, `exec/precheck.rs`).
6. **Интерфейс:** в карточке сигнала (решение 74) показать выбранный маршрут (пулы, хопы, сплит) и
   `amountOutMin`; настройки графа — на экране «Настройки».
7. **Тесты на записанных данных:** граф из записанных состояний пулов (депт-записи 25–26.10 +
   при необходимости новая запись Multicall3), проверка: путь глубины 2–3 находится; сплит не хуже
   одиночного пула; `amountOutMin` считается; переключатель `прямой+via` ↔ `граф` не меняет старое
   поведение в режиме «прямой+via».

Фазы 81 (KyberSwap Elastic) и 82 (Biswap) — отдельными PR после 80: добавляют рёбра графа новых
семейств, их математику/разбор/адреса (только по офдокам), исполнение через существующую приватную
отправку.

## 8. Охват DEX и формы маршрута — почему у агрегатора «дахера сигналов»

Причин несколько, и они перемножаются (ОХВАТ × ФОРМЫ МАРШРУТА × учёт затрат):
- **Охват всех DEX:** на монету больше пулов → лучшая цена по ним лучше любого одного пула → сторона
  DEX в спреде шире → больше монет перешагивают порог прибыли.
- **Многошаг (мосты):** достаёт монеты без прямого пула с USDT; часто 2 хопа лучше прямого.
- **Треугольники/циклы как формы пути:** ловят перекосы между тремя токенами.
- **Сплит между пулами:** меньше проскальзывание → больше максимальный выгодный объём → «большие окна».
- **Учёт газа/проскальзывания:** тонкие возможности остаются в плюсе → больше сигналов доживает.

### Охват DEX — приоритеты (вариант 2, нога DEX; KyberSwap — роутер, не арбитражник: берём его ФОРМЫ)
1. **Форк-семейства — широко и дёшево** (общая математика с нашей, добавление = family + discover + адреса):
   - V2-форки: Biswap (решение 82), ApeSwap, MDEX, BakerySwap, Nomiswap, BabySwap, SushiSwap BSC и др.
   - V3/CL-форки: Uniswap V3 (есть), THENA/Algebra (динамическая комиссия — уточнить по офдокам),
     KyberSwap Elastic (решение 81).
   Покрывает бо́льшую часть ликвидности BSC. Каждый DEX — только по офдокам (решение 23): адреса
   фабрики/роутера/квотера, ABI событий/свопа.
2. **Экзотическая математика — по очереди, по вкладу в ликвидность** (каждый = своя формула свопа,
   отдельная реализация): DODO (PMM), Wombat, Curve/Ellipsis (stableswap), WooFi (оракульная), Maverick.
   «Все разом» не обещаем — берём по ликвидности.

### Масштаб (чтобы не вернуть отставания)
Все DEX = пулов сильно больше нынешних ~2850 → больше подписок ws (дробление, решение 79), больше
состояния в графе, больше вычислений в поиске. Держим: событийный скан + точечный Multicall3
(решение 83); ограничение глубины/ширины поиска настройками; отсев мелких рёбер
(dex.min_pool_liquidity_usd). Граф и поиск проектировать с запасом на рост числа пулов.
