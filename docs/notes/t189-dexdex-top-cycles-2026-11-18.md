## а) Путь DEX ↔ DEX по коду

1. **Запуск.** Событие пула → core/tick.rs:91 `cycles.kick.notify_one()` → core/cycle_watch.rs run: толчки во время
   прохода сливаются; по каждой площадке DEX с dex_dex.execute = да — pass; затем пауза до
   dex_dex.scan_min_interval_ms (не задана — без паузы).
2. **Поиск** (venue.rs dex_cycles → quote/cycle_scan.rs scan, в потоке счёта quote/cpu.rs): цена газа =
   max(eth_gasPrice·(1 + send.gas_price_markup_pct/100), channel.min_gas_price_gwei готовых каналов). Граф —
   снимок (pools/graph_read.rs; при dex.graph_background — фоновый, пути потом гидратируются свежими записями реестра).
3. **Циклы.** Было: route_paths.rs:171-260 enumerate_cycles — DFS по рёбрам графа, остановка на первых
   dex_dex.max_cycles (:214). Стало (решение 404): quote/cycle_rank.rs top — все циклы, отбор N лучших (см. «Правка»).
4. **Фильтр налогов** cycle_scan tax_free: каждый небазовый токен — «монета подписки» (coin_tickers) с проверкой
   налогов «известно, все 0».
5. **decimals** токенов (кэш или узел).
6. **Ноги** quote/cycle.rs legs_for_cycle → quote/select.rs usable: сторона пула сверена с квотером, газ стороны
   измерен пробой (Usable.gas — gasUsed eth_simulateV1 обмена), налог пула на стороне измерен и = 0, крючок допущен.
7. **Отсев ρ** quote/bound_cycle.rs (решение 373): строгий верх отдачи < 1 и dex_dex.min_profit_base ≥ 0 → цикл не
   считается; доля sieve.audit_share отсечённых считается полностью (cycle_audit.rs).
8. **Вход сигнала** quote/cycle_opt.rs best: тернарный поиск максимума «выход − вход» на (0, probe_input_base],
   size.refine_steps шагов; газ от входа не зависит, поэтому максимум чистой = максимум валовой.
9. **Форма** exec/cycle_gate.rs form: исполнитель (адрес у кошелька и все шаги — виды исполнителя) или бандл
   (все шаги через UR, не форк, бандл-каналы); с шагом V4/Infinity — сначала бандл.
10. **Сигнал** quote/cycle.rs build_signal: газ = Σ Usable.gas × цена; чаевые — только не у бандла (только если готов
    ровно один канал и он бандловый, send/mod.rs:97-101); чистая = валовая − (газ + чаевые)·курс BNB→база.
11. **Кандидаты** core/cycle_watch.rs:87-90: executable и net_profit > 0 (на входе сигнала!). Нет кандидатов — конец.
12. Кошелёк «DEX ↔ DEX» в маппинге → risk::can_open → core/cycle_plan.rs plan: бюджет money.max_per_trade_usd
    (DEX · «DEX ↔ DEX») и money.max_per_coin_usd, баланс базовой у кошелька, подбор входа ядром (size_search, шаг
    dex_dex.size_step_base, size.*), порог dex_dex.min_profit_usd в USDT, граница minOut = max(вход + затраты + порог,
    выход·(1 − exec.dex_slippage_pct)). Затраты плана (quote/cycle_cost.rs): газ свопов + approve исполнителю (если нет
    разрешения) + у исполнителя чаевые и газ их перевода.
13. **Сделка** core/cycle_deal.rs (замок монеты) → exec/cycle_trade.rs: гейт execute, пулы перечитываются Multicall3,
    пересчёт ≥ minOut, баланс, форма → exec/cycle_exec.rs (исполнитель) или cycle_bundle_trade.rs, проба
    eth_simulateV1 до отправки, одна отправка.

## в) Арифметика

- Газ — факт записей: один шаг через исполнитель 114 817…293 939 ед. (tests/data/executor_v3_live_2026-11-17/
  summary.json); живой бот — 261–477 тыс. ед. на цикл. Цена газа: чаще всего в записанных квитанциях
  (tests/data/receipts_2026-10-25) effectiveGasPrice 0x2faf080 = 0,05 gwei; на живом боте 476 937 ед. = 0,0000477 BNB →
  ≈ 0,1 gwei (476 937 × 10⁻¹⁰ = 0,0000477) и 0,0281 USDT → курс ≈ 589 USDT/BNB.
- Чаевые: channel.tip_bnb не задана → 0 (бандл их и так не шлёт).
- Нужно: валовая ≥ 0,05 (порог) + газ ≈ 0,03 → ≈ 0,08 USDT. При входе 40 USDT — 0,2 % сверх комиссий и проскальзывания,
  при 90 USDT — 0,09 %. Наименьшая разница цен пулов = Σ комиссий + это: два пула V2 0,25 % — ≥ ~0,6–0,7 %;
  V2 0,25 % + V3 0,05 % — ≥ ~0,4–0,5 %; два V3 0,01 % — ≥ ~0,1–0,2 %. В терминах курса круга (уже с комиссиями):
  курс > 1 + (газ + порог)/вход + проскальзывание, например > 1,002 на 40 USDT.
- Газ не главный: 0,03 USDT. Порог 0,05 при входе 90 USDT требует 0,055 % — мало.
- **Почему вход сигнала 0,0001043 WBNB (вопрос 1 координатора), факт по коду и числам:** cycle_opt.rs best: если
  gain(m1) ≥ gain(m2), верх сжимается до m2 = верх − треть. С probe_input_base = 40 и 30 такими шагами подряд верх =
  40·(2/3)^30, а ответ — середина (0 + верх)/2 = 0,0001043019… — ровно вход 81 WBNB-цикла (расчёт 40·(2/3)^30/2 =
  0,000104301901…). Значит, size.refine_steps = 30 (вывод из совпадения; значение настройки сверить), и на всех 30 шагах
  «выход − вход» на меньшем входе был не хуже, чем на большем: на (0, 40 WBNB] валовая не растёт ни на каком входе —
  у этих циклов нет разницы цен сверх комиссий. Это не бюджет (бюджет — только в плане ядра) и не шаг входа
  (size_step_base — только в плане). Вход USDT-циклов 0,035–0,2 — у них нижний конец сдвигался (есть внутренний
  максимум), но валовая на максимуме — +0,0000272 USDT на 0,2 USDT (0,013 %) — меньше газа в тысячу раз.
- Ловушка (по коду): кандидат отбирается по чистой на ВХОДЕ СИГНАЛА (cycle_watch.rs:89), не на входе плана. При
  разнице цен вход сигнала растёт сам (максимум валовой), так что ловушка срабатывает только у циклов без разницы цен.
- probe_input_base одна на обе базы и в единицах базовой: 40 — это 40 USDT и 40 WBNB (FIRST_RUN советует 100 / 0,2).
  На прибыльность не влияет (план берёт бюджет и баланс), но верх подбора сигнала WBNB-цикла — 40 WBNB.

## г) Дешёвый показатель «лучший цикл»

- В коде уже был строгий верх r_e (quote/bound_rate.rs, решение 372) и ρ цикла (bound_cycle.rs) — только для V2, V3,
  Algebra, Solidly волатильного, без крючка; у прочих видов Err. Для порядка нужен показатель у всех видов.
- Выбрано: курс ребра = спот-цена пула по текущему состоянию (quote/spot.rs coins_for — все виды: V2, Solidly,
  StableSwap, PMM, TickBin, Fictive, Vault, LB, AmpV2, V3/CL/Elastic/Algebra, Bin, DODO) × (1 − комиссия пула на этом
  направлении, quote/steps.rs fee_pct). Курс круга = произведение по рёбрам (минимальные единицы сокращаются: старт и
  финиш — одна монета). Это курс на бесконечно малом входе: > 1 — круг по текущим ценам возвращает больше вложенного до
  проскальзывания и газа. Не доказательство и не отсев — только порядок (отсев остаётся у ρ, решение 373).
- При равенстве — глубина узкого места: наименьшая глубина стороны пула по книге глубины (Book::last, USD; та же
  глубина, что ранжирует пулы в ребре графа); затем ключ цикла (байты пулов и токенов входа) — порядок полный.

## Оценка числа циклов

Рёбра графа бывают трёх видов (pools/market.rs retain): монета–USDT, монета–промежуточная, промежуточная–USDT. При P
пулах на ребро (dex.route_max_pools_per_edge = 3) и M промежуточных у одной монеты базы USDT длиной ≤ 3: двухшаговых
P(P−1) = 6, трёхшаговых через промежуточную ≤ 2·M·P³ = 54·M. При N монет — ≤ N·(6 + 54·M) (N = 1000, M = 3 →
≈ 170 тыс.; реальное число меньше: у большинства монет 1–2 пула и не со всеми промежуточными). Цена одного: 2–3 умножения
Decimal по готовым курсам рёбер (курс ребра — один раз на проход) + сравнение с порогом; память — не больше 2·N
кандидатов. Длина 4: + монета → промежуточная → монета, растёт как N²·P⁴ — для этого dex_dex.rank_max_cycles.

## Правка (решение 404)

1. quote/cycle_rank.rs — перебор как enumerate_cycles, но путь — индексы рёбер (Graph::edge_ids / edge, новые), без
   копий; курс ребра — память прохода (Rates, Vec по индексу ребра, без замков, общая для баз); отбор: держится не
   больше 2·N, сжатие до N по полному порядку, порог N-го курса отсекает до выделения памяти; книга глубины
   читается только у кандидатов при сжатии (Book::last — общий замок чтения, раз на ребро-сторону, память прохода);
   рёбра (копии записей) — только у N отобранных, как раньше у N первых. Итог не зависит от порядка рёбер, пока не
   достигнут dex_dex.rank_max_cycles.
2. dex_dex.max_cycles — «сколько лучших считать полностью» (каталог, SETTINGS.md, FIRST_RUN, first_run.toml,
   SETTINGS_CASES «Смысл изменён»). Новая необязательная dex_dex.rank_max_cycles: dex.route_search_max_paths не подошла
   (это предел путей биржа ↔ DEX на монету, другой смысл и масштаб).
3. Итог прохода — quote/cycle_tally.rs → Venue::dex_cycle_tally (стык расширен, по умолчанию пусто) →
   core/cycle_scan_log.rs → core.cycle_scan.
4. Дефект tax_free: USDT не «монета подписки» → все циклы базы WBNB через USDT выбрасывались молча. Теперь USDT берётся
   по своей проверке налогов (check/service_tax.rs кладёт её под адрес USDT). Влияние на цифрах: из 54 WBNB-сигналов
   живого бота ни один не шёл через USDT (по этому дефекту — не могли); сколько WBNB-циклов через USDT было среди
   отброшенных — покажет «налоговый или непроверенный токен» в новой строке до и после.

## Почему ноль сделок

**Факты:**
1. Все 103 сигнала исполнимы — форма исполнения (исполнитель v2 / бандл) не мешает.
2. Чистая > 0 — у 0 из 103; валовая > 0 — у 4, лучшая +0,0000272 USDT при газе 0,028 USDT.
3. У 81 WBNB-цикла подбор входа 30 шагов подряд шёл к нулю — разницы цен нет на всём (0, 40 WBNB].
4. Перебор считал только первые 100 циклов на базу в случайном порядке рёбер (до 97 из них отпали молча) — по ним
   нельзя сказать, есть ли прибыльные циклы в остальном графе.
5. Циклы базы WBNB через USDT не доходили до расчёта (дефект tax_free).

**Гипотезы (не проверено):**
1. Разницы цен между пулами BSC больше комиссий закрываются другими ботами в том же блоке; бот видит состояние после
   блока — проверит строка core.cycle_scan «курс круга > 1 у N» после выкладки.
2. Покрытие: пулы монета–монета (не через USDT/промежуточную) в граф не идут — часть циклов рынка боту не видна.

## Риски

- Нагрузка: перебор всех циклов на каждый проход (проход — на каждое событие пула, толчки сливаются). Оценка выше; если
  CPU растёт — dex_dex.scan_min_interval_ms и/или dex_dex.rank_max_cycles.
- Курс круга по спот-цене — у стейблов и PMM это оценка (как у сизинга пробы): цикл с большим проскальзыванием может
  оказаться выше реально лучшего. Отбор N, а не 1, это смягчает.
- Новый метод стыка Venue::dex_cycle_tally — только чтение, по умолчанию пусто; итоги хранятся по площадке в памяти
  процесса (замок раз в проход). Поиск с «Живого экрана» (api) тоже обновляет итог.
- Локально не собиралось (cargo не запускался): возможны ошибки компиляции / clippy в новых файлах.
