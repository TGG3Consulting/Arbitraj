## Где монета «занята» (факт кода 45a9efd9)

- `core/coin_ride.rs` admit (вход исполнителя) и blocks_new (очередь расчёта, candidates.rs:81) — обе через `joinable`:
  требовалось, чтобы ВСЕ идущие сделки монеты были того же направления (`r.buy_on == d.buy_on && r.sell_on == d.sell_on`).
  Это и был запрет других направлений.
- `coin_ride::take` (ручные действия, цикл DEX ↔ DEX, продажа «Балансов») и `held` (наблюдение, прогрев, кнопка продажи
  «Балансов») — монета занята любой идущей сделкой; к «направлениям» не относятся — не тронуты.
- `coin_ride::group_running` (план возврата USDT докупки, costs_source.rs ret) смотрел направление только ПЕРВОЙ записи
  монеты.

## Общие ресурсы направлений и что с ними (факт кода)

| Ресурс | Как сейчас | Итог |
|---|---|---|
| Замок целиком `inner.active` (предпроверка + покупка) | один на монету | покупки разных направлений по-прежнему по очереди; бюджет второй считается после учёта покупки первой |
| Лимит монеты | `ledger.rs` recompute_exposure — по монете (Asset), все открытые сделки | общий на все направления (тест: 70 − 40 − 20 = 10) |
| Котировка продажи | `ride_quote.rs` sell_ahead — монеты идущих сделок ВСЕХ групп монеты с той же площадкой продажи | без правок кода (уже по площадке) |
| Котировка покупки | `ride_quote.rs` buy_fresh — идущие сделки всех групп с той же площадкой покупки | без правок кода |
| След продажи | `ride_trail.rs` — по монете и площадке | без правок |
| Зачисление | `credit_event.rs` strict — при «да» событие без хеша при ≥ 2 ожиданиях монеты у одного получателя (и кошелька) не закрывает | работает и для ожиданий разных направлений (BingX → MEXC и DEX → MEXC) |
| Кошелёк DEX | решение 132: кошелёк — по бирже; BingX → DEX доставляет на кошелёк BingX, DEX → BingX покупает с него | обмены кошелька — свои транзакции (wallet/events_tx.rs kind: Other, не Deposit) — с зачислением не путаются |
| Общий возврат USDT | `coin_group.rs` — пул по ID группы, «последняя» — по записям этой группы | у каждого направления своя группа и свой общий возврат (тест: D1 вернула, O1 не ждалась) |
| Карантин медленного перевода | по монете; при «да» снимает только своя сделка (transfer_watch.rs) | без правок |
| Остаток вне пути | `remain_fact.rs` min(учёт, факт площадки) — факт включает монеты других сделок (Н7) | поэтому сделка вне пути держит монету во всех направлениях (вопрос 1) |

## Что изменено

- `src/core/coin_ride.rs`: шапка; `same_dir`; `joinable` — все идущие с группой и на пути (любых направлений), место —
  по открытой группе СВОЕГО направления (Join) или Lead; `group_running` — по записям своего направления.
- `src/core/ride_quote.rs` — только шапка (поведение уже по площадкам).
- `src/settings/catalog/trade.rs` — описание exec.top_up (экран «Настройки»).
- Тест `tests/core_coin_reentry_t179.rs`: `on_same_direction_joins_other_directions_wait` — другие направления теперь Lead,
  застрявшая держит и другое направление; новый `other_directions_trade_in_own_groups` — «нет»: прежний отказ; «да»:
  Lead другого направления, Join каждого в свою группу, group_running по направлению, общий лимит, sell_ahead 10 + 5,
  общий возврат D1 не ждёт O1. Данные направления — записи CAKE (tests/size_common, BingX / PancakeSwap V2).

## Было / стало (пример)

CAKE, exec.top_up = да. Идёт D1 BingX → DEX (Selling, группа D1). Спред MEXC → DEX.
- Было: отказ «по монете идёт другая сделка D1 (bingx → bsc_dex, шаг Selling)», расчёт не ставится (blocks_new = true).
- Стало: расчёт идёт; сделка O1 MEXC → DEX — первая своей группы O1 (возврат USDT — с фиксированной частью в её плане);
  её продажа на DEX считается после 10 CAKE D1; следующая MEXC → DEX — докупка в O1, BingX → DEX — докупка в D1.
- exec.top_up = нет / не задана: как раньше (admit: `!top_up_on` — прежний отказ).

## Риски и вопросы

- Вопросы владельцу — docs/TASKS.md (решение 405): (1) сделка вне пути держит все направления; (2) отложенные USDT группы
  не зарезервированы от покупок на той же площадке.
- Н7 (remain_fact) теперь и между направлениями: монеты сделки другого направления на той же площадке (например, купленные
  DEX → BingX и ещё не выведенные) могут прикрыть «фантомный» остаток. Больше учёта сделка не продаёт никогда.
- Номер решения 405 — свободен в ветке и во всех локальных ветках на 18.11; параллельная задача могла занять его же.
