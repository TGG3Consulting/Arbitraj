# t194 — замки на горячем пути (18.11.2026, решение 409)

Ветка `t194/hot-locks` от `d672411b` (код живого бота). cargo локально не запускался — сборка и тесты в GitHub.

## Факт (perf живого бота 18.11 15:41, 60 с, 335 141 сэмпл)

После `dex.depth_band_pct` 2 → 10 и `dex.shallow_pools_per_pair = 3`: ядро ОС — 21,5 % сэмплов, из них
`native_queued_spin_lock_slowpath` 17,58 % (futex_wait → futex_q_lock 9,6 %, futex_wake 7,7 %); 147–150 из ~214 потоков
в futex_wait. Видимые вызывающие: `Mutex::lock_contended ← families::make`, `RwLock::read_contended ← Store::get_exact`
(в user-топе 4,77 %). User-топ: memcpy 15,85 %, Uint256 div_rem 4,74 %, SipHash 3,72 %, mi_free 2,27 %, String::clone 2,07 %.

## Где брались замки (факт кода)

- `families::make` (pools/families.rs:408–440 до правки): глобальный `static INTERNED: Mutex<Option<HashMap<…>>>`,
  замок + `id.to_string()` + SipHash кортежа на КАЖДЫЙ вызов. Горячий вызывающий — котировка на каждый пул:
  `quote/select.rs usable_with` → `families::still` (pools/dex_rules.rs:31) → `classify` → `make`; ещё
  `quote/graph_exec.rs graph_form` (на хоп, до трёх проходов) и `quote/native_gas.rs` (на хоп). Число вызовов растёт с
  числом пулов в работе.
- `Store::get_exact` (settings/store.rs:137 до правки): `cache.read()` — общий `RwLock` на все чтения настроек всех
  потоков; под нагрузкой читатели бьются за счётчик читателей замка (cache line). `classify` на каждый вызов читает dex.kind, dex.pool_enabled и все обязательные настройки вида (`required`).

## Что сделано

1. **Таблица видов DEX без замка на чтение** — `pools/family_intern.rs` (новый): снимок `HashMap<id, Vec<&'static
   Family>>` за `ArcSwap`; поиск по `&str` без выделения строки; новая запись — под замком писателя с повторным поиском
   (одна запись на сочетание, как раньше). `families::make` — через неё (то же сочетание ключа: id, протокол, graphable,
   tradable, fork, вид шага исполнителя → тот же `&'static Family`; `dex_rules::still` сравнивает указатели).
2. **Настройки в памяти — снимок за ArcSwap** — `settings/snapshot.rs` (новый): `Snapshot { now: ArcSwap<Values>,
   write: Mutex<()> }`. Читатели (`get_exact`, `all`, `pinned`, проверка id DEX в `set`) — `load()` без замка. Писатели
   (единственные: `Store::set` и `Store::mark_now`) — `update`: под замком писателя текущий снимок → копия → изменение →
   `store`, поколение (решение 352) растёт под тем же замком сразу после публикации. Решение 355 (отметка ядра сильнее
   записи `set`, пока та писала в базу) — та же проверка внутри `update`. База, история, журнал, рассылка, валидация,
   `writer` (tokio Mutex очереди изменений) — без изменений. `pinned()` — свой Snapshot с тем же Arc значений.
   Разница: раньше `Arc::make_mut` копировал значения при записи только если жив снимок `pinned`; теперь копия — на
   каждую запись (читатели могут держать снимок). Записи настроек редкие (интерфейс; отметки ядра coin_mark,
   withdraw_block, exit_gap — по событию сделки), чтения — на каждый пул.
3. **Другие явные случаи «замок на каждый вызов при чтении почти неизменных данных»** — тем же способом:
   - `pools/exec_callback.rs` `SEEN` (итог поиска селектора обратного вызова в артефакте исполнителя; артефакты
     неизменны): `usable` вызывается из `exec_kind::via_executor` на каждый хоп у DEX с `dex.v3_swap_callback`; был
     глобальный Mutex + `sig.to_string()` + клон итога. Теперь снимок за ArcSwap, ключ версия → сигнатура (поиск по
     `&str`), `usable` клона не делает.
   - `pools/registry_key.rs` `KEYS` (ключ реестра фабрики V3-форка по адресу пула; пишется при проверке пула): `get` на
     каждый запрос QuoterV2 к пулу V3 брал глобальный Mutex. Теперь снимок за ArcSwap; `remember` с тем же ключом снимок
     не меняет.
4. **Копии записей пулов (`Registry::get` → копия `Entry`) там, где нужно только читать** — заменены на
   `Registry::entry` (Arc, без копии):
   - `pools/listen_site.rs`: на КАЖДЫЙ лог пула — проверка `has_applied` у мелких пар (копия ради одного флага) и
     записи глубоких пар (каждая копировалась дважды: `entries` и `list`). Теперь Arc; записи отпускаются до
     `reg.update` (иначе `Arc::make_mut` скопировал бы удерживаемую запись). `stale` принимает свои записи и Arc
     (`Borrow<Entry>`).
   - `pools/depth.rs touch` — на каждую смену состояния пула.
   - `quote/routing.rs` (проверка цепочки токенов маршрута, на каждый хоп), `quote/breaks.rs` (разрывы стороны, на
     ногу), `quote/classic_direct.rs families` (текст причины).
