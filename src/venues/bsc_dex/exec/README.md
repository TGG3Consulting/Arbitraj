# venues/bsc_dex/exec — исполнение обмена

Прямой обмен в одном пуле (V2, V3, V4) — через Universal Router своей DEX: только в нём есть проверка
реально полученного баланса в той же транзакции (`BALANCE_CHECK_ERC20`, решение 40) и одна схема разрешений (Permit2).
Умный маршрут (решение 38) — через Universal Router PancakeSwap Infinity (`smart.universal_router`): все доли в одном
`execute`, у каждой свой минимум, в конце — проверка баланса на сумму минимумов.

| Файл | Что делает |
| --- | --- |
| `ur.rs` | Команды Universal Router, формат по DEX и версии (Uniswap 2.0 / 2.1.1+), BALANCE_CHECK_ERC20, execute |
| `swap_v2v3.rs` | Входы V2_SWAP_EXACT_IN / V3_SWAP_EXACT_IN |
| `swap_v4.rs` | Вход V4_SWAP / INFI_SWAP: обмен + SETTLE_ALL + TAKE_ALL |
| `plan.rs` | План: недостающие разрешения + команды обмена; execute с проверкой баланса собирается от базы, прочитанной прямо перед подписью; минимум 0 — ошибка |
| `precheck.rs` | Перед сделкой (решение 32): повторная проба крючка B/C, сверка с квотером на сумме сделки |
| `chain.rs` | Шаги пути: команда на пул; первый платит кошелёк, второй — роутер всем балансом (CONTRACT_BALANCE), промежуточный выход — роутеру; минимум у каждого шага |
| `live.rs` | Путь доли по живому состоянию перед сделкой (проба крючка, допуск, пара через промежуточную) |
| `order.rs` | Обмен доли: худшая цена > 0, цена не хуже допустимой, минимум выхода (не 0) |
| `txs.rs` | Одна транзакция: каналы, цена и лимит газа, подпись, чаевые (только обмену), отправка, итог до занятия nonce (задача трекера держит очередь) |
| `trade.rs` | Сделка прямого маршрута: пересчёт по живому пулу, худшая цена, минимум, разрешения, обмен; общие шаги для умного |
| `trade_smart.rs` | Сделка умного маршрута: пересчёт долей, худшая цена, сверка с MixedQuoter, один execute |
| `universal.rs` | План умного маршрута для Universal Router PancakeSwap: команда на долю, проверка баланса на сумму минимумов |
| `result.rs` | Итог сделки по квитанции |
| `fill.rs` | Суммы по событиям Transfer |

## База проверки баланса и поступления в кошелёк

BALANCE_CHECK_ERC20 проверяет «баланс выходного токена ≥ база + минимум». База читается прямо перед подписью обмена
(после разрешений), а ожидаемые поступления того же токена (депозит с биржи, возврат USDT) не совпадают с обменом
по времени: `wallet/inflows.rs` — адрес депозита ждёт конца обмена и регистрирует поступление, обмен ждёт, пока
поступлений его выходного токена нет, «Зачислен»/«отклонён» или срок `transfer.max_time_s` снимают поступление.
Перевод на кошелёк, о котором бот не знает, так не ловится: факт — по событиям Transfer квитанции; у V2 минимум
выхода проверяет и сам роутер по балансу получателя до и после обмена внутри транзакции.
