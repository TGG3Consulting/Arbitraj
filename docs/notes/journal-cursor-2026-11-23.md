# Время SQL при листании журнала

В [контрольном прогоне](https://github.com/TGG3Consulting/Arbitraj/actions/runs/45255735551) SQLite получила 9 490 468 строк с повторяющимся содержимым. Выполнен 21 замер каждой страницы в одной транзакции чтения; результаты обеих форм запроса сверены построчно. Глубокая страница из 80 строк, p95: 687,1 мс с необязательным условием OR, менее 0,2 мс с прямым диапазоном rowid. Первая страница заняла менее 0,2 мс у обеих форм. Подробности в артефакте journal-cursor.

Измерен SQL вместе с получением строк в памяти на машине GitHub. Боевые времена ожидания очереди, блокировки соединения, сериализации JSON и передачи HTTP сюда не входят. Порядок, строгая граница id и ожидание записи до чтения сохранены. Для замера на согласованной копии базы предусмотрена команда python3 tools/journal_page_probe.py --copy <путь>.
