# Кнопки «Продать сейчас» и «Продать и перегнать» — разбор и решение 235 (08.11.2026)

Требование Тиграна 08.11: «Пришёл алерт в Telegram: невыгодно, кнопки "Продать" и "Продать и перегнать". Нажимаю
"Продать" — не продаёт, потому что процент минуса больше настройки. Процент минуса меня вообще не волнует, когда я
руками нажимаю. "Продать и перегнать": один запрос по всем биржам и DEX (venue.cex_cex = нет — к бирже не стучимся,
всё по настройкам), у кого самая топовая цена с учётом всех затрат — перекидываем туда и сразу продаём, даже если цена
ушла, и возвращаем USDT туда, откуда началась сделка, фиксируем убыток или прибыль».

Факты ниже — факт кода ветки `feat/own-bsc-node` (коммит 19a1c46), строки — до правки. Данных бота (сделка из алерта
Тиграна) в этой среде нет: какой именно из путей ниже сработал в его случае — по коду не установить, исправлены все.

## Путь кнопок до правки

1. `core/commands.rs:114-131` — SellNow / SellNowReturn → `manual::sell_now(alert, ret)`; SellHalted /
   SellHaltedReturn → `manual_halted::sell_halted(deal, ret)`.
2. `core/manual.rs:167-199`, `core/manual_halted.rs:110-169` — количество по реальному балансу (on_hand_sell), шаг
   Selling; `ret` только ставит `deal.return_usdt = true` (manual.rs:187-190, manual_halted.rs:152-155); дальше в обоих
   случаях одно и то же: `sell::market(deal, sell::BUTTON)` под `risk_count::manual`.
3. `core/sell.rs:55-69` market → котировка (`trade_ops::deal_value`) → `sell` (sell.rs:93). Сама продажа порога не
   проверяет: защиты — худшая цена по свежему стакану у биржи, minOut у DEX (trade_ops.rs, worst.rs).
4. **Где кнопка упиралась в порог.** Продажа не прошла, отказ до отправки (проба откатилась, стакан устарел, нет
   маршрута — `OpError::retry_safe`): `sell_unsent::decide` (sell_unsent.rs:63-97) — у кнопки `Retry::Go`
   (решение 229). Дальше sell.rs:187-197: итог кнопки «бот повторит продажу сам», задача переключается на автоматику
   (`risk_count::auto`), `sell_unsent::retry` (sell_unsent.rs:123-160) → **`stuck::handle`** (sell_unsent.rs:159) —
   режим застрявшей монеты по `stuck.mode` (stuck.rs:79-82):
   - «Порог убытка» — stuck.rs:158-168: убыток > `stuck.max_loss_pct` → `raise_alert` «убыток … выше порога …»;
   - «Перегон» — `relay::run`: перегоны исчерпаны (relay.rs:74-76), площадка/кошелёк на паузе (81-95), вывод уже
     отклонён (99-104), перегон не выгоднее (155-156) → `relay_here::sell_here` → relay_here.rs:58-70: убыток >
     `stuck.relay_max_loss_pct` → алерт «убыток … выше порога … (stuck.relay_max_loss_pct)»; не задана — алерт
     (71-74); нет котировки — алерт (75-81). Если же перегон «выгоднее» — бот сам ВЫВОДИТ монету на другую площадку
     (relay.rs:181) и там продаёт через `sell_or_stuck` с проверкой «выгодно» (sell.rs:43-50);
   - «Ожидание» — stuck.rs:116-137: ждёт «стало выгодно» до `stuck.wait_ms`.
   Повторы исчерпаны — `Retry::Here` (sell_unsent.rs:91-92, и у кнопки тоже) → `sell_unsent::here` →
   `relay_here::sell_here` (sell_unsent.rs:188) — тот же порог stuck.relay_max_loss_pct.
5. Другие места, где кнопка уходила в автоматику с порогами: остаток после частичной продажи (sell.rs:138-146 →
   `stuck::handle`, auto) и BNB: газ продажи не помещается сверх резерва (sell.rs:155-169 → `stuck::handle`, auto).
6. Итог кнопки (manual_outcome.rs) при этом уже ушёл «Не продано: … бот повторит продажу сам», а повтор шёл как
   автоматика: его исход итогом кнопки не приходил (manual_outcome шлёт только при причине BUTTON).

## Что делала «Продать и перегнать» до правки

Решение 101: продать ЗДЕСЬ (где монета) тем же `sell::market(BUTTON)` и после закрытия перегнать выручку USDT на
площадку покупки (ledger::finish → usdt_return_deal.rs:40 `wanted` по `deal.return_usdt`; продано на площадке
покупки — «перегон не нужен», usdt_return_deal.rs:108-113). Выбора лучшей площадки не было. У остановленной сделки с
монетами на площадке покупки кнопка была недоступна (manual_feed.rs:40, 86).

## Решение 235 — что стало

- **«Продать сейчас» кнопкой** — по рынку там, где монета, без порогов убытка и без «выгодно» на всём пути
  (`core/manual_sell.rs`): отказ до отправки → снова продажа по рынку кнопкой по реальному балансу (on_hand_sell),
  предел — тот же stuck.unsent_retries_max; исчерпан — алерт с точной причиной (`decide` у кнопки → Exhausted, не
  Here); остаток после частичной продажи → снова по рынку кнопкой; газ BNB → алерт с причиной. Признак задачи остаётся
  ручным (risk_count::manual), итог кнопки — один, в конце. Защиты исполнения те же.
- **«Продать и перегнать» кнопкой** (`core/manual_relay.rs`, цели — `core/manual_relay_targets.rs`): один проход
  оценки — «здесь» (deal_value) и все цели параллельно (`relay_value::value_at` — выручка USDT после комиссии вывода,
  налога перевода, минимумов вывода/депозита; приход-пыль = 0). Цели: справочник (рынок, приём по BSC, продажа через
  API), venue.enabled, не пауза, биржа ↔ биржа — только если venue.cex_cex не «нет» у обеих бирж (где монета и цель; дополнение 235), DEX — кошельком по
  маппингу (for_relay), кошелёк не на паузе; с площадки, где монета, перегона нет при закрытом выводе, паузе или уже
  отклонённом выводе. Здесь не хуже — продать здесь; иначе `transfers::send_trade` и сразу `sell::market(BUTTON)` там
  (без порога, даже если цена ушла). Перегон один. Возврат USDT на площадку покупки — общий шаг закрытия (решения
  101, 138, 227). Оценка каждой площадки и выбор — строкой в хронологию и журнал core.manual_relay. Перевод отклонён —
  продажа здесь кнопкой; исход неизвестен — сделка остановлена.
- **Итог кнопки** (manual_outcome.rs): «Выполнено: продано X на площадке по цене, выручка; возврат N USDT A → B начат
  (зачисление — отдельным сообщением usdt.relayed) / не нужен / не вернётся сам: причина; итог сделки».
- **Автоматика не менялась**: режимы stuck.*, перегоны, порог stuck.relay_max_loss_pct, продажа здесь по порогу при
  исчерпании повторов (решение 229).
