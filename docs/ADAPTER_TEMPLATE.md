# ADAPTER_TEMPLATE — как подключить новую площадку

> Новая площадка = новая папка в `src/venues/` по этому шаблону. Ядро и шлюз не меняются.

## Набор файлов биржи (CEX)

```text
src/venues/<биржа>/
├── README.md     что за площадка, ссылки на её официальную документацию, особенности
├── mod.rs        реализация контракта адаптера (gateway/contract.rs)
├── rest.rs       REST-запросы, подпись, лимиты запросов площадки
├── ws.rs         WebSocket: пачки подписок, переподключение, пометка «устарело»
├── parse.rs      ответы площадки → типы ядра
├── errors.rs     коды ошибок площадки → единые коды
└── wallet.rs     сети, вывод, депозит
```

Набор файлов DEX — как у `src/venues/bsc_dex/` (см. ARCHITECTURE.md).

## Порядок подключения
1. Собрать по официальной документации площадки: эндпоинты справочника монет и сетей, стакана, ордеров, вывода, депозита; каналы WebSocket; лимиты запросов и подписок; коды ошибок. Записать в `README.md` адаптера со ссылками. Чего нет в документации — так и записать, не додумывать.
2. Скопировать набор файлов, реализовать контракт адаптера.
3. Перевести все коды ошибок площадки в единые коды.
4. Вынести все параметры площадки (URL, лимиты, частоты, размер пачки подписок) в настройки.
5. Добавить площадку в интерфейс: включение и выключение, статус соединений, её правила шлюза.
6. Проверить на записанных реальных сообщениях площадки.
7. Обновить `ARCHITECTURE.md` и `docs/DECISIONS.md`.
8. **Замер нагрузки до торговли (решение 109).** Включить площадку при остановленной системе (режим «Стоп»), 10–15 минут
   смотреть CPU и память процесса `arb` (`top`), загрузку сервера, рост сырого журнала площадки и отставание живого
   потока («lagged» в интерфейсе). Только если нагрузка не выросла заметно — переводить в работу. Сразу в работу —
   нельзя: MEXC 02.11 дал ~15 ядер и зависание интерфейса.

- [ ] Справочник монет: сеть BSC, адрес контракта, статусы ввода и вывода, комиссии
- [ ] WebSocket стакана по всем монетам из справочника, пачки в пределах лимита площадки
- [ ] DEX: монеты, чьи пулы найдены, но ещё не прочитаны, — событием `PoolsLoading` (полный список при изменении; решение 61): без него ядро покажет «нет пула с USDT» до конца загрузки
- [ ] При каждой подписке и при каждом изменении справочника пар — событие `SpotPairs` (монеты с торгуемой спот-парой по справочнику пар площадки и `pairs` — состояние пары каждой монеты: код статуса, торгуется ли, покупка/продажа через API): без него ядро не подпишет DEX на монеты этой биржи и не покажет точную причину отсева
- [ ] Локальный стакан пересобирается при пропуске обновлений
