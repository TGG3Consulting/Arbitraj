## 0. Коротко

- Граница U(q) = κ_B·R_B(arr⁺(q)) − C_A(q)·(1 + r_A) − F (раздел 1) — `core/bound.rs`, сборка из тех же входов, что
  полный расчёт, — `core/bound_in.rs`; отсев — `core/sieve.rs` в задаче расчёта кандидата (`candidates.rs calc_one`, не
  в потоке тика), сторона DEX — контракт `rate_bound` (`gateway/rate_bound.rs`), адаптер `quote/bound.rs`,
  `quote/bound_rate.rs` (без котировок, итог в памяти по ключу входов). Цикл DEX ↔ DEX — `quote/bound.rs cycle_may_profit`
  в `cycle_scan.rs signal` до поиска входа.
- Отсекается только доказанное: max U < money.min_profit_usd на всех объёмах q > 0, или (порог % ≥ 0) max(U − порог%·C) < 0.
- 18 записанных отказов (прокси раздела Б.4 проекта — стаканов и пулов в записи нет): отсечено 17, NXT — в расчёт.

## 2. Сторона DEX: вид пула × направление

Монета «не действует», если ЛЮБОЙ пул её набора (пары из {монета, USDT, промежуточные}, `quote/bound.rs pool_set`) — без
r_e: недопущенный пул может стать допущенным к расчёту, набор шире допуска — граница строже.

Верх курса монеты ρ (`quote/bound.rs rho_raw`): наибольшее произведение r_e по путям ≤ H хопов (динамика по слоям,
повторный заход в промежуточную разрешён — путей больше, верх строже). H: классика (direct / smart) — 2
(`quote/via_pools.rs`: пул монеты с USDT или пара пулов через промежуточную), graph — max(2, dex.route_max_hops)
(`route_paths.rs:55`). Строгость (проект А.5–А.6, лемма 3): монета и USDT в путях не внутренние (`route_paths.rs`
шапка: без повторного захода) ⇒ пулы монеты и пулы с USDT идут в одну сторону; обмены одного направления в пуле только
ухудшают его цену ⇒ каждый обмен ≤ r_e·вход (для любого числа долей сплита); телескоп по потенциалам слоёв ⇒ выход ≤ ρ·вход.

| Режим маршрута | Действует |
| --- | --- |
| classic direct / smart (≤ 2 хопов) | да |
| graph, dex.route_max_hops ≤ 2 | да |
| graph, hops ≥ 3, пулов между активными промежуточными нет | да |
| graph, hops ≥ 3, есть пул между двумя промежуточными | нет (класс `mid_pool`) — встречные доли через такой пул: доказательство проекта А.7 опирается на потенциалы Беллмана–Форда с комиссией, у слоёв по хопам их нет; V2 ≥ 3 долей не доказано |
| exec.via_kyber (и «лучший из двух») | нет (класс `kyber`) |
| сплит долями (smart.max_splits, граф) | да — оценка по пулу, не по маршруту |

Цикл DEX ↔ DEX: ρ_цикла = Π r_e ног (каждый пул в цикле один раз — `route_paths.rs enumerate_cycles`, путь один —
`cycle_opt.rs`); ρ < 1 и dex_dex.min_profit_base ≥ 0 ⇒ выход < вход на любом входе, газ ≥ 0 ⇒ чистая < 0 ≤ порога —
сигнал не строится. Налоговых токенов в цикле нет (`cycle_scan.rs tax_free`), крючок keep ≤ 1.

Биржи (все 14): сторона биржи — снимок стакана адаптера (`quote_snapshot`, копия без запросов) и ставка комиссии по
котировке снимка; одна формула для всех (`FrozenBook`). Снимка нет (стакан устарел) — метод не действует (класс `stale`).

## 3. Случаи «не отсекать» (кандидат идёт в расчёт как сейчас; класс в сводке dex.quote_count, поле sieve, ключ na_<класс>)

`kyber` — финальная котировка у внешнего исполнителя; `pool_kind` — пул без строгого r_e или с крючком; `mid_pool` —
пул между промежуточными при H ≥ 3; `taxes` — налоги монеты не измерены или < 0; `stale` — голова узла не свежая,
лента отстаёт, нет снимка стакана; `no_data` — нет адреса монеты/USDT, decimals, пул вне реестра (поколение 0),
контекст направления не собирается (σ не измерена и т. п.), пороги не заданы; `no_route` — путей по набору нет;
`inputs` — вход вне допустимого (комиссия вывода неизвестна, доля ≥ 1, ставка < 0 в иной валюте, уровень с ценой ≤ 0);
`overflow` — переполнение числа; `venue` — площадка не даёт верх. Сухой режим без бюджета — отсев не вызывается.

## 4. Расхождения проекта с кодом (код прав) и упрощения

1. Место вызова: проект/t160 — `evaluate.rs` перед enqueue (поток тика). Задача требует «не в потоке тика» — отсев в
   начале задачи расчёта кандидата (`candidates.rs calc_one`, отдельная задача tokio). Котировок DEX подбора нет, место
   расчёта занято микросекунды.
2. Порог %: проект — O(1) по предельному спреду s₀ и бюджету; в коде — точный максимум U − порог%·C по всем изломам
   (O(L), строже и без бюджета).
3. Бюджет (q_hi = бюджет/ask₀) и q_lo (минимумы) не используются: граница смотрит до всей глубины (слабее, строго:
   связь списания по худшей цене с бюджетом в границу не входит).
4. F_min (газ хопа, перевода, возврата) не вычитается: проект сам ставит F_min = 0 до проверки, что книга BNB будит
   пересчёт (Д №23).
5. Algebra и Solidly волатильный — без комиссии (проект: с комиссией): у Algebra Integral комиссия плагина/override ≠
   globalState.fee; у Solidly net_in округляет вниз — на малом входе доля комиссии меньше номинальной.
6. Беллман–Форд проекта по всем пулам с потенциалами промежуточных → в коде динамика по слоям ≤ H хопов; пулы между
   промежуточными при H ≥ 3 — метод не действует (проект А.7 требует потенциалов с комиссией в обе стороны).
7. Цикл: проект — (ρ − 1)·x + A − газ < порога; в коде — только ρ < 1 при пороге ≥ 0 (газ не вычитается).
8. LbBin (базовая комиссия), Maverick, Balancer, DODO, SmarDex, стабильные — r_e проекта не введены (нет теста-эталона
   r_e на записи в этой задаче) — метод не действует.
9. Поведение, которое меняется: у отсечённого кандидата нет расчёта ⇒ нет фонового «без потолка» (решение 141) по нему
   и нет строки core.candidate_rejected (вместо неё — core.candidate_sieved с тем же ключом направления); отсечённый
   цикл DEX ↔ DEX не попадает в список сигналов циклов (счётчик cycle_cut в сводке).

## 6. Цена отсева

На кандидата: два снимка стакана (копия уровней в памяти адаптера) или верх DEX (из памяти по ключу; пересчёт —
O(пулов набора) дробей U256 при смене состояния пула/настроек/промежуточных) + O(L_A + L_B) точек × O(L) прохода
уровней (L — уровней стакана, обычно ≤ 200: ≤ 10⁵ операций Decimal) — без котировок, без узла, без замков рынка.
Отсечённый кандидат: 0 котировок DEX подбора (было 32–149 точек подбора у 17 записанных отказов, всего 1693).
