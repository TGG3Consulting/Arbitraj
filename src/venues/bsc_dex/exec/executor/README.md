# venues/bsc_dex/exec/executor — свой контракт-исполнитель ArbExecutor (решение 122, часть X)

Контракт — `contracts/ArbExecutor.sol` (разбор безопасности — `contracts/README.md`). Графовый маршрут формы «бандл»
(не один Universal Router) при заданном `exec.executor_address` уходит **одной транзакцией** через исполнитель;
не задан — бандлом, как раньше (решение 84). Публичный интерфейс для новых семейств (часть F): `kind.rs` и `call.rs`.

| Файл | Что делает |
| --- | --- |
| `mod.rs` | Адрес исполнителя из настроек (`address`) и выбор пути (`takes`: граф «бандл» + адрес задан) Решение 272: `native_capable` (версия v2 у кошелька), `approvals` (продажа BNB — без разрешений). Ревью 272: `native_block` — точная причина, почему BNB не идёт (v1 / не сверен / обёртка в исполнителе ≠ dex.native_wrapped). |
| `abi.rs` | Типы ABI контракта — `alloy::sol!` из `contracts/out/ArbExecutor.abi` |
| `kind.rs` | ПУБЛИЧНЫЙ кодировщик шага: `Params` (вид и параметры; `StableU256Bnb` — пул с нативным BNB, вид 11), `StepSpec`, `encode` → `ArbExecutor::Step`; номера видов = константы контракта (V2 = 0 … ELASTIC = 8, STABLE_U256 = 9, SADDLE = 10) |
| `onchain.rs` | Ревью 122, пункт 1: до approve и сделки — код по `exec.executor_address` побайтно = `ArbExecutor.bin-runtime` и владелец (слот `owner`) = кошелёк бота; успех помнится по паре (адрес, кошелёк); кнопка «Проверить подключение» исполнителя (`probe`) Решение 272: код v2 (contracts/out/) или v1 (contracts/out/v1/) — версия; записывается у кошелька (settings/accounts/edit_version.rs); `ensure` возвращает версию. Ревью 272: у v2 — слот `wnative` (обёртка) пишется у кошелька рядом с версией; память совпала, запись нет — запись восстанавливается (Б2); «код не совпал» называет обе версии. |
| `entry.rs` | Шаг исполнителя для пула реестра по пометке части F (`Family.executor_kind`, pools/exec_kind.rs): V2 с комиссией пары, V3, Algebra, Solidly, DODO, Maverick; StableSwap — CURVE (Ellipsis), STABLE_U256 (PancakeSwap Stable, Lista), SADDLE (Nerve): индексы из состояния по токену входа, пул на паузе — нет; нет вида шага (Infinity/V4, KyberSwap Elastic — решение 121 B2) — исполнителем не вызывается |
| `callback_at.rs` | Задача t122 (п. 1): после сверки `onchain::ensure` — вид шага только v2 и обратный вызов пула (`dex.v3_swap_callback`) проверяются по версии, которую вернула сверка (`missing_at`), а не по записи у кошелька; правила и тексты — как `pools/exec_callback.rs` |
| `call.rs` | Вызов `execute` из долей (шаги exec/chain.rs): доли входа в bps от текущего остатка, промежуточный шаг — весь токен, вход и минимум — суммы долей, срок `dex.deadline_s` Решение 272: `with_native` — executeNative (данные, `value()` = вход продажи BNB). |
| `sim.rs` | Проба `execute` перед отправкой (eth_simulateV1) и сверка полученного с `req.worst_price`; откат — с minOut, ожидаемым и модельным налогом каждой доли (решение 234, п. 4) Решение 272: value вызова в eth_simulateV1 (продажа BNB). |
| `remeasure.rs` | Решение 247: проба execute с пере-замером — откат ровно по minOut у продажи выхода: та же продажа с minOut 1 ед. (R), граница min(R, выход при налоге в сети), minOut = граница × (1 − допуск) при границе не ниже порога ядра; монета — во внеочередную перепроверку налогов; решение 248 — замер с minOut 1 ед. и без условий ядра (первая продажа), граница по замеру — ядру (exec/exit_gap.rs), минимум меняется только при условиях ядра |
| `trade.rs` | Сделка через исполнитель: доли по живому состоянию, минимумы верификации, approve исполнителю (после него — пересборка, решение 121 B1), проба, одна транзакция, факт Решение 272: BNB монетой сделки — только исполнитель v2 (иначе прежний отказ): резерв газа, value, без разрешений у продажи. |
| `fact.rs` | Факт по Transfer (exec/result.rs) с учётом возврата неистраченного входа исполнителем Решение 272: executeNative — монеты по событию NativeSettled, USDT — Transfer; `settled` — разбор события. |
| `v1_notice.rs` | Ревью 272 (Б5): уведомление wallet.executor_v1 «у кошелька X исполнитель v1 — нативный BNB через форки не торгуется» — один раз на кошелёк и адрес за время работы (сделка через исполнитель, «Проверить подключение») |
| `code.rs` | Артефакты `contracts/out/` со сверкой SHA-256: код создания, код в сети, слот владельца Решение 272: код в сети v1 (out/v1/, свой файл хешей), `Version`, `version_of`. Ревью 272: `wnative_slot`, `creation_with` (код + адрес обёртки — аргумент конструктора). |
| `dry.rs` | Сухая сделка через исполнитель: «как сделка» (развёрнутый) или «через исполнитель» (код и владелец подставлены в симуляцию на будущий адрес развёртывания) Решение 272: нативный BNB — executeNative (режим «через исполнитель» — код v2; «как сделка» — только v2). |
| `deploy.rs` | «Развернуть исполнитель»: оценка (газ, цена, BNB/USDT, будущий адрес) и транзакция создания через очередь кошелька — только по подтверждению человека (SHA-256 кода создания и, задача t114, адрес обёртки из окна = текущей dex.native_wrapped — confirm); проверка кода в сети |

Разрешение кошелька исполнителю — обычный ERC-20 `approve` (без Permit2): `wallet/approve.rs` (`executor_missing`,
`executor_all`), память для котировки — `wallet/allow_cache.rs::erc20`, газ approve в котировке — `quote/approve_gas.rs`.
