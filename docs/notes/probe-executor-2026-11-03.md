# Проба налога через исполнитель и проба BNB у пулов без Universal Router (03.11.2026, ветка router/probe)

Две записи журнала живого бота:

1. `dex.check_not_configured` (ошибка): «thena: проба налога через этот пул идёт шагом SOLIDLY контракта-исполнителя —
   сборка пробы через исполнитель … ещё не подключена» (и topaz — шаг V3). Монеты только с такими пулами — «не проверены».
2. `dex.native_probe` (внимание): «nomiswap BNB: проба нативной монеты (WRAP/UNWRAP) не прошла — Не задана настройка
   dex.universal_router [dex:nomiswap]» (и apeswap_bsc, biswap, sushiswap_bsc, pancakeswap-v1-bsc, mdex_bsc, babyswap).

## 1. Проба налога через исполнитель (check/probe_exec.rs)

Пул вида без своего пути (family.tradable = false), у которого есть шаг исполнителя (pools/exec_kind.rs::via_executor),
пробуется **тем же вызовом, что настоящая сделка через исполнитель** (exec/executor/trade.rs): `execute` развёрнутого
исполнителя по `exec.executor_address` одним шагом этого пула на весь вход (10000 bps; exec/executor/call.rs), ERC-20
approve кошелька исполнителю (wallet/approve_executor.rs::all — в симуляции все разрешения сразу, как у пробы UR).
Код по адресу уже в сети — подстановки нет; до первой пробы код и владелец сверяются с узлом
(exec/executor/onchain.rs::ensure, успех помнится). Остальное — check/probe.rs без изменений: тот же блок, та же
последовательность (USDT из пула-источника → разрешения → квотер → покупка → перевод ½ на пул → перевод ¼ на пустой
адрес → разрешения и продажа остатка), тот же `Measured`, тот же разбор откатов.

### Как сопоставлен налог с реальной сделкой через исполнитель

Контракт (contracts/ArbExecutor.sol, `execute` / `_step` / `_sweep`), одна доля, один пул:

| Сторона | Вид шага | Как идёт монета в сделке | Что меряет проба |
| --- | --- | --- | --- |
| Покупка | V2, SOLIDLY, V3, ALGEBRA, DODO, WOO, MAVERICK | пул → кошелёк (выход последнего шага — `msg.sender`), один перевод | «пришло» = прирост баланса кошелька после того же `execute`; «ожидалось» — квотер пула (до налога токена) |
| Покупка | CURVE, STABLE_U256, SADDLE (+ _BNB) | пул → исполнитель → `_sweep` → кошелёк, два перевода | то же: прирост у кошелька включает оба перевода — ровно то, что получит кошелёк |
| Продажа | V2, SOLIDLY, DODO, WOO (первый шаг на весь вход) | `transferFrom` кошелёк → пул, один перевод | перевод ½ кошелёк → пул (рост баланса пула) — тот же один перевод «кошелёк → пул» |
| Продажа | V3, ALGEBRA, MAVERICK, StableSwap | кошелёк → исполнитель → пул, два перевода | у монеты с налогом такой маршрут неисполним — сигнал (quote/graph_executor.rs::tax, ревью 122 п. 3), решает котировка по измеренному налогу; у монеты без налога оба перевода без налога |

Итог: налог покупки — это потеря на всём пути сделки через этот пул (оба перевода, если их два); налог продажи — потеря
на переводе «кошелёк → пул», и через исполнитель монета с налогом продаётся только тем путём, где этот перевод один.
Газ обмена — gasUsed того же `execute` (с накладными исполнителя), газ разрешений — approve исполнителю: то, что
заплатит сделка.

Остаток (не меняет вердикт пробы, записано в техдолг docs/ROADMAP.md):
- налоги монеты — по первому удачному пулу (V2 впереди, check/taxes_util.rs). Если налог покупки измерен на пуле с одним
  переводом (UR, V2), а сделка покупки идёт через исполнитель шагом StableSwap (два перевода: пул → исполнитель →
  кошелёк), котировка недооценит налог; проверки «налог на выходе через StableSwap» в quote/graph_executor.rs нет.
  Защита в сделке — сверка цены пробой `execute` (exec/executor/sim.rs) и `minOut` контракта;
- токен, берущий налог только с перевода на контракт (не на пул и не на обычный адрес), даст 0 % в пробе, а продажа шагом
  V3 через исполнитель потеряет на «кошелёк → исполнитель» — защита та же (цена против req.worst_price, `minOut`).

### «Кто меняет» (решение 59)

Universal Router ищет пару по фабрике — поэтому check/emitter.rs проверяет, что событие обмена выпустил сам пул, и
исключает пул. Исполнитель вызывает пул ровно по адресу шага (как и сказано в exec/executor/sim.rs) — подменить пул
некому. Список топиков emitter.rs (V2 / V3 / V4) для исполнителя не годится: событий DODOSwap, TokenExchange, TokenSwap,
PoolSwap, WooSwap в нём нет, а «Swap от другой пары» у монеты с налогом (обмен накопленного налога внутри её перевода)
исключил бы такой пул ложно. Поэтому через исполнитель (check/probe_exec.rs::emitter): пул сам выпустил хотя бы одно
событие в вызове обмена; нет — NoRoute «проба не засчитана» (не вердикт, пул не исключается). У пулов со своим путём —
emitter.rs как раньше.

### Что стало с причинами

| Случай | Было | Стало |
| --- | --- | --- |
| Шаг исполнителя есть, `exec.executor_address` задан | `dex.check_not_configured` (ошибка) «сборка пробы … не подключена» | проба идёт; итог — налоги / «не прошла» / ждёт, как у любого пула |
| Шаг есть, адрес не задан | то же (NotConfigured без имени) | `dex.check_not_configured` «… exec.executor_address не задан …» с именем настройки — перепроверка при её задании |
| Шага исполнителя нет (KyberSwap Elastic, WooFi до сухой сделки, «не поддерживается») | `dex.check_not_configured` (ошибка) | не настройка: «не проверено» с причиной на «Монетах» (NoRoute → ожидание), без записи «не задана настройка» |
| Исполнитель откатил по сроку (`require(…, "deadline")`) | вердикт «проба не прошла» | помеха «срок вышел» (как TransactionDeadlinePassed UR), повтор |

## 2. Проба BNB у пулов форков V2 (exec/native.rs::trade_path)

Как в реальной сделке BNB идёт через пул форка V2 — **никак**:
- прямой путь форки не берёт (quote/classic_direct.rs::tradable = tradable && !fork; умный путь — только UR);
- графовый маршрут BNB через ногу форка неисполним («нативная монета BNB через ногу форка …», quote/graph_exec.rs);
  бандл такую ногу не собирает (exec/bundle.rs); у classic V2 Router форка в коде сделки нет swapExactETHForTokens /
  swapExactTokensForETH;
- через исполнитель нативная монета не идёт (exec/executor/mod.rs::takes, exec/executor/trade.rs) — значит и виды
  только с исполнителем (THENA, Topaz Slipstream, форки V3 …) BNB не торгуют.

Мерить там нечего, поэтому проба WRAP/UNWRAP для таких пулов не запускается (check/native_probe.rs::after): в факты
пула (`wrap_gas = Err(причина)`; котировка BNB этот пул и так не берёт) и в журнал `dex.native_probe` уровнем «инфо»,
один раз (при смене причины): «nomiswap BNB: проба нативной монеты (WRAP/UNWRAP) не запускается — nomiswap: сделки BNB
через этот пул нет — у форка свой classic V2 Router без обёртки WBNB в сделке (прямой путь форки не берёт, графовый
маршрут BNB через ногу форка неисполним) — проба WRAP/UNWRAP не нужна». Адреса Universal Router форкам не выдумываются.
Пулы PancakeSwap / Uniswap V2/V3 (свой UR) — проба как раньше.

## Проверить вживую

1. После развёртывания исполнителя и задания `exec.executor_address`: монеты только с пулами thena / topaz — в журнале
   нет `dex.check_not_configured` про «сборка пробы не подключена»; на «Монетах» — налоги (или точная причина).
2. Сухая сделка «как сделка» через такой пул — газ и налог сходятся с замером пробы.
3. Журнал: `dex.native_probe` для nomiswap / biswap / … — одна запись «инфо» с причиной, без dex.universal_router.
