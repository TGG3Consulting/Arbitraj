# Граф без ожидания: фоновый владелец снимка графа маршрутов (задача t137, решения 307–308)

> Проект архитектора (этап 0). Основа — ветка t132/graph-build-queue (решение 301). Номера строк — по ветке t132
> на 16.11.2026 (c3671435).

## 0. Главный принцип (Тигран, 16.11.2026)

«Маршрута нет, сделки нет — ок как страховка. Но должно быть так, чтобы маршрут БЫЛ и сделки БЫЛИ.» Отсюда:
- предохранитель «снимок отстал → маршрута графа нет» — ПОСЛЕДНИЙ рубеж; в штатной работе он не срабатывает никогда
  (целевой показатель приёмки — 0 срабатываний);
- отказ оправдан только там, где нельзя гарантировать корректность цены или исполнимости. Устаревшая ТОПОЛОГИЯ при
  свежем СОСТОЯНИИ пулов даёт не неверную цену, а, возможно, не лучший маршрут — это не «вслепую»;
- полная пересборка и самопроверка не останавливают торговлю по графу: работа идёт на действующем снимке, замена —
  атомарно; расхождение лечится заменой снимка.

## 2. Целевая архитектура

```
события пулов ─► Registry.put/update/retain ──(под замком записи)──► Changes.mark(PoolRef) ─► Notify (одно пробуждение на всплеск)
                                                                                           │
                         ┌─────────────── владелец графа (одна задача tokio, graph_owner.rs) ◄┘
                         │  круг: забрать изменённые пулы (drain) → в потоке блокирующих задач
                         │  пересчитать только их (+ пулы, чей курс к USDT зависит от изменённого пула X–USDT)
                         │  → пары, где сменился состав → новый неизменяемый Graph → publish (подмена Arc)
                         │
                         │  полная пересборка (отдельный поток блокирующих задач, graph_full.rs) — параллельно,
                         │  читатели и накопительные круги не ждут; по окончании: доводка изменений, случившихся
                         │  во время сборки, сверка с накопительной картой, атомарная замена
                         ▼
            Snapshot { graph: Arc<Graph>, version, basis (настройки графа, USDT), seq, full, at }
                         │   (RwLock<Option<Arc<Snapshot>>>: читатель берёт клон Arc — наносекунды, без ожидания построения)
                         ▼
   котировка (route_cache.paths) / поиск циклов (cycle_scan) / экран
   → пути по топологии снимка → состояние КАЖДОГО пула пути — свежее из реестра (гидратация route_cache::fresh)
   → предторговая сверка verify/precheck (как сейчас)
```

Файлы (новые, каждый — одна задача, ≤ ~200 строк): pools/graph_changes.rs (изменённые пулы, отставание),
pools/graph_eval.rs (оценка одного пула — общая для накопительной и полной сборки), pools/graph_work.rs (накопительная
карта: пулы, пары, топ-K, зависимости по курсу; сборка Graph), pools/graph_diff.rs (сравнение карт множествами),
pools/graph_snap.rs (снимок и его публикация), pools/graph_stats.rs (счётчики экрана), pools/graph_owner.rs (владелец:
цикл пробуждений), pools/graph_step.rs (одно пробуждение, накопительный круг и публикация), pools/graph_round.rs (CPU-часть
круга), pools/graph_full.rs (сборка с нуля и доводка/сверка), pools/graph_finish.rs (окончание полной сборки, самоисцеление), pools/graph_guard.rs (сторож: паника,

(построение в расчёте, кэш, замок, копии записей на промахе кэша путей). «Да» — новая архитектура.

## 3. Инварианты

| № | Инвариант | Где обеспечен |
| --- | --- | --- |
| И1 | Расчёт (котировка, поиск циклов, экран) никогда не строит граф и не ждёт построения: берёт последний опубликованный снимок (клон Arc под коротким RwLock на чтение) | graph_read.rs current; graph_snap.rs load |
| И2 | Цена всегда по СВЕЖЕМУ состоянию пулов: каждый пул пути перед расчётом берётся из реестра (гидратация); пропал / недостоверен / спит — путь отброшен | route_cache.rs fresh — на попадании и на промахе кэша путей, в cycle_scan |
| И3 | Снимок неизменяем после публикации; замена — подменой Arc; читатель видит либо прежний, либо новый целиком | graph_snap.rs publish |
| И4 | Любая запись реестра, сменившая версию, отмечает пул как изменённый ДО увеличения версии и под тем же замком записи: снимок версии V учитывает все записи с версией ≤ V | registry.rs put/update/retain + graph_changes.rs mark |
| И5 | Пробуждение владельца — только по событию (Notify::notify_one хранит одно разрешение — всплеск склеивается), смене настроек графа (подписка хранилища), команде пересборки и сроку самопроверки; опроса по таймеру нет | graph_owner.rs run |
| И6 | Накопительная карта = карта, собранная с нуля, как множества «пара → [(пул, ранг)]» на одной и той же версии реестра (при тех же настройках и той же книге глубины) | graph_work.rs apply/expand; проверяется самопроверкой и тестом |
| И7 | Снимок старше предела (dex.graph_max_lag_ms) — маршрута графа нет, расчёт идёт по классике; это событие считается, пишется (без спама) и сообщается | graph_read.rs, graph_alarm.rs |
| И8 | Падение или зависание владельца не оставляет читателей молча со старым снимком: сторож перезапускает, при отставании сверх предела — И7 и событие | graph_guard.rs |
| И9 | Снимок с другим USDT не отдаётся никогда; снимок на прежних настройках графа отдаётся до готовности нового (ступень Б, считается) | graph_read.rs |

## 4. Что и когда пересчитывается

| Событие | Что делает владелец |
| --- | --- |
| Изменился пул P (put/update: состояние, valid, asleep, fee) | оценка P заново (graph_eval: допуск, глубина из книги — обычно уже посчитана событием в depth::touch, ранг); пара P помечается для пересборки топ-K |
| P — пул «X — USDT» (встречный — USDT) | плюс все пулы со встречным X (их глубина в USD зависит от курса X через P): только перевод в USD (решение 307 — кривая не пересчитывается) |
| Пул удалён (retain) | запись убрана, пара пересобирается; если это пул X–USDT — зависимые X пересчитываются |
| Новый пул | как изменённый |
| Сменились настройки графа (dex.route_max_pools_per_edge, dex.depth_band_pct, dex.min_pool_liquidity_usd, dex.depth_hysteresis_pct) или USDT/его decimals | полная пересборка (на время — прежний снимок, ступень Б) |
| Запуск владельца, пересборка подписки на рынок (переподключение лент пулов, Parts::pools), кнопка/REST | полная пересборка со сверкой |
| Срок самопроверки dex.graph_verify_s | полная пересборка со сверкой |
| dex.graph_background выключена | снимок снят, слежение за изменениями выключено (метка — одно атомарное чтение на запись реестра) |

Публикация: из карты собирается новый Graph — только пары с изменённым составом пересчитывают топ-K, остальное — клоны Arc
готовых рёбер (O(E), без обхода N пулов реестра).

## 5. Модель согласованности

Расчёт видит: ТОПОЛОГИЮ снимка версии V (какие пулы — рёбра, их ранги на момент V) + СОСТОЯНИЕ каждого пула пути на
момент котировки (из реестра). Топология без состояния не даёт цены — она только выбирает кандидатов. Поэтому:
- цена и объём — всегда по реестру на момент котировки, затем — по свежему блоку в verify/precheck перед сделкой;
- пул, ставший недостоверным, спящим или удалённым после V, отбрасывается гидратацией (fresh), а не попадает в расчёт;
- пул, ставший глубоким после V, появится в следующем снимке (через один круг) — до этого маршрут, возможно, не лучший;
- пул, ставший мелким после V, остаётся кандидатом до следующего снимка — его цена считается по свежему состоянию
  (объём, который он реально возьмёт, — тоже), т. е. не «вслепую».

Отличие от t132 по смыслу: раньше на промахе кэша путей и в поиске циклов цена считалась по КОПИИ записи на момент
построения графа (могла быть старше котировки); теперь — по реестру на момент котировки. Это строго свежее.

## 6. Гонки и как закрыты

| Гонка | Закрытие |
| --- | --- |
| Запись реестра между drain и чтением записи владельцем | запись снова отмечена (И4) → следующий круг; в этом круге владелец читает уже новую запись — вреда нет |
| Версия выросла, а отметки ещё нет | отметка ставится под замком записи ДО увеличения версии (И4): версия, прочитанная владельцем до drain, гарантирует, что все её отметки уже в наборе |
| Полная сборка читает реестр, пока он меняется | пулы, изменённые во время сборки, собираются (набор since + остаток drain), оцениваются ОДИН раз и применяются к обеим картам перед сравнением; сборка берёт снимок реестра ПОСЛЕ включения сбора since |
| Курс X сменился во время полной сборки (часть пулов X оценена со старым курсом) | пул X–USDT в since → его зависимые X раскрываются и переоцениваются (expand по зависимостям обеих карт) |
| Два источника публикации (накопительный круг и окончание полной сборки) | оба — внутри одной задачи владельца, последовательно; публикация с номером поколения владельца: публикует только текущее поколение (после перезапуска сторожем результат зависшего потока выбрасывается) |
| Книга глубины считается параллельно владельцем, расчётами (select.rs) и событиями (depth.rs) | книга — под своим Mutex, память по ключу; гистерезис — см. п. 10 |
| Читатель взял снимок, владелец опубликовал новый | читатель досчитывает на своём Arc (И3), следующий расчёт берёт новый |
| Смена настроек во время полной сборки | итог сборки с другим basis выбрасывается, запускается новая |
| Переполнение очереди событий | очереди нет: набор изменённых пулов — множество, его размер ≤ числа пулов реестра; всплеск любого размера = один круг |

## 7. Ступени деградации и предохранитель (поручение 16.11, п. 2)

Выбрано: (б) ступени, без (а) и (в) — обоснование.

1. **Ступень А — штатно.** Снимок версии V, отставание = время от первой неопубликованной записи реестра (Changes) до
   сейчас ≤ одного круга владельца. Гидратация всегда.
2. **Ступень Б — снимок на прежних настройках графа** (идёт полная пересборка после смены dex.route_max_pools_per_edge /
   полосы / порога / гистерезиса). Снимок отдаётся с гидратацией; цена корректна, топология по прежним порогам. Счётчик
   «ступень Б», запись журнала одна на переход.
3. **Ступень В — классика.** Снимка нет (запуск, первая сборка ещё идёт) или отставание > dex.graph_max_lag_ms —
   маршрута графа нет, котировка по классике (graph_route::merge уже так делает). Отставание сверх предела — счётчик
   предохранителя, запись журнала без спама (одна на эпизод + при выходе), событие dex.graph_stale в Telegram при первом
   срабатывании и не чаще dex.graph_alert_min_s далее. Запись Warn dex.router_graph на каждую котировку для этих причин
   НЕ пишется (иначе — запись на каждую котировку).
4. Снимок с другим USDT — не отдаётся (И9): это не устаревание, а другие концы путей.

Почему не (а) «догоняющее обновление по требованию»: это вернуло бы работу графа в расчёт (то, что и сломалось), и
появился бы второй писатель карты — гонки с владельцем. Нужен он был бы, только если отставание штатно больше круга —
а штатно его нет (п. 8); при упавшем владельце расчёт тем более не должен строить.
Почему не (в) «приоритет монет в расчёте»: круг владельца обрабатывает ВСЕ изменённые пулы целиком; при круге короче
блока приоритет ничего не даёт, а при длинном круге (полная пересборка) накопительные круги идут параллельно с ней.
Если замер покажет круг длиннее блока — следующий шаг: делить круг на части, пулы монет открытых окон/сделок первыми
(записано в TASKS как условный).

## 8. Отставание снимка: формула, запас, замер

Отставание публикации записи реестра: `L ≤ T_wake + T_round(k) + T_round(k+1)` (худший случай — запись пришла сразу
после drain круга k): T_wake — пробуждение Notify (микросекунды, рабочий поток tokio);
`T_round = T_drain (O(1), mem::take) + Σ_{p∈dirty∪dep} T_eval(p) + T_publish(E)`.
- T_eval(p) для изменённого пула — чтение записи + глубина из книги (событие пула уже посчитало её в depth::touch по
  тому же ключу → память) ≈ микросекунды;
- T_eval зависимого (X–USDT сменился) после решения 307 — только два to_usdt (своп через лучший пул X–USDT) без кривой;
- T_publish(E) — клоны Arc E рёбер + построение adj (E — рёбер графа, не N пулов).
Штатно за блок меняются десятки–сотни пулов, и один-два пула WBNB–USDT дают зависимых — их число и есть главный член.
Запас: накопительный круг не зависит от N (≈15 тыс. пулов) и от полной пересборки (она в отдельном потоке).
Цель приёмки: отставание в штатной работе ≤ 1 блока; предохранитель — 0 срабатываний.
Замер (виден на живом боте): запись dex.graph_build на каждый круг при log.graph_timing — вид (incr / full),
длительность, пулов оценено (изменённых и зависимых), рёбер, пар пересобрано, отставание в момент публикации
(возраст самой старой учтённой записи), сколько изменений уже ждёт следующий круг; на экране — текущее отставание,
наибольшее за час, срабатывания предохранителя за час/сутки.

## 9. Отказоустойчивость

- Паника в круге (поток блокирующих задач) → JoinError → владелец завершается с ошибкой; сторож (graph_guard.rs) пишет
  Error, шлёт dex.graph_owner_failed, перезапускает владельца (новое поколение, полная пересборка). Цикл паник не крутит
  процессор: перезапуск ждёт следующего пробуждения реестра.
- Зависание круга → сторож видит «круг идёт дольше dex.graph_max_lag_ms» (проверка раз в предел — это не опрос данных, а
  сторожевой таймер; без предела — только паника) → снимает задачу владельца, событие, перезапуск; читатели с первого же
  превышения предела — ступень В. Поток, который висит, остановить нельзя (std), его итог выбрасывается по поколению.
- Отставание без падения → предохранитель И7.
- Полная пересборка упала → Error + событие, действующий снимок остаётся (торговля по графу не останавливается).

## 10. Гистерезис — точные моменты замера

Вердикт «глубокий» зависит от прошлого вердикта (depth_book.rs:96-103). Книга одна на реестр и помнит последний ключ
пула; пересчёт — только при смене ключа (поколение пула, настройки, поколения пулов X–USDT). Вердикт для ключа K
считается ОДИН раз — первым, кто спросил на K (обычно depth::touch на событии пула), дальше берётся из памяти. Поэтому
накопительная и полная сборка, спрашивая книгу на одном и том же ключе, получают одинаковый вердикт — детерминированно.
Отличие от старого поведения фактом: раньше построение графа на каждой версии было одним из «спрашивающих» для каждого
пула; теперь владелец спрашивает только изменённые и зависимые пулы. Пул, ключ которого не менялся, книгой не
пересчитывается ни там, ни там — вердикт тот же. Остаточный (существовавший и раньше) эффект: полная сборка, читающая
запись пула до его изменения, может записать в книгу вердикт старого ключа после того, как событие записало новый; тогда
следующий запрос нового ключа считает гистерезис от вердикта старого. Это та же семантика, что у параллельных расчётов
t132; сравнение самопроверки при этом корректно — пул в since оценивается один раз и одинаково применяется к обеим картам.

## 11. Полная пересборка и самопроверка — одна операция

Каждая полная пересборка (запуск, настройки, переподключение лент, кнопка/REST, срок dex.graph_verify_s) при наличии
накопительной карты сравнивает её с собранной с нуля как множества «пара → отсортированные (пул, ранг)»; расхождение
→ Error в журнал с перечнем отличий (пара, лишние/недостающие пулы, разные ранги; до разумного числа строк — число
строк журнала не настройка, а полный перечень пишется в data записи), событие dex.graph_mismatch, счётчик на экране; в
любом случае действующей становится собранная с нуля (самоисцеление). Поэтому отдельные настройки «периодическая
пересборка» и «периодическая самопроверка» не нужны — одна `dex.graph_verify_s`.
Процессор: полная сборка — ровно один поток блокирующих задач (одна сборка за раз), накопительные круги — ещё один;
работа графа ограничена двумя потоками вместо «до profit.calc_concurrency одновременно» в t132. Приоритета потоков в std
нет; дробление с паузами потребовало бы числа-паузы (настройки) без измеренной нужды — не делаю, замер покажет.

## 12. Сразу или двумя шагами (рёбра без копии Entry)

Ребро сохраняет `entry: Entry`, но: (1) Graph хранит рёбра за Arc (Vec<Arc<Edge>>; внешний API edges_from / between /
len не меняется — вызывающие и тесты не трогаются); (2) копия записи ребра обновляется при каждом изменении пула (он
в наборе изменённых → новое ребро), т. е. копии в снимке — на версии снимка, как у старого build; (3) расчёт в новом
режиме копии для цены не использует — гидратация из реестра. Полный переход на PoolRef без Entry затронул бы RoutePath,
Step, Leg, select, graph_legs, cycle и десятки тестов (Step.edge.entry читается повсюду) — без выигрыша в
корректности (гидратация уже даёт свежесть). Выбран вариант без переписывания этих модулей (правило Тиграна: точечно).

## 13. Этап 3 (решение 309) — не делается

Параллельный пересчёт глубин при полной пересборке: мешают Prep с RefCell (depth_key.rs), один Mutex книги на все пулы,
побочные эффекты depth_log::after и rise. После решения 307 полная сборка пересчитывает кривые только у пулов с новым
поколением; полная сборка идёт в фоне и не держит читателей. Нужен ли параллелизм — покажет замер full в dex.graph_build;
оценка работ: Prep → Sync (Mutex карты курсов), шардирование книги или сбор вердиктов без записи с последующей записью
одним проходом, порядок depth_log — 1–2 дня с тестом равенства. Записано в TASKS как следующий шаг по замеру.

## 14. Решение 307 (этап 1) — кривая не пересчитывается при смене курса

Книга глубины помнит band_units пула по (поколение состояния, полоса) отдельно от ключа курса; при смене только курса
встречного X пересчитывается лишь band_from_units (два to_usdt — своп всей суммы, смысл решения 73 не меняется).
Пулы X–USDT для курса берутся один раз на подготовку (Prep) вместе с их поколениями — одним by_pair (поколения в ключе и
пулы в расчёте курса — из одного чтения, согласованы по построению). Неудача band_units — память по (поколение, полоса)
(та же причина: band_units от курса не зависит). Бит в бит: те же band_units (чистая функция записи и полосы), те же
пулы и тот же best_in.

## 15. Настройки, события, экран

Настройки (все необязательные, раздел «DEX», площадка DEX):
- `dex.graph_background` (да/нет) — режим «граф без ожидания»; не задана/нет — как t132;
- `dex.graph_max_lag_ms` (мс) — предохранитель И7 и сторожевой срок зависания; не задана — предохранителя нет (цена всё
  равно по свежему состоянию — гидратация), сторож ловит только панику;
- `dex.graph_verify_s` (с) — периодическая полная пересборка со сверкой; не задана — только по запуску, настройкам,
  переподключению и кнопке;
- `dex.graph_alert_min_s` (с) — повтор dex.graph_stale в эпизоде не чаще; не задана — одно сообщение на эпизод.
Замер — существующие log.graph_timing / log.graph_timing_min_ms (запись dex.graph_build расширена: kind, pending, lag).
События Telegram (группа «Площадки»): dex.graph_stale (снимок отстал сверх предела — маршрутов графа нет), dex.graph_mismatch
(самопроверка нашла расхождение — снимок заменён собранным с нуля), dex.graph_owner_failed (фоновая задача упала или
зависла — перезапущена).
Экран «Площадки» (DEX): блок «Граф маршрутов (фон)» — режим, версия снимка и реестра, возраст, отставание (текущее и
наибольшее за час), рёбер, последний круг, последняя полная пересборка (когда, почему, сколько мс), расхождений
самопроверки (последнее — текст), срабатываний предохранителя за час/сутки, ступень Б за час/сутки, перезапусков;
кнопка «Пересобрать граф» (POST /api/venues/{id}/dex-graph/rebuild). REST: GET /api/venues/{id}/dex-graph.
