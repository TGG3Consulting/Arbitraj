## 0. Коротко для владельца

**Что требуется (16.11):** брать объём с наибольшей прибылью в USDT среди всех допустимых (проходящих ОБА порога),
границы и точки — из реальной ликвидности, ничего прибыльного не терять, отсекать только доказанно безнадёжное.

**Что проект гарантирует (после реализации):**
1. **Отсечение строгое.** Объём отбрасывается, только если его «потолок» U(q) ниже порога, а U(q) ≥ прибыли, которую
   бот насчитал бы на этом объёме (теорема 2 + лемма 3, п. 2). Где потолок не доказан (виды пулов и случаи из
   таблиц п. 3 со статусом «нет») — отсечения нет, работает прежний поиск.
2. **Наибольшая прибыль с доказанным недобором.** Поиск идёт, пока на каждом непросмотренном участке потолок не
   опустится ниже лучшей найденной прибыли + допуска. Недобор против лучшего возможного у бота ≤ допуска
   (size.bound_gap_usd) — доказуемое свойство, а не «около пика сетки».
3. **Порог % — ограничение поиска (ошибка №20 исправляется обязательно):** выбирается наибольшая прибыль в USDT
   среди объёмов, которые проходят и порог USDT, и порог %.
4. **Несвязное допустимое множество (№18, №19)** — участки допустимости ищутся из стакана/лесенки, а не бисекцией по
   предположению монотонности.
5. **Срок расчёта не теряет найденный проходящий объём** — поиск «в любой момент» с мягким сроком (п. 7в).
6. **Решение о сделке — как сейчас:** только по финальной котировке на свежем состоянии (`profit.rs:162-215`).

**Где честно есть дыры (п. 7):** виды пулов без строгого потолка (DODO PMM, SmarDex, Maverick, Balancer V2 —
пока), исполнитель KyberSwap (финальная цена вне нашей математики), общий пул V2/V3 в двух долях встречными
направлениями (закрыт добавкой a_e⁰, но она ослабляет потолок), смена состояния между поиском и финальной котировкой.
По каждой — готовое решение в п. 7.

## 2. Математика: теоремы и доказательства

Обозначения: q — объём покупки на A (монет), s — количество продажи на B, T_usd, T_pct — пороги направления
(`venue_dir::thresholds`, profit.rs:105-110). Всё ниже — **доказано**, предпосылки — со ссылками.

### 2.1. Теорема 1 (идеальная модель, ответ на «−20 на 50, −80 на 100»)

Если стоимость покупки C(q) выпукла, выручка R(s) вогнута, приход аффинен по q, маршрут один — ядро
g(q) = R(arr(q)) − C(q) − (пропорциональные затраты) вогнуто и g(0) = 0, значит g(q)/q не возрастает и
p(q) ≤ (q/q₁)·g(q₁) − D_min для q ≥ q₁. Доказательство — первый проект, п. 1.2 (вогнутость суммы; хорда через 0).
Плюса на [50; 100] при p(50) = −20 нет при любых постоянных затратах < 40 USDT.

### 2.2. Теорема 2 (настоящий бот: верхняя модель)

Для любого объёма q, на котором расчёт бота завершился (Calc есть):

  **p_bot(q) ≤ U(q) := f_c · R⁺_B(arr⁺(q)) − C⁻_A(q) − F⁻_A(q) − F⁻_ret**,

где
- arr⁺(q) — приход без округлений и без затрат, которые нельзя доказать снизу (п. 2.5);
- R⁺_B(s) — верх выручки B на s монет без нефиксированных затрат: биржа — `notional_B(s)·(1 − r_B)` при комиссии
  в котируемой монете (иначе `notional_B(s)`); DEX — `ρ_sell·s + A_sell` (лемма 3);
- C⁻_A(q) — низ стоимости покупки: биржа — `notional_A(q)` (вложение бота `invested = q·avg = notional`);
  DEX — `q/ρ_buy − A_buy` (лемма 3 для покупки);
- F⁻_A(q) — комиссия покупки в котируемой монете `r_A·notional_A(q)` (если план комиссии «от суммы» и монета
  комиссии — котируемая; иначе 0);
- F⁻_ret — фиксированная часть комиссии вывода USDT с B (если `return_per_trade`, B — биржа, монета — котируемая), иначе 0;
- f_c = max(0, 1 − k·σ·√T) — базовая часть запаса (reserve.rs:105; запас ≥ базовой части, :106-114).

**Доказательство.** Каждое слагаемое p_bot заменено на не меньшее: выручка бота = sell_qty·avg_B, sell_qty ≤ arrive ≤
arr⁺(q) (п. 2.5), выручка не убывает по количеству, на DEX — лемма 3; вложение бота ≥ C⁻_A; затраты в costs_usdt
неотрицательны (газ, чаевые, разрешения, налоги «в долларах», StepRemainder — вне выручки, а не затрата), выброшенные
затраты только уменьшали бы прибыль; запас ≥ f_c-части. ∎

Порог %: прибыль бота ≥ T_pct/100 · invested и invested ≥ C⁻_A(q) ⇒ (при T_pct ≥ 0) U(q) ≥ T_pct/100 · C⁻_A(q).

**Следствие (Г1).** Объём q, на котором бот насчитал бы проход обоих порогов, лежит в
I_T = {q : U(q) ≥ T_usd и U(q) ≥ T_pct/100·C⁻_A(q)}. Отсечь q ∉ I_T — строго.

U вогнута (вогнутая от аффинной минус выпуклая), U − (T_pct/100)·C⁻_A тоже вогнута ⇒ I_T — **один отрезок** (пустой
или нет). Множество допустимых объёмов бота при этом может быть несвязным (п. 3.1, №18, №19) — I_T его покрывает.

### 2.3. Лемма 3 (двойственная оценка стороны DEX)

Продажа s монет через любой набор маршрутов из пулов E. Назначим «цены узлов»: USDT = 1, монета = ν, промежуточная
m — π_m ≥ 0. Для любого исполнения (доли, порядок, общие пулы) по телескопической сумме по узлам:

  USDT_out = ν·s + Σ_e Σ_{обмены через e} (π_out·y − π_in·x).

Если для каждого пула e и каждого его обмена π_out·y ≤ π_in·x + (доля добавки a_e) — то USDT_out ≤ ν·s + Σ_e a_e.

**Строим π так, чтобы почти все a_e = 0** (новое по сравнению с первым проектом). Пусть для пула e в направлении
in→out известна строгая верхняя граница средней отдачи `r_e(in→out) ≥ y/x` для ЛЮБОГО обмена, который модель бота
может провести в этом пуле в этом направлении (таблица п. 3.2). Возьмём π — наибольшие произведения r по путям до
USDT («длиннейший путь» в мультипликативной форме, Беллман–Форд):
π_USDT = 1, π_in ≥ r_e(in→out)·π_out для всех рёбер. Тогда для обмена через e: π_out·y ≤ π_out·r_e·x ≤ π_in·x ⇒
a_e = 0. ν := π_coin = **ρ_sell**. Если в графе рёбер есть цикл с произведением r > 1 («арбитраж среди
промежуточных»), Беллман–Форд не сходится — для монеты метод не действует (прежний путь).

**Когда «граница средней отдачи на любой обмен» неверна — и что делаем:**
1. *Общий пул в двух долях одного направления* (решение 223; модель — по порядку на сдвинутом состоянии,
   graph_seq.rs:1-20). Сдвиг состояния после обмена в том же направлении только ухудшает отдачу у видов с монотонной
   ценой → r_e на исходном состоянии остаётся верхом. Общий пул возможен ТОЛЬКО у V2 и V3: `pool_after::appliable`
   (pool_after.rs:34-40); у остальных вторая доля через пул не открывается (graph_seq.rs:14-15). **Доказано.**
2. *Общий пул V2/V3 в двух долях встречными направлениями* (доля 1: X→Y, доля 2: Y→X на сдвинутом состоянии — путь
   из 3 хопов, `dex.route_max_hops ≥ 3`, `dex.router_mode = graph`, `smart.max_splits ≥ 2`). Вторая доля может
   получить отдачу выше r_e исходного состояния. Закрываем добавкой: сумма вкладов любой последовательности обменов
   пула с комиссией, остающейся в пуле (V2: резервы = балансы, pool_after.rs:8-12; V3: комиссия вне ликвидности),
   ≤ a_e⁰(π) = sup по чистым обменам БЕЗ комиссии (π_out·Δout − π_in·Δin) — инвариант пула с комиссией не
   убывает, поэтому чистый итог любой последовательности лежит в множестве обменов без комиссии. **Доказано.**
   Для V2: a_e⁰ = (√(π_Y·R_Y) − √(π_X·R_X))² (максимум π_Y(R_Y − k/(R_X+Δ)) − π_X·Δ по Δ любого знака, k = R_X·R_Y).
   Для V3: та же формула на виртуальных резервах активного диапазона, если цена π_X/π_Y лежит в его границах
   (соседние инициализированные тики, swap_cl.rs:221 `next_tick`); иначе — сумма по диапазонам (как обмен до цены,
   swap_cl.rs:75 `swap_to`), с запасом округления +1 ед. на шаг. Добавка нужна только при условиях выше; иначе 0.
   **Риск ослабления:** при π из комиссионных рёбер отношение π_X/π_Y отличается от цены пула не больше чем на
   комиссию, a_e⁰ ≈ R·(δ/2)² — для пула 5 млн $ и δ = 0,25 % ≈ 8 $ на пул. Это делает потолок DEX при графе с 3 хопами
   и сплитом заметно слабее. Решение: **гипотеза Г-встречн.** «для V2/V3 при π в полосе комиссии сумма вкладов
   встречных долей ≤ 0» (численно на примере X = Y = 100, γ = 0,997: −0,054 и −0,055 при π на обеих границах полосы) —
   доказать или опровергнуть до кода (задача математику, п. 12); до доказательства — добавка a_e⁰.
3. *Пул между двумя промежуточными* — может идти в любую сторону: рёбра в обе стороны с комиссионной r_e
   (произведение туда-обратно < 1 — цикла нет); встречное использование в двух долях — п. 2.
4. *Округление целых единиц* — функции обмена считают вниз (выход) и вверх (вход точного выхода) — только в нашу
   пользу; r_e — рациональное число из целых состояния, переводится в Decimal **с округлением вверх**; произведения
   в Беллмане–Форде — умножение с добавкой 1 единицы последнего знака результата (`mul_up`): итог ≥ точного.

Покупка (монета на выходе, A = DEX): та же лемма с ценами стоимости: c_USDT = 1, c_out ≤ c_in / r_e;
наибольшие произведения r от USDT до монеты = **ρ_buy**; USDT_in ≥ q/ρ_buy − Σ a_e. У покупки «с конца»
(route_calc.rs:93-119, нужный выход вверх) излишек на промежуточной ≥ 0 — в нужную сторону. **Доказано.**
Виды без точного выхода (StableSwap, Solidly stable, DODO, OraclePmm, SmarDex, LB — pool_quote.rs ветки `!exact_in`
→ ошибка) в маршрут покупки не входят (swap c exact_in = false даёт NoRoute) — их рёбра в покупке не нужны.

### 2.4. Огибающая из нескольких прямых (этап 1)

Для ν < ρ_sell: π для промежуточных — те же (Беллман–Форд от USDT), монета — ν; a_e = 0 у всех пулов, кроме пулов
монеты (монета → m), у них a_e(ν) = π_m·sup_x (φ_e(x) − (ν/π_m)·x) — «прибыль арбитражёра, продающего монету в пул,
пока предельная отдача не упадёт до ν/π_m». Прямая k: R ≤ ν_k·s + Σ_{e∋монета} a_e(ν_k) + A_встречн. Нижняя огибающая
K прямых — вогнутая ломаная R̂(s). a_e по видам — таблица п. 3.2 (столбец «a_e»). У вогнутых пулов при K → ∞
огибающая → лучшая выручка V(s) (сильная двойственность, Angeris et al. 2022).

### 2.5. Приход сверху arr⁺(q) (факт кода → доказательство)

- Биржа A, комиссия покупки в монете (`per_coin`, монета комиссии = монета сделки после `quote_back`):
  to_send ≤ q·(1 − r_A) (floor_precision только уменьшает; frozen.rs:96-100).
- Комиссия вывода биржи: `fee = fix + pct·amount` (transfer.rs:53-56), налог перевода t: arrive = (to_send − fee)(1 − t)
  (costs_withdraw.rs:52-65) — возрастает по to_send ⇒ arr⁺(q) = (x(1 − pct) − fix⁻)(1 − t), x = q(1 − r_A).
  fix⁻ = fix, если `transfer.seen_cost` не «да» у A; при «да» поправка по факту может УМЕНЬШИТЬ комиссию
  (withdraw_seen.rs:13-17, `max(0, …)`) ⇒ fix⁻ = 0, pct⁻ = 0. Строка «недостача по факту» (TransferShortfall) только
  уменьшает приход — не учитываем (верх).
- DEX на A: налог покупки и крючок — в цене, `coin_fee` отбирает только `!in_price` ⇒ to_send = q; перевод с DEX —
  газ (BNB, в долларах) и налог перевода (в монете) ⇒ arr⁺(q) = q.
- Если монета комиссии не совпала с монетой ядра (`in_coin` ложно, convert.rs:45-47) — бот считает её в долларах по
  `coin_price = qa.avg_price` (costs.rs:203-206): тогда в arr⁺ её не вычитаем, а в F⁻_A — 0. Строго в обе стороны.

## 3. Таблицы ситуаций (по коду)

### 3.1. Статьи затрат и ограничения: может ли прибыль бота оказаться выше потолка

«Скачок вверх» — может ли прибыль бота при росте q подпрыгнуть сверх гладкой вогнутой картины. Колонка «Потолок» —
как статья входит в U и почему это строго. Направления: К→D (биржа → DEX), D→К, К↔К, цикл.

| № | Место (факт кода) | Направл. | Скачок вверх | Потолок: как и почему строго |
| --- | --- | --- | --- | --- |

## 5. Алгоритм (псевдокод), стоимость

### 5.1. Этап 0 — функция для сигнала (t160) и для подбора

```
stage0(core, cx, budget, T_usd, T_pct) -> Ceil0 | NotApplicable(reason)
  side A: биржа → снимок quote_snapshot(A, Buy): стакан asks + BookFee (нужен геттер плана комиссии у FrozenQuote)
          DEX  → dex_bound(coin, Buy) из шлюза: ρ_buy, A_buy, отметка состояния; None → NotApplicable
  side B: биржа → снимок (B, Sell): bids + BookFee; DEX → dex_bound(coin, Sell): ρ_sell, A_sell
  внешний исполнитель на DEX-стороне и нет size.bound_external_margin_usd → NotApplicable
  U(q) = f_c·R⁺_B(arr⁺(q)) − C⁻_A(q) − F⁻_A(q) − F⁻_ret        (п. 2.2; вычисление тем же walk, что у бота)
  изломы q: накопленные уровни asks; уровни bids, переведённые обратной к arr⁺; arr⁺(q)=0; q_max = min(глубина A,
           глубина B / h через arr⁺, бюджет по худшей цене)
  U вогнута ⇒ max — в изломе; I_T — решение линейных кусков U(q) = T_usd и U(q) = T_pct/100·C⁻_A(q)
  return {max_U, q_at_max, I_T (может быть пусто), отметки состояния (время стакана, поколение пулов)}
```
Стоимость: O(уровни) при префиксных суммах; ни одной котировки DEX; dex_bound — Беллман–Форд по ≤ (узлов × пулов)
рёбрам: узлов 2 + mids, пулов — десятки.

### 5.2. Этап 1 — огибающая DEX (нужна, где этап 0 не отсёк)

K прямых: ν_k = ρ·(1 − δ)^k (δ, K — настройки dex.bound_lines, dex.bound_band_pct), прямая k = (ν_k, Σ a_e(ν_k) по пулам
монеты + A_встречн). U(q) с R̂ = min_k — вогнутая ломаная; I_T — один проход. Сетка ν от ρ неподвижна, пока ρ не уйдёт
дальше полосы (кэш a_e по пулу).

### 5.3. Этап 2 — поиск «ветви и границы» внутри I_T

```
search_bnb(memo, model U, I_T, gap) :
  P := {концы I_T ∩ [lo, hi]} ∪ изломы A (n, n+1) ∪ изломы B (обратная к arr⁺, n, n+1)
       ∪ границы бинов/тиков/точек лесенки пулов маршрута (из dex_bound: объёмы, на которых предельная отдача пула
         меняет кусок — у V2 их нет, у V3 — пересечения тиков при обмене до цены ν_k, у бинов — границы бинов, у лесенки —
         точки) ∪ начала участков допустимости (п. 5.4) ∪ «зубья» вывода около лучшей точки
  посчитать P пачкой (memo.at_many, t157)
  best := лучшая допустимая (с учётом порога %, п. 6)
  open := участки между соседними посчитанными точками
  while open не пуст и не исчерпан size.max_evals и не мягкий срок (п. 7в):
     для участка (a, b): ub = max_{q∈[a,b]} U(q) (у вогнутой — в точке касания, O(1))
     если ub < max(T_usd, best.profit) + gap → закрыть (доказанно нечего искать)
     иначе посчитать точку m = argmax U на [a,b] (если она в конце — середину); разбить
     уточнить U касательными: у биржевой стороны — точно; у DEX — новая прямая ν = предельная отдача маршрута в точке
       НЕ годится (маршрут бота не оптимален) — прямые только из двойственной задачи (этап 1)
  итог: best; сертификат «max ub по открытым участкам − best» ≤ gap или «остановлен пределом» (с числом)
```
Закрытие участка строго: на нём прибыль бота ≤ U ≤ ub < best + gap.

### 5.4. Участки допустимости (№18, №19, №20–21, бюджет DEX)

- minNotional/maxNotional продажи по худшей цене: для уровня j bids (накопленные c_{j−1} < s ≤ c_j, худшая цена p_j)
  допустимо s ∈ [max(c_{j−1}+шаг, minN/p_j), min(c_j, maxN/p_j)] — объединение отрезков, считается точно из стакана;
  в q — обратной к arr⁺ с проверкой точкой бота (floor может сдвинуть на шаг).
- Доля глубины h и исполнимость сплита DEX (№19), бюджет DEX по avg·(1+slip) (№19 табл. 3.1): точной формулы нет —
  в P добавляются точки по всей ширине I_T (их даёт B&B: участок не закрывается, пока ub ≥ best + gap, а точка
  «слишком большой» внутри не закрывает участки выше — в отличие от бисекции).
- Нижняя/верхняя бисекция size_bounds.rs остаётся только у прежнего поиска.

## 6. Порог % (ошибка №20) — исправление (обязательно)

**Сейчас (факт кода):** поиск максимизирует прибыль в USDT (size_memo.rs:165-174 `best`), финальная котировка — на
этом объёме, затем `profit_usd < T_usd` и `profit_pct < T_pct` (profit.rs:198-215). Если на оптимуме по USDT процент
ниже порога — отказ, хотя меньший объём проходит оба порога.

**По проекту (настройка size.pct_constraint, необязательная; не задана — как сейчас):**
1. Целевая функция поиска — `profit` по точкам с `profit_pct ≥ T_pct` (недопустимые по % — хуже любой допустимой).
2. В B&B закрытие участка — по U(q) < max(T_usd, best) + gap ИЛИ U(q) < T_pct/100·C⁻_A(q) (п. 2.2).
3. В прежнем поиске (до включения B&B): после сетки и уточнения — лучшая из точек, проходящих %; плюс уточнение
   тернарным поиском вокруг неё с той же целевой функцией (локальный пик ограниченной задачи).
4. Финальная котировка — на выбранном объёме; если она не прошла % — второй по прибыли проходящий объём (одна
   попытка), иначе отказ.

**Пример (числа первого проекта, иллюстрация механизма):** пороги 0,5 USDT и 0,3 %; оптимум по USDT 1,0 USDT при
вложении 1000 (0,1 %) — сейчас отказ; на вложении 200 — 0,8 USDT (0,4 %) — проходит оба: по проекту сделка на 200.
**На записанных стаканах:** в записях `tests/data/cex_samples_2026_11_04` (Bybit/Gate/KuCoin CAKE в одну минуту) и
CAKE BingX + пул V2 (`tests/size_common`) положительной разницы нет (проверено расчётом: лучший ask Gate 1,896 >
лучший bid Bybit 1,8934; BingX → пул — минус на всём диапазоне) — пример «сделка, которую сейчас теряем», на записях
не воспроизводится. Нужна запись принятого/отклонённого по % кандидата — промпт 2 п. 12. Тест №20 (обязательный)
строится на ней; до неё — тест механизма на записанных стаканах CAKE с порогами, при которых оптимум по USDT не
проходит % (пороги — параметры теста, данные — записанные): проверяется, что выбран наибольший по USDT объём среди
проходящих оба порога (перебор всех шагов — эталон).

## 7. Где новый поиск всё ещё может недобрать (честно, с решениями)

**(а) Виды пулов без строгого потолка** — DODO PMM (Pmm), SmarDex (Fictive), Maverick V2 (TickBin), Balancer V2
(VaultPool) (табл. 3.2), а также монеты, у которых в наборе пулов есть цикл r > 1 среди промежуточных. Там прежний
поиск, и прежняя дыра «пик между двумя точками сетки» остаётся. Решение без потолка: **точки по границам ликвидности
пула** — для каждого пула набора адаптер отдаёт объёмы, на которых меняется кусок его кривой (DODO: смена R-состояния
(R=ONE ↔ ABOVE/BELOW) — по целям B0/Q0; SmarDex: граница первого шага по средней цене; Maverick: границы тиков от
активного; Balancer: нет изломов — гладкая), в монетах продажи; ядро добавляет их (через arr⁺⁻¹) в P прежнего
поиска. Это не доказательство, но закрывает «пик между точками» там, где изломы и есть причина пиков. Параллельно —
вывод строгого r_e: Maverick (округление sqrt-цены активного тика, maverick_tick_math.rs) и Balancer весовой (формула
спота) — задачи математику, п. 12.

**(б) Допуск остановки.** Недобор против лучшего возможного у бота ≤ size.bound_gap_usd (+ size.bound_gap_pct от
лучшей прибыли) — доказано п. 5.3. Если допуск не задан — 0: поиск идёт до закрытия всех участков или до предела.

**(в) Срок расчёта.** Сейчас при `profit.calc_timeout_ms` весь расчёт кандидата отменяется (candidates.rs:155-170),
даже если проходящий объём уже найден — потеря. Решение: мягкий срок внутри подбора (size.soft_deadline_pct — доля
от profit.calc_timeout_ms): по его наступлении поиск прекращается, берётся лучшая проходящая точка и идёт финальная
котировка; сертификат «остановлен сроком, недобор ≤ X» в пояснении. Предел size.max_evals — так же (уже берётся лучшая,
size_search.rs:13-14) — сохраняется.

**(г) Состояние сменилось между поиском и финальной котировкой.** Финальная — на свежем состоянии (profit.rs:160-215);
если она не прошла порог, а потолок на свежем состоянии ещё допускает проход — сейчас отказ до следующего тика.
Решение: при отказе финальной — один пересчёт этапа 0/1 на свежем состоянии; I_T не пуст и содержит другие посчитанные
проходящие точки — финальная котировка следующей из них (одна попытка), иначе отказ. Решение о сделке — всё равно по
финальной (требование 6).

**(д) Где потолок опирается на предположение:**
1. Гипотеза Г-встречн. (п. 2.3, п. 2) — до доказательства используется строгая добавка a_e⁰.
2. Округление целочисленных стейблсвапов (Curve get_y, Solidly stable _get_y) — гипотеза «целый выход ≤
   вещественного»; до прохода T2 на записях этих видов — вид исключается из метода (статус «нет»).
3. Внешний исполнитель (Kyber, best_of) — потолка нет; отсечение только с запасом size.bound_external_margin_usd;
   не задан — отсечения нет. Разница «KyberSwap − своя» на финале пишется в журнал (режим записи).
4. Крючки V4 с возвратом дельты (beforeSwapReturnsDelta/afterSwapReturnsDelta, types HookFlags) — модель бота:
   keep по измеренному hook_pct; потолок ≥ модели (множитель max(1, keep)), но не ≥ сети, если крючок даёт больше
   измеренного — это тот же риск, что у самой котировки (решение 30–32), не потолка.

**(е) Набор пулов меньше, чем у бота** — исключено построением: объединение допусков по сторонам, plan_gas не
применяется, «только сигнал» включены (табл. 3.1 №34–35).
