# t167 — почему покупка на DEX раз за разом срывается при держащемся спреде (17.11.2026, решение 381)

Живой факт (из задания): ESIM bsc_dex → kucoin, 17 попыток, покупка исполнилась в 3, в 14 — нет (плановая прибыль этих
14 — 34.8 USDT, 0.9–4.9 USDT на ~40 USDT). 8 × «[свой сборщик: прямой] Цена в пуле сейчас … хуже допустимой …»
(286–401 мс после решения, один раз 1855 мс), 2 × «предторговая верификация: свежая средняя цена дороже границы
сделки» (417–434 мс), 2 × «не попала в блок за send.max_wait_blocks» (10.5 с), 1 × квотер 7.20 %, 1 × глубина.

## Путь сделки и состояние пула на каждом шаге (факт кода)

| Шаг | Где | По какому состоянию пула |
| --- | --- | --- |
| Событие пула → память | pools/* (лента логов ws или квитанций, решение 68) | реестр пулов q.reg — последнее увиденное событие блока N |
| Сигнал, дозревание, кандидат, подбор | core/signal*.rs, evaluate.rs, profit.rs | котировки адаптера по q.reg (блок N) |
| Предпроверка, пересчёт с финальной котировкой | core/precheck.rs, profit.rs | q.reg (свежее на момент пересчёта) |
| Граница сделки (DEX) | core/worst.rs:156 | средняя цена плана × (1 + exec.dex_slippage_pct) |
| Предторговая верификация (граф) | quote/verify.rs:113 | чтение пулов маршрута с узла на блоке `heads.latest()` (последний известный, опрос bsc.blocks_poll_ms) |
| Проверка цены перед сборкой | exec/trade_direct_prep.rs:54 → order.rs:50 | снова q.reg (exec/live.rs:61), не прочитанное верификацией |
| Минимум выхода | exec/order.rs, exec/leg_min.rs | max(USDT / граница, ожидаемое × (1 − допуск)) |
| Исполнение | следующий блок N+1 или позже | после чужих транзакций этого блока |

**Мемпул (pending) не читается нигде** (поиск `pending`/`txpool`/`newPendingTransactions` по src — только тексты
ошибок узла). Значит, расчёт всегда по состоянию «последний блок N», а обмен исполняется не раньше N+1, после
транзакций, которые попадут в N+1 раньше нашей. Это свойство кода, не данные: «состояние отстаёт на ≥ 1 блок от
состояния исполнения» верно всегда.

## Что ждёт намеренно

- Удержание сигнала (signal.min_hold_ms / signal.min_hold_updates) и таймер дозревания (решение 318, signal.hold_timer):
  кандидат не раньше above_since + signal.min_hold_ms. В записи core.signal_hold из задания — 985 мс от первого
  превышения порога до кандидата, запуск — таймер. Правило 317 (signal.dex_event_skip_hold) пропускает удержание, только
  если пересчёт запущен событием пула и уровни стакана биржи стоят не меньше signal.min_hold_ms; при запуске по таймеру
  оно не действует. При блоке ~0.75 с удержание ~1 с = 1–2 блока, за которые спред видят все.
- Предпроверка (≈ 286–401 мс от решения до срыва): статусы вывода/депозита и адрес — запросы к биржам (часть — в
  памяти при precheck.networks_memory), проверка продажи на B, баланс. Пересчёт с финальной котировкой — 18.1 мс
  (из хронологии). Разбивку по шагам даёт строка «Время по шагам (предпроверка)» — её нужно запросить (ниже).

## Что сравнивают проверки

- «Цена в пуле сейчас X хуже допустимой Y» (exec/order.rs:50): X = USDT / монет пути доли по q.reg на объём плана;
  Y = средняя цена плана × (1 + exec.dex_slippage_pct) (core/worst.rs:156, trade_ops.rs worst_order). Допуск —
  exec.dex_slippage_pct (значение на живом боте в задании не дано).
- Верификация (quote/verify_decide.rs:116): свежая средняя цена по чтению узла против той же границы Y; плюс грубый
  предохранитель дрейфа в обе стороны verify.max_price_drift_pct (verify_decide.rs:103; в ROADMAP — «временно 0.5»;
  совет решения 121 B4 — 10–20 %).
- Порог прибыли на этом шаге НЕ проверяется: прибыль 2.3–12 % вложения (0.9–4.9 USDT на ~40) при допуске порядка долей процента — сделка снимается при
  сдвиге цены больше допуска, даже если на свежей цене она выше порога.

## «Не попала в блок» (вопрос 4)

send/track.rs:85 — ждём send.max_wait_blocks блоков, затем отмена (0 BNB себе тем же nonce), итог «не попала» только
по квитанции отмены (nonce занят). Ожидание обязательное: пока nonce не занят, исходная может исполниться. Монета
(замок по монете, решение 118) занята всё это время. Сделка закрывается (и после решения 381): обмен был отправлен —
стартовое правило Тиграна; решение 229 («повтор после подтверждённой отмены») принято только для продажи. Повтор покупки
в этом случае — вопрос владельцу (docs/TASKS.md, ревью t167, Б2).

## Серия из 8 попыток (вопрос 5)

Каждая новая попытка — новый кандидат по q.reg, а в нём уже есть событие, из-за которого сорвалась прошлая (проверка
читала тот же реестр). Значит, следующая попытка не по «старому» состоянию — но опять по блоку N при исполнении в N+1,
и снова через удержание + предпроверку (~1.3 с). Перечитывать пул с узла на latest перед следующим расчётом бессмысленно:
реестр и так на latest; проблема — не latest, а N против N+1.

## Что сделано (решение 381)

core/buy_replan.rs + executor.rs: срыв покупки DEX до отправки по цене — QuoteMismatch с пометкой адаптера
`GatewayError::price_moved` (exec/order.rs check_price; verify_gate.rs — отказ по границе сделки, не грубый
предохранитель) и без транзакции в сети → план заново на свежих данных (тот же расчёт, что пересчёт перед покупкой;
сначала объём прошлого плана, затем полный подбор под тот же предел списания), проверка продажи на B и газа BNB
(решение 62); перед повторной покупкой — risk::can_open и замок сухого режима, как перед первой; снимок рынка
(решение 217) — к новому плану; выше порогов — покупка по новому плану (хронология + уведомление deal.replanned) без
нового удержания и без повторной проверки статусов вывода/депозита. Не больше exec.dex_buy_replan_max раз; не задана —
как раньше. Граница сделки и минимумы — прежние (решение 121 B4 не тронуто).

Ревью t167 (правки): Б1 — замки перед повтором; Б2 — «не попала в блок с отменой» убрано из пересчёта (стартовое
правило; 229 — только продажа), вопрос владельцу в docs/TASKS.md; Н1 — газ BNB; Н2 — признак price_moved вместо
«любой QuoteMismatch» (квотер, минимум 0, новый approve, «обе хуже», предохранитель — без пересчёта); Н4 — уведомление;
Н5 — снимок рынка; Н6 — в описании настройки: каждый пересчёт держит монету занятой, срока сделки/предпроверки в
настройках нет; Н7 — 2.3–12 %.

## Не сделано — нужно решение владельца

Граница сделки = цена, при которой прибыль = порогу (а не план × (1 + допуск)). ROADMAP (решение Тиграна 01.11:
«решать по свежей прибыли») и решение 121 B4 («граница — worst_price; проверка по свежей прибыли — техдолг, открыто на
решение Тиграна») — меняет смысл exec.dex_slippage_pct как границы цены. Есть и ограничение: если план упёрся в бюджет
(вложение ~39.8 при бюджете, видимо, 40 — гипотеза, бюджет плана не дан), поднять цену при том же объёме нельзя
(решение 66: вложение ≤ бюджета) — нужен меньший объём, что и делает пересчёт 381.
