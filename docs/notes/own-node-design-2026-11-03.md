# Свой узел BSC без KyberSwap — проект решения (решение 121)

Ветка `feat/own-bsc-node` (основа — `feat/kyberswap-aggregator` после решений 118–120).
Основание — три разбора 03.11: `own-node-connect-audit-2026-11-03.md` (подключение, **П**),
`own-exec-vs-kyber-audit-2026-11-03.md` (исполнитель против KyberSwap, **И**), `own-node-features-audit-2026-11-03.md`
(фичи на узле, **Ф**).

Цель (Тигран): бот работает **только** со своим узлом BSC (geth-bsc v1.8.1 на том же сервере, 127.0.0.1:8545/8546) и
делает сам всё, что делал KyberSwap: котировку, маршрут, сборку и отправку свопа. Полная боевая готовность к переключению.

Тигран в отъезде (≈20 ч, «работай без остановки»). Вопросы разборов решены техлидом по правилу «самый безопасный
вариант, ничего необратимого, всё переключается в интерфейсе»; каждое такое решение помечено **[техлид]** — Тигран может
поменять. Ничего не сливается в `main` и не ставится на сервер без Тиграна.

## Что уже готово (по разборам, без изменений)
- Все RPC-методы бота — namespace `eth`, узел их поддерживает (П): `eth_call`, `eth_simulateV1`, `eth_getLogs`,
  `eth_getBlockReceipts`, `eth_subscribe` (`newHeads`, `logs`), `eth_sendRawTransaction`, … Включать `txpool/debug/admin`
  не нужно.
- Сигналы, цены и подбор объёма — своя математика пулов (И, Ф). Финальная котировка при `exec.via_kyber = нет` — своя.
- Проверки налогов (`eth_simulateV1`, без state override), новые пулы событиями, сверка балансов (Multicall3, решение 113),
  газ, «Живой экран», эпизоды, карточка сигнала (Ф).
- Защита от сэндвичей у своего исполнителя лучше, чем у KyberSwap (тот уходил в открытый мемпул): закрытые каналы и
  бандлы, минимум выхода на каждой ноге (И).

## Что делаем (код) — по зонам исполнителей

### Зона A. Подключение к узлу и его здоровье
- **A1 🔴 Адрес своего узла не сохраняется** (П-1, Ф-R1): `src/settings/value.rs` принимает только `https`/`wss`.
  Решение **[техлид]**: `http`/`ws` разрешены только для адреса-петли (`127.0.0.1`, `::1`, `localhost`); для остальных —
  как раньше. Текст отказа объясняет правило.
- **A2 🔴 Бот не видит, что узел отстал или догоняет сеть** (П-2, Ф-R2): свежесть = рост номера блока.
  Решение **[техлид]**: новая **`feed.max_block_age_ms`** (мс, по площадке DEX, необязательная; не задана — как сейчас):
  возраст головы = часы сервера − `timestamp` блока; больше порога — данные «устарели» (`StaleData`, торговли нет) и
  запись в журнал раз на переход «свежо ↔ устарело». Время блока BSC — в секундах (в заголовке `timestamp`).
- **A3 🟠 «Проверить подключение» узла**: добавить `eth_chainId` = 56 (иначе ошибка), `eth_syncing` (не `false` —
  «узел догоняет сеть: блок X из Y»), возраст головы в секундах, ответ Multicall3. Без новых настроек.
- **A4 🟠 Ошибка старого состояния своего узла** «state … is not available» (П, Ф-O4) → `StaleData`, как «missing trie
  node» (`src/venues/bsc_dex/errors.rs`).
- **A5 🔴 Предел узла 1000 вариантов topics в подписке** (П-3): `dex.pools_per_sub` > 1000 → подписка CL/V4 падает с
  «exceed max topics». Решение: в описании настройки — предел своего узла; при ответе «exceed max topics» — понятная
  ошибка в журнал «уменьшите dex.pools_per_sub до 1000». Значение задаёт Тигран (1000).
- **A6 🟡 Multicall3 балансов частями на разных блоках** (Ф): все части — на одном номере блока (голова на момент
  запроса), а не `latest` каждой части.

### Зона B. Свой исполнитель вместо KyberSwap
- **B1 🟠 Approve устаревает** (И-🟠2, как решение 99): в прямом и умном пути маршрут и минимумы считаются до approve,
  после approve своп идёт со старыми минимумами. Решение: если approve отправлялся — котировка, минимумы и calldata
  собираются заново и снова сверяются с `req.worst_price` (как `kyberswap/trade.rs`).
- **B2 🟠 KyberSwap Elastic «исполним», а собирается вызовом роутера V2** (И-🟠1): пометить неисполнимым
  (`pools/families.rs`), пока нет своего пути.
- **B3 🟠 Бандл-маршрут при не-бандловых каналах** (И-🟠3): маршрут бандлом исполним, только если **все** включённые
  каналы отправки умеют бандлы; иначе на котировке он неисполним (сигнал есть, сделки нет) с понятной причиной.
- **B4 🟠 Проверка дрейфа цены перед сделкой — по выгоде, а не по фиксированному %** (И-🟠4; техдолг «очень срочно»
  от 01.11, решение Тиграна): `quote/verify_decide.rs` сейчас отказывает при |дрейф| > `verify.max_price_drift_pct` —
  даже если цена стала **лучше**. Решение: отказ, если свежая средняя цена **хуже** `req.worst_price` (граница сделки из
  плана ядра); `verify.max_price_drift_pct` — только грубый предохранитель от битых данных в обе стороны (советуемое
  значение — 10–20 %, Тигран меняет в интерфейсе).
- **B5 🟡 Фильтр `kyber.final_gate_usd` действует и без KyberSwap** (И, Ф-Y1): применять только при `exec.via_kyber = да`.
- **B6 🟡 Неиспользуемые `kyber.*`** (`kyber.quote_poll_ms`, `quote_concurrency`, `probe_usdt`,
  `assume_zero_transfer_tax`, `deposit_confirmations` — Ф-Y7): сделать необязательными (группа «KyberSwap» не показывает
  вечное «не задано»). Код KyberSwap **не удаляем** — `exec.via_kyber` остаётся переключателем и откатом **[техлид]**.
- **B7 Показ исполнителя**: в журнале сделки и на «Сделках» — кто исполнил своп (`свой сборщик: прямой / умный / бандл`
  или `KyberSwap`).

### Зона C. Пулы и «сухая сделка DEX»
- **C1 🟠 История V4 запускается при выключенном `dex.history_scan`** (Ф-O1): проверка выключателя — до поиска блока
  развёртывания (`pools/history_v4.rs`).
- **C2 🟠 Индексатор 404 = «непонятный ответ»** (Ф-O3): 404 по монете — «индексатор не знает пулов монеты» (Info, не
  ошибка), пулы — из других источников.
- **C3 🟠 Поиск пулов по фабрикам на своём узле** (Ф-O3, В1) **[техлид]**: новый источник справочника рядом с
  индексатором — для каждой монеты подписки и каждой подключённой DEX вида V2/форк V2 — `getPair(монета, USDT|промежуточная)`
  у фабрики; V3/форк V3 — `getPool(…, fee)` по уровням комиссии из настройки DEX; найденные пулы — через ту же проверку
  на узле, что пулы индексатора. Включается **`index.factory_scan`** (да/нет, по площадке DEX, необязательная; не задана —
  выключен, как сейчас); уровни комиссии V3 — **`dex.v3_fee_tiers`** (список, по DEX, без значений по умолчанию; не задан —
  V3 этой DEX по фабрике не ищется). Пачки — Multicall3 (`dex.load_batch`). Решение 58 дополняется.
- **C4 Сухая сделка DEX** (И-🔴1: свой своп ни разу не исполнялся с деньгами): команда «Собрать и проверить своп без
  отправки» — монета, сторона, сумма USDT → свой сборщик строит маршрут и транзакцию как для сделки, прогоняет
  `eth_simulateV1` от кошелька бота (approve в той же симуляции, если нужен) и показывает: форму маршрута, ожидаемый и
  симулированный выход, газ, минимумы, причину отказа. Ничего не отправляет, nonce не тратит. Интерфейс — экран
  «Ручное управление» (форма), API `POST /api/dex/dry-swap`. Это приёмка исполнителя перед деньгами.

## Не входит (записано в техдолг)
- DEX ↔ DEX исполнение (И-🔴2: сборщик цикла не вызывается) — отдельная задача, к KyberSwap не относится.
- Неподключённые DEX (Curve/Ellipsis/Nomiswap stable, Maverick, Trader Joe, iZiSwap, KyberSwap Classic, WooFi, THENA
  Fusion/Solidly/Slipstream/DODO/V3-форки как исполнимые) — пофазно, по картам покрытия; без них часть сделок, где
  KyberSwap давал цену лучше, пропадёт (И-🟠5) — это видно сравнением в сухом режиме (план ниже).
- История V4 через архивный узел (В2).
- Квитанции старше глубины истории узла (~3 суток при блоке 0.45 с) — перевод, не увиденный за `transfer.max_time_s`,
  уже уходит в карантин/ручной разбор.

## Прогон по сценариям (после изменений)
1. **Узел догоняет сеть после перезапуска.** Голова растёт, но `timestamp` отстаёт на минуты → A2: `StaleData`, сделок
   нет, журнал «узел отстаёт на N с»; «Проверить подключение» — «узел догоняет сеть».
2. **BingX → DEX, монета с пулом V3 PancakeSwap, первый раз (нет approve на Permit2).** Предпроверка → покупка на BingX →
   перевод → продажа: B1 — approve, затем свежий маршрут, минимумы и проверка `worst_price`; B4 — цена стала лучше плана →
   своп идёт (раньше — отказ по |дрейфу|).
3. **Маршрут через два V2-форка при включённом не-бандловом канале.** B3 — маршрут неисполним на котировке, сделки нет,
   причина видна в карточке.
4. **Монета, пул которой есть только у фабрики (индексатор отдаёт 404).** C2 — без ошибки; C3 (если включён) — пул
   найден фабрикой, проверен на узле, подписан.
5. **Перед деньгами.** C4 по каждой форме (V2, V3, Infinity, Uniswap V3/V4, умный сплит, бандл, BNB) — симуляция без
   отправки; все формы — «выход ≥ минимума, газ N».
