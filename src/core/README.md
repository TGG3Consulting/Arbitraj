# core — ядро

Ничего не знает о конкретных площадках. Работает только со своими типами (`types/`) и со шлюзом.
Никогда не импортирует `venues/`. Карта и поток тика — ARCHITECTURE.md.

| Файл | Что делает |
| --- | --- |
| `types/` | Общие типы (стык, меняется только через запрос на изменение стыка) |
| `mod.rs` | Список модулей ядра |
| `deps.rs` | Зависимости ядра (шлюз, настройки, журнал, уведомления, база) и помощники журнала/уведомлений |
| `engine.rs` | `Core`: создание состояния, загрузка учёта, запуск фоновых задач; чтение состояния для api |
| `inner.rs` | Общее состояние ядра (рынок, справочник, сигналы, сделки, риск, ручное управление) |
| `wait.rs` | Паузы фоновых задач по настройке; не задана — запись в журнал и ожидание, пока зададут |
| `market_state.rs` | Стаканы, пулы, проверки монет и крючков, каналы отправки, спот-пары бирж (SpotPairs) — из событий адаптеров |
| `market_read.rs` | Чтение рыночного состояния: пулы «загружаются», пары и свежесть, стаканы и цены, пулы с USDT, проверки, каналы |
| `registry.rs` | Справочник: первичный фильтр монет и направлений с причинами отсева |
| `registry_build.rs` | Сборка справочника из сетей бирж, рынка и пулов DEX; адрес USDT в BSC |
| `intermediate.rs` | Промежуточные монеты (решение 52): переключатель и список адресов по площадке DEX, тикер по адресу |
| `native.rs` | Нативная монета BNB (решение 62): запись биржи «тикер dex.native_ticker, сеть BSC, адреса нет» получает адрес обёртки dex.native_wrapped (WBNB) при чтении справочника сетей (registry_sync.rs, precheck.rs) |
| `pairs_fresh.rs` | Свежесть справочника пар биржи (venue.symbols_stale_s) и сторона сделки по нему (покупка/продажа через API) — для справочника и предпроверки |
| `presence.rs` | Есть ли монета на площадке и в какой роли (биржа: сеть BSC и адрес контракта, ввод/вывод, пара — статус и покупка/продажа через API, стакан; DEX: пул с USDT) |
| `transfer_status.rs` | Смены статусов ввода/вывода между опросами: по монете или одна сводка при массовой смене (venue.status_bulk_min) |
| `registry_sync.rs` | Обновление справочника сетей бирж (coin_networks) и уведомление об открытии/закрытии ввода и вывода |
| `rebuild.rs` | Пересборка справочника и чёрного списка по «толчку»; уведомления о чёрном списке и исключённых пулах |
| `rebuild_blacklist.rs` | Чёрный список при пересборке; без проверок из-за снятых пулов — вердикт не меняется (решение 71) |
| `rebuild_report.rs` | Уведомления пересборки: чёрный список, итог проверки налогов, исключённые пулы |
| `blacklist.rs` | Чёрный список (ручной, проверка налогов, налог выше порога) и допуск пулов с крючками V4 |
| `sub_state.rs` | Состояние подписок площадок: на что подписана, идёт ли подписка, причина сбоя (одна запись на причину) |
| `subscribe.rs` | Подписки площадок на рыночные данные по справочнику; DEX — только монеты с сетью BSC и торгуемой спот-парой у биржи (SpotPairs) |
| `tick.rs` | Поток тика: событие → состояние рынка → пересчёт направлений монеты → сигнал |
| `evaluate.rs` | Пересчёт направлений одной монеты на тике: цены, волатильность, сигнал, строка «Живого экрана»; «налоги не проверены» — без котировок |
| `prices.rs` | Цены направления для грубого спреда — котировки шлюза на объём сравнения |
| `signal.rs` | Грубый спред, порог (процентные комиссии) и фильтр шума |
| `view.rs` | Живой поток ядра для интерфейса (`{"type","data"}`) |
| `coins_view.rs` | Данные экрана «Монеты и направления» (формат GET /api/coins) |
| `vol.rs` | Волатильность σ по замерам цен сигнала в окне profit.sigma_window_min (решение 49) |
| `transit.rs` | Время в пути T: «вручную» / «вручную + авто» (решение 50); история переводов в SQLite |
| `partial.rs` | Частичная покупка (решение 48): больший итог из «довезти и продать» и «продать на A» |
| `convert.rs` | Перевод затрат в USDT: монета — по цене сделки, BNB и промежуточные монеты — по живому стакану биржи |
| `dirctx.rs` | Неизменная часть расчёта направления: сети, USDT, σ, T, k, h, режим возврата, минимумы вывода и депозита |
| `limits.rs` | Бюджет сделки: лимиты money.* с учётом открытых сделок и свободный баланс на A |
| `costs.rs` | Полный расчёт направления на объём: все затраты решения 35 в USDT, прибыль; отказ с видом (решение 66) |
| `costs_quote.rs` | Котировка стороны с видом отказа, шаг количества пары, minNotional/maxNotional (решение 66) |
| `costs_withdraw.rs` | Комиссии вывода A и возврата USDT с B: биржа — из справочника сетей ядра, без REST; DEX — шлюз; точность вывода (решение 66) |
| `dirctx_venue.rs` | Правила пары, сеть из справочника сетей, свежесть справочника сетей (venue.networks_stale_s), минимальный депозит B (решение 66) |
| `worst.rs` | Худшая цена ордера: лимит биржи по стакану, средняя DEX с допуском — для исполнения и расчёта (решение 66) |
| `dust.rs` | Пыль после продажи: остаток меньше шага, minQty или minNotional — сделка закрывается, Deal.dust (решение 66) |
| `costs_types.rs` | Типы расчёта: CostLine, Calc (с итогом подбора объёма size) |
| `profit.rs` | Решение по кандидату: сначала объём с наибольшей прибылью при вложении ≤ бюджета, потом пороги в USDT и % (решение 66) |
| `size.rs` | Типы подбора объёма: Fail (меньше минимума / больше возможного / невозможно), Point, Curve, Params, SizeChoice |
| `size_search.rs` | Поиск оптимума: границы, изломы стаканов, сетка size.grid_points, тернарный поиск у каждого локального максимума |
| `size_bounds.rs` | Границы бисекцией: наибольший объём — точно по бюджету, наименьший — по минимумам площадок |
| `size_memo.rs` | Расчёт по целым шагам stepSize с запоминанием; инвариант «списание ≤ бюджета» в каждой точке; предел size.max_evals |
| `size_curve.rs` | Кривая ядра (costs.rs на каждый объём) и параметры поиска из настроек size.* и стаканов |
| `dry.rs` | Сухой режим (решение 74): dry.enabled, виртуальный бюджет dry.budget_usdt; замок новых действий с деньгами |
| `card.rs` | Карточка сигнала (решение 74): монета и контракт, направление, количество и цены, стакан и пулы маршрута, максимум без бюджета, ссылки |
| `card_book.rs` | Ликвидность стакана в полосе dex.depth_band_pct от лучшей цены (решение 74) |
| `card_links.rs` | Ссылки на пару и пул по шаблонам venue.pair_url_template / dex.pool_url_template (решение 74) |
| `card_max.rs` | Максимальный объём и прибыль без бюджета на кривой ядра до card.max_search_usdt (решение 74) |
| `card_text.rs` | Текст карточки для журнала и Telegram (решение 74) |
| `size_max.rs` | Поиск без бюджета: оптимум и наибольший объём, проходящий пороги прибыли; чем ограничен край (решение 74) |
| `episode.rs` | Эпизоды арбитражной ситуации (решение 74): открытие, интервал записей, закрытие с причиной — без диска |
| `episode_run.rs` | Вход в эпизоды (решение 74): открытие, запись, закрытие и уборка пропавших направлений — только память и сообщения задаче эпизодов |
| `episode_snap.rs` | Запись эпизода: верхние уровни стаканов, пулы маршрута с блоком, пересчёт и карточка (решение 74) |
| `episode_cfg.rs` | Настройки эпизодов, удаление по сроку и месту, закрытие прерванных перезапуском (решение 74) |
| `episode_view.rs` | Данные экрана «Эпизоды» (решение 74) |
| `episode_worker.rs` | Задача эпизодов (решение 74): файл, SQLite, журнал, уборка по таймеру — вне тика и очереди кандидатов |
| `episode_notify.rs` | Telegram эпизодов с защитой от дребезга episode.min_notify_ms (решение 74) |
| `card_job.rs` | Карточка сигнала отдельной задачей класса Quote, одна на направление (решение 74) |
| `candidates.rs` | Отдельная очередь тяжёлого расчёта; итог — в интерфейс, журнал, Telegram; прошедший — карточка, эпизод, исполнитель (не в сухом режиме) |
| `persist.rs` | Учёт ядра в SQLite: таблица core_state (вид, id, JSON; схема — storage/db.rs) |
| `deal.rs` | Сделка: план и факт по шагам, где монеты, вложено, получено, потрачено |
| `risk.rs` | Режим системы (старт/стоп/пауза), пауза площадки, карантин монеты, убыток дня; торговля — только при заданных money.* и risk.* |
| `rules_apply.rs` | Применение правил шлюза к ошибке операции; уведомления ошибок исполнения |
| `precheck.rs` | Предпроверка перед покупкой: стоп-условия, статусы ввода/вывода из API, BNB на газ, пересчёт |
| `trade_ops.rs` | Покупка/продажа через шлюз с худшей ценой; «сколько получим, если продать сейчас» |
| `fills.rs` | Факт исполнения и перевода → учёт сделки (комиссии в монете — в количество, остальное — в затраты) |
| `op_error.rs` | Ошибка операции через шлюз с кодом (OutcomeUnknown — сделка остановлена до ручной проверки) |
| `queue_notify.rs` | Очередь кошелька DEX: живой поток и уведомления на смену состояния |
| `executor.rs` | Сделка: предпроверка → покупка → перевод → продажа; частичная покупка — пересчёт на факт |
| `transfers.rs` | Перевод по BSC: адрес депозита → ожидаемое зачисление (решение 76) → вывод → хеш → зачисление |
| `transfer_credit.rs` | Шаг зачисления: событие баланса или опрос deposit_status, кто первый (решение 76); время в пути — от момента события |
| `credit_expect.rs` | Ожидаемый приход перевода: сумма минус затраты вывода в монете (как приход в costs.rs) |
| `credit_watch.rs` | Ожидаемые зачисления (Ticket): регистрация, событие, подошедшее к ожиданию |
| `credit_event.rs` | Сверка события MarketEvent::Balance: зачисление, свой вывод или «внешнее изменение баланса» (журнал, balance.external) |
| `credit_match.rs` | Выбор ожидания по сумме с допуском: одно / несколько (неоднозначно) / ни одного |
| `credit_mismatch.rs` | Расхождение события и статуса дольше transfer.credit_mismatch_s — журнал и exec.credit_mismatch |
| `transfer_watch.rs` | Медленный перевод — уведомление и карантин; время в пути — в историю |
| `sell.rs` | Продажа, если итог не ниже нуля (решение 47), иначе застрявшая монета; продажа по рынку |
| `stuck.rs` | Застрявшая монета (решение 37): «Ожидание», «Порог убытка» |
| `relay.rs` | Застрявшая монета: «Перегон» на площадку, где выгоднее с учётом затрат |
| `manual.rs` | Алерт «убыток выше порога», «Продать сейчас», «Беру на себя» |
| `manual_return.rs` | «Вернуть боту» по реальному балансу; данные экрана «Ручное управление» |
| `commands.rs` | Команды человека (интерфейс, Telegram — только из настроенного чата) и управление системой |
| `usdt_return.rs` | Возврат USDT (решение 34): в каждой сделке или отдельно по порогу |
| `ledger.rs` | Учёт сделок: хранение, итог, план против факта, итог дня, пауза направления; перезапуск |
| `gas_stats.rs` | Статистика газа по монете (решение 36) |
| `reconcile.rs` | Сверка балансов, мало BNB/USDT, возврат USDT «отдельно»; расхождение — пауза новых сделок |
| `ids.rs` | UUID v4 для id алертов и монет человека (влезает в callback_data Telegram) |
| `daily.rs` | Итог дня (решение 53): факт закрытых сделок, предварительный убыток остановленных и «Беру на себя», коррекция при разборе; SQLite daily_result |
| `day_view.rs` | Итог дня для экрана «Управление» |
| `low_usdt.rs` | Алерт «мало USDT» по площадке (решение 54): один раз на пересечение порога, состояние в учёте ядра |
| `first_pass.rs` | Первый проход проверки налогов: посмонетные уведомления чёрного списка копятся, в конце — одно сводное coin.check_done |
| `touched.rs` | Тип Touched — что изменилось в рыночном состоянии после события адаптера |
