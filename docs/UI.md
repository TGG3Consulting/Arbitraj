# UI — экраны интерфейса

> Каждая фича обязана появиться здесь и в интерфейсе. Экран — один файл в `ui/src/pages/`.

| Экран | Что показывает | Чем управляет | Откуда данные |
| --- | --- | --- | --- |
| Площадки | Подключённые площадки, статус соединений, задержки, разрывы; у DEX — виды пулов и адреса их контрактов | Включить или выключить площадку, DEX и вид пула (dex.enabled, dex.pool_enabled); режим обмена | api/venues.rs, api/check.rs ← gateway; статусы — api/stream.rs (позже) |
| Монеты и направления | Справочник, причина исключения монеты; налоги (покупка, продажа, перевод) и состояние проверки; пулы монеты с видом, крючком и группой A/B/C; чёрный список с причиной | Исключить или вернуть монету (ручной чёрный список coin.blocked), «Перепроверить», снять карантин | core/registry.rs, core/blacklist.rs; маршруты — src/api/README.md |
| Ручное управление | Алерты застрявших монет, монеты «Беру на себя» с причиной | «Продать сейчас», «Беру на себя», «Вернуть боту» | core/stuck.rs, core/manual.rs |
| Каналы отправки | Каналы DEX: состояние, отправлено, в блоке, откатов, газ впустую | Вкл/выкл, адрес, способ одиночная/бандл, минимальная цена газа, чаевые; ключ; «Проверить подключение» | адаптер DEX через шлюз (send_channels), core |
| Статистика газа | По монете: попытки, успехи, отмены, газ впустую и всего, итог | — | core/gas_stats.rs |
| Живой экран | Текущие спреды по направлениям, кандидаты, причины отказа | Фильтры отображения | core/signal.rs, core/candidates.rs |
| Разблокировка | Заблокированы ли секреты | Ввод пароля, добавление и замена секретов (docs/SECURITY.md) | settings/, хранилище секретов |
| Сделки | Идущие сделки по шагам (покупка, перевод, продажа), история, план против факта | Остановка сделки | core/executor.rs, core/ledger.rs |
| Балансы | BingX, кошелёк, монеты в пути, BNB на газ | — | core/ledger.rs |
| Настройки | Все параметры из settings/schema.rs, с описанием и допустимым диапазоном | Изменение на лету | settings/ |
| Правила шлюза | Общие правила и правила площадок | Создать, изменить, выключить правило | gateway/rules.rs |
| Управление | Состояние системы (плашка режима на всех экранах) | Старт, стоп, пауза системы; снятие паузы площадки и карантина монеты | core/risk.rs, core/commands.rs |
| Журнал | Ошибки, уведомления, история изменений настроек (кто, что, когда) | Фильтры | storage/, settings/ |
| Уведомления | Какие события уходят в Telegram | Вкл/выкл каждого события, площадки и условие события; токен бота и ID чата; кнопка «Проверить подключение» | notify/, settings/ |

Правила:
- Изменение в интерфейсе применяется сразу, без перезапуска, и пишется в журнал.
- Везде, где вводится ключ, токен или адрес подключения (биржа, кошелёк, узел BSC, Telegram), есть кнопка «Проверить подключение». Ответ — «Подключено» или точная причина сбоя: единый код ошибки + исходный текст ответа сервиса.

## Что сделано сейчас (ui/, Svelte 5 + Vite)

Запуск и откуда данные — `ui/README.md`. Экран — файл в `ui/src/pages/`, общие элементы — `ui/src/components/`.
На всех экранах: плашка «Система заблокирована», пока секреты не разблокированы; плашка «Нет живой связи», пока нет WebSocket.
Изменения из других вкладок видны сразу (`/api/ws`). Ошибки бэкенда показываются как есть. Значений по умолчанию нет.

| Экран | Что есть сейчас |
| --- | --- |
| Разблокировка | Создание файла (пароль + подтверждение), разблокировка, блокировка, известные секреты: введён ли, ввод значения с паролем, удаление; смена пароля. Переход к секрету по ссылке `#/unlock/<имя>` |
| Площадки | Площадки из реестра шлюза (`GET /api/venues`); по каждой: «Проверить подключение», её ключи (секреты с её scope), все её настройки области «площадка» по группам. Статусов соединений, задержек и разрывов пока нет — бэкенд их ещё не отдаёт; включение площадки — настройка `venue.enabled` |
| Настройки | Все настройки по группам: описание, единица, вид, ограничение, области; значения: вся система, каждая площадка, монеты (ввод тикера), события (выбор кода); «Очистить»; история; поиск и «только незаданные» |
| Правила шлюза | Список, создание, изменение, выключение/включение; списки — `GET /api/rules/meta`; условие хранится, но помечено «не применяется до этапа 5» |
| Уведомления | Адрес Bot API, ID чата, таймаут HTTP, токен (переход на «Разблокировку»), «Проверить подключение»; по каждому событию: вкл/выкл, площадки, условие (с этапа 5) |
| Журнал | Листание страницами (размер задаёт зритель), фильтры по уровню, виду, площадке (по загруженным записям), живые записи |
| Монеты | Справочник из ядра (`GET /api/coins`): площадки, налоги, пулы с крючками, причина исключения пула и номер блока; «Перепроверить» по монете с адресом контракта |
| Ручное управление, Статистика газа, Каналы отправки | Данные ядра (`/api/manual`, `/api/gas-stats`, статистика каналов из событий адаптера); команды «Продать сейчас», «Беру на себя», «Вернуть боту» выполняет ядро |
| Живой экран | Спреды всех направлений на каждый тик (цены A и B, спред, порог комиссий, состояние фильтра шума с причиной), кандидаты: прошёл или отказ с причиной, полный список затрат; фильтр по монете и «только выше порога» |
| Сделки | Идущие и закрытые сделки: шаг, где монеты, вложено, выручка, затраты, итог против плана; хронология и план |
| Плашка режима (на всех экранах) | Режим системы «Стоп» / «В работе» / «Пауза» и причина (после запуска — «Стоп» до «Старт», решение 46); кнопки «Старт», «Пауза», «Стоп»; паузы площадок и карантины монет с кнопкой снятия; итог дня |
| Промежуточные монеты (решение 52) | «Настройки»: dex.intermediate_enabled и список адресов dex.intermediate_tokens; «Монеты»: пара каждого пула, «маршрут через …», причины отсева по площадкам; «Живой экран»: затраты кандидата по шагам маршрута |
