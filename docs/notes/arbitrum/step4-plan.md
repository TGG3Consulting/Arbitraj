## 1. Как сейчас работают «Старт / Пауза / Стоп» (факт кода)

- Режим системы — `core/risk.rs:40-48` `Mode {Stopped, Running, Paused}`, состояние `Risk.mode` (`:50-103`), после
  запуска — `Stopped` (`:105-127`, «ждёт команды «Старт»»). В базу не пишется: перезапуск — снова «Стоп».
- Вход в сделку — только через `risk::can_open` (`:138-191`): `r.mode != Running` → отказ «торговля в режиме «Стоп»
  — причина» (`:150-162`). Вызывают: `core/precheck.rs:352` (биржа ↔ DEX, биржа ↔ биржа), `core/cycle_watch.rs:114`
  (DEX ↔ DEX), `core/executor.rs:494` (докупка). Больше режим нигде не проверяется: идущие сделки (перевод, продажа,
  возврат USDT, перегон, ручные действия) режим не смотрят — «Стоп» = «новые не начинаются, идущие доводятся».
- Команда человека: интерфейс `POST /api/control {mode}` (`api/core_api.rs:69`) и Telegram (`core/commands_control.rs:20`)
  → `Core::set_mode_by` (`core/commands.rs:208-221`: `risk::set_mode`, журнал core.control, уведомление
  system.started / system.stopped). Софт («стоп всё» правила шлюза `core/rules_stop.rs:147`, общий лимит дня
  `core/daily_limit.rs:95-106`, остановка процесса `core/shutdown.rs`) ставит `Stopped` тем же `risk::set_mode` или
  прямо полем; автоснятие софтового «Стоп» (`core/auto_pause.rs:196-205`, `day_roll.rs:55`) возвращает прежний режим.
- Интерфейс: плашка `ui/src/components/ControlBar.svelte:73-77` (Старт / Пауза / Стоп), `ui/src/lib/control.svelte.js:50`.

## 2. Запуск по сети (часть 4.1)

Модель: общий режим `Risk.mode` остаётся как есть (все софтовые «Стоп», «Пауза», лимиты — прежние). Добавляется
`Risk.chain_off: BTreeMap<id сети, причина>` — сети, остановленные человеком. Сделка направления сети X начинается,
только если `mode == Running` и X нет в `chain_off`. Вычисляет и проверяет новый файл `core/chain_run.rs`:
- `chains(core)` — сети площадок DEX (dex.chain, без повторов, по порядку реестра). **Сетей меньше двух — `[]`**: кнопок
  по сети нет, `chain_off` всегда пуст, `can_open` не читает ни одной настройки сверх прежнего — BSC как раньше.
- «Старт сети X»: режим не «В работе» → режим «В работе», остальные сети — в `chain_off` («не запускалась»); режим
  «В работе» → X убирается из `chain_off`. «Стоп сети X»: X в `chain_off`; запущенных сетей не осталось → общий «Стоп»
  (тот же `risk::set_mode`). Общий «Старт» человека (кнопка «Старт» = обе сети, Telegram /start) — `chain_off` пуст.
  Общий «Стоп»/«Пауза» и все софтовые остановки — `chain_off` не трогают (автоснятие вернёт прежний набор сетей).
- `can_open` (`core/risk.rs:150-162`): после проверки режима — сеть направления (`chain::of_dir`) в `chain_off` →
  отказ «сеть X остановлена: причина». Сеть направления считается до замка риска и только при двух сетях и непустом
  `chain_off`; не прочитать сеть при остановленной сети — отказ с причиной (не торгуем вслепую).
- Ядро: `Core::set_chain_by(chain, run, who)` (`core/commands.rs` рядом с `set_mode_by`) — журнал core.control,
  уведомление system.started / system.stopped с сетью. API: `POST /api/control/chain/{id} {run}` → Risk
  (`api/core_api.rs`, `api/server.rs`). Сетей меньше двух — 400 «одна сеть — кнопки «Старт»/«Стоп»».
- Экран: `Risk.chains` — `[{id, running, why}]` (пусто при одной сети). Плашка: при двух сетях — строка «Сети:» с
  кнопками «Старт <сеть>» / «Стоп <сеть>» по каждой; общий «Старт» подписан «Старт (все сети)». Одна сеть — плашка
  байт в байт прежняя.
- Telegram: общие /start /stop прежние; кнопки по сети в Telegram — не в этом шаге (вопрос Тиграну, TASKS).

## 3. Кошельки по сети (часть 4.2)

Кошелёк один (тот же ключ = тот же адрес в обеих сетях). По сети разное: баланс газа и USDT, исполнитель (развёртывается
в каждой сети отдельно — свой адрес, версия, обёртка), очередь nonce. Одна площадка DEX на сеть (решение 430,
`chain::dex_of`), поэтому «сеть кошелька» = площадка DEX этой сети.

- **Баланс** — уже по (площадка DEX, кошелёк): `core/balances_cache.rs:146` `wallet_balances_on`. Меняется только
  показ: API `GET /api/wallets/{id}/balances?venue=` (`api/wallets_dex.rs:69-107`, сейчас — DEX сети по умолчанию
  `:41-54`), экран — по сети; слепок `report/snap_dex.rs:69` — кошелёк на каждой площадке DEX.
- **Исполнитель** — сейчас одно поле у кошелька (`settings/accounts/mod.rs:37-56`, таблица `dex_wallets`
  `storage/db.rs:107-114`, `:146-153`). Делается: «домашняя» площадка кошелька — та, где он заведён (начало
  `queue_key`: «bsc_dex» / «bsc_dex:w2» — `api/wallets.rs:76`, `main.rs:300`); её исполнитель — прежние столбцы
  `dex_wallets.executor*` (**у BSC ничего не меняется и не переносится**). Исполнитель на другой площадке DEX — новая
  таблица `dex_wallet_exec (wallet, venue, executor, executor_version, executor_wrapped, updated_at)`, поле
  `Wallet.chains` (в JSON — только если не пусто). `Wallet::at(venue)` — запись кошелька глазами площадки: домашняя —
  как есть; другая — исполнитель этой площадки (нет — None), `queue_key` — «<площадка>:<id>».
  Запись: `Accounts::set_executor_at` / `set_executor_version_at` (домашняя — прежние `set_executor`
  `edit.rs:96-142` / `set_executor_version` `edit_version.rs:28-79`; другая — строка новой таблицы + история).
- **Адаптер DEX** (только чтение «своей» записи): `venues/bsc_dex/ctx_wallet.rs:46-62` `wallet()` → `at(своя
  площадка)`; `:76-89` `executor()`, `:94-101` `exec_info()`, `pools/exec_callback.rs:87` — `with_wallet_at` (домашняя
  площадка — без копии, как решение 401); `exec/executor/onchain.rs:82-90` — `set_executor_version_at`;
  `exec/executor/pass_view.rs:36-41`, `check/pass_cycle.rs:118,163` — кошельки глазами площадки. Площадка адаптера —
  `ctx.venue()` (сейчас одна, bsc_dex — всё прежнее).
- **Nonce** — в памяти очередь своя у каждого экземпляра адаптера (`wallet/nonce.rs`, по площадке). В SQLite
  (`wallet/queue_store.rs:22,37`) ключ — `queue_key` записи; через `at()` у другой площадки — «<площадка>:<id>»,
  у домашней — прежний. Экран очереди уже по площадке (`api/wallet_queue.rs`, `/api/wallet-queue/{venue}`).
- **Развёртывание**: `core/executor_deploy.rs:92-120` (сверка «исполнитель не сменился» — `at(venue)`), `:160-163`
  (запись — `set_executor_at(venue, …)`); `api/wallets_dex.rs:142-190` `PUT /api/wallets/{id}/executor?venue=`.
- **Экран «Маппинг кошельков»** (`api/wallets_view.rs:37-117`): у кошелька — `chains: [{venue, chain, executor,
  executor_version, executor_wrapped, native_wrapped}]` по каждой площадке DEX; при одной DEX — пусто, прежние поля.
