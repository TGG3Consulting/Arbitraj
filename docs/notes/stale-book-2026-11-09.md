## Факты кода (до правки)

1. **Котировка исполнения** (core/trade_ops.rs sell_value → адаптер quote → venues/mexc/book.rs freeze): свежесть —
   время последнего КАДРА пары `seen`, которое обновляется и на кадре с тем же снимком (ws_conn.rs: `books.touch` —
   решение 109, снимок ядру не отдаётся), или действующее подтверждение тихой пары (решение 213, `until`).
2. **Худшая цена ордера** (core/worst.rs worst_order): свежесть — `received_at` стакана ЯДРА (последний изменённый
   снимок) или `quiet_until` ядра (то же подтверждение 213 — feed_watch_act.rs `set_quiet`).
3. Значит, меры расходятся ровно на кадрах с тем же снимком (touch): адаптер — «свежий», ядро — «устарел». Подтверждение
   213 обе стороны видят одинаково. Отказ worst_order — код StaleData (retry_safe) → sell_unsent повторяет через режим
   застрявшей монеты с паузой 0 → снова та же котировка и тот же отказ. Журнал core.feed_watch по паре XTER я не читал
   (только /api/deals) — что именно держало адаптерную свежесть (кадры с тем же снимком или подтверждение), по данным
   сделки не установить; по коду расхождение возможно только при кадрах с тем же снимком.
4. venue.book_stale_ms необязательна у BingX, Bitget, KuCoin, OKX, CoinEx, HTX, Kraken, Phemex, Poloniex — без неё
   возраст кадра пары не проверялся ни на входе, ни у ордера (worst.rs: «Не задана … — без проверки»).
5. Снимок REST для котировки исполнения был только у Bitget (решение 201, rest_book.rs), причём до ядра он шёл
   асинхронно (событие рынка) — ордер мог посчитать худшую цену по старому стакану ядра (комментарий в bitget/mod.rs).

## Что сделано (решение 237)

- **Вход:** venue.book_stale_ms обязательна у всех 14 бирж; freeze каждой биржи отказывает, если кадр пары старше и нет
  действующего подтверждения тихой пары (у HTX, Kraken, Phemex, Poloniex подтверждения 213 нет — тихая пара старше не
  котируется). Не задана — NotConfigured (котировок нет), как уже было у MEXC, Binance, Bybit, Gate, XT.
- **Одна мера и один стакан на котировке и ордере:** core/exec_book.rs — снимок REST пути ордера (не старше
  venue.book_stale_ms) → стакан адаптера (quote_snapshot, мера котировки) → снимок REST (контракт quote_rest). Котировка
  исполнения биржи (sell_value) и худшая цена ордера (worst_order) — оба через него; снимок REST хранится в ядре, второй
  запрос не идёт. Стакан ядра для ордера больше не используется.
- **REST не ответил:** один повтор через exec.rest_book_retry_ms, затем ошибка с причиной без кода — продажа уходит в
  алерт человеку (sell_unsent Retry::No), а не в повторы по тому же стакану.
- REST каждой биржи — официальный публичный запрос стакана (ссылки и лимиты — в шапках файлов адаптеров).
