# Запас на движение цены k·σ·√T: как считается, завышен ли, как оценивать правильно (t161, 16.11.2026)

База — релизный коммит `8fe83aa1` (ветка `t161/price-risk`). Код — файл:строка этой базы. Данные — 18 отказов живого
бота 14–16.11 (`core.candidate_rejected`, поле data = Calc расчёта; разбор отказов —
`cand-rejects-analysis-2026-11-16.md`), разбор 983 сделок `docs/notes/price-move-vs-reserve-2026-11-09.md` и записи
`tests/data`. Где факта нет — написано «нет данных» или «гипотеза».

## А. Как считается сейчас (факт кода)

### Формула и единицы

- Запас в котируемой монете A: `r = k · σ · √T · выручка` — `core/reserve.rs:105`; с `profit.closure_share` —
  `max(r, доля · спред · выручка)` при спреде > 0 — `reserve.rs:107-114`. Вызов — `core/costs.rs:177-190`
  (`√T` — `costs.rs:178-181`, выручка `proceeds = sell_qty · sell_avg` — `costs.rs:161`). Строка
  `PriceMoveReserve` переводится в USDT и вычитается из прибыли (`costs.rs:192-199`, `:210-239`).
- σ — доля за секунду (лог-доходность), T — секунды, k — число. `k·σ·√T` — доля выручки.
- Линейная форма `k·σ·√T` вместо `1 − e^(−k·σ·√T)` даёт запас не меньше точного (1 − e^(−x) < x) — осторожная сторона.

### σ: какой ряд

- Замер — на каждом пересчёте монеты, только если цены направления получены: `core/evaluate.rs:79-88`.
  Пишутся два ряда: покупка на A (`p.buy`) и продажа на B (`p.sell`), ключ — (площадка, монета, сторона,
  площадка-напарник) — `core/vol.rs:36-38`, решение 118.
- Цена ряда — **средняя цена котировки на объём сравнения сигнала**, а не лучший бид, не середина и не последняя
  сделка: `core/prices.rs:167-168` (`avg_price` котировок). Объём сравнения — `prices.rs:136-157`:
  `want = money.max_per_trade_usd / опорная цена` или объём проверки `signal.probe_usd` (`signal_probe.rs:64`), затем
  `qty = min(fillable покупки, fillable продажи)` (`prices.rs:149`). Опорная цена — лучший аск монеты на любой бирже
  (шапка `prices.rs:7`). Значит, объём ряда меняется от пересчёта к пересчёту (опорная цена, глубина другой стороны).
- Сторона биржи (все 14 бирж: binance, bingx, bitget, bybit, coinex, gate, htx, kraken, kucoin, mexc, okx, phemex,
  poloniex, xt): котировка — проход по уровням стакана, `gateway/frozen.rs:164-177` (`walk`, общий для всех
  адаптеров: `venues/*/book.rs`). Для продажи — по бидам. То есть цена ряда продажи на бирже = VWAP бидов на объём
  сравнения.
- Сторона DEX (`bsc_dex`): средняя цена котировки пула/маршрута на объём сравнения (комиссия пула в цене); на тике
  может браться из памяти (`signal.dex_quote_cache_ms`, `prices.rs:62`) — тогда замер повторяет прошлую цену.
- В расчёт запаса идёт **только ряд продажи на B** с напарником A: `reserve.rs:76` (`Side::Sell`, `d.sell_on`,
  напарник `d.buy_on`); ряд покупки на A в запас не входит. Это верная сторона: покупка на A исполнена сейчас, под
  риском — только цена продажи на B через T.
- Но ряд — цена **на объёме сигнала**, а продаём **объём расчёта** (у JCT/ZIG — 1 USDT). Ряд σ измеряет движение VWAP
  другого объёма. Это факт кода, величину расхождения по записи не установить.

### σ: формула оценки

- `σ² = Σ (ln pᵢ/pᵢ₋₁)² / Σ Δtᵢ` по шагам в окне `profit.sigma_window_min` — `vol.rs:128-142`; шаг пишется на каждом
  замере с ценой (`vol.rs:72-79`), квадрат лог-доходности и Δt в секундах (миллисекунды / 1000).
- Одинаковые цены: шаг с r = 0 и своим Δt входит (σ уменьшается) — это правильно для ряда без шума.
- Пропуски (цены нет, стакан устарел): замера нет; следующий шаг несёт всё изменение и всё Δt с прошлого замера —
  Σr²/ΣΔt остаётся согласованной.
- Шаг цены площадки в оценке **не участвует** (нигде не читается; у ядра в `SpotPairState` шага цены нет —
  `gateway/events.rs:94-120`; у MEXC шаг цены = 10^−quotePrecision знает только адаптер, `venues/mexc/symbols.rs:19`).
- Выбросы: никак не ограничиваются (одиночный скачок входит целиком).
- Нехватка данных: шагов в окне нет — «волатильность … ещё не измерена», расчёта нет (`vol.rs:113-137`);
  `profit.sigma_min_changes` — меньше N ненулевых изменений → то же (`reserve.rs:77-85`); `profit.sigma_floor_per_s [B]`
  — σ = max(σ ряда, граница) (`reserve.rs:86-89`). Окно не задано — ряд не копится, σ нет (`vol.rs:80`).
- Моменты (`dirctx.rs:161-176`): план входа — σ с проверкой и границей; сделка уже идёт (частичная покупка) — σ ряда
  без границы; момент решения — σ из плана (решение 237).

### T и k

- T — `core/transit.rs:108-149`: режим `profit.transit_mode [A]`; `manual` = `profit.transit_manual_s [A]` +
  `profit.transit_credit_s [B]`; `manual_auto` — среднее последних `profit.transit_auto_after [A]` **фактических
  переводов этой монеты в этом направлении** (`transit.rs:130-141`, история — `transit.rs:66-101`), иначе manual.
  Подтверждения сети и время депозита биржи из API в T не входят (кроме того, что попало в факт перевода).
- k — `profit.price_move_k`: монета → площадка + тип направления → вся система (`dirctx.rs:186-191`,
  `settings/venue_dir.rs:155`). Площадка типа — правило стороны `core/venue_dir.rs:32-49`: биржа → DEX — биржа
  покупки; **DEX → биржа — биржа продажи**; биржа → биржа — биржа покупки; DEX ↔ DEX — свой набор.
  По 18 записям k = 4,5 (binance → DEX, DEX → mexc, DEX → bitget), 2,0 (mexc → DEX), 2,5 (bingx → DEX) — выведено
  из `PriceMoveReserve / (σ·√T·выручка)` с точностью 1e-4.
- Пересчёт «без потолка» по окну: σ и T из плана, k по монете/паре — `uncapped_recompute_ctx.rs:128`.

движения; σ плана в 2,1 раза (медиана) ниже реализованной. Общее снижение σ у DEX → биржа на этих данных увеличило бы
убытки.

### (1) Дрожание на шаг цены / отскок — **опровергнуто числами для JCT и ZIG; для PARTI нет данных**

Доказательство. Если цена ряда меняется только на ±1 шаг s, каждый ненулевой шаг даёт r² ≤ (s/p)², и при частоте
ненулевых изменений λ в секунду `σ² ≤ λ·(s/p)²`. Значит, чтобы получить σ записи, нужно `λ ≥ σ²/(s/p)²`.

Шаг цены. Продажа JCT на объёме расчёта — ровно 0,002402 (VWAP 416,32 JCT = одна цена ⇒ весь объём на одном уровне ⇒
это цена уровня). Шаг MEXC — 10^−quotePrecision (`venues/mexc/symbols.rs:19`); 0,002402 кратна шагу ⇒ шаг ≤ 1e-6.
Так же ZIG 0,034334 ⇒ шаг ≤ 1e-6; PARTI на Bitget 0,03621 ⇒ шаг ≤ 1e-5 (точного шага из API в записи нет).

| | один шаг, % цены | нужно ненулевых изменений в секунду (весь час окна) |
|---|---|---|
| JCT | ≤ 0,0416 % | ≥ **12,1** |
| ZIG | ≤ 0,0029 % | ≥ **884** |
| PARTI | ≤ 0,0276 % | ≥ 0,77 |

Замер σ — один на пересчёт монеты; пересчёт не чаще `signal.eval_min_interval_ms` = 500 мс на живом боте
(`docs/notes/mexc-cpu-starve-2026-11-03.md:17`, FIRST_RUN 322) — до 2 замеров/с (плюс пересчёты по событию пула и
таймеру, если включены). 12,1/с и 884/с недостижимы ⇒ σ JCT и ZIG **не объясняется** дрожанием на один шаг. При 2
замерах/с нужен средний (RMS) шаг 0,103 % у JCT (≈ 2,5 шага цены на каждом замере весь час) и 0,061 % у ZIG
(≈ 21 шаг). Что это — многошаговое мерцание бидов, смена объёма сравнения, скачки или настоящее движение — по записи
**нет данных** (ряда в записи нет).

### (2) Масштабирование √(T/Δ) при автокорреляции — **механизм доказан, величина для JCT/ZIG — нет данных**

Модель: наблюдаемая лог-цена Y = X + ε, X — «настоящая» цена (мартингал), ε — шум (стационарный, независимый от X,
дисперсия ω²). За окно длины W с n замерами:
`E[Σ(ΔY)²] = σ²·W + Σ E[(Δε)²] ≈ σ²·W + 2n·ω²·(1 − ρ_ε)`, а оценка кода — `σ̂² = Σ(ΔY)²/W`. Запас берёт
`σ̂²·T = σ²T + 2ω²(1 − ρ_ε)·(n·T/W)`. Нам же нужен риск цены продажи через T:
`Var(Y_{t+T} − Y_t) = σ²T + 2(γ_ε(0) − γ_ε(T)) ≈ σ²T + 2ω²`. Шумовая часть в коде умножена на `n·T/W` — число замеров
за время T (при 2 замерах/с и T = 34 с — до ≈ 69 раз). Отрицательная автокорреляция замеров (отскок) — ровно этот
случай; ρ₁ = −ω²/(σ²Δ + 2ω²) < 0. Обратно: при положительной автокорреляции (тренд, закрытие разницы) код
**занижает** риск — это и есть 09.11 «σ плана ниже реализованной в 2–7 раз».
Иллюстрация на записи (`tests/data/cex_samples_2026_11_04/gate_ws.jsonl`, Gate CAKE_USDT, 56 кадров за 18,4 с — это
не доказательство, ряд слишком короткий для T ≈ 35 с): лучший бид σ = 0,0035 %/с, ρ₁ = 0; VWAP бидов на 500 CAKE —
0,0159 %/с (в 4,5 раза больше, 31 ненулевое изменение против 5); отношение дисперсий горизонта 1–4 с к мелкому шагу
(VR) — 0,58–2,0 при 4–18 блоках, то есть разброс оценки больше эффекта.

### (3) Неравномерная выборка по событиям — **опровергнуто как отдельная причина**

Для мартингала X приращения на любых непересекающихся отрезках некоррелированы, и `E[Σ(ΔX)²] = σ²·ΣΔt` при любых
моментах замеров (моменты могут зависеть от прошлого — теорема об остановке). Код делит на ΣΔt тех же шагов
(`vol.rs:129-139`) — смещения нет. Неравномерность действует только через шум (п. 2): чем чаще замеры, тем больше
вклад 2n·ω².

### (4) Выбросы и одиночные скачки — **нет данных**

Скачок входит целиком. Σr² за час у JCT = 0,00758 — это один скачок ~8,7 % за час (ZIG ~5,2 %, PARTI ~1,45 %).
Были ли такие скачки, по записи не видно. Важно: робастная оценка (MAD, bipower) выбросила бы скачки, а скачок к
закрытию разницы — главный реальный риск (09.11: хвосты 8 : 1 вниз, 10 худших сделок = 59 % убытка). Поэтому
робастные оценки здесь **занижают** риск и не годятся.

### (5) Двойной счёт — **опровергнуто (факт кода и записи)**

- `profit.liquidity_share_h` — только проверка исполнимости `sell_qty / h` (`costs.rs:127-142`), в деньгах не
  вычитается.
- Худшая цена (`core/worst.rs`, `costs_quote.rs:119`) — предел ордера и бюджет списания (`spend_max`), в прибыль не
  входит; допуск `exec.dex_slippage_pct` — то же.
- Проскальзывание — в средней цене текущего стакана/пула (статика «сейчас»), запас — движение через T.
- `closure_share` — `max`, не сумма (`reserve.rs:114`). Ряд покупки на A в запас не входит.
- По 18 записям тождество `qty·(sell_avg − buy_avg) − (qty − sell_qty)·sell_avg − costs_usdt = profit` сходится до 1e-28.

### (6) Симметрия — **опровергнуто: берётся односторонний квантиль, не размах**

`k·σ·√T` вычитается один раз как потеря при падении цены продажи. При нормальной модели это односторонний квантиль:
вероятность, что падение больше запаса, — Φ(−k): k = 2 → 2,3 %; 2,5 → 0,62 %; 4,5 → 3,4·10⁻⁶. Без допущения о
распределении (неравенство Кантелли, среднее ≤ 0): ≤ 1/(1 + k²) → 20 %; 13,8 %; 4,7 %. Квантиль вычитается как затрата
(не матожидание, которое у мартингала 0) — это осознанная осторожность владельца, k не трогаем.

### (7) Другие причины, найденные по коду

- **Объём ряда ≠ объём сделки** (факт кода, `prices.rs:136-168`): σ меряется по VWAP объёма сигнала, а продаётся
  объём расчёта. У крупного объёма VWAP задевает больше уровней и меняется чаще (Gate CAKE: ×4,5 к лучшему биду на
  18 с). Величина для JCT/ZIG — нет данных (значения `signal.probe_usd` в записи нет).
- **Объём ряда плавает между замерами** (факт кода: опорная цена и fillable другой стороны, `prices.rs:136-157`):
  изменение VWAP от смены объёма — не движение рынка, но в Σr² входит. Величина — нет данных.

## В. Правильная оценка (проект)

Цель — величина, которую реально несёт сделка: `D_T = Var(ln P_прод(t+T) − ln P_прод(t))`, P_прод — цена, по которой
продадим объём расчёта.

**Выбор: дисперсия приращений ряда на горизонте T (реализованная волатильность на разрежённой сетке с шагом Δ = T).**
`σ_T² = (1/(m·T)) · Σ_{j=1..m} (L(now − (j−1)T) − L(now − jT))²`, L(t) — лог-цена последнего замера не позже t
(предыдущая цена), m = ⌊покрытое окном время / T⌋ полных блоков, без вычитания среднего.

Почему она, а не другие:
- середина вместо бида — продаём по бидам; середина добавляет шум аска (Gate CAKE: σ середины 0,0063 против 0,0035
  у бида) — не то;
- TSRV / Roll-поправка оценивают σ² «чистой» цены без шума, а наша цена продажи шум содержит (`+2ω²` в D_T) — они
  занизили бы риск на 2ω²; Roll к тому же верна только для отскока на один шаг (MA(1)). ρ₁ пишем как диагностику;
- Parkinson / Garman–Klass требуют свечей OHLC, которых у ряда нет, и смещены дискретностью цены;
- MAD / bipower выбрасывают скачки — главный риск (п. 4) — занижение;
- σ_T не требует ни одной новой настройки: шаг сетки = T направления.

**Доказательство «не занижает».**
1. Несмещённость: при стационарных приращениях `E[σ_T²·T] = D_T` — оценка измеряет ровно риск сделки (вместе с шумом,
   который продажа тоже несёт, и со сносом — среднее не вычитается).
2. Нижняя граница: `D_T = σ²T + 2(γ_ε(0) − γ_ε(T)) ≥ σ²T`, так как |γ_ε(T)| ≤ γ_ε(0). Оценка в среднем не ниже
   дисперсии «настоящей» цены — снижение идёт только за счёт лишней шумовой части 2ω²·(n·T/W − 1).
3. Тренд и закрытие разницы (положительная автокорреляция): `σ_T² > σ̂²` кода — оценка **поднимает** запас там, где
   код его занижал (09.11).
4. Случайная ошибка: ≈ √(2/m) по дисперсии (нормальный случай): окно 60 мин, T = 35 с → m ≈ 100 → ±14 % по σ², ±7 % по
   σ. Защита при малом m — правило «m меньше порога (настройка-число) → σ плана = max(σ_T, σ̂ кода)», плюс
   действующие `profit.sigma_floor_per_s`, `profit.sigma_min_changes`, `profit.closure_share` (все через max).
5. Чего доказательство не даёт: стационарности окна (новости, листинг). Это то же допущение, что у кода сейчас.

**Риск при продаже по стакану.** Правильная цена ряда — VWAP бидов на объёме расчёта, а не лучший бид и не объём
сигнала. Объём расчёта до расчёта неизвестен, поэтому проект: второй ряд продажи — лучший бид (объём расчёта у отказов
— минимумы, 1 USDT), σ продажи = σ_T того ряда, чей объём ближе к объёму расчёта; для объёмов между — большее из двух
(не занижает). Это требует второго ряда в `vol.rs` — после данных.

**k.** Не меняется (настройка владельца). При σ_T смысл k становится точным: k = число стандартных отклонений
движения цены продажи **за T** (а не «мелкой σ, растянутой на T»), уровень доверия — Φ(−k) при нормальном движении,
≤ 1/(1 + k²) без допущений.
