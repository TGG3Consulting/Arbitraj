# venues/bsc_dex/send — каналы отправки транзакций (решения 33, 41–45)

Каждый канал — свой файл по своей официальной документации (ссылки — в шапке). Общий вид — `channel.rs`.
Канал с ключом без ключа не используется. Открытый канал — только один и не вместе с закрытыми; несколько
закрытых — одна и та же транзакция параллельно, без чаевых. Чаевые — только при одном канале и бандле.
Попадание в блок — только своим узлом (`track.rs`).

| Файл | Что делает |
| --- | --- |
| `mod.rs` | Выбор готовых каналов и правила, нижняя граница цены газа (и для котировки), параллельная отправка (принявшие и «без ясного ответа»), ожидаемые чаевые |
| `channel.rs` | Вид канала: одиночная/бандл и их форматы, закрытый ли, чаевые, ключ (адрес или заголовок) |
| `channels.rs` | Список каналов адаптера (id — ARCHITECTURE.md) |

| `check.rs` | «Проверить подключение» канала: пустая транзакция — канал должен ответить ошибкой JSON-RPC |

## BlockRazor RPC: противоречие документации бандла

Страница https://docs.blockrazor.io/transaction-submission/rpc/bsc/eth_sendbundle.md в заголовке называет метод
`eth_sendBundle`, а в примере запроса — `eth_sendMevBundle`; поле списка транзакций — то `txs`, то `Txs`.
Решение техлида (Issue #7): бандл через BlockRazor RPC не подключать, канал работает только одиночной отправкой
(`eth_sendRawTransaction`); верное имя метода и поля проверим на реальных ответах API.

## Счётчик «в блоке»

`sent` и `rejected` считаются по каждому каналу. «В блоке» (`included`, `reverted`, сожжённый газ) — только каналу,
если отправляли в один канал: при параллельной отправке неизвестно, какой канал довёз транзакцию. Счётчика для
отправки целиком в стыке `SendChannelStats` нет — запрос на изменение стыка.

## Blink: только одиночная отправка

Бандл Blink на BSC пересылает только `txs` — без `maxBlockNumber` (https://docs.blinklabs.xyz/blink/bnb-smart-chain-bsc/api-reference.md,
«Only txs is forwarded»). Такой бандл не истекает сам и может попасть в блок уже после того, как не попавшая транзакция
отменена и nonce освобождён. Поэтому каналы Blink работают только одиночной отправкой (`eth_sendRawTransaction`).

## Не попала — отмена, очередь кошелька ждёт

Очередь кошелька не освобождается, пока nonce транзакции не занят в блоке (`eth_getTransactionCount(кошелёк, "latest")`
больше nonce). Нет квитанции за `send.max_wait_blocks` — отмена: перевод 0 BNB себе с тем же nonce, цена газа выше прошлой
на `send.cancel_gas_bump_pct` (и не ниже минимума каналов); снова не занят — следующая отмена дороже. Сбой чтения
квитанции или nonce, нет новых блоков — повтор на следующем блоке, не ошибка. Канал без ясного ответа (таймаут, обрыв,
ответ не разобран) считается возможно принявшим: транзакция отслеживается и при необходимости отменяется. Ожидание идёт
в отдельной задаче, которая держит место в очереди кошелька, даже если сделку прервали. `send.max_wait_blocks` должен быть не меньше `send.bundle_max_blocks`:
иначе бандл ещё может попасть в блок, когда трекер уже отменяет, — отправка не работает с понятной причиной.
