# venues/bingx — адаптер BingX (спот)

Реализует контракт `gateway/contract.rs`. Всё — только по официальной документации BingX (CLAUDE.md, решение 23).

## Как работает WebSocket

- Адрес — настройка `venue.ws_url` (официально: `wss://open-api-ws.bingx.com/market`).
- Все сообщения сжаты GZIP. Ping спота — JSON с полем `ping`; ответ — текст `Pong` (официальный пример для спота).
- Подписка: `{"id","reqType":"sub","dataType":"<SYMBOL>@depth<N>"}`, не чаще `venue.ws_subs_per_sec` в секунду (FAQ: не больше 10/с).
- Не больше 200 подписок на соединение (официально), монет на соединение — `venue.ws_symbols_per_conn`.
- Уровни стакана сортируются здесь: в официальном примере asks пришли по убыванию, хотя в описании — по возрастанию.
- Нет сообщений дольше `venue.ws_silence_ms` — соединение оборвано: стаканы объявляются недостоверными, переподключение через `venue.ws_reconnect_pause_ms`.
- Каждое сообщение пишется в сырые сообщения (`raw.*`).

## Проверено на реальном потоке (2026-10-23, запись в tests/data/bingx)

- Ping спота: `{"ping":"<id>","time":"<время>"}` в GZIP, раз в ~30 с; после ответа `Pong` соединение живёт (проверено 3,5 мин).
- Соединение без ответов на ping тоже не было разорвано за 3 мин — сервер не наказывает сразу; отвечаем всё равно, как требует документация.
- Стакан `@depth<N>` приходит только при изменении, а не каждые 300 мс. Поэтому «устаревание» считается по тишине соединения
  (любое сообщение, включая ping), а не по возрасту стакана: `feed.stale_after_ms` должен быть больше интервала ping.
- asks приходят по убыванию цены (сортируем сами), bids — по убыванию.
- Ответ на подписку: `{"code":0,"id","msg":"SUCCESS"}`; ошибка — например `{"code":100400,"msg":"dataType is error: …"}` (пишется в журнал).
- В справочнике 2293 пары, торгуются (status 1) — 651.

## Справочник пар (common/symbols)

- Торгуется только `status` 1 (docs-v3: 0 offline, 1 online, 5 pre-open, 10 accessed, 25 suspended, 29 pre-delisted,
  30 delisted; api-ai-skills — только «1 active, 0 inactive»). Что значит 10 — не объяснено, вопрос Тиграну; ядру уходит код.
- `apiStateBuy` / `apiStateSell` — покупка / продажа через API. Обе false — монета отсеивается («пара не торгуется через
  API»); одна false — закрыта только своя сторона (ядро: `can_buy` / `can_sell`). Ордер всё равно проверяется (trade.rs).
- Живой ответ 2026-10-24 (tests/data/bingx_2026-10-24): 9 монет с BEP20 — status 1, но API закрыт (TAG, TA, B, USD1,
  SKYAI, RWA, NIULAI, TUT, XPIN); флаги у всех пар совпадают.
- Справочник перечитывается раз в `venue.symbols_refresh_s` (pairs_watch.rs) и перед ордером. После каждой попытки ядру уходит
  `SpotPairs` с `loaded_at` — временем последнего успешного получения; старше `venue.symbols_stale_s` — ядро не торгует по парам.
- Нет `apiStateBuy`/`apiStateSell` или не boolean — BadResponse на весь справочник (прежний остаётся и стареет).

## Защита денег

- Ордер: ждём окончательного состояния (FILLED / CANCELED / FAILED) не дольше `venue.order_final_wait_ms`; не дождались — отменяем остаток и читаем итог (правило Тиграна).
- Резервный адрес REST — только если соединение не установилось. Таймаут ордера или вывода не повторяется (иначе возможна двойная сделка) — возвращается Timeout для проверки.
- Депозит «зачислен» — только при статусе 1 и всех подтверждениях сети (`confirmTimes` x/y, x ≥ y): официальные источники расходятся в значении статуса 1.
- Количество округляется вниз по `stepSize`, цена — в безопасную сторону по `tickSize`; проверяются min/max сумма и количество больше нуля.
- Повторная подписка останавливает задачи старой (без дублей соединений).

## Открытые вопросы

- На какой счёт BingX зачисляет депозит (спот или фондовый) — в документации не сказано; проверяется на первом реальном депозите.
- Приватный поток (listenKey: ордера и балансы в реальном времени) — следующий шаг; сейчас балансы и статусы — по REST.

Сырой журнал: сообщения WebSocket и ответы REST (соединение «rest <путь>», в том числе config/getall) — в data/raw/bingx (raw.*); пути listenKey не пишутся (ключ потока аккаунта). Флаги сети depositEnable/withdrawEnable — только boolean по официальной таблице полей; иначе ответ не понят (BadResponse), справочник сетей остаётся прежним.
