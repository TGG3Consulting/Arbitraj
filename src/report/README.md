# report

Отчёты Excel для скачивания из интерфейса и чата «Управление» Telegram (решения 193, 215, 255, 256, 257).

| Файл | Что делает |
|---|---|
| mod.rs | Вход отчётов: «Итоги сделок» (реэкспорт results.rs) и «Упущено» → байты .xlsx; имя файла, подпись периода |
| results.rs | Решение 257: «Итоги сделок» — данные из ядра (сделки, итог дня бота daily_result, дни оценок, площадки DEX, слепок балансов) и сборка; results_file — одна функция для интерфейса и Telegram |
| rows.rs | Решение 257: строки листа «Сделки» — закончившиеся в окне и двигавшие деньги (и оценки, и вложение 0 с затратами), факт / оценка раздельно, план и его части, статьи затрат |
| rows_text.rs | Решение 257: статус, площадка итога (правило владельца — core/daily_venue.rs owner, то же у бота с t91), состояние возврата USDT, части плана (запас, возврат), подписи видов затрат |
| rows_time.rs | Решение 257: окно выгрузки (UTC), календарные дни кнопок, конец сделки по хронологии |
| day_rows.rs | Решение 257: строки «Учёта дня» — начисления сделок в итог дня бота (Deal.day_book), остаток старых сделок — «восстановлено» |
| results_xlsx.rs | Книга «Итоги сделок»: порядок листов и ключей сводок |
| res_deals.rs | Решение 257: лист «Сделки» (колонки, формулы «факт − план» одинакового состава, статьи затрат); буквы колонок для формул |
| res_days.rs | Решение 257: лист «По дням» (итог дня как у бота, запись бота, разница) |
| res_ledger.rs | Решение 257: лист «Учёт дня» — начисления сделок в итог дня бота |
| res_summary.rs | Решение 257: сводный лист по ключу (биржа итога, направление, монета, час конца), «Лучшая / Худшая» — формулой массива |
| res_total.rs | Решение 257: лист «Итог» — окно, показатели формулами, что не прочитано, пояснения |
| res_notes.rs | Решение 257: пояснения листа «Итог» по нынешнему коду |
| snap.rs | Решение 257: «Слепок по балансам» — общий срок report.snapshot_timeout_ms, площадки, сделки по шагу (где их монеты и деньги) |
| snap_cex.rs | Решение 257: блок биржи — все счета чтением адаптера, цена каждой монеты |
| snap_dex.rs | Решение 257: кошельки DEX — BNB, USDT, монеты своих сделок; прочие токены — «не учитывается» |
| snap_transit.rs | Решение 257: «В пути» (перевод монет, возврат USDT «идёт») и сделки на площадках вне реестра |
| snap_price.rs | Решение 257: цена и остаток только чтением (Venue::quote, balance) с общим сроком — путь ордера и память торговли не трогаются |
| snap_sheet.rs | Решение 257: лист «Слепок по балансам» — стоимость = количество × цена, итоги формулами, «нет данных» / «нет цены», полнота итога |
| results_sheet.rs | Оформление (шапка, форматы, примечания, цвет итога), ключ строки сводки |
| missed_rows.rs | Строки «Упущено» из итогов экрана «Упущено из-за потолка»: сделки (решение 217 — отдельно посчитанные после покупки, столбец «Данные»), кандидаты-эпизоды, топ направлений; подписи как на экране |
| missed_labels.rs | Подписи «Упущено»: что ограничило, вердикт, на каких данных посчитано (решение 217; пересчитано по окну — решение 218) |
| recompute.rs | Решение 218: отчёт пересчёта старых записей «без потолка» по окнам — CSV и итоги по группам для stdout (src/bin/uncapped_recompute.rs) |
| missed_xlsx.rs | Книга «Упущено»: листы «Сделки», «Топ направлений», «Сделки — несравнимо», строки «Итого» формулами SUM |
| missed_cands.rs | Лист «Кандидаты» книги «Упущено»; решение 245 — столбцы окна максимального объёма, длительности сделки пары и «успели бы» (M–Y) |
| missed_maxwin.rs | Решение 245: столбцы окна максимального объёма строки эпизода из показа core/maxwin_view.rs |
| sig_period.rs | Решение 255: периоды «Сигналы и сделки» (всё время, текущий день, 3 / 5 / 7 дней, свой интервал «дд.мм.гг – дд.мм.гг», UTC) |
| sig_model.rs | Решение 255: данные книги — сигнал (окно), строка главного листа, строки «Тики», «Стаканы», «Ликвидность пула» |
| sig_build.rs | Решение 255: сигналы периода (окна и сделки без окна) и чтение одного сигнала — объёмные листы и строки направлений |
| sig_link.rs | Решение 255: строка направления окна, привязка сделок к окну (список окна → монета + направление + время → своя строка), время и размер трейдов |
| sig_frames.rs | Решение 255: файл окна → сделки ленты, стаканы (снимки и стакан по изменениям), точки цены DEX и состояния пулов |
| sig_episodes.rs | Решение 255: эпизоды направления в окне → состояния и глубина пулов, стакан биржи без записи в окне |
| sig_pool.rs | Решение 255: строка «Ликвидность пула» из состояния пула (числа десятичные), предел ячейки Excel |
| sig_xlsx.rs | Решение 255: книга — «Сигналы» (колонки задачи Тиграна), «Тики», «Стаканы», «Ликвидность пула», «Пояснения»; продолжение листа после предела строк Excel |
| sig_sheet.rs | Решение 255: помощники листов — доля строк части, таблица с продолжением после предела строк Excel, запись строк и чисел |
| sig_parts.rs | Решение 255: деление на файлы не больше предела отправки (по сигналам по времени, у большого сигнала — доли строк) |
| sig_stream.rs | Решение 255: отчёт потоком — сигналы по одному, пачки до предела строк листа, файлы по одному в отправку (память не растёт с периодом) |
| sig_summary.rs | Решение 255: сводки «Данные по тикам / стакану / ликвидности» главной строки или «нет данных» с причиной |
| sig_notes.rs | Решение 255: лист «Пояснения» — что такое сигнал, откуда колонки, что сейчас не пишется |
| cap_rows.rs | Решение 256: строки листа «Сделки» — сделки, касающиеся окна; «В итоге периода» = отбор «Итогов сделок» (rows.rs selected); затраты, оценка, статус |
| cap_hold.rs | Решение 256 (аудит п. 4–6): занятость денег покупки — площадка (биржа / кошелёк DEX), до возврата USDT, остановленные с монетами, «конец не найден» — вне расчёта |
| cap_addr.rs | Решение 256 (владелец 11.11): адреса сделки из учёта — кошелёк DEX, пулы маршрута, id ордеров, хеши свопов, вывод и зачисление |
| cap_episodes.rs | Решение 256: эпизоды «без потолка» (направление + начало) → строки «день × направление»: наибольшая прибыль на бюджете и потолках, что ограничило у пика |
| cap_sheets.rs | Решение 256: имена листов, буквы столбцов, время числом Excel; лист «Упущено из-за потолка» |
| cap_deals.rs | Решение 256: лист «Сделки» — значения, адреса, длительность и занятость в момент начала формулами (SUMIFS / COUNTIFS) |
| cap_summary.rs | Решение 256: лист «Итоги» — заголовок, примечания, таблица 1 «Что ограничивает объём» |
| cap_total.rs | Решение 256 (аудит п. 3): таблица 2 «Итог периода» = «Итог факт + оценка» «Итогов сделок» |
| cap_capital.rs | Решение 256: таблицы 3 «Сколько добавил бы больший лимит», 4 «Сколько держать на балансе» по площадке (MAX(IF(…))), 5 потолок модели × максимум открытых |
| cap_limits.rs | Решение 256 (аудит п. 2): лист «Лимиты на момент выгрузки» — значения так, как читает бот, и откуда взято |
| cap_notes.rs | Решение 256: примечания «Итогов» — окно, правила по коду, uncapped.keep_days |
| cap_xlsx.rs | Решение 256: книга — «Сделки», «Упущено», «Итоги», «Лимиты», «Слепок по балансам» (snap_sheet.rs) |
| cap_parts.rs | Решение 256 (аудит п. 10): деление на файлы по дням; каждая часть отдаётся сразу по сборке (_part<K>) |
| cap_send.rs | Решение 256: что прочитать у ядра (gather), данные книги (capital_data), файлы по одному (spawn_blocking) |
| missed_total.rs | Лист «Итог» книги «Упущено»: две группы, таблица «Потолок → прибыль», примечания |

«Итоги сделок» — tests/report_results.rs (400 записанных сделок tests/data/report_2026-11-05/deals.csv закрыты ядром на настоящей SQLite: итог дня отчёта = итог дня бота; книга — в REPORT_OUT для пересчёта LibreOffice); tests/report_old_format.rs (конец старых записей, несколько дней); tests/report_snap.rs (слепок без настройки; страж: слепок не идёт путём ордера).
«Сигналы и сделки» — tests/report_signals.rs (файл окна из записанных кадров BingX, котировка и пулы записи CAKE).
«Сделки, лимиты и капитал» — tests/report_capital.rs (400 записанных сделок deals.csv, записи «без потолка» ядра на
данных CAKE; пересчёт формул LibreOffice headless, если он есть, и сверка с прямым расчётом; части по дням, отдача
сразу; календарные периоды); tests/report_capital_total.rs (настоящее ядро: итог периода = «Итоги сделок» за то же
окно, крайние случаи занятости, адреса из учёта, лимиты = чтение бота); общее — tests/cap_common.
«Упущено» — tests/report_missed.rs (записи «без потолка», посчитанные ядром на записанных данных CAKE).
