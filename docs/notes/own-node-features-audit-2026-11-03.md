# Свой узел BSC без KyberSwap — разбор остальных фич бота (03.11.2026)

> Разбор Claude по коду `main` (локальная копия /home/claude/arbitraj), код не менялся.
> Зона этого разбора — всё, что зависит от узла или от KyberSwap, **кроме** (а) самих RPC-вызовов и подключения к узлу
> и (б) исполнения свопа против KyberSwap: их разбирают параллельно. Где пункт касается и их зоны, это отмечено «стык с (а)/(б)».
> Обозначения: готовность ✅ работает как есть / 🟡 работает с оговорками или после настройки / ❌ не работает;
> проблемы 🔴 блокирует / 🟠 важно / 🟡 желательно.

## Исходные факты об узле

- geth-bsc v1.8.1 на том же сервере: HTTP `127.0.0.1:8545`, WS `127.0.0.1:8546`, namespaces `eth,net,web3`.
- `--history.logs/transactions/blocks=600000`, PBSS, pruned-снапшот `pruneancient`: блоков до 125 973 687 на узле нет
  вообще (tail фризера, память проекта «arbitrage-bot-infra»).
- **Поправка к постановке:** блок BSC сейчас ≈ 0,45 с (решения 68, 69 — «≈2,2 блока/с»), а не 3 с.
  600 000 блоков ≈ 600 000 × 0,45 с ≈ 75 ч ≈ **3,1 суток** истории логов, квитанций и индекса транзакций, не 21 день.
- Состояние (eth_call, eth_getBalance, eth_getCode) на прошлых блоках у PBSS без архива — только у последних
  блоков (у geth по умолчанию около 128 — ≈ 1 мин при 0,45 с). Точную глубину и текст ошибки надо снять вживую (раздел 9, п. 5).

## 1. Поиск и справочник пулов

### 1.1 Индексатор (решение 58) — ✅ работает, от узла не зависит; 🟠 O3 по полноте

**Как сейчас.** `directory/refresh.rs`: по каждой монете подписки (и промежуточным) — `GET {index.api_url}/networks/{index.network}/tokens/{адрес}/pools?page=N&include=…`
не чаще `index.refresh_s`, темп `index.requests_per_min`. Найденные пулы проверяются **на своём узле** (`pools/verify*.rs`,
Multicall3 на `latest`: factory/token0/token1, реестр фабрики getPair/getPool, у V4 — ключ у менеджера или PositionManager).
Цены и состояние — только с узла.

**Ошибка из журнала** «Индексатор: непонятный ответ, HTTP 404 (/networks/bsc/tokens/…/pools)»: это ответ самого
индексатора на одну монету — `gt_http.rs:74-97` пропускает его в `errors::from_http`, где 404 → BadResponse «непонятный
ответ» (`errors.rs:85`). Монета получает ошибку, повтор через `index.error_retry_s`, пулов у неё нет (или остаются прежние
из SQLite). Узел тут ни при чём, своим узлом не лечится. По коду и по виду пути наиболее вероятно, что индексатор не знает
этот токен в сети `bsc`; подтвердить по сырому ответу (раздел 9, п. 12) — тело 404 пишется в сырой журнал.

**Что изменится на своём узле.** Проверка пулов из справочника станет быстрее (нет лимита CU). Сам справочник — нет:
по-прежнему 10 запросов/мин без ключа; с MEXC монет стало намного больше — полный проход справочника растягивается на часы.

**Нужен ли другой источник.** Для V2/V3/форков/DODO/Solidly — пулы можно находить прямо на своём узле по фабрикам:
адреса фабрик уже есть в настройках `dex.*` (они нужны для проверки), вызовы уже есть в коде — `getPair` (V2),
`getPool(a,b,fee)` (V3), `getDODOPoolBidirection` (`pools/verify_dodo.rs`), `getPool(a,b,stable)` (`pools/verify_solidly.rs`).
Решение 58 отказалось от перебора фабрик из-за двух причин: «не находит форки и новые DEX» и «тратит CU узла». Вторая на
своём узле ушла; первая закрывается тем, что фабрики подключённых DEX известны. Индексатор нужен для V4/Infinity (PoolId —
хеш ключа, по фабрике не перечислить) и как подсказка о новых DEX. Плюс: DODO индексатор на BSC не отдаёт
(`docs/notes/dex-coverage-map.md`) — поиск по фабрике его закроет. **Это меняет решение 58 — вопрос Тиграну (В1).**

**Исправить (Y2).** 404 на странице 1 пулов монеты — отдельный исход «у индексатора этой монеты нет» (пустой справочник,
понятная причина на экране «Монеты», журнал один раз), а не «непонятный ответ». Делать после подтверждения на записанном
ответе (правило «только факты»).

### 1.2 История пулов V4 (dex.history_scan, eth_getLogs + eth_getCode) — ❌ на своём узле; 🟠 O1, O2

**Как сейчас.** `pools/history_v4.rs`: по каждому включённому виду V4 — старт из памяти → SQLite → блок развёртывания
менеджера (`deploy_block.rs`: бинарный поиск первого блока с кодом по `eth_getCode` от блока 0 — около 27 вызовов на старом
состоянии), затем `eth_getLogs` Initialize кусками `dex.logs_block_batch` до головы. Нужна только для пулов Uniswap V4 без
позиций через PositionManager (решение 58).

**Нынешняя ошибка** «история пулов: узел BSC (HTTP): доступ не разрешён … HTTP 403» на publicnode: 403 даёт
`errors::from_http` (`errors.rs:79-82`). По коду она возникает в `deploy_block::get` или `scan::one`; если в журнале перед
ней есть строка «ищу блок развёртывания … (eth_getCode)» — это поиск блока развёртывания (O1).

**O1 (🟠, баг).** `load()` вызывает `start()` (`history_v4.rs:82`), а он — `deploy_block::get` (`:175`) **до** проверки
`history_gate::allowed` (`:103`). При `dex.history_scan` = нет и пустом SQLite бот всё равно идёт за старым состоянием.
На своём PBSS-узле это ошибка (`eth_getCode` на старом блоке) при каждой подписке на рынок, по каждому виду V4.
Исправить: проверять выключатель до `start()`; выключено — только подключить известное из памяти и SQLite (`connect(known)`),
блок развёртывания не искать.

**O2 (🟠, ограничение узла).** Даже включённая история не дочитает: логов на узле ≈ 3,1 суток, блоков до 125 973 687 нет,
старого состояния нет. Новые пулы V4 при этом ловятся событиями Initialize в реальном времени (`pools/created.rs`,
подписка `logs` по WS) — это на своём узле работает. Уже существующие пулы Uniswap V4 без позиций PositionManager своим
узлом не найти. Варианты — **вопрос Тиграну (В2)**: (а) отказаться от таких пулов (`dex.history_scan` = нет навсегда);
(б) один раз прочитать историю через внешний архивный провайдер, сохранить в SQLite (`history_store.rs` хранит пулы и
последний прочитанный блок), дальше свой узел продолжит от `last+1` — сработает, только если разрыв меньше 600 000 блоков,
то есть переключить адрес узла обратно на свой в пределах ~3 суток после чтения.

«Проверить подключение» → «История состояния» (`connection.rs`, `history()`) при `dex.history_scan` = да и сохранённом
блоке развёртывания тоже упадёт на своём узле — при «нет» пишет «не нужна».

### 1.3 Новые пулы событиями создания — ✅

`pools/created.rs`, `created_log.rs`: подписка `logs` на события создания у фабрик и менеджеров, проверка на узле
(Multicall3 на `latest`), подключение. На своём узле — то же, без лимитов. Фильтры подписки — стык с (а).

## 2. Проверки налогов и крючков (check/*) — 🟡 работает, зависит от прочитанных пулов

**Как сейчас.** Налоги монеты (`check/probe.rs`, `taxes.rs`) и USDT (`service_tax.rs`, решение 67), газ обмена и перевода,
нативный BNB (`native_probe.rs`) — `eth_simulateV1` (`check/simulate.rs:96-130`) поверх **номера** свежего блока
(`heads.at`), `validation: false`. USDT для пробы берётся переводом от пула-источника (вызов от имени пула — без state
override). **eth_call со state override в коде нет нигде** (поиск по `stateOverride`/`overrides` — пусто).
Крючки V4 (`hooks_probe.rs`) и сверка с квотером (`quoter_*`) — `eth_call` квотеров на `latest`.

**На своём узле.** `eth_simulateV1` есть в namespace `eth` узла BSC (ссылка в `simulate.rs:11`); «Проверить подключение» →
«Симуляция» проверяет его пустым вызовом. Базовый блок — голова, то есть в пределах глубины состояния PBSS. Лимиты
`RPCGasCap=100M`, `RPCEVMTimeout=30s` достаточно. Проверки станут быстрее (нет очереди 2–20 вызовов/с).

**«нет прочитанного пула с суммой check.probe_usdt USDT для пробы перевода»** (`service_tax.rs:59-63`). Это не ошибка узла:
источником может быть только пул V2/V3 (`PoolRef::Contract`) реестра — достоверный, глубокий по `dex.min_pool_liquidity_usd`,
со встречным USDT и балансом USDT ≥ `check.probe_usdt` (`taxes_util.rs:63-117`). Пока пулы не прочитаны или все мелкие —
источника нет, налог USDT «не проверен», и при `usdt_return.mode = per_trade` все направления биржа → DEX отклоняются
(решение 67). На своём узле пулы читаются быстрее — пройдёт само, как только прочитается хоть один глубокий пул USDT V2/V3.
Повтор — по сигналу «пул готов».
Если не проходит долго — проверить `check.probe_usdt` (не больше баланса USDT у крупных пулов) и наличие прочитанных V2/V3
пулов с USDT на экране «Монеты». Без пула-источника можно было бы через `stateOverrides` у `eth_simulateV1`, но для этого
нужно знать слот баланса в хранилище токена — это гадание, не предлагаю без факта.

**Y3 (🟡).** Готовность к `exec.via_kyber` = нет: пробы налогов и газа нужны своему исполнителю всегда (при KyberSwap налог
перевода тоже брался из них). Ничего менять не нужно.

## 3. Баланс кошелька: события, депозиты, сверка

### 3.1 События баланса (решение 76, venue.balance_events) — 🟡 выключено сейчас, на своём узле — включать

**Y4 (🟡).** `events_native.rs:81` читает состояние на блоке «голова − send.deposit_confirmations». На PBSS это работает,

`send.deposit_confirmations` маленьким — по `finalized` (п. 9) достаточно нескольких блоков.

### 3.2 Статус вывода и зачисления по квитанции (wallet/transfer_status.rs) — ✅ для текущих сделок; 🟡 Y5

**Y5 (🟡).** Индекс транзакций — 600 000 блоков (≈3,1 суток). Перевод старше (остановленная сделка, «Продать сейчас»,

окна узла — отдельная причина «узел не хранит такую старую транзакцию», не Pending.

- Цена газа — `eth_gasPrice` + `send.gas_price_markup_pct`, кэш на блок, фоновый прогрев на каждой голове
  (`quote/gas.rs`, `quote/warm.rs`, решение 89). На своём узле — то же, ответ быстрее. Узел советует цену по своему оракулу
  (свой txpool и последние блоки); минимум канала (`channel.min_gas_price_gwei`) применяется при отправке. Сверить разовым
  `eth_gasPrice` своего и публичного узла (п. 8).
- Газ обмена, разрешений, перевода — измерен пробами `eth_simulateV1` (раздел 2), не зависит от KyberSwap.
- BNB на газ — `risk.min_bnb_balance` + газ сделки, баланс BNB — `eth_getBalance("latest")` (`core/precheck.rs:85-115`,
  решение 113). На своём узле предпроверка «баланс BNB» — миллисекунды вместо ~11 с из решения 113.
- Статистика газа (`core/gas_stats.rs`) — из квитанций своих транзакций; без изменений.
- `kyber.gas_price_markup_pct`, `kyber.gas_limit_margin_pct` — только для свопов KyberSwap; при `exec.via_kyber` = нет не читаются.

## 5. «Живой экран», сигналы, эпизоды, карточка сигнала при exec.via_kyber = нет — ✅; 🟡 Y1

**Как сейчас.** Экран, грубый фильтр и подбор объёма всегда считались своей математикой пулов (решения 92, 95). KyberSwap
участвовал только в **финальной котировке** кандидата: `venue.rs:66-80` — при `quote_stage::is_final()` и
`exec.via_kyber` = да котировка KyberSwap. При «нет» финальная котировка — та же своя математика, что и при подборе
(повторный расчёт, без узла: газ и время блока — из тёплого кэша). Значит: сигнал, карточка, эпизод и решение «торговать»
считаются одной математикой — расхождения «сигнал есть, а KyberSwap дал хуже» (RVV 02.11, решение 111) исчезают.
Карточка сигнала (`pool_depths_of`) и эпизоды узел не трогают.

**Y1 (🟡, баг смысла).** Фильтр `kyber.final_gate_usd` применяется к любому направлению с DEX, даже при
`exec.via_kyber` = нет: `core/profit.rs:92-104` и `final_gate()` `:209-222` проверяют только «есть ли DEX». С `−0.05`
вреда нет (кандидат всё равно не пройдёт `money.min_profit_usd`), но в отказах появится «ниже фильтра финальной котировки
kyber.final_gate_usd», хотя KyberSwap не спрашивается; при положительном значении выше порога прибыли — лишние отказы.
Исправить: фильтр только при `exec.via_kyber` = да (или поставить 0 — раздел 0).

**O5 (🟠, бизнес-риск, стык с (б)).** Без KyberSwap исполнитель и сигнал видят одинаково мало: только пулы своего
реестра (а их полнота упирается в справочник — O3). Раньше KyberSwap мог пройти по DEX, которых бот не знает, и давал
откат «нет маршрута у KyberSwap → свой сборщик» (`venue.rs:90-98`). Теперь сделок будет меньше там, где KyberSwap был
лучше, зато каждая — по той цене, которую показал сигнал. Мерить по журналу кандидатов первые дни.

## 9. Проверки вживую (на сервере)

Помощник для HTTP (вставить в shell на сервере):

```bash
rpc(){ curl -s -X POST -H 'content-type: application/json' \
  --data "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"$1\",\"params\":$2}" http://127.0.0.1:8545; echo; }
hex(){ printf '0x%x' "$1"; }
H=$(rpc eth_blockNumber '[]' | python3 -c 'import sys,json;print(int(json.load(sys.stdin)["result"],16))'); echo "голова $H"
```
