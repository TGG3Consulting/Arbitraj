# t171 — контроль отсева циклов DEX ↔ DEX (решение 385) и строка отсева без таймера (решение 386), 17.11.2026

## Причина (факт кода до правки)
- `venues/bsc_dex/quote/cycle_scan.rs` (signal): цикл с ρ < 1 (`quote/bound_cycle.rs` cycle_may_profit) возвращал None —
  cycle_opt::best не считался, сигнала нет. Живого контроля у этого отсева не было (у кандидатов есть — core/sieve_audit.rs).
  Ошибка границы теряла бы прибыльный цикл молча. Живые числа (из задания): cycle_cut 600–858 в минуту.
- `core/sieve_rate.rs`: показ отсева кандидата (строка «Кандидатов», запись, закрытие эпизода) — не чаще
  sieve.row_interval_ms. Владелец 17.11: лишняя настройка.

## Что сделано
### Решение 385
- `quote/bound_cycle.rs`: cycle_sieve → Pass / Cut(ρ) / Na (счётчики как раньше); cycle_may_profit — обёртка.
- `quote/cycle_audit.rs` (новый): накопитель доли sieve.audit_share (тот же смысл, что у кандидатов; свой накопитель),
  violated (ρ < 1 и валовая > 0 или чистая > 0), check (счётчик, запоминание пути), report (текст и данные, вид «cycle»).
- `quote/cycle_scan.rs`: отсечённый и выбранный долей цикл считается тем же путём (best, форма, сигнал) и идёт в сигналы
  как любой; сверка с ρ тех же ног. Путь с нарушением — не отсекается до перезапуска (счётчик cycle_na). scan отдаёт
  (сигналы, нарушения).
- `venue.rs` dex_cycles: нарушение — запись Error core.sieve_violation (площадка bsc_dex) и Notice тем же кодом → ядро →
  Telegram (notify/journal_off.rs: своя запись есть, второй нет).
- `gateway/rate_bound.rs`, `core/quote_count_log.rs`: cycle_audit, cycle_audit_violation в сводке dex.quote_count.

«Те же данные»: Leg несёт копию записи пула (`route_calc.rs` Leg.entry: Entry, Clone) — ρ и полный счёт идут по одному
и тому же вектору ног, т. е. строго по одному снимку.

Нагрузка: контрольный счёт — внутри поиска циклов (то же место бюджета CPU quote/cpu.rs, ярус вызывающего; у
core/cycle_watch.rs — фон; те же потоки dex.graph_threads). При доле 1 поиск считает каждый отсечённый — объём работы
поиска как до решения 373. Путь сделок биржа ↔ DEX не затронут.

### Решение 386
- `core/reject_log.rs`: RejectLog::note возвращает Noted (New / Flushed / Held).
- `core/sieve_log.rs` cut: сначала запись журнала (ключ — направление, как у отказа расчёта), строка и эпизод — только
  при New/Flushed. Ключ общий с core.candidate_rejected: любой полный расчёт меняет вид строки или закрывает её — следующий
  отсев показывается сразу (так раньше делал sieve_rate::clear).
- `core/sieve_rate.rs` удалён; sieve.row_interval_ms удалена из каталога, SETTINGS, FIRST_RUN (в first_run.toml её не
  было). Сохранённое значение в базе запуск не ломает (settings/store.rs: имени нет в каталоге — значение можно только
  очистить).

## Ограничения
- Без journal.repeat_flush_ms строка отсева в браузере показывает числа первого отсева своего вида до смены вида.
- Повтор, дописанный отложенной задачей журнала, в браузер не уходит (числа строки — последнего показа).
