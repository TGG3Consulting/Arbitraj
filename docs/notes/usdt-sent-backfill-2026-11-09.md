# Запись «ушло» в старые возвраты USDT — инструкция для сервера (решение 236, дополнение п. 5, 09.11.2026)

Решение техлида 09.11 по поручению Тиграна (вопрос 1 решения 236). Программа **не запускалась** — запускает Тигран.

## Зачем

Решение 236: затраты части возврата «вернулись» = **ушло** с площадки − **зачислено** (+ газ не в USDT). У записей до
решения 236 поля «ушло» (`sent`) нет — бот считает «запрошено − зачислено», и в затраты попадает остаток округления
вывода, который лежит на площадке-отправителе. На данных бота это MEXC (точность вывода USDT 0.1): 145 возвратов,
6.34 USDT лишних затрат, 42 лишних «минусовых» сделки (docs/notes/deal-accounting-2026-11-09.md, раздел 4). Пример —
20261108205335162HELLO: запрошено 27.6554…, ушло 27.6, зачислено 27.59 → затраты 0.01, а не 0.0655.

Факт «ушло» есть только в журнале: запись `core.transfer_sent`, которую бот пишет после хеша вывода
(core/transfers.rs): «`<id> <ушло> <монета>: <откуда> → <куда>, хеш <tx>`». Программа `usdt_sent_backfill` один раз
переносит это число в запись сделки.

## Что делает

- Берёт из базы все сделки (`core_state`, вид `deal`) и все записи журнала `core.transfer_sent`.
- Для каждой части возврата «вернулись» без `sent` ищет запись журнала: id = id сделки + `u` (первая попытка),
  `u<n>` (повтор) или `m<цифры>` («Перегнать»); откуда и куда — как у части.
- Ровно одна такая запись и зачислено ≤ ушло ≤ запрошено — дописывает в эту часть `"sent": "<ушло>"`. Остальной JSON
  записи не меняется.
- Иначе — пропуск с причиной в отчёте («в журнале нет записи…», «… записей этого перегона — неясно, какая», «ушло
  больше запрошенного», «ушло меньше зачисленного»). У пропущенных всё остаётся как сейчас (запрошено − зачислено).
- Повторный запуск ничего не дублирует: части с `sent` не трогаются.

Итог сделки бот пересчитает **при запуске** (ledger_load.rs → deal_return_cost::apply: вычитается только разница с
уже учтённым). Итоги прошлых дней (`daily_result`) не пересчитываются — как в решении 236.

## Где взять

Артефакт сборки `arb-linux` (GitHub → Actions → Linux build → Artifacts): рядом с `arb` и `uncapped_recompute` лежит
`usdt_sent_backfill` (статический musl, как бот). Бот нужен с решением 236 (он читает `sent`).

## Запуск на сервере

Папка данных — та, что передаётся боту в `--data-dir` (в ней `arb.sqlite`). Пути ниже — пример.

1. Отчёт без записи (бот может работать — база открывается только на чтение):

   ```sh
   ./usdt_sent_backfill --data-dir /opt/arb/data --dry-run
   ```

   Строка на каждую часть: «`<сделка> mexc → bsc_dex: запрошено …, ушло …, зачислено …; затраты A → B (остаток … на
   mexc; журнал <время>)`», затем «ПРОПУСК …» с причинами, затем итоги по площадкам («частей N, затраты возврата A → B
   USDT, остаток округления …»). Ожидаемо для MEXC — около 145 частей и около 6.34 USDT разницы; у бирж, где вывод
   USDT не округляется (BingX, Bitget, Gate, DEX), разница 0. Только MEXC — `--from mexc` (можно несколько `--from`).

2. Показать отчёт Тиграну, получить «да».

3. Остановить бота. Обязательно: бот держит сделки в памяти и при следующем сохранении сделки записал бы её поверх
   правки; `--apply` при запущенном боте откажет: «база занята — бот запущен … Остановите бота и повторите --apply».

4. Копия базы:

   ```sh
   for f in arb.sqlite arb.sqlite-wal arb.sqlite-shm; do [ -f /opt/arb/data/$f ] && cp /opt/arb/data/$f /opt/arb/data/$f.before-236sent; done
   ```

5. Записать (тот же фильтр, что в п. 1, если он был):

   ```sh
   ./usdt_sent_backfill --data-dir /opt/arb/data --apply
   ```

   В конце: «Режим --apply: записано сделок N…».

6. Запустить бота. Экран «Сделки»: у исправленных частей «ушло … (остаток округления вывода — на mexc)», пометки «запись
   до решения 236» нет; итог сделки — с затратами «ушло − зачислено».

## Почему бот должен быть остановлен

База — SQLite в режиме WAL. `--apply` открывает её с исключительной блокировкой (`PRAGMA locking_mode = EXCLUSIVE`,
`BEGIN EXCLUSIVE`, без ожидания; storage/db.rs open_existing — тот же путь, что у `uncapped_recompute`): бот запущен —
отказ; пока программа пишет, бот базу не откроет. Все сделки пишутся одной транзакцией.

## Откат

При остановленном боте — вернуть копию `arb.sqlite.before-236sent` (и `-wal`, `-shm`, если копировались).
