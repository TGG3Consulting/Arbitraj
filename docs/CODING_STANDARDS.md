# CODING_STANDARDS — как пишем код

> Обязательно для любого кода в проекте, кем бы он ни был написан.

## Файлы и папки
- Один файл — одна задача. Ориентир — не больше 200 строк. Вырос больше — делим по задачам.
- В каждой папке `README.md`: назначение папки и по одной строке на каждый файл.
- Новый файл → сразу строка в `README.md` своей папки.
- Ядро (`core/`) не импортирует ничего из `venues/` — только из `gateway/`.
- Адаптер не импортирует другие адаптеры.

## Шапка каждого файла (Rust)

```rust
//! Файл: core/signal.rs
//! Что делает: быстрый спред по направлениям монеты и фильтр шума (шаг 3 ТЗ).
//! Кто вызывает: core/market_state.rs — на каждый тик.
//! От чего зависит: core/types.rs, settings (пороги и фильтры), gateway/events.rs.
//! Настройки: signal.* (список — docs/SETTINGS.md).
```

## Комментарий к каждой функции

```rust
/// Что делает: считает грубый спред направления A→B.
/// Принимает: лучший ask на A, лучший bid на B.
/// Возвращает: спред в долях; None, если любая цена устарела.
/// Ошибки: нет.
```

## Никаких хардкодов
- Ни одного зашитого числа, порога, лимита, таймаута, процента, списка, адреса или URL.
- Любой параметр: описан в `settings/schema.rs` (имя, тип, единица, допустимый диапазон, описание) → читается из хранилища настроек → виден и меняется в интерфейсе.
- Данные площадок (комиссии, сети, шаги цены, минимумы, адреса контрактов) — только из API площадок.
- Исключение одно: значения, заданные самим протоколом в его официальной документации (например, формат события пула). У такой константы рядом — комментарий со ссылкой на официальный источник.

## Никаких моков
- Нет заглушек, выдуманных данных и «временных» значений в рабочем коде.
- Нет данных → явная ошибка или статус «нет данных» в интерфейсе; торговли по этому направлению нет.
- Тесты — только на реально записанных сообщениях площадок (`storage/raw_log`).

## Ошибки
- Адаптер переводит любую ошибку площадки в единый код (`gateway/errors.rs`) и прикладывает исходный ответ.
- Что делать при ошибке, решает правило шлюза (`gateway/rules.rs`), а не код адаптера.
- Никаких молчаливых `unwrap()` в рабочем коде: ошибка либо обрабатывается, либо уходит выше с понятным текстом.

## Числа
- Деньги, цены, объёмы — `rust_decimal`. Значения из блокчейна — `U256` (alloy). Float для денег не используется.

## Логи
- `tracing`, структурные поля: площадка, монета, направление, ID сделки.
- Всё, что важно человеку, попадает и в журнал интерфейса.

## Готовая фича — пять частей
1. Код.
2. Её настройки в `settings/schema.rs` и хранилище, меняются на лету.
3. Экран или элементы в интерфейсе: фича полностью видна, управляется и настраивается оттуда.
4. Шапки и комментарии в коде, строки в `README.md` папок.
5. Строка в таблице «Готовые фичи» в `ARCHITECTURE.md`; если менялось решение — запись в `docs/DECISIONS.md`.

Без любой из пяти частей фича не готова.
