85: ## 4. Quote Asset Rules
86: 
87: From `getTokenInfo` / events:
88: 
89: - `quote == address(0)` → the token trades against native BNB on the bonding curve.
90: - `quote != address(0)` → the token trades against a BEP20 quote (for example USDT).
91: 
92: Implications:
93: 
94: - BNB pairs: send `msg.value` on buys; sells return BNB.
95: - ERC20 quote pairs: approve quote to TokenManager2 before buy; approve the meme token before sell.
96: - Helper3 `buyWithEth` / `sellForEth` only apply to **ERC20/ERC20** pairs (quote ≠ 0). They are not for native BNB pairs.
116: ## 6. Migration and External Market Routing
117: 
118: While the bonding curve is active:
119: 
120: - Route buys/sells through TokenManager V1/V2 (or Helper3 wrappers where applicable).
121: 
122: After migration:
123: 
124: - `getTokenInfo(...).liquidityAdded == true`
125: - V2 emits `TradeStop(token)` and `LiquidityAdded(base, tokenAmountToLp, quote, funds)`
126: - Internal curve trading stops; route via the external DEX pool for that token/quote
127: 
128: Note: `LiquidityAdded`’s second parameter is the **token amount added to LP**, not remaining bonding-curve offers. See [Trade guide events](./trade-guide.md#43-events).
138: ## 8. Scope Boundaries
139: 
140: Included:
141: 
142: - Public trade, create, estimate, and tax claim surfaces documented for third parties.
143: - Lite ABIs under `abi/` and interfaces under `contracts/interfaces/`.
144: 
145: Not included:
146: 
147: - Bonding-curve math internals and proprietary libraries.
148: - Admin / operator / upgrade / fee-collector privileged APIs.
149: - OpenFour modular protocol (separate docs).

### docs/trade-guide.md
16: ## 1. Recommended Trade Flow
17: 
18: ```text
19: token address
20:     -> Helper3.getTokenInfo(token)
21:     -> read version / tokenManager / quote / liquidityAdded
22:     -> if liquidityAdded: route externally (Pancake / DEX)
23:     -> else Helper3.tryBuy / trySell
24:     -> approve if needed
25:     -> call V1 or V2 trade method on tokenManager
26:     -> index TokenPurchase / TokenSale (and TradeStop / LiquidityAdded)
27: ```
39: ### 2.1 `getTokenInfo`
40: 
41: ```solidity
42: function getTokenInfo(address token) returns (
43:     uint256 version,
44:     address tokenManager,
45:     address quote,
46:     uint256 lastPrice,
47:     uint256 tradingFeeRate,
48:     uint256 minTradingFee,
49:     uint256 launchTime,
50:     uint256 offers,
51:     uint256 maxOffers,
52:     uint256 funds,
53:     uint256 maxFunds,
54:     bool liquidityAdded
55: );
56: ```
57: 
58: | Field | Meaning |
59: |-------|---------|
60: | `version` | `1` → trade via V1 methods; `2` → trade via V2 methods |
61: | `tokenManager` | Canonical manager for that version (`TOKEN_MANAGER` or `TOKEN_MANAGER_2`) |
62: | `quote` | `address(0)` = BNB pair; otherwise BEP20 quote |
63: | `tradingFeeRate` | Protocol trading-fee numerator; actual rate is `tradingFeeRate / 10000` |
64: | `minTradingFee` | Minimum protocol trading fee amount |
65: | `offers` / `maxOffers` | Remaining / max tokens for sale on the curve. For V1, Helper returns fixed `maxOffers` / `maxFunds` constants rather than per-token storage |
66: | `funds` / `maxFunds` | Raised / max raise in quote units |
67: | `liquidityAdded` | V2: `true` when token `status == COMPLETED (3)`. V1: from V1 liquidity flag |
68: 
69: ### 2.2 `tryBuy`
70: 
71: ```solidity
72: function tryBuy(address token, uint256 amount, uint256 funds) view returns (
73:     address tokenManager,
74:     address quote,
75:     uint256 estimatedAmount,
76:     uint256 estimatedCost,
77:     uint256 estimatedFee,
78:     uint256 amountMsgValue,
79:     uint256 amountApproval,
80:     uint256 amountFunds
81: );
82: ```
83: 
84: Examples:
85: 
86: - Buy a fixed token amount: `tryBuy(token, 10000e18, 0)`
87: - Spend a fixed quote budget: `tryBuy(token, 0, 10e18)`
88: 
89: Return usage:
90: 
91: | Field | Meaning |
92: |-------|---------|
93: | `estimatedCost` | Curve quote cost (before protocol fee) |
94: | `estimatedFee` | Estimated protocol trading fee. Under AntiSniperFeeMode this can include base+extra; the buy event `fee` field only records base fee |
95: | `amountMsgValue` | Suggested `msg.value` for the trade call (may include pending `launchFee`) |
96: | `amountApproval` | Suggested ERC20 quote approval when `quote != 0` |
97: | `amountFunds` | Suggested `funds` argument for AMAP buys |
98: 
99: For TaxToken8 and TaxToken9, Helper also folds estimated buy tax into `amountMsgValue` / `amountApproval` where applicable.
100: 
101: ### 2.3 `trySell`
102: 
103: ```solidity
104: function trySell(address token, uint256 amount) returns (
105:     address tokenManager,
106:     address quote,
107:     uint256 funds,
108:     uint256 fee
109: );
110: ```
111: 
112: | Field | Meaning |
113: |-------|---------|
114: | `tokenManager` | Manager to call for the real trade |
115: | `quote` | Quote asset (`address(0)` = native BNB) |
116: | `funds` | Estimated **net** quote to the seller: `curveGross - protocolFee - taxTokenSellTax`. Does **not** subtract any third-party router `feeRate` cut. Token8/TaxToken9 tax is deducted here but **not** included in `fee` |
117: | `fee` | Protocol trading fee only (not TaxToken8/TaxToken9 tax, not router cut) |
195: ## 4. TokenManager2 (V2)
196: 
197: **BSC address:** `0x5c952063c7fc8610FFDB798152D69F0B9550762b`
198: 
199: Supports tokens created on/after 2024-09-05. Quote may be BNB (`quote == 0`) or BEP20.
200: 
201: ### 4.1 Buy
202: 
203: | Method | Use |
204: |--------|-----|
205: | `buyTokenAMAP(token, funds, minAmount)` | Spend fixed quote for tokens |
206: | `buyTokenAMAP(token, to, funds, minAmount)` | AMAP buy to `to` |
207: | `buyToken(token, amount, maxFunds)` | Buy fixed token amount |
208: | `buyToken(token, to, amount, maxFunds)` | Fixed-amount buy to `to` |
209: 
210: For BNB pairs, send `msg.value`. For ERC20 quote pairs, approve quote to TokenManager2 first. Prefer filling `msg.value` / approvals from Helper3 `tryBuy`.
211: 
212: ### 4.2 Sell
213: 
214: | Method | Use |
215: |--------|-----|
216: | `sellToken(token, amount)` | Simple sell |
217: | `sellToken(origin, token, amount, minFunds, feeRate, feeRecipient)` | Sell with router fee |
218: | `sellToken(origin, token, from, amount, minFunds, feeRate, feeRecipient)` | Router path; `tx.origin == from` |
219: 
220: - `origin`: set `0`
221: - `feeRate`: max 5%; `100` = 1%, `10` = 0.1% (`cut = funds * feeRate / 10000`)
222: - `minFunds`: compared against the **gross curve quote** (`calcSellCost`) **before** protocol fee and router cut. Net proceeds to the seller are lower.
223: - Before sell: `ERC20(token).approve(tokenManager, amount)`

279: ## 5. Error Codes
280: 
281: ### buyToken
282: 
283: | Code | Meaning |
284: |------|---------|
285: | `GW` | Amount precision not aligned to GWEI |
286: | `ZA` | `to` must not be `address(0)` |
287: | `TO` | `to` must not be the Pancake pair |
288: | `Slippage` | Fixed-amount buy: curve cost exceeds `maxFunds`. AMAP buy: purchased amount below `minAmount` |
289: | `More BNB` | Insufficient `msg.value` |
290: 
291: ### sellToken
292: 
293: | Code | Meaning |
294: |------|---------|
295: | `GW` | Amount precision not aligned to GWEI |
296: | `FR` | Fee rate exceeds 5% (`feeRate > 500`) |
297: | `SO` | Order amount too small (`funds <= protocol fee`) |
298: | `Slippage` | Gross curve quote is below `minFunds` (not net proceeds) |

300: ## 6. AntiSniperFeeMode Tokens
301: 
302: AntiSniperFeeMode applies a dynamic fee that decreases block-by-block after creation. Indicated by `feeSetting > 0` in `TokenInfoEx1`.
303: 
304: ### On-chain
305: 
306: ```solidity
307: TokenInfoEx1 memory tix1 = TokenManager2._tokenInfoEx1s(token);
308: bool antiSniper = tix1.feeSetting > 0;
309: ```
310: 
311: ### Off-chain
312: 
313: In token info API response, `feePlan == true` means AntiSniperFeeMode is enabled.
314: 
315: Block-by-block fee schedule may change for future launches. Product reference: [Product Update 25-10-30](https://four-meme.gitbook.io/four.meme/product-update/6-product-update-25-10-30).
