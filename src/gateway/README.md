# gateway — шлюз

Единственный путь между ядром и площадками.

| Файл | Что делает |
| --- | --- |
| `contract.rs` | Контракт адаптера `Venue`: функции, обязательные для каждой площадки (стык); `DexFamily`. Неприменимая функция отвечает `NotApplicable` |
| `errors.rs` | Единые коды ошибок + понятное сообщение + сырой ответ площадки (стык) |
| `events.rs` | События адаптеров (стакан, пул, недостоверно, проверка монеты и пула, канал отправки, спот-пары биржи `SpotPairs`, монеты DEX с ещё не прочитанными пулами `PoolsLoading`) и служебные события шлюза (стык) |
| `rules.rs` | Модель правил при сбоях и выбор правила: правило площадки сильнее общего. Повтор запрещён для «результат неизвестен» (retry_allowed, решение 64). |
| `http.rs` | HTTP-обмен с двумя сроками: до заголовков (http.timeout_ms) и тишина при чтении тела (http.body_idle_ms); правдивая причина сбоя (нет связи / нет ответа / ответ не дочитан); `exchange_full` — ещё и заголовок Retry-After в секундах (решение 118, А-🔴3) |
| `tx_hash.rs` | Сравнение хешей транзакций из ответов площадок: нижний регистр, без `0x`, до `:` (решение 118, Я-16) |
| `quote_stage.rs` | Признак «финальная котировка расчёта» на задачу tokio (решение 95); `final_external` — финальная котировка площадки у внешнего исполнителя (exec.via_kyber = да): по нему ядро применяет kyber.final_gate_usd (решение 121 B5) |
| `urgency.rs` | Срочность запросов (решение 61): Trade → Check → Quote → Background на задачу tokio; ядро помечает путь сделки Trade |
| `tap.rs` | Запись окон (решение 125): приёмник кадров окна `TapSink` (не ждёт: полон — потеря и счёт), кадр `TapFrame` (площадка, поток Book/Trades/Diff/Snapshot, соединение, время получения нс, текст или байты как пришли), приёмники адаптера по тикеру `Taps`, что включено `TapInfo` |
| `registry.rs` | Реестр подключённых адаптеров |

Готовых правил в коде нет — все вводятся в интерфейсе. Если для ошибки правила нет,
шлюз останавливает операцию и уведомляет (применение правил — этап 5).
