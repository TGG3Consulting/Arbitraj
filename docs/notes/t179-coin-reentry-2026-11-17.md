## Что сделано

1. **Замок в двух частях** (`core/coin_ride.rs`): целиком (`active`) — от входа до учёта покупки; после
   `ledger::save` с шагом Transfer — «идущая» (`inner.rides`, `board`). Конец задачи сделки снимает только своё
   (`release`): до board — замок целиком, после — свою запись (замок целиком может держать уже следующая сделка).
2. **Условия следующей сделки** (`coin_ride::refuse`): идущих < money.max_deals_per_coin (не задана — 1, отказ прежним
   текстом `start_reason::busy`); не встречная (не покупает там, где идущая продаёт; не продаёт там, где идущая
   покупала); все идущие на шаге Transfer / Selling. То же условие — у очереди расчёта (`blocks_new`).
3. **Ручные действия, цикл DEX ↔ DEX, продажа «Балансов»** — только при свободной монете (`take`): как раньше.
4. **Ликвидность** (`core/ride_quote.rs`, вызывается из `costs_source.rs` Live — расчёт кандидата и предпроверка):
   продажа — разность котировок (идущие + наш объём) − (идущие) с той же B; исполнимое и худшая цена — со сдвигом;
   покупка на A идущей — данные новее её покупки (стакан: `Quote.at` > конец её ордера; DEX: маршрут через её пулы
   по блоку ≥ блок её покупки). Симуляция продажи DEX до покупки (`precheck_dex_sell.rs`) при монетах впереди план
   только понижает.
5. **Пауза после удачной сделки снята** (`route_pause::won`, `ledger.rs`): Closed, продажа бота, продано на B плана без
   перегонов, итог ≥ 0 — паузы нет, в хронологии строка «Пауза направления не поставлена…».
6. Настройка `money.max_deals_per_coin` (каталог base.rs, SETTINGS.md, FIRST_RUN.md, first_run.toml; экран
   «Настройки» → «Деньги и риск» строится по схеме каталога).

## Что доказано тестами (tests/core_coin_reentry_t179.rs)

- Замок: не задана — одна сделка, текст как раньше; 2 — вторая после учёта покупки первой, третья — нет; встречная и
  застрявшая — нет; ручное действие при идущей — отказ; release снимает только своё.
- Деньги: бюджет второй = лимит монеты − вложенное первой; «в пути» — так же.
- Ликвидность продажи: на записанных bids BingX CAKE-USDT и настоящей котировке стакана (`FrozenBook::price`)
  разность совпадает с продажей по стакану без монет первой (выручка, исполнимое, комиссия); на записанном пуле
  CAKE/USDT V2 и математике адаптера — с продажей в пул после первой до 1e-6 доли (по расчёту на тех же резервах
  разность выше последовательной на ~1.2e-7 доли — формула V2 с комиссией; газ — одного обмена, комиссия пула — нашей
  части).
- Свежесть покупки: стакан не новее конца её ордера — отказ; DEX — блок раньше её блока — отказ, тот же блок — можно,
  другой пул — проверки нет.
- won: удачная — паузы нет; убыток, перегон, без продажи бота — пауза.

## Что НЕ доказано / не покрыто

- Путь `executor::accepted → run → board → release` целиком (нужны площадки; на стенде без площадок сделка не идёт).
- Live-источник (`costs_source.rs`) с котировками шлюза: что сдвиг реально попадает в расчёт кандидата и предпроверки —
  по коду, тестом не проверено.
- Симуляция продажи DEX при монетах впереди — нужна запись `dex_presell`.
- Свежесть стакана по времени получения: кадр, полученный после ответа на наш ордер, отражает наше исполнение —
  предположение (порядок отправки биржей не проверен); защита сверху — лимит IOC покупки = худший уровень плана
  (решение 262) и minOut / пересчёт DEX (решение 381).
- DEX: `DexRoute.block` — наименьший блок пулов маршрута; пул маршрута, не тронутый нашей покупкой, со старым блоком
  даёт отказ (лишний — в сторону «не торговать»).
- Дневной лимит убытка: проверяется на каждую сделку (risk::can_open), но нереализованный убыток идущих сделок в нём
  не учитывается — как и сейчас у сделок разных монет.

## Проверить на живом боте (чтением) после выкладки и задания money.max_deals_per_coin

- Журнал core.deal_closed / хронологии: две сделки одной монеты с пересечением по времени; у второй «План: объём …» —
  бюджет за вычетом первой.
- core.start_refused / «Кандидаты»: причины «встречная сделка: …», «по монете идут N сделки — предел …»,
  «… не на пути «перевод / продажа» …»; core.precheck / отказы расчёта: «данные старше покупки сделки …».
- Хронология удачных: «Пауза направления не поставлена: сделка удачная …».
- Сверка балансов (reconcile) — без расхождений при двух сделках одной монеты на одной площадке.

## Какие решения меняет

- 118 (Я-2): одна сделка на монету → замок целиком до учёта покупки, потом до money.max_deals_per_coin.
- 105 / route_cooldown: пауза после удачной сделки больше не ставится (срыв, отказ, перегон, убыток — как раньше).
- 269 (записка): частично реализована как «следующая сделка» без группы и общего возврата USDT.
