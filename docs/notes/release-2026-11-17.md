## Откат

**На 982e0503 откат совместим, пока exec.top_up не включали и v3 не развёртывали.** Тогда: записи сделок без поля
`group` такие же, как пишет 982e0503; новых таблиц и ключей состояния нет; ключ exec.top_up (если создан в хранилище)
старая сборка прочитает и проигнорирует. Газ неудачных перегонов, уже вычтенный из итогов (п. 5), в итогах останется —
старая сборка их не пересчитывает. **t183 / t184 на откат не влияют:** схема SQLite и ключи настроек не менялись.

Что произойдёт иначе:

- **exec.top_up включали.** Старая сборка поле `group` у сделок не знает: при чтении пропустит (serde игнорирует
  неизвестные поля), при первом сохранении сделки — потеряет. Сделки группы, чья выручка ждёт общего возврата
  (`group.wait`), у старой сборки не имеют части возврата «идёт» — после её запуска эти USDT не будут ни перегнаны, ни
  помечены «USDT не вернулись» (новая сборка делает это при загрузке, core/ledger_load.rs) и останутся лежать на
  площадке продажи без записи (точный вид — гипотеза ревью). Перед откатом: exec.top_up = нет и дождаться, пока все
  группы закончат общий возврат.
- **v3 развёртывали** (этой сборкой невозможно — решение 399; возможно сборкой 5203fdff без этой правки, вручную или
  внешним развёртыванием + PUT /api/wallets/{id}/executor). 982e0503 `version_of` знает только v2 и v1: у кошелька с
  v3 — «код по адресу не совпал», исполнитель этого кошелька не работает (ни approve, ни сделки через исполнитель); метку
  версии «v3» старая сборка не распознаёт. Перед откатом такому кошельку нужен прежний исполнитель v2 (развернуть его
  может только 982e0503).

## Решение 400 (t185): исполнитель v3 — что принято, что НЕ доказано, что проверить первой сделкой

Решение 400 заменяет п. 9 выше: развёртывание v3 разрешено, потому что запись симуляции на живых пулах
(tests/data/executor_v3_live_2026-11-17) приняла два класса шага — **Uniswap V4 без крючка** и **Infinity CL без

**Важно:** если развернуть v3 на кошельке и записать его адрес, через новый контракт пойдут ВСЕ маршруты этого
кошелька, которые идут через исполнитель, — и старые виды шагов (V2, V3, DODO, Solidly и др.), не только V4 / Infinity.
Кроме того, маршруты с шагом V4 / Infinity CL без крючка, которые бандл не собирает (смешаны с другой DEX в одной ноге,
роутеров больше dex.bundle_max_routers, бандл-каналы не готовы, циклы DEX ↔ DEX без бандла), раньше были только
сигналом — теперь это будут настоящие сделки.

**Что запись НЕ доказывает (ревью t185, простыми словами):**
- сравнения с Universal Router не было — правильность проверена только против квотера DEX (там точное совпадение);
- проверено мало и на мелких пулах: по 3 пула на класс, у 5 из 6 пулов круг 20 USDT дал около 0,002 USDT; на глубоком
  пуле путь тот же, но вживую не гонялся;

- нет продажи BNB как монеты сделки (executeNative вместе с шагом 19 / 20) — вживую не проверено;
- нет токенов с налогом (по коду налог на входе — откат всей транзакции, налог на выходе — проверка минимума выхода;
  вживую не проверено);
- нет частичного исполнения (пул взял меньше суммы шага) и отката по минимуму выхода — вживую не проверено;
- старые виды шагов в новом байткоде v3 вживую почти не гонялись (только V2 внутри сплита). По исходнику v2 → v3 — только
  добавления.

симуляции — сделки нет.
