# best_of — «лучший из двух» на DEX-стороне сделки (решение 123)

Слова Тиграна: «мы спрашиваем КС всегда, но если наш маршрут лучше то делаем посвоему».
Включается `exec.dex_best_of` = да [bsc_dex] вместе с `exec.via_kyber` = да. Не задано / нет — как раньше.

| Файл | Что делает |
|---|---|
| `mod.rs` | Включён ли режим (`enabled`) |
| `choose.rs` | Чистый выбор: две котировки (или ошибки) и их затраты вне цены в USDT → кто исполняет и почему. Своя — только исполнимая как есть; полный объём лучше неполного; покупка — меньше USDT, продажа — больше; равенство — своя (Тигран 03.11); на сделке — не хуже `req.worst_price` |
| `extra.rs` | Затраты вне цены в USDT: газ в BNB — по пулу «BNB — USDT» реестра (`quote/pick.rs gas_usdt`), USDT — как есть |
| `quote.rs` | Финальная котировка расчёта кандидата: KyberSwap ∥ своя → победитель от имени bsc_dex, текст выбора в `Quote.pick` |
| `trade.rs` | Сделка: подготовка свопа KyberSwap (`kyberswap/trade_prep.rs`) ∥ свой свежий маршрут → выбор → исполнение победителя со всеми его проверками; победитель отказал до отправки (`pre_send`) — в той же сделке другая сторона, если годна (в обе стороны); после отправки повторов нет; журнал `dex.best_of` |

Ядро о площадках не знает: получает обычную котировку и факт сделки; тексты `Quote.pick` и `TradeResult.executor`
только показывает. Тесты — `tests/bsc_dex_best_of.rs` (выбор на записанных котировках CAKE).
