# t193 — тревоги из Telegram (решение 408), 18.11.2026

Ветка `t193/tg-buttons` от 5f7a0e2a (t191 с текстами тревог). Локально не собиралось (cargo не запускался; сборка,
clippy и тесты — в GitHub). Форматирование — rustfmt (edition 2024) по изменённым файлам.
Запрос Тиграна 18.11: «обрабатывать тревоги прямо из Telegram, без перехода в интерфейс; больше автоматики».

## Механизм (факт кода)

- Кнопки событий каталога (catalog.rs buttons, callback::keyboard, Notifier::send_with_buttons) по-прежнему никем не
  используются. Новое: кнопки ставит МЕСТО события (там известны площадка, кошелёк, монета, сделка) —
  `core/deps.rs notify_acts / notify_tagged_acts` → `notify/acts.rs send_acts / send_tagged_acts`: задание очереди
  уведомлений (queue.rs) с кнопками в task-local (как снимок карточки alert_card.rs); `dispatch.rs deliver` и
  `dispatch_role.rs to_role` берут их оттуда — клавиатура и в «Общем», и в чатах ролей.
- callback_data: «c:…» — тот же, что у меню /menu (menu_press.rs control_action: та же доступность, тот же вопрос
  «Да, …»); «e:<что>.<данные>» — notify/press_event.rs, press_event_money.rs. Данные кнопки — только «что и где»,
  всё остальное читается В МОМЕНТ НАЖАТИЯ (очередь кошелька, ожидание, балансы, сводка перевода, оценка газа, отметка
  настройки), затем «Да/Отмена» (press_confirm.rs ask) и Core::command (журнал core.command: источник, кто нажал).
- Предел callback_data 1–64 байта (https://core.telegram.org/bots/api#inlinekeyboardbutton): у кнопок тревог —
  `acts::keyboard` (длинная — не в клавиатуре, строкой «… — только в интерфейсе» в тексте, как mirror_view.rs);
  в меню — `menu.rs b` (длинная — «… — только в интерфейсе», callback «c:x» → ответ «только в интерфейсе»). Текст —
  fit_text (4096), ответ кнопки — answer_callback (200) — прежние.
- Роли (press.rs accepts): «Неудачные» — теперь и «c», «e»; «Аккаунты» — «y», «n», «c», «e» (Тигран «да»); роль
  «Аккаунты» опрашивается (новая настройка `notify.accounts_users`, без неё — любой участник чата, как у других ролей).

## Примеры сообщений (по коду)

- risk.stop (правило шлюза «стоп площадка» на BingX): текст как раньше + кнопка `[Снять паузу BingX]` (`c:vr.bingx`) →
  «Снять паузу площадки BingX?» `[Да, снять паузу] [Отмена]`.
- risk.daily_loss: `[Сбросить лимит дня]` (`c:dr.x`), `[Старт]` (`c:mode.Running`).
- send.queue_halted (`bsc_dex «MEXC»: отправки остановлены до ручной проверки — …`): `[Снять очередь кошелька]`
  (`e:qh.bsc_dex.w2`) → «Очередь кошелька «MEXC» (bsc_dex) остановлена: … Удержано: nonce 812, транзакция 0x…
  (nonce уже занят в блоке). Кошелёк и транзакция проверены вручную? …» `[Да, снять очередь кошелька] [Отмена]`; nonce
  не занят — «⚠️ Nonce ещё не занят в блоке — висящая транзакция может пройти позже. Всё равно снять очередь?»
  `[Да, снять очередь при незанятом nonce]`.
- usdt.relay_failed (100 USDT DEX «MEXC» → MEXC): `[Перегнать 100 USDT снова]` (`e:tu.bsc_dex/w2.mexc.100`) → «Перевести
  100 USDT с Кошелёк DEX «MEXC» на MEXC? газ BNB с кошелька, дойдёт …, сеть BSC (…).» `[Да, перевести USDT]`.
- risk.low_usdt (BingX): `[Перевести USDT на BingX]` → «Перевести USDT на BingX — откуда?» `[MEXC — 512.3 USDT]` →
  «… — сколько? Можно вывести …» `[Всё (511.3)] [25% (127.825)]` → вопрос «Да, перевести USDT».
- coin.withdraw_refused: `[Открыть вход CAKE с Binance]` (`e:oe.binance.0x0e09…ce82`) → «Открыть входы монеты 0x… с
  Binance? Закрыто после отказа вывода: … Правка настройки coin.entry_blocked_venues — как «Открыть» на экране
  «Монеты», в историю настроек с вашим именем.» `[Да, открыть вход монеты]`.
- Запись «своих монет не видно»: кнопки записи + `[Открыть сделку 20261118…CAKE]` (`e:od.…`).
- Нажатие «Продать сейчас» при идущих сделках: вопрос правится «Ждёт: @tigran (…), «Продать сейчас» — «Продать сейчас»
  по CAKE … ждёт окончания сделок …»; держащая застряла — «… \n\nНе выполнено: «Продать сейчас» по CAKE (нажал …):
  ожидание прервано: …», кнопка записи снова работает.

## Вопросы Тиграну первого коммита (ответы и что сделано — ниже)

- **9а. «Ожидание X по монете Y потеряно при перезапуске» с той же кнопкой.** Факт кода: ожидания — только в памяти
  (`inner.manual_waits`, задача manual_wait_run.rs), после перезапуска их нет и узнать о них не из чего; условие
  «ожидания НЕ хранить» исключает запись в базу. Варианты: (а) при штатной остановке (core/shutdown.rs) отправить по
  каждому ожиданию сообщение «прервано остановкой бота» с той же кнопкой (кнопка записи работает и после запуска —
  по текущим записям экрана) — при падении процесса сообщения не будет; (б) хранить в базе только «ожидание было»
  (что, монета, кто) без команды — тогда после запуска сообщение «потеряно» с кнопкой. Какой вариант?
- **9б. Самоснятие очереди кошелька.** Факт кода: занят ли nonce — есть (wallet/deposit.rs taken, eth_getTransactionCount
  «latest»); квитанции по хешу удержанной транзакции у контракта шлюза нет (нужен новый метод адаптера DEX по
  eth_getTransactionReceipt — execution-apis). И главное — КОГДА проверять: очередь останавливается, когда исход
  транзакции неизвестен (nonce в этот момент обычно не занят), а дальше событий нет — нужна проверка на каждом новом
  блоке (номер блока узла уже опрашивается, решение 57) или по интервалу (настройка). Подтвердите: проверять на
  каждом новом блоке, пока очередь остановлена; совпадение — хеш квитанции = хеш удержанной транзакции и nonce
  занят; при совпадении снять с журналом «снято ботом: квитанция …» и сообщением send.queue_released?
- **Денежные кнопки тревог без срока.** «e:tu», «e:sb» данных не хранят — сумма и доступность проверяются заново при
  нажатии, затем «Да» (номер вопроса — с времени запуска, после перезапуска не совпадёт). notify.dialog_ttl_s
  (решение 176) к ним не применён: это не экран диалога. Если нужен срок у кнопок тревог — скажите.
- **«Продать» пыли.** deal.dust шлётся, когда остаток меньше минимума ордера — «Продать» (всё свободное монеты на
  торговом счёте) пройдёт, только если вместе с другими остатками набирается минимум; иначе — отказ биржи текстом.

## Повторное ревью t193 (третий коммит)

Н1 — «Да» денежных команд со сроком от вопроса, чистка вопросов без ответа (press_confirm.rs, press_event_ttl.rs,
mirror_state.rs); М1 — время тревоги по цепочке перевода (e:tf / e:tx); М2 — сверка остановки и без nonce / hash

null-квитанция — ждать, чужая — человек, ключ закрыт — ждать разблокировки, кошелёк удалён — конец, снятие под замком
очереди (venues/bsc_dex/wallet/auto_release.rs, queue_ref.rs); М9 — чистка wait_ended по сроку (mirror_wait.rs).
М7, М10, М11 — отложены (docs/TASKS.md).
