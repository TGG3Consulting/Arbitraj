# Локальный маршрутизатор DEX — проект (решения 80–82)

> Статус: проект на утверждение Тиграна. Код не начат. Оформлено 2026-10-28.
> Основание: решение Тиграна (28.10) — свой граф-маршрутизатор в ОЗУ вместо чужого API,
> KyberSwap только как ещё одна площадка DEX. Вариант 2: BingX ↔ DEX, BingX в игре.

## 1. Итог решения Тиграна (28.10)

- **Вариант 2:** арбитраж BingX ↔ DEX с транзитным мостом на стороне DEX. BingX остаётся. Миссия
  проекта НЕ меняется — это улучшение ноги DEX, а не новый источник.
- **Свой граф, не чужой API.** Маршруты ищем сами в ОЗУ. KyberSwap Aggregator API для поиска НЕ
  используем (офдока: лимит 3 запроса/с, один запрос = одна пара/сумма, кэш маршрута ≤ 5–10 с —
  «все монеты без отставания» через него невозможно).
- **KyberSwap = ещё одна площадка DEX:** её пулы (KyberSwap Elastic) участвуют в графе наравне с
  Pancake/Uniswap/Biswap; её роутер — одна из целей исполнения свапа, когда путь выгоднее через неё.

## 2. Что УЖЕ построено (НЕ переписываем, переиспользуем)

- **Приватное исполнение ноги DEX:** каналы приватной отправки + бандлы + мин-газ по каналам
  (решения 41–45: 48 Club, BlockRazor, PancakeSwap MEV Guard, Blink, JetBuilder, NodeReal, bloXroute,
  Flashblock). Проверка попадания в блок своим узлом (42).
- **Защита от убытка = amountOutMin:** проверка реально полученного баланса в той же транзакции
  обмена, откат всей tx при недоборе (решение 40) — всегда включена.
- **Математика пулов:** V2, V3 (Pancake/Uniswap), Infinity CL/Bin, Uniswap V4 — `math/*`,
  карта тиков и глубина по сторонам (решение 73).
- **Маршрутизация (частичная):** путь через одну промежуточную монету (решение 52, `quote/via.rs`);
  умный сплит суммы (решение 38, `quote/smart*.rs`); выбор лучшего (`quote/pick.rs`, `select.rs`).
- **Данные:** обнаружение пулов, разбор событий по семействам, ws-источник событий (решение 79).

## 3. Что НОВОЕ (объём работ)

### Решение 80 — полноценный локальный граф-маршрутизатор
Сейчас маршрут ограничен: мост `via` — одна промежуточная монета, а в `smart_ways` мост считается
только по пулам PancakeSwap и по списку `mids`. Это не полный граф по рынку.

Новое:
- **граф токенов в ОЗУ по ВСЕМ отслеживаемым пулам всех DEX** (а не только Pancake на мосту);
- **поиск путей глубины 2–3** (BFS/DFS) через набор промежуточных монет (BNB, USDT и настраиваемый
  список) с любой площадки;
- **сплит суммы между несколькими пулами** одной пары (как агрегатор), нашей математикой (73) и со
  всеми затратами (`quote/costs.rs` остаётся);
- **глобально лучший маршрут на сторону** (покупка/продажа), `amountOutMin` — наш;
- всё в памяти, без внешних вызовов; глубина/ширина поиска — настройки (чтобы держать скорость).

Переиспользуем: `math/*`, `quote/pool_quote.rs`, `costs.rs`, `select.rs`, `pools/mids.rs`; обобщаем
`via`/`smart` в граф. Ядро и шлюз не меняются — расширяется адаптер DEX.

### Решение 81 — KyberSwap Elastic как семейство DEX
- Elastic — концентрированная ликвидность (похоже на V3, но своя: reinvestment liquidity, свой
  tick-механизм, свои Factory/Router/QuoterV2/TickReader, свои события Swap).
- Только по офдокам KyberSwap: адреса контрактов на BSC, ABI событий и свопа, формула шага цены.
- Добавить: `families` (classify), `discover` пулов, разбор событий, математику свопа Elastic
  (отдельный модуль рядом со `swap_cl.rs`), квотер/роутер для сверки и исполнения.
- Исполнение свопа Elastic — через её роутер, тем же путём приватной отправки (41–45).

### Решение 82 — Biswap как семейство DEX
- Biswap — форк Uniswap V2 с иной комиссией пула (уточнить по офдокам/контракту). V2-математика уже
  есть; добавить `families` + `discover` + адреса фабрики/роутера.

## 4. Открытый вопрос по данным (нужно решение Тиграна)

Твоя схема рисует Multicall3 на всё состояние каждый блок. Текущий бот — событийный (ws, решение 79)
плюс чтение глубины по требованию. Два варианта:
- **(A)** оставить событийный (ws) + чтение по требованию, Multicall3 — только на кандидатах и перед
  сделкой. Легче для узла, уже построено.
- **(B)** добавить периодический Multicall3-снимок всех пулов каждый блок. «Полная карта» всегда
  свежая, но тяжелее по узлу (и это та нагрузка, из-за которой были отставания).

Рекомендация: **(A)** — событийный скан + Multicall3 точечно. Подтвердить.
