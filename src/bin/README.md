# src/bin — отдельные программы крейта

Программы собираются вместе с ботом (`cargo build --release` — все бинарники крейта) и пользуются той же
библиотекой (`arb::*`): никакой второй модели или переписанных расчётов.

| Файл | Что делает |
| --- | --- |
| `uncapped_recompute.rs` | Решение 218: один раз пересчитать СТАРЫЕ записи «без потолка» по исполненным сделкам, посчитанные после нашей покупки (basis `live_after_buy` — занижены, решение 217), по записанным окнам сделок. Та же модель и поиск, что у бота (`core/uncapped_recompute*.rs` → `costs::evaluate_with` → `size_uncapped.rs`). `--dry-run` (по умолчанию) — только отчёт, база на чтение; `--apply` — дописать новые записи одной транзакцией, база с исключительной блокировкой (бот должен быть остановлен, иначе отказ «база занята»). Отчёт — stdout и CSV. Инструкция — `docs/notes/uncapped-recompute-2026-11-07.md` |

| `usdt_sent_backfill.rs` | Решение 236, дополнение п. 5: один раз дописать «ушло» (`sent`) в СТАРЫЕ части возврата USDT «вернулись» по журналу `core.transfer_sent` (логика — `core/usdt_sent_backfill.rs`): у записей до решения 236 в затраты возврата попадал остаток округления вывода (MEXC). `--dry-run` (по умолчанию) — отчёт, база на чтение; `--apply` — запись одной транзакцией, база с исключительной блокировкой (бот должен быть остановлен); `--from <площадка>` — фильтр. Инструкция — `docs/notes/usdt-sent-backfill-2026-11-09.md` |

Главная программа бота — `src/main.rs` (бинарник `arb`).

Сборка для Linux (`.github/workflows/linux.yml`) кладёт в артефакт `arb-linux` и `arb`, и `uncapped_recompute`, и
`usdt_sent_backfill`.
