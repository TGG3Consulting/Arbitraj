# venues/bsc_dex/wallet — кошелёк бота

Один кошелёк (решение 45). Ключ — секрет `bsc_dex.wallet_key`, только в памяти, в журнал и ошибки не попадает.

| Файл | Что делает |
| --- | --- |
| `mod.rs` | Модуль |
| `signer.rs` | Ключ кошелька счёта (решение 132; без счёта — кошелёк «пробы», подпись запрещена) → подписант alloy, адрес, подпись EIP-155/EIP-2718, хеш до отправки (тест — официальный пример EIP-155) |
| `nonce.rs` | Строгая очередь (своя у каждого кошелька, решение 132; без счёта место не выдаётся): одна транзакция кошелька за раз, до занятия её nonce в блоке; nonce — `eth_getTransactionCount(адрес, "latest")`, не меньше запомненного |
| `deposit.rs` | Статус зачисления со снятием ожидания поступления, отказ от депозита, состояние и снятие очереди кошелька |
| `inflows.rs` | Ожидаемые поступления в кошелёк и идущие обмены: не совпадают по времени (база BALANCE_CHECK_ERC20) |
| `events.rs` | Решение 76: изменения баланса кошелька событиями (venue.balance_events) — подписка logs Transfer на кошелёк и с кошелька у источника пулов, ждёт send.deposit_confirmations блоков, отменённое реоргом снимает; событие ядру MarketEvent::Balance |
| `events_log.rs` | Фильтры «Transfer на кошелёк / с кошелька», разбор лога (направление, сумма, ключ лога) |
| `events_tx.rs` | Своя ли транзакция (eth_getTransactionByHash.from = кошелёк) и перевод в формате ядра (WBNB и токены вне подписки — тикер = адрес) |
| `events_native.rs` | BNB по блокам, пока ожидается BNB: баланс и nonce на «голова − подтверждения»; своя транзакция в блоках — не раскладываем, решает опрос |
| `balances.rs` | Балансы: BNB (`eth_getBalance`) и известные токены (`balanceOf`); WBNB нативной монеты (решение 62) — в locked строки BNB |
| `balances_mc.rs` | Все балансы кошелька одним eth_call Multicall3: getEthBalance + balanceOf, частями по dex.load_batch (решение 113) |
| `allow_cache.rs` | Разрешения кошелька для котировки в памяти до любой его транзакции (решение 61): котировка не читает их с узла на каждом тике; с решения 122 — и ERC-20 allowance исполнителю ArbExecutor (`erc20`) |
| `approve.rs` | Разрешения ERC-20 → Permit2 и Permit2 → Universal Router: каких не хватает (`dex.approve_unlimited`, `dex.permit2_expiration_s`); прямой ERC-20 approve роутеру форка |
| `approve_executor.rs` | Решение 122 (часть X): разрешения своему исполнителю ArbExecutor — прямой ERC-20 approve без Permit2 (`missing`, `all`), `allowance` для памяти котировки |
| `transfer.rs` | Перевод монеты из кошелька на адрес (вывод на биржу); BNB (решение 62) — нативный перевод value, сверх резерва на газ; «вытеснена» — OutcomeUnknown с «чем найти» и хешами отмен (выяснение — resolve_withdraw.rs) |
| `transfer_cost.rs` | Стоимость перевода: газ пробного перевода × цена газа и налог на перевод; BNB — газ пробного нативного перевода, без налога |
| `native_status.rs` | Статус нативного перевода BNB по самой транзакции (eth_getTransactionByHash: from, to, value) — у него нет события Transfer |
| `transfer_status.rs` | Статусы вывода и зачисления по квитанции; «Зачислен» — ненулевой Transfer на кошелёк и `send.deposit_confirmations` блоков |
