# venues/bsc_dex/exec/executor — свой контракт-исполнитель ArbExecutor (решение 122, часть X)

Контракт — `contracts/ArbExecutor.sol` (разбор безопасности — `contracts/README.md`). Графовый маршрут формы «бандл»
(не один Universal Router) при заданном `exec.executor_address` уходит **одной транзакцией** через исполнитель;
не задан — бандлом, как раньше (решение 84). Публичный интерфейс для новых семейств (часть F): `kind.rs` и `call.rs`.

| Файл | Что делает |
| --- | --- |
| `mod.rs` | Адрес исполнителя из настроек (`address`) и выбор пути (`takes`: граф «бандл» + адрес задан) |
| `abi.rs` | Типы ABI контракта — `alloy::sol!` из `contracts/out/ArbExecutor.abi` |
| `kind.rs` | ПУБЛИЧНЫЙ кодировщик шага: `Params` (вид и параметры; `StableU256Bnb` — пул с нативным BNB, вид 11), `StepSpec`, `encode` → `ArbExecutor::Step`; номера видов = константы контракта (V2 = 0 … ELASTIC = 8, STABLE_U256 = 9, SADDLE = 10) |
| `onchain.rs` | Ревью 122, пункт 1: до approve и сделки — код по `exec.executor_address` побайтно = `ArbExecutor.bin-runtime` и владелец (слот `owner`) = кошелёк бота; успех помнится по паре (адрес, кошелёк); кнопка «Проверить подключение» исполнителя (`probe`) |
| `entry.rs` | Шаг исполнителя для пула реестра по пометке части F (`Family.executor_kind`, pools/exec_kind.rs): V2 с комиссией пары, V3, Algebra, Solidly, DODO, Maverick; StableSwap — CURVE (Ellipsis), STABLE_U256 (PancakeSwap Stable, Lista), SADDLE (Nerve): индексы из состояния по токену входа, пул на паузе — нет; нет вида шага (Infinity/V4, KyberSwap Elastic — решение 121 B2) — исполнителем не вызывается |
| `call.rs` | Вызов `execute` из долей (шаги exec/chain.rs): доли входа в bps от текущего остатка, промежуточный шаг — весь токен, вход и минимум — суммы долей, срок `dex.deadline_s` |
| `sim.rs` | Проба `execute` перед отправкой (eth_simulateV1) и сверка полученного с `req.worst_price`; откат — с minOut, ожидаемым и модельным налогом каждой доли (решение 234, п. 4) |
| `remeasure.rs` | Решение 247: проба execute с пере-замером — откат ровно по minOut у продажи выхода: та же продажа с minOut 1 ед. (R), граница min(R, выход при налоге в сети), minOut = граница × (1 − допуск) при границе не ниже порога ядра; монета — во внеочередную перепроверку налогов |
| `trade.rs` | Сделка через исполнитель: доли по живому состоянию, минимумы верификации, approve исполнителю (после него — пересборка, решение 121 B1), проба, одна транзакция, факт |
| `fact.rs` | Факт по Transfer (exec/result.rs) с учётом возврата неистраченного входа исполнителем |
| `code.rs` | Артефакты `contracts/out/` со сверкой SHA-256: код создания, код в сети, слот владельца |
| `dry.rs` | Сухая сделка через исполнитель: «как сделка» (развёрнутый) или «через исполнитель» (код и владелец подставлены в симуляцию на будущий адрес развёртывания) |
| `deploy.rs` | «Развернуть исполнитель»: оценка (газ, цена, BNB/USDT, будущий адрес) и транзакция создания через очередь кошелька — только по подтверждению человека; проверка кода в сети |

Разрешение кошелька исполнителю — обычный ERC-20 `approve` (без Permit2): `wallet/approve.rs` (`executor_missing`,
`executor_all`), память для котировки — `wallet/allow_cache.rs::erc20`, газ approve в котировке — `quote/approve_gas.rs`.
