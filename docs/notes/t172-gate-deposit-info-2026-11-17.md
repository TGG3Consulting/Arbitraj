## Причина (код до решения 387, b23c7a09)
- Минимум депозита Gate — только в ответе адреса депозита: venues/gate/deposit_addr.rs (fetch, min_deposit_amount) →
  wallet.rs note_deposit → networks_parse.rs (deposit_min из Extra).
- Фоновый круг venues/gate/deposit_info.rs шёл по ВСЕМ монетам подписки по одной с паузой
  1/venue.deposit_info_requests_per_sec (2/с → ~1070 × 0,5 с ≈ 535 с), без повтора при сбое, затем сон
  venue.deposit_info_refresh_s (3600 с), ничем не прерываемый.
- Минимум, полученный кругом, ядро видело не сразу: справочник Gate отдаётся из кэша (wallet.rs shared, окно
  venue.networks_fresh_ms), минимум попадал в него только при следующей сборке, а ядро — при следующем опросе
  (registry_sync.rs).
- Расчёт отсекал кандидата раньше предпроверки: costs.rs `cx.check_deposit(arrive)?` (dirctx_venue.rs check_deposit:
  минимум None → Fail::Stop), а адрес депозита (и с ним минимум) запрашивался только в предпроверке.
- На записи справочника Gate 04.11 (tests/data/cex_samples_2026_11_04/gate_spot_currencies.json) ввод в сети BSC
  закрыт (deposit_disabled сети BSC или delisted) у 724 из 1075 монет с сетью BSC; на живом — 728 «deposit disabled» из
  1070. Что это одни и те же монеты — гипотеза (совпадение чисел), проверка — по журналу после выкладки (TASKS).

## Что сделано
1. Ядро, core/deposit_min_ask.rs: DirCtx::build (и relay_value deposit_ok) видит у B запись сети без минимума → запрос
   сведений монеты у B сразу через существующий Venue::coin_networks_of (как предпроверка), ответ — в справочник ядра
   (core/networks_merge.rs — код вынесен из precheck.rs без изменения смысла), пересборка. Очередь по бирже (по одному,
   в порядке обращений). Ответ получен — больше не спрашиваем до смены секретов (у бирж без минимума в API — не
   спамим); сбой — повтор не раньше интервала опроса справочника сетей биржи (venue.networks_poll_ms /
   venue.status_poll_ms) или сразу после Core::secrets_changed (forget).
2. Gate coin_networks_of (mod.rs): минимум не получен и venue.deposit_min_absent_ok не «да» — адрес депозита
   запрашивается одновременно с тремя запросами сетей монеты (tokio::join — на пути предпроверки лишнего времени нет),
   сведения монеты переносятся в записи (deposit_min.rs apply). Временный сбой адреса — ошибка (ядро повторит).
   Запись Extra из currency_chains теперь — чтение и запись под одной блокировкой (не затирает одновременный минимум).
3. Gate note_deposit: новый минимум и подтверждения сразу и в собранный справочник (кэш) — опрос ядра не затирает
   минимум прежним справочником.
4. Фоновый круг (deposit_plan.rs + deposit_info.rs): не спрашиваются монеты с закрытым по последнему справочнику Gate
   вводом в BSC и без сети BSC (справочника нет — все, как раньше); сначала неизвестный минимум; сбой временной
   причины (SecretsLocked, Unreachable, Timeout, RateLimited, VenueNotConnected) — повтор только этих монет, как только
   справочник Gate снова получен удачно (Networks::mark_fetched в shared; после разблокировки ядро перечитывает
   справочники); «секреты закрыты» прекращает круг; пауза между полными кругами прерывается сменой настроек круга
   (venue.deposit_info_*, venue.bsc_network, venue.deposit_min_absent_ok; вся система или gate).
5. Кэш на диске — не вводился (вопрос владельцу в TASKS).

## Через сколько «→ gate» откроется по монете с сигналом (по коду, 2 запроса/с)
Фоновый круг больше не на пути: первый расчёт направления «X → gate» с неизвестным минимумом ставит запрос. Путь:
ask (микросекунды) → очередь Gate (если она пуста) → coin_networks_of Gate: max(1 запрос адреса депозита; 3
последовательных запроса сетей монеты) ≈ 3 RTT → запись в справочник ядра + пересборка → следующий тик кандидата
считается с минимумом. Число venue.deposit_info_requests_per_sec на этот путь не влияет. Время одного
coin_networks_of на живом (замеры 13.11, все биржи, docs/FIRST_RUN.md precheck.networks_memory): 3–1044 мс. Итого для
первой монеты с сигналом — порядка 1 с после её первого кандидата (плюс время пересборки справочника, не замерено);
k-я монета в очереди Gate — примерно k × время одного запроса. Было: позиция монеты в списке подписки × 0,5 с (до
~535 с) плюс окно кэша справочника Gate и опрос ядра.
Монеты без сигнала получают минимум фоновым кругом: ~342–351 монет с открытым вводом × 0,5 с ≈ 171–176 с,
неизвестные первыми.

## Другие биржи
Минимум депозита у остальных бирж — поле справочника сетей (BingX depositMin, Bybit depositMin, KuCoin depositMinSize,
OKX minDep, Bitget minDepositAmount, HTX minDepositAmt, CoinEx/XT/Phemex — свои поля; Kraken — методы депозита
minimum_amount; MEXC и Poloniex — поля нет, venue.deposit_min_absent_ok). Схемы «минимум только из адреса» нет —
адаптерных правок не нужно; запрос ядра по требованию — общий и работает для всех (у бирж без минимума в API — один
ответ на монету, без повторов).

## Без теста на записи
Порядок ожидания круга (select: настройки / справочник / срок), очередь ядра с запросом к бирже и запись ответа в
справочник — асинхронные пути с сетью; покрыты чистой логикой (due, plan, transient, apply) в tests/gate_deposit_plan.rs.
