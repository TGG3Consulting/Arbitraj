# SETTINGS — каталог настроек

> Каждый параметр системы описан здесь и в `src/settings/schema.rs`. В коде значений нет.
> **Стартовых значений нет.** Все параметры задаёт Тигран в интерфейсе.
> Параметр не задан → функция, которой он нужен, не работает, а интерфейс показывает, что его нужно задать.
> Торговля не включается, пока не заданы все параметры групп `money.*` и `risk.*`.
> Новый параметр → строка здесь + описание в `schema.rs` + поле в интерфейсе (экран «Настройки»).
>
> **Советуемые стартовые значения** (с чего начать на первом запуске) собраны в `docs/FIRST_RUN.md` и на экране
> «Первый запуск» (`GET /api/first-run`, источник — `config/first_run.toml`). Это советы, а не значения по умолчанию:
> подтверждает и сохраняет их Тигран сам, автоматической записи нет.
>
> **Импорт/экспорт** (экран «Импорт/экспорт настроек», `GET /api/settings/export`, `POST /api/settings/import`):
> все настройки можно залить разом одним файлом TOML (имя + область + значение) и выгрузить для бэкапа/переноса.
> Импорт применяет значения через то же хранилище (с журналом изменений и проверкой по схеме), новых настроек не
> вводит. Секреты (`docs/SECURITY.md`) в обычный экспорт не входят; «Экспорт с секретами» добавляет их ТОЛЬКО в
> зашифрованном виде (файл хранилища как есть), не открытым текстом.

## Подбор объёма (решение 66)

Объём сделки ищется так, чтобы прибыль в долларах после всех затрат была наибольшей при вложении ≤ бюджета; пороги
money.min_profit_* проверяются только после. Каждая точка поиска — полный расчёт (core/costs.rs). Не задана любая из
пяти — подбора нет, сделок нет (отказ «не задана настройка»).

| Имя | Что означает | Единица | Область |
| --- | --- | --- | --- |
| size.bisect_steps | Наибольшее число шагов бисекции каждой границы объёма: наибольший (вложение в бюджете, глубина) и наименьший (минимумы вывода, депозита, суммы ордера). Точная граница до шага монеты — log2(объём / stepSize) шагов; не хватило — безопасная сторона | шагов | вся система |
| size.grid_points | Равномерных точек между границами сверх изломов стакана — ловят изломы, которых ядро не видит (тики пула, смена маршрута DEX) | точек | вся система |
| size.refine_steps | Наибольшее число шагов тернарного поиска у каждого локального максимума прибыли (уточняются все) | шагов | вся система |
| size.max_evals | Общий предел полных расчётов на одного кандидата. Исчерпан на границах — отказ; дальше — лучший из посчитанных (все в бюджете) | расчётов | вся система |
| size.tolerance_pct | Уточнение у максимума останавливается, когда отрезок не шире этой доли наибольшего объёма (не точнее шага монеты) | % | вся система |

### Каналы отправки (область «канал», id — из списка адаптера DEX)

Ключ канала — секрет `channel.<id>.key`; если по документации канала ключ стоит в адресе — в `channel.url` пишется `{key}`.
Открытая отправка (`public`) идёт через узел или провайдера: `{key}` в её `channel.url` заменяется ключом узла — секрет `bsc.node_http_key` (как в `bsc.node_http_url`).

Поиск пулов (решение 58): из справочника индексатора (раздел «Справочник пулов») с проверкой каждого пула на своём узле;
новые пулы между обновлениями — события создания своих фабрик и менеджеров. История V4 `Initialize` — необязательна
(dex.history_scan): от блока развёртывания менеджера (бинарный поиск `eth_getCode`), блок и пулы — в SQLite (`venue_state`);
ей нужен узел с историей состояния — «Проверить подключение» показывает это, когда история включена.
Канал с ключом не используется, пока ключ не введён (решение 41). Несколько закрытых каналов — параллельно и без чаевых;
открытый канал — только один, не вместе с закрытыми (решение 33).

## Области значений

Значение задаётся для области: вся система, площадка, монета, событие, DEX, канал отправки.
Для системы, площадки и монеты действует самое узкое заданное: монета сильнее площадки, площадка сильнее всей системы.
Событие, DEX и канал — отдельные предметы: значение задаётся ровно для своего id, без подстановки.
Для какой области можно задавать настройку — в `src/settings/catalog/`.

| Область | id | Откуда список id |
| --- | --- | --- |
| Площадка (`venue:`) | `bingx`, `bsc_dex` | реестр шлюза (`GET /api/venues`) |
| Монета (`coin:`) | тикер | справочник монет |
| Событие (`event:`) | код события | `src/notify/catalog.rs` |
| DEX (`dex:`) | имя DEX (`pancakeswap`) или вид пула (`pancakeswap_v3`) | адаптер DEX: `dex_families()` |
| Канал (`channel:`) | id канала (`club48`) | адаптер DEX: `send_channels()` |

Почему DEX и канал — свои области, а не «площадка»: это части одного адаптера `bsc_dex` (один кошелёк, один узел),
а не отдельные площадки реестра; у них свой набор настроек, и подстановка «монета → площадка → система» к ним не подходит.

## Виды значений

`Decimal`, `Integer` (может иметь верхнюю границу `max`), `Bool`, `Text`, `Url` (https/wss; http/ws — только адрес-петля 127.0.0.0/8, ::1, localhost — свой узел на том же сервере, решение 121), `TextList`, `Ip`,
`Choice` (один из вариантов `choices`), `Address` (адрес BSC: 0x + 40 hex), `AddressList` (список адресов BSC). Описание — `src/settings/schema.rs`.

Область «площадка» у настроек времени в пути (`profit.transit_*`) означает **площадку, с которой переводим** (решение 51):
`bingx` — вывод BingX → кошелёк, `bsc_dex` — кошелёк → биржа. В схеме это `venue_role: "TransferSource"`; интерфейс подписывает области направлением.
