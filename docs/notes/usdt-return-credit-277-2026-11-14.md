# Сверка шести возвратов USDT 14.11.2026 (решение 277, ревью)

Источник — живой бот (веб-интерфейс 127.0.0.1:8787, только GET): `/api/deals` (поле `usdt_return`, план — строка
затрат `UsdtReturn` этапа «возврат USDT»), `/api/journal?limit=10000` (окно журнала 17:19–20:06 UTC 14.11),
`/api/settings`.

## Формула (core/credit_expect.rs arrival, ветка справочника сетей)

ожидаемый приход = (выведено − комиссия вывода из справочника сетей отправителя) · (1 − налог перевода USDT / 100).

- **выведено** — `usdt_return.sent` (сумма после округления до точности вывода, transfers.rs floored_on; её же получает
  credit_expect::ticket).
- **комиссия вывода** — справочник сетей ядра. Через GET бот справочник USDT не отдаёт (`/api/coins/0x55d3…7955` — 404:
  USDT нет в справочнике монет). Значение — строка плана сделки `UsdtReturn` (costs_withdraw.rs return_b → fee_line —
  тот же справочник сетей, запись USDT сети BSC у биржи B; поиск dirctx_venue::quote_network — по тикеру, у
  credit_expect — dirctx_venue::network — по адресу и тикеру). Что у всех шести возвратов credit_expect дошёл до налога
  (то есть запись сети и комиссия в справочнике были), — факт журнала: причина «USDT: налог перевода не проверен»
  пишется только после успешного fee_for (credit_expect.rs, ветка Some).
- **налог перевода USDT** — замер пробы переводов (журнал dex.check 17:31–17:32: «USDT: налоги перевода измерены
  (eth_simulateV1): из пула 0%, в пул 0%, на адрес 0%»).
- **допуск** — transfer.credit_amount_tolerance_pct у bsc_dex = 1 (%). transfer.credit_by_event у bsc_dex не задан
  (событие прикрепляется, но не закрывает — закрывает статус; has_event снимает «поступления на балансе нет»).

## Хеш и порядок событий

- Хеш события DEX (`Transfer в блоке …, хеш …`) у всех шести **совпал** с хешем вывода от биржи (core.transfer_sent).
- Событие DEX приходило **раньше** хеша от биржи (на 2–13 с): AVAX 17:54:27 / 17:54:31, CREO 18:05:59 / 18:06:01,
  CREO 18:15:46 / 18:15:51, XTER 18:18:10 / 18:18:23, TST 18:48:10 / 18:48:23, TST 18:52:11 / 18:52:22.
- По коду (credit_event.rs deposit, credit_watch.rs set_tx): событие с хешем до хеша отправителя прикрепляется по сумме;
  set_tx с тем же хешем его оставляет — has_event = да, credit_mismatch::no_event расхождения не пишет. Ложного
  core.credit_mismatch / exec.credit_mismatch по этим данным не будет. Тест того же пути —
  tests/core_usdt_return_tax_277_hash.rs.

## Что не проверено фактом

- Значение комиссии в справочнике сетей ядра на момент возврата напрямую не видно (нет GET); взято из плана сделки
  (тот же справочник, момент решения). Комиссия BingX 0.15 совпадает с записью config_getall 2026-10-24.
- MEXC «USDT-BSC» в затрате факта (withdraw/history `coin`) — не трогалось, см. docs/TASKS.md (нужны сырые ответы).
