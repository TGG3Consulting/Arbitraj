# Итог сделки: аудит «план ↔ факт» и затраты возврата USDT (09.11.2026, решение 236)

Повод — Тигран 08–09.11: «Везде, всегда должна быть точная, чёткая, честная, правильная сумма с учётом ВСЕХ затрат —
и в расчёте (плане), и в фиксации прибыли/убытка». Разбор docs/notes/price-move-vs-reserve-2026-11-09.md (раздел «Курс»,
п. 1; сделка PIT). Данные — живой бот, только чтение: GET /api/deals (2374 сделки), GET /api/journal
(core.transfer_sent, 31.10 21:41 — 08.11), GET /api/gas-stats. Ветка t45/deal-accounting.

## 1. Как считается итог (факт кода, до правки)

- План: `profit = proceeds − invested − costs_usdt` (src/core/costs.rs:194). В costs_usdt — все строки не «в цене»
  и не «в количестве» (costs.rs:170–177).
- Факт: `result_usd = proceeds − invested − spent` (src/core/ledger.rs:72–74, finish). Покупка → invested, продажа →
  proceeds (src/core/fills.rs:99, 103); комиссия в монете → qty (fills.rs:68), иначе → spent по живой цене
  (fills.rs:72), Fee.usd (баллы HTX) → spent как есть (fills.rs:109); перевод: qty = дошло (fills.rs:143), затрата не
  в монете (газ) → spent (fills.rs:148).
- Возврат USDT — после закрытия (ledger.rs, usdt_return_deal::prepare), итог не менял: `relay_try` отбрасывал вывод
  (`let (_, t) = …`, газ кошелька терялся), состояние «вернулись» хранило только amount/credited.

**Затраты возврата USDT в ПЛАНЕ есть** — costs.rs:125–139: при `usdt_return.mode = per_trade` (dirctx.rs:209 cx_return)

На данных: план UsdtReturn есть у 1116 сделок; у бирж-отправителей план = факт комиссии (BingX 0.15, Bitget 0.01,

площадок, где продажа не планировалась (непланируемые пути).

## 3. Что исправлено (решение 236)

1. Затраты части «вернулись» = **ушло с площадки** (запрос вниз до точности и шага вывода — `transfers::floored`, та же
   функция, что в самом выводе) − **зачислено** + **затраты вывода не в USDT** в USDT (газ BNB кошелька — `fills::usdt` по
   живой цене; нет цены — в итог не входит, строка в хронологию и журнал). Комиссия вывода в USDT — уже в разнице
   (на данных: BingX, Bitget, Gate — разница = комиссии справочника). Остаток округления (запрошено − ушло) лежит на
   площадке-отправителе — не затрата: MEXC выводит USDT с точностью 0.1 (HELLO: запрошено 27.6554, ушло 27.6, зачислено
   27.59 → затраты 0.01, остаток 0.0554 на MEXC).
2. Вычитается из `result_usd` по каждой части при «вернулись» (usdt_return_state::set → deal_return_cost::apply),
   идемпотентно (Deal.return_cost_usd — уже вычтенное); поправка — в итог дня (daily::settle −затраты), итог монеты
   (gas_stats), журнал core.usdt_return.
3. «Не вернулись» — деньги на площадке, затраты не было; «перегнано вручную» — зачисление неизвестно. Оба — без затрат
   в итоге, в алерте строка «Возврат USDT: … стоимость неизвестна, в факт не вошла» (вопросы 2, 3).
4. Telegram deal.closed при идущем возврате ждёт его конца (Deal.closed_notice, переживает перезапуск; при повторах
   решения 163 — до их итога): «Факт», заголовок и чат «Сделки» / «Неудачные» — по итогу с возвратом; строка
   «Возврат USDT». Экран «Сделки» и отчёт «Итоги сделок» берут result_usd — уже исправленный.
5. «Продано вручную» (PIT): вопрос был «Сколько USDT вы получили за 729.325787234 PIT? Сделка закроется этой выручкой» —
   выручку продаж бота (44.8595) не называл; человек ввёл 44.88 (вся сделка), ядро прибавило к выручке бота
   (manual_halted.rs:235) → proceeds 89.74, итог +44.78. Теперь вопрос и подтверждение называют выручку бота
   («уже в итоге, их не вводите»), у остановленной сделки строка «Выручка бота», хронология и ответ — обе части и сумма.
   Честный итог PIT (0 за 729 PIT): 44.8595 − 44.8831 − 0.0722 = **−0.0958** (тест tests/core_deal_accounting_236.rs).

**Старые записи:** пересчёт при загрузке в памяти (ledger_load.rs), запись в базе не меняется. Точно — для всех бирж,
кроме случаев округления вывода: в записи нет «ушло», поэтому затраты = запрошено − зачислено (вместе с остатком
округления). Факт «ушло» есть только в тексте журнала (core.transfer_sent «<id>u <сумма> USDT: …»); читать журнал при
каждом запуске — полный проход таблицы без индекса (сотни тысяч записей в сутки), поэтому не сделано (вопрос 1).
Газа возврата из кошелька DEX в старых записях нет — не восстанавливается. Итоги прошлых дней не пересчитываются.

## 5. Вопросы Тиграну

1. **Старые записи с округлением вывода (MEXC, 145 возвратов, 6.34 USDT):** факт «ушло» — только в журнале. (а) Разово
   дописать «ушло» в записи сделок из журнала core.transfer_sent (отдельной программой при остановленном боте, как
   uncapped_recompute) — тогда итоги точные; (б) оставить «запрошено − зачислено» (сверху). Сейчас — (б), на экране
   пометка у таких записей.
2. **«Перегнано вручную»:** зачисление неизвестно — затраты возврата в итог не входят. Спрашивать у человека «сколько
   зачислено» при нажатии?
3. **«Не вернулись»:** USDT лежат на площадке продажи — затрат нет, итог без них. Согласен? (После «Перегнать» —
   затраты войдут по факту.)
4. **deal.closed ждёт конца возврата** (секунды–минуты; при повторах решения 163 — до их итога). Так подходит, или слать
   сразу и вторым сообщением «итог с возвратом»?
5. **Защита ввода «Продано вручную»:** сейчас только понятный вопрос. Нужна ли проверка «ввод больше стоимости остатка
   по рынку больше чем на N %» — тогда нужна настройка N.
6. **Дыры факта вне возврата (не исправлены):** газ approve (адаптер DEX не отдаёт его ядру; план 1.5 USDT на 231
   сделку), газ откатившихся / отменённых свопов сделки биржа ↔ DEX (только в статистике монеты; на данных
   0.000014 BNB), чаевые канала (сейчас не заданы). Исправлять (газ approve — в TradeResult.fees, газ отката — в
   spent сделки)?

## 6. Дополнение 09.11 (техлид по поручению Тиграна, ветка t50/accounting-2)

1. **Газ вне итога обмена — в итоге сделки** (вопрос 6): approve (адаптер отдаёт газ разрешений по квитанциям —
   ChainTx::approve_gas_bnb у успеха, GatewayError::approve_gas_bnb у ошибки), чаевые канала (ChainTx.tip_bnb), газ
   откатившихся / отменённых / неисполненных обменов сделки биржа ↔ DEX, газ неудачного вывода из кошелька DEX (откат,
   отмена, занявшая nonce). Один раз, BNB → USDT живой ценой (fills::usdt), строка «Газ вне итога обмена» в хронологии
   (core/deal_gas.rs). Факта нет и не входит: газ транзакции перевода чаевых, газ вывода, найденного после «исход
   неизвестен».
2. **«Перегнано вручную»** (вопрос 2): бот спрашивает, сколько USDT зачислено (ответ числом, «-» — не знает). Затраты
   возврата = сумма части − зачислено — в итоге, как у «вернулись» (сумма части — «ушло»: бот не знает, сколько вывел
   человек). Больше суммы части, меньше нуля, не число — отказ с причиной.
3. **Проверка ввода «Продано вручную»** (вопрос 5): manual.sold_max_over_pct — ввод больше стоимости остатка по рынку
   (котировка продажи остатка кошельком сделки, количество × средняя цена) больше чем на N % — отказ с причиной; нет
   котировки — проверки нет, пометка; не задана — как раньше. Совет 20 % (FIRST_RUN, метод).
