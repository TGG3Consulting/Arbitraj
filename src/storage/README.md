# storage — хранение

| Файл | Что делает |
| --- | --- |
| `db.rs` | Открывает SQLite (`<data-dir>/arb.sqlite`), создаёт таблицы, выполняет запросы в отдельном потоке; решение 218 — `open_existing`: уже существующая база для внешней программы (чтение или запись с исключительной блокировкой — бот должен быть остановлен) |
| `journal.rs` | Журнал: запись + живой поток в интерфейс |
| `journal_repeat.rs` | Решение 155: повторяющиеся записи журнала — одна строка на смену причины, счётчик повторов (`repeats`) и время последнего (`last_at`) обновляются в той же строке |
| `rules.rs` | Правила шлюза: список, создание, изменение |
| `wallet_queue.rs` | Состояние очереди кошелька DEX (переживает перезапуск) |
| `episode_files.rs` | Файлы эпизодов арбитражной ситуации (решение 74): `<data-dir>/episodes/<id>.jsonl.zst`, запись в отдельном потоке, занятое место |
| `episodes_db.rs` | Список эпизодов (таблица `episodes`: id, начало, JSON сводки) |
| `windows_db.rs` | Список окон (решение 125; таблица `windows`: id, начало, тикер, была ли сделка, итог, JSON сводки) — страница с фильтрами монеты, сделки и итога. Файлы окон — тот же `episode_files.rs`, папка `<data-dir>/windows` |
| `uncapped_db.rs` | Записи расчёта «без потолка» (решение 141; таблица `uncapped`: вид, id сделки, тикер, начало, JSON) — выборка за период, запись сделки, уборка по сроку; решение 218 — записи сделок для пересчёта по окнам (`deal_rows`) и запись новых строк одной транзакцией (`insert_all`) |
| `venue_state.rs` | Найденные адаптером факты, которые не нужно искать заново (площадка, вид, id → значение) |

Таблицы: `settings`, `settings_history`, `rules`, `journal` (решение 155: столбцы `repeats`, `last_at` — у повторяющихся записей; старая база получает их при открытии, db.rs ADDED_COLUMNS), `wallet_queue` (очередь кошелька DEX — площадка, JSON состояния), `venue_state` (факты адаптеров: блок развёртывания контракта, история пулов V4 — площадка, вид, id, значение), `daily_result` (итог дня по датам: фактический и предварительные убытки сделок — core/daily.rs, решение 53), `core_state` (учёт ядра: сделки, переводы, газ, ручное управление — вид, id, JSON; core/persist.rs). `episodes` (сводки эпизодов, решение 74 — episodes_db.rs). `uncapped` (расчёт «без потолка», решение 141 — uncapped_db.rs). `dex_wallets`, `dex_wallet_map`, `dex_wallet_meta`, `dex_wallet_history` — кошельки DEX и маппинг «биржа → кошелёк» с историей (решение 132; settings/accounts/), ключей там нет — только имя секрета. Сырые сообщения и записи эпизодов — файлы zstd (raw_log.rs, episode_files.rs).
