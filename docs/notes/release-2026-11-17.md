## Откат

**На 982e0503 откат совместим, пока exec.top_up не включали и v3 не развёртывали.** Тогда: записи сделок без поля
`group` такие же, как пишет 982e0503; новых таблиц и ключей состояния нет; ключ exec.top_up (если создан в хранилище)
старая сборка прочитает и проигнорирует. Газ неудачных перегонов, уже вычтенный из итогов (п. 5), в итогах останется —
старая сборка их не пересчитывает.

Что произойдёт иначе:

- **exec.top_up включали.** Старая сборка поле `group` у сделок не знает: при чтении пропустит (serde игнорирует
  неизвестные поля), при первом сохранении сделки — потеряет. Сделки группы, чья выручка ждёт общего возврата
  (`group.wait`), у старой сборки не имеют части возврата «идёт» — после её запуска эти USDT не будут ни перегнаны, ни
  помечены «USDT не вернулись» (новая сборка делает это при загрузке, core/ledger_load.rs) и останутся лежать на
  площадке продажи без записи (точный вид — гипотеза ревью). Перед откатом: exec.top_up = нет и дождаться, пока все
  группы закончат общий возврат.
- **v3 развёртывали** (с этой сборкой невозможно — решение 399; возможно только сборкой 5203fdff без этой правки или
  вручную). 982e0503 `version_of` знает только v2 и v1: у кошелька с v3 — «код по адресу не совпал», исполнитель этого
  кошелька не работает (ни approve, ни сделки через исполнитель); метку версии «v3» старая сборка не распознаёт
  (не сверена). Перед откатом такому кошельку нужен прежний исполнитель v2 (развернуть его может только 982e0503).
