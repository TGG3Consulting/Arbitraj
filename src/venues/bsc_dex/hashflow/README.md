# Hashflow Taker API v3

Модуль использует Multi-Wallet доступ для Ethereum mainnet (1), BSC (56), Base (8453) и Arbitrum One (42161). Официальные роутеры закреплены в `config/hashflow_routers.json`. Идентификатор `hashflow.source` задаётся глобально. Выданный для него ключ `hashflow.taker_key` хранится в vault. Он передаётся только службе Hashflow через Authorization. [Порядок подключения](https://docs.hashflow.com/hashflow/taker/getting-started-api-v3)

**Ручная проверка.** Вызов `POST /api/venues/{id}/hashflow/quote` принимает публичный адрес `trader`, контракты `input` и `output`, а также строчное `amount_tokens` либо `amount` в минимальных единицах. Десятичный объём должен соответствовать decimals входного токена на проверенном блоке. Нативный токен обозначается нулевым адресом. Ответ содержит публичные идентификаторы, селектор, хеш calldata, суммы, срок, газ и хеш канонической головы. У ручной операции отсутствуют подпись кошелька и отправка транзакции.

| Этап | Первичные данные | Условие продолжения |
|---|---|---|
| Поиск рынка | `/market-makers` и `/price-levels` | Сеть и оба адреса совпадают. Один маркетмейкер покрывает весь объём с соблюдением своего минимума. Истёкшие уровни исключаются. |
| Подбор размера | Локальный кэш глубины, баланс, allowance официальному роутеру и запас нативной валюты на том же каноническом блоке | Кошелёк покрывает нужный вход и резерв газа. Стандартные проверки монеты и направления пройдены. Размеры включают изломы уровней. |
| Финальный выбор | Подписанный ответ `/rfq` и данные официального ABI | Проверяются chainId, адрес роутера, селектор, pool, trader/effectiveTrader, токены, суммы, value, nonce, подпись и срок. При одинаковом размере сравниваются расходы и поступления с газом в фактической котируемой валюте площадки. |
| Симуляция | `eth_simulateV1` без overrides, закреплённая каноническая голова | Реальный кошелёк теряет и получает согласованные суммы. Совпадают поля единственного события Trade из указанного пула. |
| До отправки | Очередь nonce, исходный TradeRequest, подписанная транзакция, текущая стоимость сети и резерв газа | Повторная проверка цены, срока и симуляции. Хеш, nonce и публичные параметры разбора хранятся до обращения к каналам. При отмене запроса очередь помнит зарезервированную транзакцию. |
| После отправки | Квитанция исходного хеша | Для успеха нужны Trade и обе ERC-20 передачи кошелька. Фактический газ определяется квитанцией. После перезапуска восстанавливаются тот же запрос и результат. |

**Два правила перехода к AMM**

1. До выбора подписанной цены недоступный источник, устаревшие уровни, недостаточная глубина, отсутствие средств, превышение бюджета ожидания или отказ симуляции возвращают доступный обычный результат. Отсутствие AMM допускает рассмотрение адресной пары RFQ при выполнении остальных требований.
2. После выбора RFQ перейти к обычному исполнителю можно при подтверждённом отказе до сетевой отправки выбранной подписи. Бот заново котирует весь объём, проверяет худшую цену и сопоставляет сумму с газом с денежным пределом сделки. Существующая запись неопределённой отправки требует сверки по прежним nonce и хешу. Подтверждённый результат возвращается повторному вызову, подтверждённый откат либо включённая отмена освобождает этап для следующего решения ядра.

**Параметры допуска.** `hashflow.trading`, `hashflow.levels_max_age_ms`, `hashflow.quote_budget_ms`, `hashflow.min_validity_ms` и `hashflow.gas_budget_native` задаются на площадке. В расчёте объёма резервируется весь лимит газа, на финале применяется модель сети к измеренному расходу. Автоматический путь работает с ERC-20, существующим разрешением и уже доступным на кошельке входом. Для канала с отдельной транзакцией чаевых, нативной стороны либо неполного допуска остаётся обычный маршрут. Запрос firm у оператора требует реальных реквизитов выданного источника. [Каталог сценариев](../../../../docs/SETTINGS_CASES.md)

**Проверки на GitHub.** В `tests/data/hashflow_direct_2026-11-26` сохранены четыре состоявшихся прямых обмена и отдельные контрольные AMM-транзакции. Тесты проверяют ABI, события, движения кошелька, срок, точность суммы, сохранение обычного маршрута при выключенной опции и восстановление из SQLite с заблокированным vault. Уровни и минимум маркетмейкера дополнительно проверяются на опубликованном числовом примере Hashflow. Архивные результаты относятся к указанным блокам. Задержка закрытого API и расходы конкретных договорных условий измеряются при подключении. [Доказательства](../../../../tests/data/hashflow_direct_2026-11-26/README.md)
